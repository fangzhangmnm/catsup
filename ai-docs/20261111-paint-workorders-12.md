# 贴图主线施工单（十二）：画的每一步进三维的撤销栈（1-8a）

> created 20261111 by Claude Fable 5.2 · as-of 三维 v0.19.19、画画 v0.14.75 · 2026-11-11
> 给谁：Catsup小弟。**等 Fable 看过才合。** 分支 `paint-undo`。短施工单：细则你动手前补在页末。没有界面入口，只有调试钩子、测试、探针。
> 这张关系到会不会丢画、撤销会不会把东西弄坏。拿不准的停下来问，不猜。

## 要达到什么

user 定的：画画和建模是一条撤销线。在模型上画一笔、切一刀、再画一笔，按三下撤销，按相反的顺序退回去；重做同理。

## 关键的形状

1. **画板改用 0-2 的 `HostedSteps`**：内核封好的每一步交给三维的撤销栈，不进内核自带的栈。白名单里的 `UndoStack` 删掉。
2. **三维的撤销栈多一种成分「画」**（照 `history.ts` 里网格体、场景那两种成分的写法）：一条记录 = 哪张贴图 + 内核的那一步。翻 = 叫内核翻这一步（方向和顺序内核自己认）；占多少 = 问内核；不要了 = 告诉内核丢掉。
3. **一次手势 = 三维的一步**：一笔画到了几张贴图，就是几条「画」的记录装在三维的同一步里。
4. **改模型让画布加高，和改模型的那一步是同一步**：画板跟着贴图坐标改大小，现在是在每帧的「准备」里做的，挪进指令提交的收尾里（和补位置、强行对称同一个地方），它封出来的那一步并进这条指令的那一步。撤销时一起退。「准备」里不再改大小，只读。
5. **要么全翻，要么不翻**：三维的一步里有好几条记录时，其中一条翻不成（内核说没翻，比如这幅画锁着；或者顺序不对抛了），已经翻过的翻回去，这一步算没做，提示行说清原因。三维的撤销游标不动。
6. **截断和驱逐**：三维的栈丢掉还没重做的那一段、或者因为额度把最老的步挤掉时，里面每一条「画」的记录都要告诉内核丢掉。额度的账里算上画的字节。
7. **内核说「这张画以前的步全部作废」时**（装载、或者状态不可信）：三维的栈里这张贴图的记录全部摘掉，摘空了的步删掉；状态不可信那一种要在提示行告诉用户「这张画的撤销记录清掉了」和原因。刚建画板时收到的那一次是空的，什么都不用做。
8. **撤销、重做之前先封口**：有画板开着写令牌（一笔画到一半）时，先取消这一笔再撤销，不许带着开着的令牌翻。
9. 标签：「画一笔」「擦一笔」进撤销标签表。画的一步落下，文档算改过（没存）。

## 不能破的规矩

- **混着来回逐字节对**：随机一串「画一笔 / 切一刀 / 挤出（让画布加高）/ 擦一笔 / 换材质」，每做一步记下模型和每张画的像素；一路撤销到头，每退一步都和当时记下的逐字节相同；再一路重做回来同样。中间随机插「撤销几步再做新的」（截断）。几个种子。
- **一笔画到两张贴图**：一次撤销两张都退；人为让第二张翻不成：第一张被翻回去、三维的状态和撤销之前逐字节相同、提示行有话。
- **额度**：把额度调小，最老的步被挤掉时内核那边活着的步数跟着减；没有泄漏（内核的小块池泄漏门是零）。
- **画布加高那一步**：挤出让画布加高，撤销之后画板和贴图坐标都缩回去；再重做回来。加高之后在新的行上画过、又撤销到加高之前：那几行是空白所以缩得回去。
- 不画画的时候，撤销的每一步花的时间和内存和现在一样（量一下）。
- 现有的撤销测试一个都不改。

## 碰到这些就停下来报

- 三维的撤销栈没有「一步里某个成分翻不成就整步退回」的地方，要加的话得动它的结构。
- 三维的栈丢一步的时候没有通知成分的口。
- 内核翻步要求的顺序和三维的栈实际翻的顺序对不上（比如三维的一步里成分的先后）。
- 有任何一种情况，撤销之后画和模型对不上，而且不会报错。

## 施工细则

（2026-11-11 晚，Catsup小弟 = Claude Opus 5.5，侦察之后、动手之前写。**第 1、2 条碰到了「停下来报」，等统筹定了再动撤销栈的结构**；别的先做。）

**侦察看到的**
- 内核 `HostedSteps`（0-2）：`onStep(step)` 在一笔落层（档口 `end`）时同步调；`flip(step)` 自己认方向、顺序不对 / 令牌开着 = 抛 `StepOrderError`（什么都没碰）；`bytes` / `drop` / `clear → onReset` 都有。翻不成的唯一表现是**抛**（没有「返回没翻」）。
- 三维 `History`：成分登记制（`UndoComponent`：swap / bytes / dispose）有；丢步（截断重做段、配额驱逐）会调成分的 `dispose`，所以「通知内核丢掉」有口子可接。`record(kind, data)` 能往栈顶那一步挂记录。
- **没有的两样**：① 一步里某条记录 swap 抛了，`undo` / `redo` 停在半路、已经翻过的不翻回去（停止条件第 1 条）；② 没有「摘掉某种成分的一批记录、摘空的步删掉」的口（第 7 条要）。
- 画板跟大小现在在每帧「准备」的 `sync` 里（`board.follow`）；画板在「画没了」时（贴图被清、材质不指它、那一套坐标没了）当场 `dispose`。

**1. 撤销栈的结构要动（停止条件第 1 条；要统筹点头）**
- `History.undo` / `redo` 改成**整步事务**：按原来的顺序 swap，记下翻过的（第几条 op 的第几条记录）；中间有一条抛了 → 把翻过的倒着再 swap 一遍（每种成分都是自反的，再 swap 一次就回去；画的那条再 flip 一次 = 内核自己认出是反方向）→ 游标不动 → 抛一个带原因和标签的错。编辑器接住：场景装回去、提示行「撤销没做成：……」。
- 加一个口 `History.dropRecords(kind, 判断)`：从所有步里摘掉这种成分里判断为真的记录；摘完只剩「记号」（下面第 3 条那种空的 batch 指令）的步整步删掉，游标 / 驱逐线跟着重算。只给第 7 条（内核说这张画以前的步全作废）用。
- 现有撤销测试一个不改；新加：事务（人为让第二条翻不成，场景逐字节回到撤销前）、摘记录（摘空的步消失、游标对）。

**2. 画板不能在「画没了」时扔掉（新发现，同属停止条件第 4 条「撤销之后画和模型对不上、不报错」）**
- 现在：删掉画着的物件、或者撤销「开始画」，画就「没了」，画板当场扔掉；再撤销 / 重做回来，画板是新建的空白一块，它的 HostedSteps 也是新的，三维栈里那些画的记录翻不了（StepOrderError）或者翻进一块空白——**画丢了**。
- 打算：同一份文件开着的期间，画板只在**换文件**时扔掉；画没了 = 画板**歇着**（不合成、不进每帧的活、不占显示图），画回来了接着用（同一块画板、同一个 HostedSteps）。歇着的画板的内存归 1-8b「没在画的画只留显示用的图」一起管。
- 要统筹定：这样做对不对；还是有别的打算（比如歇着的画板在三维栈里已经没有它的记录时才扔）。

**3. 一笔怎么进三维的栈**
- `PaintBoards` 建画板时给它 `HostedSteps`（不再给 `UndoStack`），宿主那一面转给编辑器那边的一个小口 `PaintUndo`：`onStep(贴图, step)` / `onReset(贴图, 为什么)`。
- 撤销栈加一种成分 `paint`：记录 = { 贴图 GUID, 内核那一步 }；swap = 找到那块画板的 HostedSteps `flip`；bytes = 问内核；dispose = `drop`。
- 一笔：档口 `end` 时内核调 `onStep` → 先攒着 → 这一笔收完，编辑器开一步（标签「画一笔」/「擦一笔」）、提交一条**空的 batch 记号指令**（和「只改选区的一步」同一种，进指令流、重放是空操作，不拷场景）、把攒的画的记录挂上去。一笔碰到几张贴图就是几条记录、同一步。文档算改过（编辑器的版本号加一）。
- 截断：新的一步之前三维栈丢掉重做段 → 成分的 dispose → `drop`（内核的约定「先把自己还没重做的那一段丢掉，再收下这一步」：落层先于提交记号，所以顺序上是内核先收了新步、三维再丢旧的那几步——旧步的 id 和新步不同，drop 不碰新步；测试里验）。

**4. 改模型让画布加高：挪进提交的收尾**
- 编辑器 `commitIn` 在补位置 / 强行对称之后调一次「画板跟大小」（遍历有画板的画），跟大小时内核封的那一步经 `onStep` 进来、直接 `record` 挂在这条指令的那一步上（游标在顶上）。
- 「准备」里的 `sync` 只剩：换文件全扔、底色跟着材质、画没了 = 歇着（第 2 条）。不再改大小。
- 撤销 / 重做不跟大小（画板的大小由栈里那条画的记录翻回去）。

**5. 撤销、重做之前先封口**：编辑器的 undo / redo 开头叫宿主一个口 → 正开着的那一笔取消（档口 cancel，零痕迹），再翻。

**6. 内核说「以前的步全作废」**：`onReset` → `dropRecords("paint", 这张贴图)`；不是「刚建画板」那一次的，提示行「这张画的撤销记录清掉了」+ 原因（装载 / 状态不可信）。

**7. 量**：不画画时撤销一步的时间和内存（加成分前后各量一次，同一串操作）。

**8. 白名单**：`UndoStack` 从正式表删掉（src 里不再用；测试里照用，测试不受限）。

## 施工记录

### 统筹 11-11 的裁定（细则里那两件）
- **第 1 件，整步事务 + 摘记录：同意，补四条。** ① 先问、再翻：翻任何一条之前，每条记录先问「能不能翻」（画 = 三维这边的写门、内核 directionOf、有没有开着的令牌；别的成分默认能）；有一条不能 = 什么都不碰、游标不动、报原因。② 翻的时候真抛了：翻过的倒着翻回去、游标不动、抛带原因的错，编辑器提示行「撤销没做成：……」。③ 翻回去又出错：那张画走内核「不可恢复」——步全部作废、用摘记录的口摘掉、明着说「这张画的撤销记录清掉了」和原因；别的成分照常翻回去，不许停在半路。④ 一步里记录的先后：撤销反着、重做正着；画布加高那一步里模型和画谁先谁后定下来写进注释，两头都有测试。测试：一步里每个位置各注入「问的时候说不能」「翻的时候抛」（撤销、重做各一遍），再注入一次「翻回去也抛」；摘记录（游标前 / 后 / 正好是游标那一步）单独测；不画画时撤销的花费量一下。
- **第 2 件，画板活多久：看三维的撤销栈里还有没有它的记录，不看场景里现在有没有这张画。** 场景里有、画板建过 = 留着；场景里没了 = 歇着（不合成、不进每帧的活、不占显示用的图；同一个贴图身份号回来接着用）；歇着而且栈里没有它的任何记录了（截断 / 挤掉 / 摘掉）= 这时才扔，数记录用栈丢一步时通知成分的口；换文件全扔。测试：开始画 → 画一笔 → 撤两下 → 重做两下逐字节；删掉画着的物件再撤销回来，画和它之前的每一步都还能撤；额度调小让记录被挤掉，歇着的画板跟着被扔、内核那边一条不剩。

### 交审（2026-11-11 晚，Catsup小弟；分支 `paint-undo`）
**做了什么**
- `editor/history.ts`：成分多三个可选口（`check` 先问、`untrusted` 翻回去也失败、`forget` 被摘）；`undo` / `redo` / `undoOp` 都走 `flipStep`（两段、整步事务，失败抛 `StepFlipError`，什么都没动）；`commitRecords`（一步只有成分记录：空的 batch 记号指令，不拷场景；这种步之后的指令不许 join 进来）；`dropRecords`（摘记录、摘空的「只有记录」的步整步删、游标和驱逐线重算）。先后写进头注释：一条指令的记录里模型的在前、画的在后（画布跟大小在收尾里记），所以撤销先翻画（缩回去）再翻模型，重做反过来。
- `paint/boards.ts`：画板用内核的 `HostedSteps`（不再用 `UndoStack`，白名单正式表删了它）；内核交来的步先攒着（`takePending`）；`follow`（跟大小，编辑器提交的收尾里调）；「准备」里的 `sync` 不再改大小，画没了 = 歇着、栈里没记录了 = 扔；`undoComponent()` = 「画」这一种撤销成分（问：画板在不在、有没有一笔开着、内核认不认这个方向，同一张画只问它这一步里的第一条，后几条靠翻的时候内核把关；翻 = `flip`；丢 = `drop` + 记录数减一；忘 = 记录数减一；不可信 = `distrust` → 内核 `clear` → `onReset` → 三维的栈摘掉它的记录、告诉用户）；`trackOpen` / `cancelOpen`（撤销 / 重做之前取消开着的那一笔）；`load`（装载：以前的步作废，不告诉用户）。
- 编辑器：两个宿主钩子 `afterCommit`（每条指令提交完）/ `beforeHistoryMove`（撤销 / 重做之前）；`registerUndoComponent`（换文件新建的栈也带上）/ `recordUndo` / `commitRecordsStep`（文档算改过）/ `dropUndoRecords`；撤销 / 重做没做成 = 提示行「撤销没做成：……」（翻回去也失败的那几样一起说），不弹错误胶囊。为了腾行把复现包「上一步」整块搬去 `editor/last-step.ts`（算法一字没改），行数棘轮 4111 → 4110。
- `main.ts`：登记「画」成分；`afterCommit` = follow + 挂记录；`beforeHistoryMove` = 取消开着的那一笔；内核说作废 = `dropUndoRecords` + 状态不可信时通知用户。`space-paint.ts` 抬笔落层之后 `commitStep`（标签「画一笔」/「擦一笔」，在 `step-labels.ts`）。

**和施工单不一样的地方**
- 第 3 条说「三维的一步里成分的先后」——一条指令里模型在前、画在后（收尾里记的），定下来写进了 `history.ts` 头注释；「画布加高」两个方向都有测试。
- 第 1、2 件的结构改动照统筹裁定做了（见上）。
- 「这幅画锁着」这种写门：三维这边现在没有画的修改锁，`check` 里先问的是「画板在不在 / 有没有一笔开着 / 内核认不认这个方向」；以后有了画的锁，加在同一个 `check` 里。
- 内核的小块池泄漏门在这一张没另跑（node 里看的是内核 `HostedSteps.liveCount` 和三维栈里的记录数对得上）；全套里内核那套照跑。

**不放心的地方**
- 「同一张画在一步里有好几条记录」时，`check` 只问第一条，后几条靠翻的时候内核把关、抛了整步翻回去。现在只有「一个手势里提交了好几条指令、每条都让画布跟着改大小」会出现这种情况。
- 摘记录会把被额度挤掉的「只有记录」的步也一起删掉（它们本来就撤不回去），能撤的步数不变；测试里验了。
- 一笔画得太细、一格都碰不到时，内核什么都没改就不封步，三维也就不长一步——用户看到的是「画了但撤销撤掉的是上一笔」。这在现在的调试钩子里碰到过（探针参数太小），真的笔有了界面之后要看会不会常见。


**全套**：两次（这张工单的上限）。第一次 2045 过 1 红（「画」记录里的字段叫 `texture`，被贴图表守卫拦下——它不许任何「点 texture」，改名 `tex`）；第二次 2046 条全过、内核那套 598 过，墙上 15.6 秒（以前约 12 秒，多出来的主要是新的画撤销测试一个文件约 9 秒）。之后把它拆成两个文件（随机来回那三个种子单独一份），点名跑两份并行墙上 6.4 秒；拆完没有再跑第三次全套。

### 统筹审查（2026-11-11 夜）：批了，合之前补两件 + 记一条给 1-7

统筹的裁定（原意照录）：① `dropRecords` 删掉的步要是「一步的开头、下一条 join 在它后面」，下一条要接班当开头，不许粘到前一步上；手搭一个「记号步后面跟着 join 进来的指令」的测试。② 补一个不漏的测试：一长串随机的画 / 撤销 / 截断 / 额度驱逐 / 删物件再撤回，最后换文件（画板全扔），用内核的内部数据核对图块池回到零。③ 记给 1-7：一笔一格都没碰到时，界面上不能显示成「画了一笔」。拆测试文件可以；不再跑第三次全套。之后自己合、bump patch、推开发版，接着 1-8b。

**补的两件（Catsup小弟，同一个分支）**
- ① `history.ts dropRecords`：过滤之前正着走一遍，删掉的那条后面跟着 join 进来的，就把 join 位、这一步的会话、标签交给下一条（连着删几条也一路交下去）。`commitRecords` 本来不许 join 进来，这是给规矩以外的形状兜底。测试 `history-transaction.test.ts`「删掉的步后面有 join 进来的指令」：手改 History 内部把 C 硬塞进 B 那一步，摘掉 B 的记录 → 剩两条，C 自己是一步、标签是「B」，撤一下只撤 C、A 没动，再撤一下才到 A（没改之前会把 A 一起撤掉）。
- ② **补测试时查出画板扔了图块不还**：`PaintBoard.dispose()` 以前只记一个「扔了」，图块一直占在内核的图块池里——换文件、歇着的画板记录被挤光，都漏。改成和画画仓 `WeebPaintBackend.dispose` 同一手：换 1×1 的空根（现在的内容随旧根还池）→ 装载顺手清栈（`HostedSteps.clear` 逐步释放，交给三维的栈的步攒着的旧图块也还池）→ 图块账退租。登记处那边：扔之前先取消开着的一笔（`disposeAll` 先 `cancelOpen`；有一笔开着的歇着画板先不扔）；扔的时候内核清栈发的 `onReset` 不再往三维的栈里摘记录（那时栈里已经没有它的记录，或者整个栈换了）。
  测试 `test/paint-undo-leak.test.ts`（新文件，登记了）：三个种子，各 70 个随机动作（画 / 擦 / 撤几步再做新的 / 重做 / 挪点 / 删物件，有时再撤回来），撤销额度 400 字节逼出驱逐（驱逐线 9–23、中途扔画板 2–6 次、图块最多 3–7 块），最后换文件 → 画板 0 块、内核图块池（`appTilePool().stats().count`）回到开始之前；再一张定死的：A 删掉之后只画 B，额度把 A 的记录一条条挤掉 → A 当场被扔，最后 B 也扔了，图块池回到开始之前（A 已经不在登记处了，要是扔的时候没还，这里回不去）。把 `dispose` 改回旧的验过：四个全红（每个剩 6–11 块）。点名跑 3.1 秒。

**这次查出来、要统筹定的两件（没动）**
1. **显卡那一侧也没退租口**：每块画板有一个内核的 `GLBoard`（里面是 `GlRoom`：图块纹理、索引纹理、选区 / 填充纹理），内核的 `GlRoom.dispose()` 是有的，但 `GLBoard` 没有把它露出来，所以扔画板时显卡上那份留着，要等浏览器自己回收。要补就是画画仓 `src/shell/gl-board.ts` 加一个 `dispose()`（转调 `_room.dispose()`）再拉一次内核；那个夹子归画画仓那条线，我没动。
2. **画的撤销额度实际上没有上限**：内核给画一笔的记录只算约 64 字节——它的规矩是没压缩的图块记 0、归图块池自己的额度管（384 MB，超了就压缩最老的），但那个额度**要接上压缩才生效**，画画仓是开机时 `tile-jobs.ts` 接的（`setTilePoolCodec(deflateTileCodec)` + 泄漏上报 + 空闲时压缩 + 切后台全压），CatsUp 没接。另外内核自己的栈每次重算字节（压缩之后会变），三维的 `History` 是记录挂上时算一次就存着。结果：画很多笔，撤销记录攒着的旧图块（每块 256 KB）不会被挤掉，内存一直涨，iPad 上画久了可能把页面撑崩。修法两半：CatsUp 开机接上压缩（编码器已经在拷来的内核里，接线约 30 行，照 `tile-jobs.ts`）；`History` 按画画仓的规矩在驱逐时重算成分的字节。建议另开一张小工单，不挡 1-8a 合并。

### 1-8a 的画板寿命改判（统筹 2026-11-11，0-3a 一起做）

**原裁定作废**：「画板活多久看三维的撤销栈里还有没有它的记录；歇着、而且记录数为零 = 扔」。原因（统筹原意）：画板是这张画的像素**唯一的一份**（编成字节存进文件之前），模型那一侧的步（删物件、撤销开始画、清理贴图）撤回来时要的正是它；唯一的一份不能因为省内存就扔，不管栈里还有没有画的记录。复现（Catsup小弟 11-11）：A 画三笔 → 删 A 的物件 → 只画 B，额度把 A 的记录挤光 → A 的画板按旧规矩扔了 → 撤回删物件之前，A 回到场景、画是空白的，没有任何提示。（画画的界面还没有，开发版上只有调试钩子能画，用户碰不到。）
**改成**：画板只在换文件时扔；画没了就歇着，留到关文件，同一个身份号回来接着用；画的记录被额度挤掉 = 只告诉内核丢那几步，画板内容不动；数记录的那套删了。歇着那块的内存靠图块池接上压缩之后自己压。以后要再省（编好字节、变冷）等 1-8b 有了编码缓存，那时的规矩：先有一份字节挂在所有还回得去的地方，才许放画板。
