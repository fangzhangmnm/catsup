# 贴图主线施工单（十二）：画的每一步进三维的撤销栈（1-8a）

> created 20261111 by Claude Fable 5.2 · as-of 三维 v0.19.19、画画 v0.14.75 · 2026-11-11
> 给谁：Catsup小弟。**等 Fable 看过才合。** 分支 `paint-undo`。短施工单：细则你动手前补在页末。没有界面入口，只有调试钩子、测试、探针。
> 这张关系到会不会丢画、撤销会不会把东西弄坏。拿不准的停下来问，不猜。

## 要达到什么

user 定的：画画和建模是一条撤销线。在模型上画一笔、切一刀、再画一笔，按三下撤销，按相反的顺序退回去；重做同理。

## 关键的形状

1. **画板改用 0-2 的 `HostedSteps`**：内核封好的每一步交给三维的撤销栈，不进内核自带的栈。白名单里的 `UndoStack` 删掉。
2. **三维的撤销栈多一种成分「画」**（照 `history.ts` 里网格体、场景那两种成分的写法）：一条记录 = 哪张贴图 + 内核的那一步。翻 = 叫内核翻这一步（方向和顺序内核自己认）；占多少 = 问内核；不要了 = 告诉内核丢掉。
3. **一次手势 = 三维的一步**：一笔画到了几张贴图，就是几条「画」的记录装在三维的同一步里。
4. **改模型让画布加高，和改模型的那一步是同一步**：画板跟着贴图坐标改大小，现在是在每帧的「准备」里做的，挪进指令提交的收尾里（和补位置、强行对称同一个地方），它封出来的那一步并进这条指令的那一步。撤销时一起退。「准备」里不再改大小，只读。
5. **要么全翻，要么不翻**：三维的一步里有好几条记录时，其中一条翻不成（内核说没翻，比如这幅画锁着；或者顺序不对抛了），已经翻过的翻回去，这一步算没做，提示行说清原因。三维的撤销游标不动。
6. **截断和驱逐**：三维的栈丢掉还没重做的那一段、或者因为额度把最老的步挤掉时，里面每一条「画」的记录都要告诉内核丢掉。额度的账里算上画的字节。
7. **内核说「这张画以前的步全部作废」时**（装载、或者状态不可信）：三维的栈里这张贴图的记录全部摘掉，摘空了的步删掉；状态不可信那一种要在提示行告诉用户「这张画的撤销记录清掉了」和原因。刚建画板时收到的那一次是空的，什么都不用做。
8. **撤销、重做之前先封口**：有画板开着写令牌（一笔画到一半）时，先取消这一笔再撤销，不许带着开着的令牌翻。
9. 标签：「画一笔」「擦一笔」进撤销标签表。画的一步落下，文档算改过（没存）。

## 不能破的规矩

- **混着来回逐字节对**：随机一串「画一笔 / 切一刀 / 挤出（让画布加高）/ 擦一笔 / 换材质」，每做一步记下模型和每张画的像素；一路撤销到头，每退一步都和当时记下的逐字节相同；再一路重做回来同样。中间随机插「撤销几步再做新的」（截断）。几个种子。
- **一笔画到两张贴图**：一次撤销两张都退；人为让第二张翻不成：第一张被翻回去、三维的状态和撤销之前逐字节相同、提示行有话。
- **额度**：把额度调小，最老的步被挤掉时内核那边活着的步数跟着减；没有泄漏（内核的小块池泄漏门是零）。
- **画布加高那一步**：挤出让画布加高，撤销之后画板和贴图坐标都缩回去；再重做回来。加高之后在新的行上画过、又撤销到加高之前：那几行是空白所以缩得回去。
- 不画画的时候，撤销的每一步花的时间和内存和现在一样（量一下）。
- 现有的撤销测试一个都不改。

## 碰到这些就停下来报

- 三维的撤销栈没有「一步里某个成分翻不成就整步退回」的地方，要加的话得动它的结构。
- 三维的栈丢一步的时候没有通知成分的口。
- 内核翻步要求的顺序和三维的栈实际翻的顺序对不上（比如三维的一步里成分的先后）。
- 有任何一种情况，撤销之后画和模型对不上，而且不会报错。

## 施工细则

（2026-11-11 晚，Catsup小弟 = Claude Opus 5.5，侦察之后、动手之前写。**第 1、2 条碰到了「停下来报」，等统筹定了再动撤销栈的结构**；别的先做。）

**侦察看到的**
- 内核 `HostedSteps`（0-2）：`onStep(step)` 在一笔落层（档口 `end`）时同步调；`flip(step)` 自己认方向、顺序不对 / 令牌开着 = 抛 `StepOrderError`（什么都没碰）；`bytes` / `drop` / `clear → onReset` 都有。翻不成的唯一表现是**抛**（没有「返回没翻」）。
- 三维 `History`：成分登记制（`UndoComponent`：swap / bytes / dispose）有；丢步（截断重做段、配额驱逐）会调成分的 `dispose`，所以「通知内核丢掉」有口子可接。`record(kind, data)` 能往栈顶那一步挂记录。
- **没有的两样**：① 一步里某条记录 swap 抛了，`undo` / `redo` 停在半路、已经翻过的不翻回去（停止条件第 1 条）；② 没有「摘掉某种成分的一批记录、摘空的步删掉」的口（第 7 条要）。
- 画板跟大小现在在每帧「准备」的 `sync` 里（`board.follow`）；画板在「画没了」时（贴图被清、材质不指它、那一套坐标没了）当场 `dispose`。

**1. 撤销栈的结构要动（停止条件第 1 条；要统筹点头）**
- `History.undo` / `redo` 改成**整步事务**：按原来的顺序 swap，记下翻过的（第几条 op 的第几条记录）；中间有一条抛了 → 把翻过的倒着再 swap 一遍（每种成分都是自反的，再 swap 一次就回去；画的那条再 flip 一次 = 内核自己认出是反方向）→ 游标不动 → 抛一个带原因和标签的错。编辑器接住：场景装回去、提示行「撤销没做成：……」。
- 加一个口 `History.dropRecords(kind, 判断)`：从所有步里摘掉这种成分里判断为真的记录；摘完只剩「记号」（下面第 3 条那种空的 batch 指令）的步整步删掉，游标 / 驱逐线跟着重算。只给第 7 条（内核说这张画以前的步全作废）用。
- 现有撤销测试一个不改；新加：事务（人为让第二条翻不成，场景逐字节回到撤销前）、摘记录（摘空的步消失、游标对）。

**2. 画板不能在「画没了」时扔掉（新发现，同属停止条件第 4 条「撤销之后画和模型对不上、不报错」）**
- 现在：删掉画着的物件、或者撤销「开始画」，画就「没了」，画板当场扔掉；再撤销 / 重做回来，画板是新建的空白一块，它的 HostedSteps 也是新的，三维栈里那些画的记录翻不了（StepOrderError）或者翻进一块空白——**画丢了**。
- 打算：同一份文件开着的期间，画板只在**换文件**时扔掉；画没了 = 画板**歇着**（不合成、不进每帧的活、不占显示图），画回来了接着用（同一块画板、同一个 HostedSteps）。歇着的画板的内存归 1-8b「没在画的画只留显示用的图」一起管。
- 要统筹定：这样做对不对；还是有别的打算（比如歇着的画板在三维栈里已经没有它的记录时才扔）。

**3. 一笔怎么进三维的栈**
- `PaintBoards` 建画板时给它 `HostedSteps`（不再给 `UndoStack`），宿主那一面转给编辑器那边的一个小口 `PaintUndo`：`onStep(贴图, step)` / `onReset(贴图, 为什么)`。
- 撤销栈加一种成分 `paint`：记录 = { 贴图 GUID, 内核那一步 }；swap = 找到那块画板的 HostedSteps `flip`；bytes = 问内核；dispose = `drop`。
- 一笔：档口 `end` 时内核调 `onStep` → 先攒着 → 这一笔收完，编辑器开一步（标签「画一笔」/「擦一笔」）、提交一条**空的 batch 记号指令**（和「只改选区的一步」同一种，进指令流、重放是空操作，不拷场景）、把攒的画的记录挂上去。一笔碰到几张贴图就是几条记录、同一步。文档算改过（编辑器的版本号加一）。
- 截断：新的一步之前三维栈丢掉重做段 → 成分的 dispose → `drop`（内核的约定「先把自己还没重做的那一段丢掉，再收下这一步」：落层先于提交记号，所以顺序上是内核先收了新步、三维再丢旧的那几步——旧步的 id 和新步不同，drop 不碰新步；测试里验）。

**4. 改模型让画布加高：挪进提交的收尾**
- 编辑器 `commitIn` 在补位置 / 强行对称之后调一次「画板跟大小」（遍历有画板的画），跟大小时内核封的那一步经 `onStep` 进来、直接 `record` 挂在这条指令的那一步上（游标在顶上）。
- 「准备」里的 `sync` 只剩：换文件全扔、底色跟着材质、画没了 = 歇着（第 2 条）。不再改大小。
- 撤销 / 重做不跟大小（画板的大小由栈里那条画的记录翻回去）。

**5. 撤销、重做之前先封口**：编辑器的 undo / redo 开头叫宿主一个口 → 正开着的那一笔取消（档口 cancel，零痕迹），再翻。

**6. 内核说「以前的步全作废」**：`onReset` → `dropRecords("paint", 这张贴图)`；不是「刚建画板」那一次的，提示行「这张画的撤销记录清掉了」+ 原因（装载 / 状态不可信）。

**7. 量**：不画画时撤销一步的时间和内存（加成分前后各量一次，同一串操作）。

**8. 白名单**：`UndoStack` 从正式表删掉（src 里不再用；测试里照用，测试不受限）。
