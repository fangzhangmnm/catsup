## 要达到的一句话

**一笔当中每帧的花费，不随画布大小涨、不随模型大小涨、不随这一笔已经画了多长涨。**（user 11-11：「画的时候 fps 尽量流畅」；又说「一些常识级别肯定有意义的优化还是需要做的，就是至少把低效的草稿算法优化掉」——明摆着低效的写法不等读数直接换，读数用来决定换完之后还慢在哪。）

## 不能破的

- 不为了快去简化预览：预览就是结果，结果逐位或逐像素不变。
- 要动内核对外的口（画画仓的内核）先停下来报统筹形状；某一段怎么都压不下来，停下来报。

## 没做的、留给以后的

- **「一颗笔尖下超过 8 张面共用一块画布」这一条还是取消这一笔**（统筹 11-11 记给「画布成为中心、画跟着面走」那一轮；记录 Claude Opus 5.5）：
  - 8 从哪来：`src/paint/space-layer.ts` 的 `MAX_FACES = 8`，1-4b（2026-11-11，Catsup小弟）定的。一颗笔尖在一块画布多边形上 = 一个 item；item 的面单子列出这块画布上挂着、笔尖碰得到的面。薄层着色器在每一格对面单子里的每张面（再对每张面的三角形）找离取样点最近的那张，按那张面上的世界位置算浓度——几张面共用同一块画布（镜像的两半、做成多份的副本）时只画离笔尖最近的那份。GLSL 的循环要常数上界，外圈就定了 8（循环里有 break，面少不花钱）。当时想到的是镜像（2 张）和少数几份副本，**8 这个数没有量过，也没有别的依据**。超了 = `SpaceLayer.update` 抛 PaintLimitError（「这一笔画不了：笔下有 n 张面共用画布上同一块地方……」），1-7 接成取消这一笔 + 提示行。容量表在 `ai-docs/20261111-paint-workorders-11.md`。
  - 会撞上什么：user 定的「复制、分出去、做成唯一默认共用同一块画布」。到那一轮之后，把一扇画好的窗复制十份是设计里鼓励的用法，一支大笔盖住其中九份就会把这一笔取消掉。
  - 不能照第 4 条的分批办：第 4 条是每批各画各的 item；这里是同一个 item 里在几张面之间挑最近的，拆开 = 每一批各挑一个「最近的」、同一格被画好几次（叠色叠多了，取最大也可能取到不对的那份）。办法要在那一轮开工前定：放大上界（着色器循环和面单子跟着长）、两遍（先每格找全局最近的那张面再画）、或者想清楚这时候该是什么行为（比如共用画布的副本只按一份算）。

- **落层的读回改成异步（像素包缓冲 + 栅栏，过几帧再取）没做**（统筹 11-11 定：等真机的数说话）：这一下现在还是同步等显卡做完；第 8 条只把读回的字节降到这一笔碰过的格。真机上要是同步等那一下还长，再做这一条，落层和撤销那一步要跟着变成「过几帧才落定」。

### 第 2 条 走步只走还会变的尾巴（2026-11-11，Catsup小弟）
- **改在画画仓**（WeebPaint v0.14.78，main 8f4d2cf，已推开发版）：`StrokeCore` 加定型缓存（`stroke-core.ts`）。路上前 frozenCount 个点不会再变，从头走到最后一个不会再变的点时的游标（`Walk` 五个数），和这一段交出的笔尖原料（第几段、位置、压感、走了多远），都不会再变：记下来，下一帧从游标接着走，只重走尾巴。原料算成笔尖（大小、浓度）也缓存，收笔总长变了（抬笔）就重算一遍。`collect` 的定型颗数 = 缓存里那些（尾巴上的段都碰到会变的点）；收笔渐细的裁剪改成二分，和一颗一颗数结果一样。抬笔量总长也从游标接着走。路说定型的变少了 = 丢掉缓存从头走（保底，不该发生）。

### 第 3 条 公式表挪进准备（2026-11-11，Catsup小弟）
- **做了什么**：
  - 面表、三角形表（显卡上的两张数据图），每张面三角形的反解数据（算笔尖在贴图上的外接框用），每块画布多边形的格子范围：以前在 `SpaceLayer` 的构造里现做，也就是落笔那一下，随整个物件的三角形数涨。现在抽成 `FaceTables`（`space-layer.ts buildFaceTables`），进「画画的准备」（`space-prep.ts`）：和整份几何、每格的表一起建、一起过期、一起放。落笔只借（`take` 多给一样 `tables`，`SpaceLayer` 的 `tables` 选项），dispose 不放借来的。
  - 原点从「落笔那一点」改成物件原点 `objectOrigin`（这项目标所有三角形世界位置的外接框中心），笔尖也减它。三角形的公式照旧钉在自己的第一个角上（1-4c），所以这里改的只是一个整体平移。测试自己建表时仍可以给 `origin`，用来比较。
- **标准答案、软件版、显卡版用的是同一个原点**：标准答案（`tip-truth.ts`）在 64 位世界坐标里算，没有原点。软件版和显卡版吃的是同一份上传的表（减的是同一个物件原点）。
- **换原点前后差多少**：

### 第 7 条 落成路时少打射线（2026-11-11，Catsup小弟；v0.19.39）
- 做法和施工单写的不一样的地方：没有「这一段不再分」，而是照旧对半分、只是中点不打整条射线——两头打中同一个三角形、屏幕上相距不超过 2 像素（`space-path.ts SAME_TRI_MAX_PX`）时，中点只和那个三角形求交（`space-target.ts rayHitTri`：和 `rayHit` 同样换进定义坐标、同一个求交 `surface-pick.ts rayTriangle`，所以打中时 t 和落点与整条射线打中这个三角形时逐位相同），没中就照旧打整条。这样路上的点和以前逐点相同（不再分会改掉路上的点）。第一版在 space-stroke 里另写了一份世界坐标的求交，守卫 `paint-space-guard` ①（射线求交全仓只许一份）当场红了，改成复用。
- 为什么限 2 像素：同一个三角形上两点之间被别的东西挡住，整条射线会撞上、平面求交看不见；只在屏幕上很近的两点走捷径 = 漏看的只有比 2 像素还窄的东西。贵的本来就是陡的面：世界里差得远、屏幕上只差零点几像素。
- 量（单测 `paint-space-path.test.ts`，平面上同一条 80 像素的线，20 个采样点）：整条射线 60° 161 → 43、85° 648 → 46、89° 1036 → 48（其余是平面求交：118 / 602 / 988）。
- 测试：同一笔开 / 关两遍（关 = 实例上 hitTri 永远交 null），60° / 85° / 89° 的平面和球上路上的点、笔尖在 1e-9 以内相同，「射线 + 平面」= 关着时的射线数；细杆（屏幕上比 2 像素宽）挡在板前、线一下子跳过去：照旧断开，断的次数和关着一样。

- 结论：落层里 85–93% 是读回；读回的是这一笔碰过的整个外接框（内核 `bakeStamps` 按薄层的方框 bx / by / bw / bh 读），跨片的笔外接框很大、墨很少——读回来的 8 × 8 格只有 4–16% 有墨（这个数还含这一层以前的画，是上界）。抬笔之后那一帧（落定的内容变了 = 整张重合 + 整张拷 + 画场景）另有 180–315 ms，大头是软件显卡画 15534 个三角形的场景（画的时候每帧中位就有 150–190 ms）。
- 要改就得动内核对外的口（停手线：先报统筹）：① 只读回这一笔碰过的格——宿主把整笔的脏格子位图（每帧 takeChanged 的并）交给写回，内核按行段读回、只对这些格做图块比对；量的读回字节会降到 4–16%。② 读回改成异步（像素包缓冲 + 栅栏，下一帧或几帧之后再取），这一下不等显卡；落层和撤销那一步要跟着变成「过几帧才落定」，牵扯大。③ 两个都做。真显卡上读回是同步等显卡做完、按字节算，绝对数这台机器量不了。

### 第 8 条施工：落层只读回这一笔碰过的格（2026-11-11，Catsup小弟；内核 v0.14.82–84，三维 v0.19.43）
- 统筹定的形状（头文件过目过）：`HostOverlayInput.cells`（不给 = 照旧读整框）、`GLBoard.lastBake`（box / cells / box-unreported + 读了几次、多少字节、报了几格、漏了几格）。
- 内核（`bake-cells.ts` + `raster-service.ts bakeStamps`）：region-load 取这一层存着的字节（= CPU 那份）→ 一张小暂存图一次画完（上半 = 报的格原样拷进格位；下半 = 核对片，方框里每格一个像素 = 合出来的和存着的任一通道差的最大值，报了的格写 0，前后都全透明不算变）→ 一次 readPixels → 核对片干净 = 一个图块一次 apply（那一块存着的字节贴上读回来的格）；有 = 照旧读整框。行段夹进方框（方框外全透明带色的像素合一遍颜色会归 0，不许写回去）。
- 三维：整笔重画那一帧 SpaceLayer 把画进去的 item 另记一份（`strokeCells`，resetFrozen 起、只在 update 里跟那几个 item 一起标，守卫钉住），交档口时带上；画板落层后看 lastBake，box-unreported 记一行调试日志。落层中途出错 = 档口取消令牌、已写的回滚 = 整笔不落，space-paint 收干净、提示行说「这一笔没能落进画里，已经整笔撤掉」。
- 证明：内核随机测试 34 个场景（含跨好几个图块、全透明带颜色的像素）只读格 = 读整框（看得见的逐字节一样、改的图块 ⊆ 读整框的）；少报一段真变了的 → 查出来；假叠法（α = 0 的一格合出来的被改了）→ 查出来；显卡冒烟三条（真 WebGL）。CatsUp `paint-board.test.ts`：交格 = 读整框、只读一次字节少；第 2 次写图层抛 → 图层逐字节回到落笔之前、撤销没多一步。探针 space-rules（预览 = 结果）/ live-region / paint-save / paint-workbench 照过。
- 施工当中修过的三处：① 报格的位图存 1，r8 取样是归一的 = 1/255，着色器 > 0.5 判不出（全报成漏了）→ 存 255；② 拆回的行段没夹进方框，方框外全透明带色的像素被写成 0 → 夹进方框；③ 一段行程一次 apply = 几百次，CPU 那一半比读整框还慢 → 一个图块一次。

### 第 10 条 连续画 300 帧的读数（2026-11-11，Catsup小弟；v0.19.44）
- **量法**：规模探针 L 节。仓里现造的三档每次都跑，给了 `--models=` 再加 wip2021 两档。读数角标加了 `record(on)`，逐帧记各段和这一帧画完的时刻。一笔 300 个点 = 300 帧，每帧画完**先等显卡做完再画下一帧**：调试钩子 `paint.stroke` 的 `pace`，等的时间不进任何一段，和真页面在交换画面那一下等显卡是一个节奏。统计时去掉头 10 帧和核对的那几帧，记各段的中位、最慢、最慢那帧是第几帧。开头 = 第 10–40 帧；末段 = 最后 30 帧还在往画上写的（真模型上笔后面会走出模型）。另外把会话的存盘、崩溃快照和画的 freeze / refresh 包一层，记笔画期间有没有跑。
- **数**（软件显卡，绝对数只作参考；毫秒，合计 = 各段相加）：

| 档 | 合计中位 | 最慢一帧（第几帧） | 开头 → 末段（合计中位） |
|---|---|---|---|
| 六千面、1024² | 1.2 | 1.9（第 21 帧） | 1.5 → 1.2 |
| 六千面、4194304 格 | 1.4 | 2.3（第 43 帧） | 1.4 → 1.4 |
| 两万四千面、1024² | 1.5 | 3.8（第 103 帧） | 1.6 → 1.6 |
| wip2021、1024² | 1.2 | 2.7（第 267 帧） | 1.7 → 1.3（末段 = 第 236–300 帧） |
| wip2021、4194304 格 | 1.5 | 3.2（第 32 帧） | 1.8 → 1.6（第 244–300 帧） |

  每一段的中位数都不到 0.5 ms，最大的是写层（0.3–0.5）、找面（两万四千面 0.3）、画场景（0.2–0.3）。
- **三条「不随……涨」都成立**：同一段的中位数，1024² 和 4194304 格比、六千面和两万四千面比、wip2021 两档比、一笔的开头和末段比，没有一段涨过 1.5 倍且多出 1 毫秒。笔画期间存盘那几条路五档都一次没跑。
- **量的时候撞上的一个坑（探针的，不是 app 的）**：第一版没等显卡，wip2021 两档最慢一帧 0.6–5.4 秒，写层、合成、缩小图、画场景几段同时变慢，四次跑落在第 172–268 帧之间、每次不一样。查了两件事：
  - 不是存盘：笔画期间存盘那几条路一次都没跑。探针这一笔是在一个同步循环里画完的，会话每秒一次的 tick 根本插不进来。
  - 是显卡活攒多了：在同一处每帧等显卡再画一笔，wip2021 在软件显卡上一整帧要 120–230 ms（大头是画场景），画画那几段只有 2–4 ms，也没有几秒的卡顿。所以是提交比显卡快，活越攒越多，到某一帧某个调用被卡住、等队列排空，那几秒就记到碰巧在跑的那一段上。
  - 加上 `pace` 之后最慢一帧是 2.7 / 3.2 ms。真页面每帧在交换画面那一下等显卡，不会这样攒。
- **顺手查到、没改、报统筹的一件**：会话判断「空闲、可以自动保存 / 崩溃快照」只问编辑器的手势（`session.ts` 的 `tick`：`editor.isGestureActive()`）；画画工作台的一笔（`paint-workbench.ts` 的 `stroking`）不在里面，`main.ts` 只拿它锁相机。所以上一次改动过了 30 秒再接着画一长笔，自动保存可能落在这一笔中间。存下来的是落笔前那一版，数据不丢，代价是那一下卡；这个探针量不到（理由同上），真页面上也没量过，笔画中间存盘会不会碰出别的问题也没验。背后的结构：「用户手上正在做的一下」现在有两个来源，会话只问了其中一个；以后草稿笔、雕刻笔刷还会再加。要不要改、改成什么样（例如会话改成问一个合起来的「手上还有没有一下没收」）归统筹定。
