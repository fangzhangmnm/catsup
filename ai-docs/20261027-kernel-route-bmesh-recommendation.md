## 0. 推荐（一句话）

**另做一个网格内核（Blender bmesh 式：面是显式的、允许不平的 n 边形、刀只切不长、挪点不丢面），不做无缝切换，物体有「brep / mesh」两种类型，手动转换，每种类型自己的工作台；折边退役，SU 的自动折缝改成软 + 平滑（SU 同款）。** 和 user 的倾向一致，理由在 §2–§3；代价在 §4，不小但是一次性的；利滚利的那一头（每个自由建模动词都要在共面公理上开一个口子）比它贵。

## 1. 为什么共面公理和自由建模天生打架

CatsUp 的 brep 是「肥皂膜」：面不是你画的，是闭合共面环**长**出来的（公理 1 平面性 + 面的涌现）；点一重合就是同一个点（公理 3）；每一步结算机按影响域重算面（局部化定理）。这套东西给 SU 式硬表面是对的——它就是 SU 的优雅所在。

自由建模（Blender 式）的每个基本动词都踩在这三条上：

| 动词 | 要的行为 | 在 brep 上要开的口子 | 要证的东西 |
|---|---|---|---|
| 刀（环切） | 只切不长面 | 结算机的「闭环长面」要能关 | 关了以后局部化定理还成立吗（闭环不长面 = 像表少一种像） |
| 挪点 | 面不平也不丢 | 不平的多边形要「折」成平面块（autofold）或者当一张 | K3：凹的、带洞的、拧的多边形怎么拆（现在 L 形拆到外面、带洞的破掉、八边形拧了就破）|
| 溶解 | 两张不共面的面并成一张 | 折线亚种（DT87） | 折线的面算一张面的所有下游（选、涂、导出、结算）|
| 合 / 塌缩 | 点并成一个 | 公理 3 本来就管（白得） | — |
| 软挪 / 雕 | 一次挪一大片点、每帧 | 每帧 autofold 一大片面 | K3 每帧跑；性能（O1）|
| 填 | 选洞显式长面 | 要能长不平的面 | 同挪点 |

每开一个口子就是一条新定理，而且这些定理（autofold 的分解、局部化的补丁、擦边局部化）全是**因为共面这个前提才存在的**。网格内核上这些题目不存在：面是显式的，不平就不平，显示时三角化；刀是拓扑操作，永远不会多出一张面；挪点只改坐标。网格内核要的数学是 Euler 算子（劈边、劈面、并面、并点、删、挤出、环切）——每条几十行、能用性质测试钉死（点 − 边 + 面 = 2 − 2g 这类不变量），没有几何前提。

## 2. user 的三条标准逐条

1. **「初中级和高中级的两个性能优化是不是要做两遍」**：大部分**不用**。brep 上最贵的几件（结算机局部化、擦边局部化、autofold）在网格上根本不需要做；共用的那些（渲染缓存增量更新、屏幕索引 / 空间网格、场景 / 组件 / 实例、撤销的 op 日志、格式拍子）是对着一个 `Body` 接口写一次，两种内核各自实现几何查询。真要做两遍的只有「拖动预演每帧拷贝」（O1）——而网格的软挪只改坐标数组，预演 = 一份坐标的差量，比 brep 那半便宜得多。
2. **「sketchup 的功能很多自由建模都用不到」**：对，而且反过来更要紧——推断引擎、结算机、曲线登记表、autofold、肥皂膜长面，自由建模一样都不要；留在同一个内核上，每个动词都得绕着它们走。
3. **「无缝切换有多慢、能不能无损」**：user 已经改口不要无缝。手动转换：brep → mesh **无损**（每张 brep 面本来就是平面多边形 → 一张网格面；边层照搬；材质 / 层 / 曲线参数当属性带着，这就是「同一个灵魂」）；mesh → brep **有损但诚实**（量化合点、不平的面三角化成平面块、交给结算机修；报「N 张面三角化了、M 个点合并了」）。现成数据：小红帽 291 三角 78 ms、熊 392 三角 127 ms、1.2 万三角 8 s——手动、低频、带「要等一会儿」的提示，可以接受。

## 3. 两个已复现的坑在两条路线下

| 坑 | brep 加开关 | 另做网格内核 |
|---|---|---|
| ① 刀绕一圈长出夹层面（10 → 19 张面） | 结算机加「只切不长」开关 + 重证局部化 | 不存在（刀 = 劈边 + 劈面） |
| ② 拖乱凹的 / 带洞的 / 拧的面 → 破或折到外面 | K3 必须解到「任意多边形都能正确拆」，**每一步都跑** | 自由建模里不存在；**SU 工作台里还在**（SU 用户也会拖点），但只要一个兜底（§9），不要最优解 |

## 4. 代价（诚实的清单）

第二种物体要贯穿整个栈，一次性：

| 层 | 要做什么 | 量 |
|---|---|---|
| 内核 | `src/mesh/`：点 / 边 / 面（面 = 环，边带两侧面的径向链），Euler 算子（劈边、劈面、并面 = 溶解、并点、删、挤出、环切、填）、边层（软 / 平滑 / 缝）、按面的材质两侧、三角化（不平的 n 边形：投影到最佳拟合平面做耳切）、性质测试（欧拉数、流形性、每条算子前后不变量） | 最大的一块；几千行 + 测试 |
| 场景 | `Scene.kernelOf(at)` → `bodyOf(at)`，池里装的是 `Body`（brep 或 mesh）；组件 / 实例 / 组 / 镜像不变 | 小，但碰的地方多 |
| 选区 | `Selection` 现在只认 brep 的面 / 边 / 点 id + 参考几何 + 实例 / 组（Fable 账单 A2）；要变成按物体类型的 id | 中；**和 A2 一起做** |
| 指令 / 撤销 | 新的一族 op（`mesh.*`，按点坐标寻址照旧）；op 日志 / 快照 / 会话状态不变 | 中 |
| 渲染 / 拾取 / 吸附 | 渲染缓存吃三角 + 边，网格给它三角化结果；屏幕索引吃点 / 边；吸附在自由建模里由人声明，推断不跑 | 小 |
| 格式 | glTF 本来就存三角网；n 边形的环 + 边层 + 材质两侧进 `CATSUP_mesh` 扩展（有自己的拍子，照家族格式纪律）；导入 glb → **直接成 mesh 物体（无损，熊不再痛苦）**，要 brep 再手动转 | 中 |
| 工具 | 自由建模工作台 = mesh 物体的编辑模式（`mode.ts` 早就按物体类型分模式：「物体模式 + 编辑模式按 kind」）；动词按指令注册表写一次 | 这是本来就要写的 UX 接线，不算额外 |
| 表面模式 / 绘制 / 物理 / 验证 | 按面材质两侧、画布绑面、碰撞三角——都按 `Body` 接口 | 小 |

不做网格内核省下的是上面这张表；换来的是 §1 那张表里的每一行都要在共面公理上开口子、每个口子一条定理，而且**自由建模之后的雕刻（稠密网格 + 加速树）和物理（输出本来就是网格，user 10-27 定的）照样要一个网格结构**——那时候还是得做。

## 5. 「两边混着做的概率高不高」

| 场景 | 概率 | 怎么走 |
|---|---|---|
| 同一个场景里硬表面物体（坦克、房子）和有机物体（角色、布）并存 | **高** | 场景级，物体各自是 brep 或 mesh，零成本 |
| 同一个物体先 SU 式精确起型（盒子、推拉、吸附），再转 mesh 拉形 | **中**（Blender 用户也是先 box modeling 再雕） | 一次 brep → mesh，无损，单向 |
| mesh 再转回 brep | **低**（有机形状不会想再精确共面；导入的模型想修成 brep 算一种） | 手动，有损报数，带预估 |
| 一个物体里一半 brep 一半 mesh、逐步混着编辑 | **极低**，也不该支持 | 不支持；要混就分成两个子物体（组件嵌套本来就能进出） |

所以 user 说的「手动类型转换」够用，而且比无缝切换安全：转换是一次显式动作，有损的地方当场报。

## 6. 工作流归谁：类型归文件，工作流归会话

- **物体类型（brep / mesh）归 workpiece**（文件）：它决定数据长什么样。
- **当前工作流 / 工作台归 workbench**（会话）：`mode.ts` 的设计已经是「物体模式 + 编辑模式按 kind」——进一个 mesh 物体，可用的编辑模式就是 mesh 的那几个（自由建模、以后雕刻 / bodypaint）；进 brep 物体就是硬表面 / 表面模式。会话记住「每种类型上次用的模式」就够，不按每个物体记、不进文件（和 user 的判断一致；Blender 把模式存进文件那一条不借，和「历史不存在」同一立场）。
- 「可以选中进出子物体」：场景级（组件 / 组嵌套）本来就和类型无关，进出照旧；进到一个 mesh 子物体 = 工作台自动换成 mesh 的模式。

## 7. 折边还要不要：退役

折边（DT87，v0.14.51）是为了「在 brep 上做 Blender」才有的：让不平的两张膜算一张多边形、让溶解不破面。网格内核接管了这两件（不平的 n 边形是原生的、溶解是 Euler 算子），折边就没有独立的用途了。

- **SU 工作台的自动折缝改成软 + 平滑**（user「su 要不要变成折边而不是硬边，然后用户有需要再弄」）：对，而且 **SketchUp 自己就是这样做的**——拖点把面拖不平时它自动折开，折出来的线是软 + 平滑（藏着，开「显示隐藏几何」才看见）（凭记忆，没在 SU 里重验）。现在 CatsUp 硬表面默认折缝画硬线（DT87 的 `autofold: "hard"`），比 SU 更吵。改成软 + 平滑默认，要硬就用现成的「软边变硬」修复 → UX 更干净，和 user 的判断一致。
- **退役清单**：`fold` 边层、`Mode.workflow.eraseNonCoplanar / autofold` 两个亚种开关、`moveVertices(..., { creaseLayers })`、`flood.ts polygonFaces` 的折边合并——这些是 brep 上「为 Blender 开的口子」，全部收回，内核少一套分叉。SU 的擦边照旧 burst（SU 同款）。
- **格式**：v0.14.51 起文件里可能有 `fold` 层 → 升级链加一步「fold → soft + smooth」（minor 拍子），旧文件照开。user 自己的文件扫一眼有没有用到。

## 8. 转换的语义（两条指令，走指令注册表）

- **`body.toMesh`（brep → mesh，无损）**：一张 brep 面 = 一张网格面（平面 n 边形）；边层（软 / 平滑 / 缝）照搬；材质两侧照搬；曲线登记表（这是圆、半径多少）和平面记录当**属性**带着（「同一个灵魂」= 元数据跟着走，转回去时能认回圆）。不把软边连着的面合成大 n 边形（圆柱侧面该是一圈四边形，不是一张大面）；要 n 边形用网格的「有限溶解」（Blender 的 Limited Dissolve）。
- **`body.toBrep`（mesh → brep，有损、诚实）**：量化合点（公理 3）→ 不平的面按 §9 拆成平面块 → `Kernel.fromBrep` 整批装 → 内核精确谓词挑不干净的交结算机修（= 现在 `from-triangles.ts` 那条路）→ **报**：三角化了 N 张、合并了 M 个点、拒收 K 张（拒收的留成一个 mesh 子物体，不丢）；走 `estimate` 先问「要等一会儿」。
- 两条都是一步撤销；都是选中的物体上的右键指令；转换后工作台跟着物体类型换。

## 9. K3 的新答案（SU 工作台自己的 autofold 兜底；自由建模里不再需要）

现在 `autofold.ts` 找极大共面段、段之间连折缝弦，k ≥ 4 的结点多边形还不平就返回 null → BURST。L 形折到外面是因为连弦时没看多边形的包含关系；带洞的破掉是因为根本没处理洞。

替换成两步，**正确性来自三角化、好看来自合并**：
1. 把多边形（含洞）投影到它的最佳拟合平面；投影是简单多边形时（绝大多数：拖一个点、拖一条边、拧一下都是）→ 洞先用桥接边并进外环 → **耳切三角化**（经典算法，简单多边形上保证成功、三角形全在多边形内、互不重叠）。投影不简单（真拧成麻花）→ 换一个投影平面再试；都不行 → 报「这张面拧得太厉害，折不开」并**保留原面当不平的面**（不 BURST；SU 这时也只是显示得怪）。
2. 把共面的相邻三角形贪心合回最大平面块（折缝尽量少）。
性质（要留档证明）：不出多边形、块的投影互不重叠、带洞也行、确定性。折缝 = 软 + 平滑（§7）。
