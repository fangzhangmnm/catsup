# 施工单：硬盘上打开的模型存进图库；图库里加「导入」

> created 2026-11-13 by Claude Fable 5.2（Catsup统筹）· as-of 三维开发版 v0.19.109
> user 11-13 深夜同意（原话在 `talks/20261103-keymap-blender.md` 第十六轮）：「导出与另存加一项存进图库同义（= 同意，语音），然后图库里也加入导入」「存完是搬到图库那份上接着干当然需要这个，硬盘上只是救急的」。
> 施工：Catsup小弟。排在锁的一轮之后、键位之前。**这是存盘的路：diff 合之前发统筹，红线组要绿。**

## 一、存进图库

- 入口：「导出与另存」菜单加一项「存进图库」，只在这份模型的家不是图库时出现（硬盘上的文件、还没有家的临时模型）。
- 做什么：把眼前的内容存成图库里的一份新模型，然后**当前打开的就换成图库那一份**，以后保存都进图库。
- 名字 = 现在的名字，撞名加序号（现成的 `freeName`）。放在图库的根（统筹定的），存完说出放到了哪。
- 写法复用「离开时存一份副本」那条现成的路（`session.ts` 的 `copyIntoGallery`：库的 save，再读回来字节数对得上才算成），不另写一条，不动同步库。推不推照心跳的规矩。
- 顺序是死的：写成 → 读回对上 → 才换家。换家之前出任何错 = 留在原来那份、改动还在、说原因。
- 换家之后：没存的标记清掉（眼前这份刚写进去）；硬盘上原来那个文件不再写，界面上说一句「硬盘上原来那个文件没动」。
- 加密的本地文件（解开来当临时模型开的那种）：这一项灰着并说原因（新的一份会先以明文落地）。「存进图库并加密」以后再说，不在这一刀。
- 崩溃恢复的影子：换家之后跟着新家走。核一遍「换家那一下之前崩」「之后崩」各会怎样，写进施工记录。
- 验收：硬盘上打开 → 改两下 → 存进图库 → 标题和家变成图库那份 → 再改、Ctrl+S 进的是图库 → 硬盘上那个文件的字节没变；撞名；断网（「先存在这台设备上，稍后同步」的说法对）；写失败（留在原来那份）；加密的灰着。

## 二、图库里的「导入」

- 要的东西：在图库界面里把硬盘上的工程文件放进图库。
- 文件管理的界面归图库库，app 不手写。**先只读清点，发统筹**：图库库现在有没有「导入本地文件」的入口、画画软件是怎么接的、三维接上要不要动库。要动库（哪怕只升补丁号）先停，统筹报 user。
- 统筹的默认（清点回来再定）：一次可以选多个；存成图库里新的几份，不自动打开；撞名加序号；老的 .glb 工程照「打开本地工程文件」那道门的规矩认；外来的 glb 不算工程，指去「导入 glb」。

## 三、和别的东西的关系

- 几个软件的图库和文件操作以后统一（家族周账 F-280，不急）。这一刀只做三维自己的，做法尽量照画画软件现成的。
- user 顺带说的一句：「可能一般的用户反而是把打开本地文件然后保存这个做得好一点」——本地打开、保存那条路对一般用户更要紧，这一刀不许把它弄差。
