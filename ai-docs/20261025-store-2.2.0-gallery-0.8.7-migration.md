## 1. 一句话

CatsUp 是家族里最后一个还钉着 store 0.15.2 / gallery 0.4.0 的 app（WeebPaint / JRB / WXHW / MoonSinger / KudsRocket 10-21 都到了 2.2.0 / 0.8.7）。这次把它接到最新，**只推 dev，不推正式版**（prod 仍 v0.9.17）。

修的是一件**有症状的数据安全问题**（10-21 道 2 只读核出的根因；user 10-21「CatsUp 为什么一直弹云端冲突」）：CatsUp 开机先从本地恢复上次的模型、**再** initAuth（v0.5.7 的秒开顺序）。恢复那一刻 store 视为未登录 → `open()` 走本地、本 tab 没有「这份字节是云端哪一版」的基准；登录落地后 `refreshOpenDoc → pullIfClean`，0.15.2 在「云端没动」时**不记基准**；于是第一次保存的推云**没有 If-Match** → 云端已有同名文件 → 409 → `CloudNameCollisionError` → 弹「保存撞上云端新版本」——**云端其实没人动**。每刷新一次复现一次；10-21 CatsUp 一天发 12 版 = 弹 12 次。库在 0.16.2（refresh 在 in-sync 时也重捕基准）和 0.18.0（open 时云端核对没跑成 ∧ 本地干净 ∧ 磁盘有上次同步的 etag → 记为基准）两处修了，CatsUp 收进来就好。这不是新库 bug，是旧库没修。

顺带收的三件家族决定（都是 user 已拍板、不是本次新造）：① 图库卡片「推送到云端」退役——方向动词不在词汇表上（user 10-16「禁止越狱」），没同步好的文件只剩「处理…」→ store `file.resolve()` 三选一；② 冲突面词汇 = 「云端覆盖本地 / 本地覆盖云端」、主按钮云端（user 10-16「默认云端才是 authority」）、措辞按 cloudState 分四条；③ 图库名册库名归宿主（0.4.0 写死的是 WeebPaint 的 GUID 名）。

## 4. 2.x 开关：这次怎么定

家族政策（store 0.17.2，user 10-15「123同意」）：**行为变更默认关、消费方显式开**。

| 开关 | 在哪 | 库默认 | 这次 | 为什么 |
|---|---|---|---|---|
| `transport.timeouts` | `createOneDriveProvider({ transport })` | 关 | **开**（`DEFAULT_GRAPH_TIMEOUTS`：meta 30 s / 块 120 s / range 60 s / 整文件 15 min） | iPad 锁屏后在途 fetch 常常永远挂着。`session.save()` 把 `saving = true` 然后 `await store.save()`（推云内联）→ 推挂死 = `saving` 永远 true → `tick()` 的 30 s 自动保存全部跳过（`idle = !this.saving && …`）、编辑只在内存里直到 reload。碰第 2 条（没传上去的改动不能丢），§3 A3。到点 → `CloudNetworkError` = 和断网同一类：save 返 `pushed:false`、文件留脏（`pushPending`）、下次保存补推。WeebPaint 同形同病，user 10-21「没问题」开了同三个（v0.14.39）；总账票 1 的接线清单也点名开 |
| `transport.chunkResume` | 同上 | 关 | 开 | 贴图多的 .glb 会过 4 MB 走分块；网络抖一下整份重来 = 流量 × N。只影响成功率 |
| `transport.verifyChunkedCommit` | 同上 | 关 | **开** | 两台设备同时覆盖同一文件，分块上传「传那几十秒」有窗口；开了 = 提交最后一块前再比一次 eTag，窗口缩到最后一块那几秒。第 1 条，§3 A6 / A9。代价 = 每次分块覆盖多一个 GET |
| `pushRetry` | `createStore` | 4 × 200·n ms | 默认 | 推云在 `saving` 锁内；拉到 15 s 会让自动保存停 15 s；建模 app 没有 KudsRocket「每 20 s 一片」的压力 |
| `openLineageFromDurable` | `createStore` | **开** | 开 | §2 0.18.0 行——就是修 §1 的那一半 |
| `trustHints:false` | `pullIfClean` 调用点 | 默认 true | **传 false**（唯一调用点 `refreshOpenDoc`） | 不是开关是用法；三处调用全是「怀疑过期」时刻 |
| `streaming` | `createStore` | 不传 | 不传 | 没有流式读 |
| `docKinds[].tier` | `createStore` | 不传 = work | 不传 | 崩溃影子不在 store；没有二等 |
| `offlineUploadReplay` | `createStore` | manual | `"ask"`（**和 0.15.2 一样**，没动） | 离线保存的模型回线问一次再补推（`confirmReplay` sheet）——0.5.1 起就是这样 |
| `uploads.resumable` | `createStore` | 关 | **没开** | 新持久化键（kv 里多一类 `internal.upload-session:*`）= app 的表态，家规「store 持久化改动需显式同意」；WeebPaint 的批准不覆盖 CatsUp（票 1 写明「CatsUp 另问」）。§7 |
| 登录后 / 回线后「问一次」`pushAll` | app 侧 | — | 没加 | §2 最后一行：挂在 F-70 等 user 重新想 |
