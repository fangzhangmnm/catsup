## 1. 病根（批判地看 SU）

「画错 hierarchy 的事故」不是「物体有 kind 又有子物体」本身的错——glTF node / Blender object / Unity GameObject 都是一个节点既有 mesh 又有 children。病在 SU 的两件事叠加：
1. **任何层级都能有散几何**（定义的 Entities 里散边面与子组件混住）；
2. **散几何在那一层黏连**（sticky）。
于是「进错层画了一笔」= 几何黏进了错的地方，事后很难拆。我们 0.13 的 body 联合（definition = body + instances）照抄了 SU 这一点。

## 2. 提案：容器 / 身体严格分层

- **容器（container）**：只装子物体（实例 / 组 / 身体），**没有散几何**。站在容器里 = **物体模式**：画图工具不存在，只能选 / 摆 / 移 / 转 / 缩 / 复制 / 打组 / 炸开 / 锁定 / 元数据。
- **身体（body）**：一种 kind（brep / 以后 card …），**没有子物体**。站在身体里 = **编辑模式**（brep → 几何 / 表面）。
- **每个容器带一个隐式「散件」brep 身体**（空时树里不显示）。画图永远画进某个身体；开 app 默认站在根容器的「散件」身体里（随手画不受影响）。
- **模式不是另设的开关，就是你站在哪一层**：左上下拉框 = 显示当前层的种类 + 跳层（物体 ↔ 几何 / 表面）；面包屑同步。
- **动词映射**：「建组」= 把散几何切成一个新身体（兄弟，住同一容器）；要给一个身体加子物体 → 它先变成容器（系统做：容器{原身体}，原身体改名「散件」）；在身体里「放实例」= 放进身体的父容器，不往身体里塞；「进入」身体 = 编辑几何，「进入」容器 = 物体模式；炸开容器 = 子物体升一级，炸开身体 = 几何并进父容器的散件身体。
- **对齐不丢**：推断世界照旧合成所有可见身体（现在的 WorldView 就是），parent 提供对齐这个好处不需要 parent 自己有散几何。
- **代价**：房子 + 窗 = 容器{墙身体, 窗实例}，比 SU 多一层；group 的心智从「一坨几何」变成「容器或身体之一」；格式 = definition 分成两种节点（CATSUP_definitions 升 minor，老文件迁移：每个有子物体的定义 → 容器 + 散件身体）。
- **换来的**：进错层最多画进错的身体（整体可搬），不会黏进别人的几何；面包屑 + 模式两处都告诉你站在哪；物体模式天然没有画图工具。

替代方案（不推荐，列出来免得再问）：
- **保留 SU 模型 + 护栏**（提示「你现在在容器里画」）：治标，黏连事故仍会发生。
- **自动包裹**（往身体里放实例时系统自动把它变容器并把原几何塞进散件）：行为对用户不可预测，违反「不许自动替补」。

## 3. 能力组合（ECS 读法）

每种物体声明自己吃哪些**公用动词** = 能力：
`selectable · erasable · movable · rotatable · scalable · copyable · lockable · enterable · paintable(表面) · …`
通用工具只问「选中的东西有没有这个能力」，没有就跳过并提示（和锁定现在的做法一致：`movablePoolPicks` 过滤 + 提示一次）。能力的实现按 kind 派发（门 1 的 `ops.poolOf` 分叉就是落点）。不做继承树：abc 一层（能力接口）+ 按 kind 的实现表就够。

| 物体 | 能力 |
|---|---|
| brep 身体 | 全部 + 可进入（几何 / 表面） |
| 容器 / 组 / 实例 | 选 擦 移 转 缩 复制 锁 进入（物体模式） |
| 参考几何（线 / 点） | 选 擦（A31）；移 = 以后 |
| 卡片（A26，延后） | 选 擦 移 转（绕竖轴）缩 复制 锁；不可进入（有自己的帧 / 状态机面板） |

## 4. 参考人卡片（A26）——延后，先记规格

user 2026-10-24：「如果你想做参考billboard导入的时候，不要直接复制，而是弹一个窗口，让你裁剪，调分辨率，png or jpg，以及设置参考高度。才能进，然后是bottom middle为origin」「其实我觉得现在我们不一定有条件做参考卡片」。
→ 导入流程 = 弹窗：裁剪 → 分辨率 → PNG / JPG → 参考高度（米）→ 才进文件；**原点 = 底边中点**（落地站立）。其余（帧集 / 状态机 / billboard 朝向）等条件成熟再设计。
