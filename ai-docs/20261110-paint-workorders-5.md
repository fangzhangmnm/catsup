## 要达到什么

user 定的（canonical）：**笔和橡皮，轨迹在屏幕上，笔尖在空间里。**

- 滤抖在手所在的地方做（屏幕上）；压感是手的力度。
- 间距、走了多远，在空间里量。
- 笔的大小是屏幕大小，落笔那一刻换成空间里的大小，一笔之内不变。

画画内核现在的一笔是这样走的（都在 `BrushEngine` 里，坐标全是画布上的像素）：

```
原始的点（x, y, 压感, 时间） → 滤抖 + 压感平滑 → 一条平滑的中心线 → 沿中心线按间距走步 → 每一步一颗笔尖（位置、大小、浓度）
```

三维要在中间插一步：

```
原始的点（屏幕） → 滤抖 + 压感平滑（屏幕上） → 【宿主：把这条线落到模型表面上，变成空间里的一条路】 → 沿这条路按间距走步（空间里量） → 每一步一颗笔尖（空间里的位置、大小、浓度）
```

所以要把「一笔的手感」（滤抖、压感、停顿、走步、每颗笔尖多大多浓、起笔收笔的渐细）从「往一张二维图层上画」里拆出来，成为不认识图层、不管几维的一段；`BrushEngine` 变成它的一个用户。

**画画软件的结果必须逐位不变。** 这一张对画画软件是纯重构。

## 一、形状（Fable 定的，照做；觉得不对停下来说）

### 1. 不认识图层的那一段（暂叫 `StrokeCore`，名字你定）

它管：`StrokeSmoother`、`PressureLPF`、停顿不积压感那条规矩、走步、`_stampParams`（压感曲线、大小 / 流量 / 浓度的联动、起笔和收笔的渐细）、收笔时量总长。

它不管：图层、画布的边界、包围盒、像素笔直接落层的那条路、脏区、颜色怎么合成。这些留在 `BrushEngine`。

`BrushEngine` 对外的每一个方法、每一个返回值都不变（它的用户很多：形状笔、涂抹、液化、选区笔、滤镜笔、`input.ts`、`board.ts`，一个都不许跟着改）。

### 2. 路（走步吃的东西）

```ts
/** 一条路：若干个点，每个点 dim 个坐标和一个压感。 */
export interface StrokePath {
  readonly dim: number;                 // 2 或 3
  readonly count: number;
  coord(i: number, k: number): number;  // 第 i 个点的第 k 个坐标
  pressure(i: number): number;
  /** 第 i 个点和它前一个点之间不连（落点跳到了别处，比如从胳膊跳到了身子）。 */
  breakBefore(i: number): boolean;
  /** 前多少个点不会再变。 */
  readonly frozenCount: number;
}
```

- 走步的函数吃一条路，不管几维。两点之间的距离是这条路自己坐标里的直线距离。
- **断开的地方**：不在两头之间插笔尖，那一段的长度不算进「走了多远」；间距的余数带过去（不在断点重新起一颗）。
- **二维时每一个数和现在逐位相同**：长度还是 `Math.hypot(dx, dy)`，插值的算式照抄，循环的顺序不变。三维用 `Math.hypot(dx, dy, dz)`。

### 3. 宿主的落点（中间插的那一步）

```ts
export interface PathPlacer {
  readonly dim: number;
  /** 路的坐标里，「一个像素」有多大（见下面第 4 条）。 */
  readonly unit: number;
  /**
   * 把平滑好的中心线（屏幕上的点 cx / cy / cp，前 frozenCount 个不会再变）换成一条路。
   * 每次要走步之前调一次。路上的点可以比中心线上的多（宿主会把线落密，好贴着表面走）。
   * 宿主自己记着上次换到哪了；前面不会再变的部分不用重算。
   */
  place(cx: readonly number[], cy: readonly number[], cp: readonly number[], count: number, frozenCount: number): StrokePath;
}
```

- 开始一笔时可以给一个 `PathPlacer`。不给 = 路就是中心线本身（二维、`unit` 是 1、没有断点）。`BrushEngine` 永远不给。
- 落密、打射线、判断断开，都是宿主的事，内核不知道。

### 4. 单位

走步和笔尖里有几个写死的数是按「画布上的一个像素」来的：间距最少半个像素、笔尖最小半个像素。路的坐标换成米之后，这些数要跟着换。所以有 `unit`：路的坐标里一个像素有多大。

- 二维：`unit = 1`。乘 1 不改变任何一位。
- 三维：宿主给，是贴图上一格在空间里的大小（一米除以密度）。
- 笔的大小（`settings.size`）调用的人已经换成路的单位了，内核不换算。渐细的长度是大小的倍数，本来就不带单位。
- 把 `brush.ts` 里所有带单位的常数找出来列进记录，逐个说明乘不乘 `unit`。

### 5. 出来的东西

```ts
/** 笔尖列表：不认识图层。 */
export interface StrokeTips {
  readonly dim: number;
  readonly count: number;
  /** 每颗笔尖 dim + 3 个数：位置（dim 个）、大小、浓度、这一颗落下时已经走了多远。 */
  readonly data: Float64Array;
  /** 前多少颗已经定型，以后每次再收集，它们都逐位不变。 */
  readonly frozenCount: number;
}
```

- `BrushEngine.collectStamps()` 照旧返回它现在的东西，里面用这一份拼。
- **定型的条件**：这颗笔尖来自路上不会再变的部分，**而且**离现在的路尾已经超过收笔渐细的长度（收笔渐细要等抬笔才知道总长，但总长只会变长，所以离路尾够远的笔尖不会再被它改）。没有收笔渐细的笔，只看第一条。
- 二维这边现在每帧从头重走一遍，不用定型这个数；它是给三维用的（定型的笔尖只往贴图上画一次）。这一张只要求数是对的、有测试。

## 二、门

1. 画画仓 `npm test` 全过，逐像素基线不变，显卡那套基线（`npm run smoke`）不变，`tsc` 干净。现有测试文件一个字不改（要改哪个，先说）。
2. **动手之前先冻**：用现在的代码，对十来条造出来的笔画（快的、慢的、中途停顿的、压感乱跳的、带起笔和收笔渐细的、椭圆笔尖的、极小的笔、极大的笔、只有一个点的），把 `collectStamps()` 每一帧的结果按位存成样本。改完之后同样的输入，结果按位相等。这条是这一张的主门。
3. **新测试 A：三维的间距。** 测试里写一个假的落点：把屏幕上的点落到一个球面上。出来的笔尖，相邻两颗在空间里的直线距离等于那一步的间距（误差不超过路上相邻两点之间那一小段弦和弧的差）。
4. **新测试 B：单位。** 同一笔，把世界、笔的大小、`unit` 一起放大十倍，出来的笔尖位置和大小正好是十倍，颗数、浓度不变。
5. **新测试 C：断开。** 路中间有一处断开：断点两头之间没有笔尖；「走了多远」不含那一段；断点后第一颗和断点前最后一颗沿路的距离加起来正好是一步。
6. **新测试 D：定型。** 一笔边画边收集：每次收集时前 `frozenCount` 颗，和下一次收集的前这么多颗逐位相同；`frozenCount` 只增不减；抬笔之后的最终结果里，这些颗也逐位相同（带收笔渐细的笔和不带的各测一遍）。
7. **新测试 E：停顿。** 落笔后原地停一会儿再走（现有的 `brush-dwell-pressure` 那条规矩），在三维的假落点下结果和「不停直接走」一样。
8. **守卫**：不认识图层的那一段不 import 图层、画布、显卡的任何东西；走步的循环全仓只有一处（`BrushEngine` 里现在那两份走步——带缓冲的和像素笔直接落的——像素笔那一份这一张不动，在记录里写明留着，1-5 再看）。
9. `api/` 重新生成；画画仓的流程图文档里「一笔」那条流程更新；0-1 定的「内核自己的测试」名单里加上新测试。升一个末位版本。

## 三、碰到这些就停下来报

- 第 2 条按位对不上，而且不是因为你漏抄了哪一步。
- `BrushEngine` 的某个用户（形状笔、涂抹、液化……）用了它里面带下划线的东西，拆的时候绕不开。
- 发现还有别的地方悄悄假设了「坐标是画布像素」（比如滤抖里的死区、起笔的判断），列出来问：哪些该在屏幕上量（留着），哪些该换成路的单位。Fable 的读法是：滤抖、死区、停顿都在屏幕上，不换；走步、大小、渐细在路上。
- 定型的条件在某种笔上不成立（比如有按总长归一的别的效果）。

## 这一张不做的

宿主那一边的落点、落密、射线（1-4）；像素笔在三维里怎么走（1-5）；笔尖怎么画成贴图上的薄层（0-5、1-4）；笔的姿态（倾斜、转向）进接口——user 定了「笔吃的是空间里的姿态」，第一天只实现球，接口等 1-4 用到时再加，这一张不留空壳。
