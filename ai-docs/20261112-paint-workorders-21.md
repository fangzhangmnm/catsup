# 施工单（二十一）：小窗里能画，第一步

> created 2026-11-12 by Claude Fable 5.2 · as-of 三维 v0.19.55（开发版）
> 施工：Catsup小弟。排在施工单二十 1b 之后。先后和起因 = 设计日记第四十七到四十九轮；小窗和工具栏的关系 = `ai-docs/20261112-canvas-window-modes-design.md`（设计稿，这一张只用到第四节「一只手，两块画面」）。

## 一、为什么，做完是什么样

user 11-12：「其实我要真开始做东西的话，最大的杠杆是在窗口里面画，因为这样的话我可以画一些普通的二维像素贴图。」「就是说不切 app，我能画二维贴图。」

做完：画布小窗浮着的时候，手上的笔、橡皮、吸管落在小窗的画布上就能用；画的是和模型上同一块画板，三维那边实时跟着变；能新建一张不属于哪个物件的二维贴图（平铺的画），在小窗里画，再用油漆桶贴到面上。

这一张不做：选区、填色桶、移动和变换（等三维自己的选区交互那一步）；小窗停在下面和全屏；图层面板；别的画画软件的工具。

## 二、定下来的（改之前先问统筹）

1. **一只手，两块画面。** 手上的工具只有左边工具柱里的那一个。落在模型上走空间那条路，落在小窗的画布上走内核自己的二维笔。小窗不带自己的工具栏。
2. **同一块画板、同一套底子。** 二维笔画在 `PaintBoard` 上，不另起一份：撤销进同一串（一笔 = 编辑器撤销里的一步）、存盘和崩溃快照走同一个钉点、锁照样四层都问、睡和醒照第 3 刀的规矩（小窗里开着的那块算「正在编辑」）、「手上有一下没收」的名册里有它。
3. **笔的记录两边共用。** 小窗里用的就是笔的表里那几行，经 `resolvedBrushOf` 交给内核的二维笔。一支笔在画布上能不能用，照笔的模型第四节做成「这块画面认得什么」的单子和一个函数；用不了的在画布上是灰的、说原因。
4. **手势和模型上一样**：笔画，手指看（挪、缩）；鼠标左键画、滚轮缩。手在哪块画面上就动哪块。
5. **平铺的画**是贴图表里的一行：内容是分层的（和别的画一样），带 `sizeM`、不带 `layout`。这个组合现在的格式本来就允许（`sizeM` 和 `layout` 正好有一个），但以前没有意思；给它意思 = `CATSUP_textures` 升 1.2（旧版本读到它当成不认识的画、按底色显示、原样带回）。施工单十八原来打算用的 1.2 顺延成 1.3，我去改那一页。
6. 平铺的画只能在小窗里画。手上拿着笔落到贴着它的面上 = 不画、说原因（一格对着模型上很多个地方，在模型上画没有意义）。

## 三、分三刀

**第 1 刀：画板多一个二维落笔的口**（没有界面；内核白名单要加的名字、撤销和锁那几行发统筹）

你 11-12 列的六截照做：
- `PaintBoard` 多一个开二维笔的口：档口用内核的 overlay 方式加 `BrushEngine`，落层经 `gpu()` 走 `commitBrushStroke`（照画画仓后端那十几行）。
- 合成时把笔尖的薄层也递进去；`strokeOpen` 认它，画着的时候不许睡。
- 封的步交给同一个 `HostedSteps`，接到编辑器撤销那一步的入口。
- 问锁（开一笔、落层两问），进像素写入名单，「睡着时怎么办」那一栏填上。
- 名册：这一笔开着时 `hand.busy()` 是真的；来源用现成的还是加一行你定，加了就要有那条「没收时存盘」的检查。
- 内核白名单要加哪些名字，合之前列给我，连同为什么不能少。
- 检查在 node 里：二维笔画几笔，图层和合成逐字节等于内核自己那套测试里同样几笔的结果；撤销逐位还原；锁着画不上；一笔当中存盘存的是落定那一版。

**第 2 刀：小窗接上手**（自己合，一个版本）
- 指针落在小窗的画布上：屏幕坐标换成画布像素（跟着小窗的缩放和平移），交给第 1 刀的口。事件时间和压感照 1a 的规矩。
- 笔、橡皮、吸管能用；别的工具在画布上是灰的。
- 放大到看得见格子时画出像素格；悬停时会被涂到的格子亮出来。
- 三维那边实时跟着变（同一块画板，不用另做）；核一下一笔当中每帧只重做改到的那一块，小窗和三维各自都对（开着核对开关）。
- 两块画面来回画：在模型上画一笔、在小窗里画一笔、撤销两次、重做两次，每一步两边看到的都一样。

**第 3 刀：平铺的画**（格式的 diff 发统筹）
- 小窗「…」里「新建平铺的画…」：选像素大小（16 / 32 / 64 / 128 / 256）和它在模型上多大（米，默认 1）。建一行贴图和一个用它的材质，开在小窗里。
- 渲染器认它：贴着它的面显示它的合成图，按 `sizeM` 平铺，过滤照现在自由的图的规矩。
- 存盘、读盘、撤销、睡和醒、锁，和别的画一样走；`CATSUP_textures` 1.2，冻样本，旧版本真代码当读者（照门 6）：打得开、按底色显示、存回去这一行还在。
- 没有面的轮廓，小窗里就是一张图。

### 第 1 刀：画板多一个二维落笔的口（2026-11-12，Catsup小弟；白名单 + 撤销 / 锁那几行已发统筹）
- **口**：`PaintBoard.openBrushStroke(笔, 第一个点, {erase, smooth, layerId})` → `BoardStroke {open, move, end, cancel}`。档口 = 内核 `StrokeSession` 的 overlay 方式 + 内核 `BrushEngine`（照画画仓后端 strokeBegin 那几行）；画着时笔尖单子（`collectStamps`）垫进合成；落层经 `gpu()` 走 `commitBrushStroke`（照后端 `_commitStamps`，没有选区 = 不带蒙版），返回 false 也响亮地抛。三维那一笔和二维笔共用 `sessionDeps`（只差落笔尖单子那个口）。登记处 `PaintBoards.openBrushStroke(贴图, …)` 包一层：登记成开着的一笔，撤销 / 重做 / 扔画板之前 `cancelOpen` 取消（连登记一起摘）。
- **同一块画板只许一笔**（二维开着再开二维 / 三维 = 抛，三维那边同样）；`strokeOpen` 认二维笔 = 开着时不睡。
- **撤销**：同一个令牌、同一个 `HostedSteps`、抬笔后同一个 `commitRecordsStep`。
- **锁**：开一笔、落层两问；像素写入名单两行（画板的问锁、登记处的经画板），睡着时那栏填了；锁 / 睡两条守卫改成认「开一笔在方法体里问、落层在 sessionDeps 里问」，要求没变。
- **名册**：没加新来源，「画画的一笔」改问「工作台按着 ∨ 哪块画板开着一笔」，「没收时存盘」那条检查照旧管它（mid-stroke-save V12）。
- **内核**：白名单加 `BrushEngine` 一个名字（别的类型都从已放行的名字推出来）。画画仓 v0.14.87：档口落笔尖单子那一步抛 = 先取消令牌再抛（和区域笔、宿主薄层两条路一致；以前漏了，锁上那一笔之后下一笔被单令牌墙挡住——node 检查 ④ 撞上的）。
- **调试钩子**：`paint.stroke2dOpen`（开一笔交回把手，能跨几次异步调用按着）/ `paint.stroke2d`（一口气画完）；和画画工作台同一个笔的解析 + 平滑、同一道落笔的门、同一个「一笔 = 一步」。第 2 刀小窗接上手走同一个 `paintStroke2dOpen`。
- **检查**：node `paint-2d-stroke`（7 条）——四支笔的图层 = 画画仓后端同样几笔逐字节、合成 = 后端那几层装进干净画板合出来的逐字节、画着时图层不动 / 存盘那张 = 落笔之前 / 显示 = 整张重合 / 不能睡、带平滑的笔每动一下显示 = 整张重合、经登记处一笔一步 + 撤销逐位还原 + 画到一半撤销零痕迹、锁两问、只许一笔。红线组三个探针各加一段二维笔：paint-undo ⑤、paint-save ③½、mid-stroke-save V12，都绿。
- **自己的毛病，探针抓到、已修**：只在引擎报脏区时让画板的版本往前走 → 带平滑的笔（勾线笔）尾巴在变、画板拿旧图交差（mid-stroke-save V12 每帧核对红）。改成每动一下都算变了；node ②′ 钉住（改之前红）。
- 探针那两处前提也照实写：paint-save ③½ 最后补画的那一笔换了线和颜色（同色重画不改像素 = 不算改过）。
- 第 2 刀要量：内核对笔尖单子这种 overlay 一律整张重合，「一笔当中每帧只重做改到的那一块」可能要动内核。

### 第 2 刀：小窗接上手（进行中，2026-11-12，Catsup小弟）
- **先量了（统筹要的，已报）**：二维笔一笔当中每帧比底数多出（软件显卡，参照）：128 ≈ 6、256 ≈ 9、1024 ≈ 36、2048 ≈ 98 毫秒；拆开 = 内核整张重合（128 4.4 / 256 7.1 / 1024 24 / 2048 62）+ 显示那侧整张重拷和缩小图（1.5 / 2.2 / 12 / 35）。抬笔 37 / 47 / 86–100 / 230。统筹 11-12 定：① 显示那侧按这一下真变了的块报（只动三维）、② 内核对笔尖单子也走「只重合几块」**现在都不做**——≤256 是主要用法、多几毫秒不用管；大画布内核那一半就是画画软件每一笔都在走的路（iPad 上天天用着没问题），真要动是周账 F-257（内核只重合变了的图块，先真机量），不在这一张开；显示那一半省得少、报小了会显示旧图（V12 同类坑），没有真机卡的证据不担这个风险（user 的停止线：不在软件显卡上抠毫秒）。
  - 原样的数（毫秒，中位，swiftshader）：底数（什么都没变画一帧）23–25；模型上的笔每帧 26–32。二维笔每帧：128 = 27、256 = 34、1024 = 57–63、2048 = 122–138。拆开（比底数多出）：内核整张重合 4.4 / 7.1 / 24 / 62，显示那侧整张重拷 + 缩小图 1.5 / 2.2 / 12 / 35。抬笔：37 / 47 / 86–100 / 230。
  - **什么时候必须动**：真机上在小窗里画 1024 以上的图看得见卡。到那时先量是哪一半（内核整张重合 / 显示那侧整张重拷），再定动哪边。

- **统筹 11-12 裁定内核三件**（全文 = 设计日记 `ai-docs/talks/20261110-marriage-route.md` 第五十三轮）：
  - 先限时在真显卡上量：量到了——无头 Chrome `--use-gl=angle --use-angle=gl --ignore-gpu-blocklist --enable-gpu`，WebGL 报 D3D12 (AMD Radeon 780M Graphics)（GPD 的核显，走 WSL 的 /dev/dxg；不动系统配置）。真显卡上（毫秒中位，底数一帧 8）：2048 二维笔每一下 28、抬笔 60（落层约 24 / 落层后整张重合 13）；模型上的笔抬笔 80（整笔重画 15.6 / 落层 23.7 / 整张重合 13）；256 上这几样 14 / 19 / 26。**v0.19.58 → v0.19.59 在真显卡上量不出差别**（显示那侧整张重拷在真显卡上本来就便宜，软件显卡上的 30 多毫秒是放大出来的），改动留着（报大不报小、有测试、只影响显示），以后不算成收益。
  - **K2 批、形状改**：只限到这一笔的方框（不许限到格：v0.14.84 的核对片比的是方框里报的格以外合出来的和原来的一不一样，只合格子会让「绝不少写」那道保险空了）；StampOverlayInput 不加 cells（二维笔按格读回只省约 4 毫秒；以后要也是内核自己从笔尖脚印算）；bakeStamps 注释写明「这一遍合成是逐点的」并加守卫（以后 overlay 那一段加带半径的东西 = 方框按半径外扩或退回整张）；随机测试含贴边、半出界、橡皮、锁透明、带选区、几种混合方式，限 / 不限落进图层的字节和 lastBake 都逐字节相同；落层是存进图层的路 = 内核 diff 先发统筹审。
