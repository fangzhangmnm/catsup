## 1. 范式：3D 游戏 HUD，不吃视口

user：「我说个我们ui要参考3d video game对吧，因为他们的优化目标也是不吃3d视口」。参照物 = 原神（截图 2026-10-24）：

## 3. 规矩

- **不吃视口**：常驻 HUD 只占四个角和两条边的薄层；大面板从底部抽，不从侧面推。
- **左 tool，右 view**：工具归左柱（工具的选项 v0.14.7 起在右下参数小窗里 = 上下文选项）；相机 / 渲染 / 视角归右上；SU 的视角钮不进左柱。
- **工具的事归工具**：轴 / 参考线 / 段数 / 中心对齐这类进工具上下文菜单，不进 ☰。
- **菜单用分区小标题不用子菜单**（票 2，WeebPaint 范式）。
- **嵌入纸面**：左上横排没有底板，靠留白和按下态表达可按；图标走共享图标库，风格一致（商城图标也是：user「钻石商店的图标（但是风格保持一致）」）。

## 原则追记（2026-10-29，user 原话，Claude Fable 5.1 记）：形状编码

> user：「最硬的证据其实来自另一类问题：控件长得像。二战时 B-17 等机型多次在着陆时误收起落架。Chapanis 发现，起落架和襟翼的控制杆外形几乎一样、并排放置，压力下飞行员会抓错。他给起落架杆加了一个小轮子，给襟翼杆加了楔形头，这类混淆几乎消失，战后成了全球标准。“驾驶盘长得像方向盘”是同一个道理：手感相同、功能不同，才是最容易打架的地方。随手帮我记一下帐，以后磨ui时再处理」

**原则**：手感 / 样子相同而功能不同的两个控件，必须靠**形状和手感**区分，不靠标签。磨 UI 时过一遍的嫌疑点：右上挂件条锁钮 / X 光钮并排同形；左柱合租格（挤出 / 沿法线、插入 / 倒角）；键名芯片「按住」vs「锁住」只差亮暗；右下胶囊两个去向同一颗；两个 ☰ 同图标。Tron 账本 T34；家族记忆 feedback_shape_coding_controls_20261029。
