# 贴图主线施工单（十三）：画存进文件、读回来；没画过的画只留显示用的图（1-8b）

> created 20261111 by Claude Fable 5.2 · as-of 三维 v0.19.19、画画 v0.14.75 · 2026-11-11
> 给谁：Catsup小弟。**等 Fable 看过才合。** 排在 1-8a 之后。分支 `paint-save`。短施工单：细则你动手前补在页末。
> 这张做完，带着画的文件才存得下来。它是整条线上数据安全最重的一张：**先把细则报给我看过再动手**（怎么钉住那一刻、怎么和现有的存盘排队接、崩溃快照怎么带画），别的短施工单不用这一步。
> 不碰同步库和它的规矩；只管「交给存盘的那一包字节里有什么」。

## 要达到什么

画了几笔，存盘，关掉，再打开：画还在，一格不差，图层也在。没存就崩了：恢复回来最多少最后几笔，而且明说。

## 关键的形状

1. **存的是按下存那一刻的样子**：模型和每一张画都钉在同一刻。编码是异步的（画画内核把一张画编成分层的那种文件要时间）；编码期间用户接着画，存出去的仍然是那一刻的；存完之后文档仍然算改过。画画软件自己存盘时是怎么钉住的（它 11-09 修过「自动保存中换画」那一类毛病），照它的办法，不另想一套。
2. **只重新编码改过的画**：一张画自上次编码之后没有新的步，直接用上次的字节。贴图条目里的字节就是这份缓存；`ora: null`（新建的、还没编过）这时候第一次有字节。1-3b 那处「分层的贴图没有字节就不许写盘」到这里换成真的写。
3. **读**：读进来的画是**冷的**：不建画板，只留字节。要显示时：建画板、解开、合成一次、把合成好的图拷进显示用的图，然后**放掉画板**。显示出来之前照材质的底色显示。材质的底色变了，再走一遍。
4. **热**：这一次会话里画过的画一直热着（画板留着），直到关文件。原因：它的撤销步指着画板里的东西，放掉画板就得清它的撤销。读进来没动过的画不会变热。
   - 落笔时画板还是冷的：先解开再画。解开要时间，所以进画画的工作台时（1-7 接）或者调试钩子里可以提前把目标的画板热好。落笔那一下如果还没热好：这一笔不开始，提示行说「这张画还在打开」。不许卡住，也不许悄悄丢笔。
   - 目标（写给你量的）：读进来没画过的画，1024 见方每张常驻不超过约 6 MB。
5. **画布大小和贴图坐标**：存的时候，画板比那一套坐标高、多出来的行是空白 → 按坐标的高存。多出来的行有内容（11-11 定的「不砍有内容的行」留下的）→ 照画板的高存，不砍。读的时候：分层的画宽度和那一套坐标一样、高度不小于它 = 正常；别的情况 = 这张贴图当孤儿留着、记一笔并告诉用户（附属数据坏了不拒开的那条规矩）。
6. **崩溃快照带上画**：照现有崩溃快照的节奏，带的是每张画「最近一次编好的字节」。为了不落后太多：画板改过之后，空下来的时候（不在一笔当中）在后台编一次。恢复时如果快照里的画比模型旧，明说「画可能少了最后几笔」。
7. **读进来时丢过东西的文件**（1-2½ 的那些坏数据）：第一次存盘之前要用户明着点一次头（存 / 另存为 / 先不存），在那之前自动保存不动这份文件。
8. **画画内核靠一个全局的 `zip`**：三维这边在用内核之前把它备好（三维仓里本来就 vendor 了同一个 zip.js），加一条守卫；不改内核。

## 不能破的规矩

- **来回一格不差**：随机的几张画（几层、有透明、有橡皮擦过的洞），存、读、让它热起来，每一层的像素和存之前逐字节相同；没动过再存一遍，文件逐字节相同。
- **钉在同一刻**：编码到一半时再画一笔、再切一刀：存出去的文件里是存那一刻的画和那一刻的模型；之后文档仍然算改过；再存一次才带上新的。
- **存盘失败不留半截**：编码中途出错，这一次存盘整个算失败、明说，上一次存好的文件不受影响，内存里的画不受影响。
- **冷的画不占画板**：读一份有十张画的文件，全部显示出来之后，活着的画板数是零；量常驻内存。
- **冷热之间显示不变**：同一张画冷的时候显示的和热起来之后显示的，逐像素相同。
- **撤销不受存盘影响**：存盘前后撤销栈一步不少，撤销还是对的。
- 不带画的文件，写出来和现在逐字节一样；旧版本读新文件的那个脚本（`scripts/old-reader-check.mjs`）再跑一遍，结论不变。
- 冻样本：带一张真的两层的画的文件（1-2½ 已经有一份），加一份画板比坐标高的。

## 碰到这些就停下来报

- 画画内核没有现成的办法钉住一张画那一刻的样子，要钉得改内核。
- 现有的存盘排队、自动保存、崩溃快照里，有哪一处会在编码还没完的时候就把文档当成存好了。
- 冷的画要显示得先整张解开，十张画一起解开时界面会卡多久（量出来）。
- 任何「存了但其实没存上」「读了但少了东西却没说」的可能。

## 这一张不做的

给别的软件看的那一半带上画（合成图加贴图坐标，另一张）；画跟着面搬家（1-3d）；几块画板共用内核的额度（0-3）；界面（1-7）。

## 做完

`api/` 重新生成；流程图「存盘」「读盘」两节加上画；一个末位版本。交审：最后一个提交、八条规矩各自的结果、量出来的数、和这里不一样的地方、不放心的地方。

## 施工细则

> Catsup小弟（Claude Opus 5.5）2026-11-11 夜写，as-of 三维 v0.19.22 / 画画 v0.14.77；**统筹 11-11 看过、改了冷画的方向、七处都定了**（定的原意照录在各节；第一稿的「冷的画排队解开」「改活图契约加 held」作废）。

### 〇 量的数（node + 内核软件显卡，桌面；iPad 没量）
- 1024 × 1280、两层各盖一半：编码成分层文件 平涂 135 ms / 325 KB，最坏（每像素随机）339 ms / 6.1 MB；解开 19 ms / 113 ms。都是主线程上的一整块活。
- 变热时的解开仍在主线程：统筹接受，记下触发条件——**iPad 上单张超过半秒、或者 user 说卡，就挪到 worker**。

### 一 怎么钉住那一刻（统筹同意）
- 照画画仓：编码的同步那一段就是钉点；`wp.exportData()` = 冻结拷贝，不改内核。`Session.encode()` 拆两段：
  - `freeze()` 同步一口气（中间不 await）：记 `revAtStart`；`documentFromScene`（新拷的；贴图行共用但从不改——测试钉住）；每张分层的画定死这一次的来源：
    1. 有画板、提交版本 = 缓存的版本 → 缓存里的分层字节和合成图；
    2. 有画板、版本不同 → 当场 `exportData()` + 当场合成读回（合成图，见二）+ 画布高度判断（见五）；
    3. 冷的（没有画板、贴图行里有字节）→ 原样用行里的分层字节和合成图（文件里的字节不重编，没动过再存一遍逐字节相同）；
    4. 新建了还没画过（`ora: null`）→ 分层字节编一份空白的（按宽高缓存）；**合成图不存**（照底色显示，统筹定）。
  - `finish()` 异步：2、4 交内核编码（一张一张）、合成图编 PNG → 填进冻结那份文档的贴图行（新行对象）→ `writeCatsup`。编完按版本进缓存（只在更新时替换）。
- 缓存住场景外（`src/paint/`，按贴图 GUID + 画板身份 + 提交版本；分层字节和合成图同理）——统筹同意：贴图行被撤销快照共用，往里写字节撤销历史就带上别的时刻的字节。
- 分层文件里给别的软件看的合成预览：内核缺省的透明占位（统筹同意；我们自己的合成图在外面那个键上，不重复存）。文件里「哪个版本写的」= `catsup vX.Y.Z`。

### 二 合成图（统筹改的方向：冷的画不解开，直接显示存盘时存下的合成图）
- 每张有内容的画，存盘时除了分层字节另存一张**合成好的图**：合成在材质的底色上、不透明、PNG。放在贴图那一行一个新的可选键上，`CATSUP_textures` 升 **1.1**（旧读者按「不认识的键原样带回」带着）。和分层字节一样只在画改过时重做。
- 带两个记号：照哪份分层字节做的（字节长度 + 一个便宜的校验和）、合成时用的底色。读的时候记号和旁边的分层字节对不上、或者底色和材质现在的底色不一样 = 当它没有。
- 必须是钉点那一刻的：在 `freeze()` 里同步合成、读回这一张（画板的 compose = 显示用的同一张图）；PNG 编码在 `finish()`。测试证明它和那一刻显示的逐字节相同。
- 冷的画显示 = 这张 PNG 当普通的图走现有导入贴图的那条路（浏览器异步解码，不上主线程、不碰画画内核），贴图坐标用角上的数。**不建画板、不占图块池**；只是打开看模型，画画内核根本不起来。
- 渲染器契约只加一小样：一张图可以声明自己是「画」的取样方式（夹边、放大最近邻、有缩小图），不走平铺。`LiveImage.current()` 不加参数。
- 合成图没有或作废（老文件、底色改了）：照底色显示；底色改了的冷画 = 把它热一次重新合成。
- 「冷热之间显示不变」：同一张画，冷的时候显示的（存下的合成图）和热起来之后显示的（内核现合成的），逐像素相同（探针）。
- 给别的软件看的那一半（标准材质贴图 + TEXCOORD）仍是另一张单，到时候直接用这张合成图。

### 三 冷、热
- 读：贴图行带着分层字节和合成图读进来，不建画板。
- 热：这次会话里画过的画一直热着，直到关文件（0-3a 的规矩）。读进来没动过的不会变热。
- **冷的画绝不能被建成空白画板**（数据安全）：画板登记处只给「没有字节的」建空白画板；有字节的要先解开（变热）。
- 落笔时画还是冷的：这一笔不开始，提示行「这张画还在打开」，同时解开、留着画板（变热）。不卡住、不悄悄丢笔。进画画工作台时提前热留给 1-7；调试钩子 `__catsup.paint.warm(guid)`。
- 变热时查分层字节：宽 = 坐标的宽、高 ≥ 坐标的高；不对或解不开 = 这张画**只能看不能画**，明着告诉用户原因，照合成图继续显示，不当孤儿、不改任何数据（统筹定）。
- 目标（统筹改成说得准的）：冷的画不建画板、图块池占用是零；显卡上只有显示用的那一张；内存里只有文件里本来就有的字节。量出来写进记录。

### 四 和现有存盘排队、后台编码、崩溃快照
- `save()` 一次一轮不变；`savedRevision = revAtStart` 只在库写完之后；编码中途出错 = 这一轮失败、明说、上一份文件和内存里的画不动。所有 encode 的调用点（写家、安家、导出、快照）都走 freeze + finish。已核：没有「编码没完就当存好了」的地方。
- **后台编码不单开定时器**（统筹定：一次 135–339 ms 不让出，用户停一秒正要落笔会撞上）：跟自动保存同一个节奏（它要存就在那时编）；切到后台时缓存是旧的再编一次。量编码正在跑时落笔要等多久，写进记录。
- 崩溃快照：不现编，用缓存里最近一次的分层字节和合成图；有画板的画比缓存新 = 快照记 `paintStale`，恢复时说「画可能少了最后几笔」；缓存一新快照重拍（快照的键加上画的缓存版本）。

### 五 画布大小
- 存：画板比坐标高、多出来的行全空白 → 按坐标的高存（分层字节和合成图都按这个高）；有内容 → 照画板的高存。
- 读：合成图的宽高打开时就查（只读 PNG 头），不对 = 当它没有；分层字节的尺寸在变热时查（见三）。

### 六 读进来时丢过东西的文件（统筹定）
- 「再存盘就去掉」= `uvDropped`、`foreignPaintSlots`、`danglingTextureRefs`、`danglingShelfRefs`。`format-notes.ts` 旁边加「会丢 / 不丢」名单，每个键都表态，守卫查。
- 有这几种：自动保存 / 切后台落本机不写这份文件（崩溃快照照拍）；人按存 → 先弹「存（丢掉那几处）/ 另存为一份新的 / 先不存」，点了「存」才放开。

### 七 zip
- index.html 里 zip.js 是 classic defer、排在主模块前面。守卫：顺序；内核拷来的 zip.js 和三维 vendor 那份逐字节相同；存盘第一步查 `globalThis.zip`，不在 = 明说存不了。

### 八 测试 / 探针 / 样本
- node（内核测试的 zip / DOMParser 垫片放在不叫 .test 的工具文件里引）：来回一格不差（几层、透明、橡皮擦过的洞；存 → 读 → 热起来逐层逐字节）；没动过再存文件逐字节相同；钉在同一刻（finish 的空档里画一笔、切一刀）；编码中途抛 = 失败、旧文件不动、内存不动；撤销栈存盘前后一样；不带画的文件和 v0.19.22 逐字节一样；画布比坐标高（空白 / 有内容）；合成图记号对不上 / 底色变了 = 当没有；合成图和钉点那一刻的显示逐字节相同；冷的画绝不建空白画板；变热时尺寸不对 = 只能看不能画。
- 浏览器探针：读一份十张画的文件、全部显示出来之后画板数 0、图块池 0；冷热逐像素相同；落笔撞上冷的画（提示、没丢笔、变热）；崩溃快照带画 + `paintStale` 那句话；编码正在跑时落笔等多久。
- `scripts/old-reader-check.mjs` 再跑一遍；冻样本：带合成图的两层画（textures 1.1）、画板比坐标高的那份。
