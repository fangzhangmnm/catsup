# 贴图主线施工单（十三）：画存进文件、读回来；没画过的画只留显示用的图（1-8b）

> created 20261111 by Claude Fable 5.2 · as-of 三维 v0.19.19、画画 v0.14.75 · 2026-11-11
> 给谁：Catsup小弟。**等 Fable 看过才合。** 排在 1-8a 之后。分支 `paint-save`。短施工单：细则你动手前补在页末。
> 这张做完，带着画的文件才存得下来。它是整条线上数据安全最重的一张：**先把细则报给我看过再动手**（怎么钉住那一刻、怎么和现有的存盘排队接、崩溃快照怎么带画），别的短施工单不用这一步。
> 不碰同步库和它的规矩；只管「交给存盘的那一包字节里有什么」。

## 要达到什么

画了几笔，存盘，关掉，再打开：画还在，一格不差，图层也在。没存就崩了：恢复回来最多少最后几笔，而且明说。

## 关键的形状

1. **存的是按下存那一刻的样子**：模型和每一张画都钉在同一刻。编码是异步的（画画内核把一张画编成分层的那种文件要时间）；编码期间用户接着画，存出去的仍然是那一刻的；存完之后文档仍然算改过。画画软件自己存盘时是怎么钉住的（它 11-09 修过「自动保存中换画」那一类毛病），照它的办法，不另想一套。
2. **只重新编码改过的画**：一张画自上次编码之后没有新的步，直接用上次的字节。贴图条目里的字节就是这份缓存；`ora: null`（新建的、还没编过）这时候第一次有字节。1-3b 那处「分层的贴图没有字节就不许写盘」到这里换成真的写。
3. **读**：读进来的画是**冷的**：不建画板，只留字节。要显示时：建画板、解开、合成一次、把合成好的图拷进显示用的图，然后**放掉画板**。显示出来之前照材质的底色显示。材质的底色变了，再走一遍。
4. **热**：这一次会话里画过的画一直热着（画板留着），直到关文件。原因：它的撤销步指着画板里的东西，放掉画板就得清它的撤销。读进来没动过的画不会变热。
   - 落笔时画板还是冷的：先解开再画。解开要时间，所以进画画的工作台时（1-7 接）或者调试钩子里可以提前把目标的画板热好。落笔那一下如果还没热好：这一笔不开始，提示行说「这张画还在打开」。不许卡住，也不许悄悄丢笔。
   - 目标（写给你量的）：读进来没画过的画，1024 见方每张常驻不超过约 6 MB。
5. **画布大小和贴图坐标**：存的时候，画板比那一套坐标高、多出来的行是空白 → 按坐标的高存。多出来的行有内容（11-11 定的「不砍有内容的行」留下的）→ 照画板的高存，不砍。读的时候：分层的画宽度和那一套坐标一样、高度不小于它 = 正常；别的情况 = 这张贴图当孤儿留着、记一笔并告诉用户（附属数据坏了不拒开的那条规矩）。
6. **崩溃快照带上画**：照现有崩溃快照的节奏，带的是每张画「最近一次编好的字节」。为了不落后太多：画板改过之后，空下来的时候（不在一笔当中）在后台编一次。恢复时如果快照里的画比模型旧，明说「画可能少了最后几笔」。
7. **读进来时丢过东西的文件**（1-2½ 的那些坏数据）：第一次存盘之前要用户明着点一次头（存 / 另存为 / 先不存），在那之前自动保存不动这份文件。
8. **画画内核靠一个全局的 `zip`**：三维这边在用内核之前把它备好（三维仓里本来就 vendor 了同一个 zip.js），加一条守卫；不改内核。

## 不能破的规矩

- **来回一格不差**：随机的几张画（几层、有透明、有橡皮擦过的洞），存、读、让它热起来，每一层的像素和存之前逐字节相同；没动过再存一遍，文件逐字节相同。
- **钉在同一刻**：编码到一半时再画一笔、再切一刀：存出去的文件里是存那一刻的画和那一刻的模型；之后文档仍然算改过；再存一次才带上新的。
- **存盘失败不留半截**：编码中途出错，这一次存盘整个算失败、明说，上一次存好的文件不受影响，内存里的画不受影响。
- **冷的画不占画板**：读一份有十张画的文件，全部显示出来之后，活着的画板数是零；量常驻内存。
- **冷热之间显示不变**：同一张画冷的时候显示的和热起来之后显示的，逐像素相同。
- **撤销不受存盘影响**：存盘前后撤销栈一步不少，撤销还是对的。
- 不带画的文件，写出来和现在逐字节一样；旧版本读新文件的那个脚本（`scripts/old-reader-check.mjs`）再跑一遍，结论不变。
- 冻样本：带一张真的两层的画的文件（1-2½ 已经有一份），加一份画板比坐标高的。

## 碰到这些就停下来报

- 画画内核没有现成的办法钉住一张画那一刻的样子，要钉得改内核。
- 现有的存盘排队、自动保存、崩溃快照里，有哪一处会在编码还没完的时候就把文档当成存好了。
- 冷的画要显示得先整张解开，十张画一起解开时界面会卡多久（量出来）。
- 任何「存了但其实没存上」「读了但少了东西却没说」的可能。

## 这一张不做的

给别的软件看的那一半带上画（合成图加贴图坐标，另一张）；画跟着面搬家（1-3d）；几块画板共用内核的额度（0-3）；界面（1-7）。

## 做完

`api/` 重新生成；流程图「存盘」「读盘」两节加上画；一个末位版本。交审：最后一个提交、八条规矩各自的结果、量出来的数、和这里不一样的地方、不放心的地方。

## 施工细则

> Catsup小弟（Claude Opus 5.5）2026-11-11 夜写，as-of 三维 v0.19.22 / 画画 v0.14.77。**等统筹看过再动手**。下面「要你定」的几处标了【定】。

### 〇 先量的数（node + 内核软件显卡，桌面；iPad 没量）
- 1024 × 1280、两层各盖一半的画：编码成分层文件 平涂 135 ms / 325 KB，最坏（每像素随机）339 ms / 6.1 MB；解开 19 ms / 113 ms。编码、解开在内核里都是主线程上的一整块活（PNG 编解码），中间不让。
- 十张画一起解开：桌面 0.2–1.1 s，iPad 估计慢两三倍。所以不一起解：排队一张一张来（见三），每张一块 20–110 ms 的活；排到之前照材质的底色显示。【定】这个卡顿能接受吗（一张最坏 ~110 ms 桌面），还是要把解开挪到 worker（内核的解码能不能在 worker 里跑要另查，现在不做）。

### 一 怎么钉住那一刻（照画画仓：编码的同步前缀就是钉点）
- 画画仓 11-09 的做法（家族根 ai-docs/20261109-editor-session-serialize.md）：一轮存盘只认开头钉下的那一份；编码的同步那一段把字节拷出来（`wp.exportData()` = 冻结拷贝），之后的异步编码只碰拷贝；清脏之前对版本号。内核现成就能钉，**不改内核**。
- 三维这边 `Session.encode()` 拆两段：
  - `freeze()`（同步，一口气做完，中间不 await）：记 `revAtStart`；`documentFromScene`（已核：定义、材质、层都是新拷的；贴图表的行是共用的，但行本身从来不改——写进测试：钉完之后改模型、画一笔，存出去的字节不变）；桌面态 / 参考窗 / 缩略图照旧；**每张分层的画**按下面四种情况定它这一次的来源，都在这一段里定死：
    1. 有画板、而且画板的提交版本号 = 缓存里那份的版本 → 直接用缓存的字节；
    2. 有画板、版本不一样 → 当场 `exportData()`（冻结拷贝）+ 画布高度判断（见五），记下这次要编的版本号；
    3. 没有画板、贴图表里有字节（读文件读进来、没动过）→ 原样用那份字节（文件里的字节不重编，没动过再存一遍逐字节相同）；
    4. 没有画板、没有字节（`ora: null`，新建了还没画过）→ 编一份那一套坐标大小的空白分层文件（一层空的；按宽高缓存，同样大小只编一次）。
  - `finish()`（异步）：把 2、4 那几张交给内核编码（`paintingDataToEncodeDoc` + `encodeDocToOra`，一张一张来）→ 填进冻结那份文档的贴图行（换一个新的行对象，不改场景里的）→ `writeCatsup`。编完一张就按它的版本号进缓存（只在比缓存里的新时才替换）。
- 缓存住 `src/paint/`（贴图 GUID → { 画板身份, 提交版本号, 字节 }），不住场景、不进撤销（场景里的贴图行被撤销快照共用，往里写字节会让撤销历史带上另一个时刻的字节）。【定】施工单写的是「贴图条目里的字节就是这份缓存」，我改成缓存在场景外、存盘时才把字节放进冻结那份文档的行里，理由如上。
- mergedimage（分层文件里给别的软件看的合成预览）：【定】我建议先用内核的缺省（透明占位，内核注释里写了 node / 显卡丢了的时候就这么做）——它在 .catsup 里面、三维自己不读它；给别的软件看的那一半是另一张单。要合成的话得在钉点同步读回一整张图（1024 见方约 4 MB 读回）。
- 文件里写的「哪个版本写的」= `catsup vX.Y.Z`。

### 二 和现有存盘排队怎么接（逐个 encode 的调用点）
- `save()` 已经是一次只有一轮（`saving` + `inflight`），`writeHome` 里 `revAtStart` 在编码之前记、`savedRevision = revAtStart` 在库写完之后才设——编码变成异步之后这个顺序不变，编码期间画的笔 / 切的刀让版本号往前走，存完文档仍然算改过，下一次存才带上。
- 编码中途出错：这一轮整个算失败（不调库的写），状态行明说「存盘没成：画「X」编码出错（原因）」，`savedRevision` 不动，上一次存好的文件不受影响，内存里的画不动。
- 其余调用点：`snapshotOnce`（崩溃快照，见四）、`settleToFile`（临时模型安家，同 writeHome）、导出工程文件 / `containerNow`（导出不清脏，照旧）、`exportProject`。全部改成走 freeze + finish。
- 切后台 / 关页时的「先落本机」：还是同一个 `save({ implicit, localOnly })`。编码没编完页面就没了 = 什么都没写（库的写在最后、一次写完），不会写出半截；兜底是崩溃快照（四）。为了让这时候多半不用编：画板改过、空闲了（不在一笔当中、停够 1 秒，和 0-3a 同一张空闲表）就在后台先编一次进缓存——平常切后台时缓存已经是新的，存盘只是拼字节。
- 已核：`savedRevision` 只在库写完 / 安家写完之后设；打开 / 新建 / 领养那几处设它是因为内容就是刚读的那份，和编码无关。**没有发现「编码没完就当存好了」的地方**（停下来报的第二条：没碰到）。

### 三 读、冷、热
- 读：贴图表的行带着字节读进来（1-2½ 已经这样），不建画板。
- **冷的显示**（排队、一张一张）：画板登记处多一种状态「冷」（只有字节、没有画板）。要显示时排进解开的队：解开 → 建一块临时画板 → 灌进去 → 合成一次 → 交给渲染器拷进显示用的图 → **渲染器拷完的下一帧**放掉临时画板。显示出来之前：编辑器拿不到这张画的图，材质照底色显示（现在「还没有画板 = 照底色」的那条路）。材质的底色变了 = 再排一次。
  - 要渲染器那边告诉我「拷好了」/「显示的图丢了要重拷」（显卡画面丢了以后，冷的画得重新解开）。现在的活图契约 `LiveImage.current()` 只有一个方向。【定】我建议契约加一个参数：`current(held)`，held = 渲染器手里现在那份的版本（没有 = −1）；冷的画看到 held 等于自己交出去的那个版本 = 拷好了、可以放画板；看到 −1 = 要重新解开。这是小栗鼠契约（`src/minccino/contract/stream.ts`）的改动，要你点头。
- **热**：这次会话里画过（建过画板）的画一直热着，直到关文件（0-3a 已经是这条规矩）。读进来没动过的不会变热。
- 落笔时还是冷的：这一笔不开始，提示行说「这张画还在打开」，同时排进解开的队、解开后**留着画板**（变热，不放）。不卡住、不悄悄丢笔。进画画工作台时（1-7 接）、调试钩子里可以先热好：`__catsup.paint.warm(guid)`。
- 冷热显示一样：冷的那次合成和热的合成是同一块内核画板、同一个底色，走同一条拷贝；探针逐像素比。
- 目标「1024 见方每张常驻 ≤ 6 MB」：冷的常驻 = 文件字节（量的 0.3–6.1 MB，看内容）+ 渲染器的显示图（显卡上 1024 见方 4 MB + 缩小图 ≈ 5.3 MB）。【定】6 MB 是只算内存里的（字节），还是连显卡上的显示图一起算？连显卡算的话最坏情况超。

### 四 崩溃快照带上画
- 快照照现在的节奏，不在快照里现编（快照路上不做长活）：每张画用缓存里最近一次编好的字节；新建了没画过的用空白的那份；冷的用文件字节。
- 有画板的画，提交版本号比缓存里的新 = 这份快照里的画比模型旧 → 快照的记录多一个 `paintStale: true`（崩溃库自家的记录，`list()` 那里要把它带出来）。
- 后台那次空闲编码（二）编完 = 缓存更新 → 快照的「这一版记过了」的键里加上画的缓存版本，所以缓存一新快照就会重拍一次。
- 恢复时 `paintStale` = 通知「画可能少了最后几笔（崩溃前还没来得及存进快照）」。

### 五 画布大小
- 存的时候：画板比那一套坐标高、多出来的行全空白（`contentBounds` 已有）→ 按坐标的高存（导出时裁）；多出来的行有内容 → 照画板的高存，不砍。
- 读的时候：分层文件的宽 = 坐标的宽、高 ≥ 坐标的高 = 正常；别的 = 这张贴图当孤儿留着（原字节存回）、记一笔、告诉用户。【定】什么时候查：分层文件的宽高在 stack.xml 里，要先解压才知道；我建议在第一次解开时查（打开之后看得见的画马上就会排队解开，实际就在打开后一两秒内说），不在打开时为了查大小把所有画都解压一遍。

### 六 读进来时丢过东西的文件
- 「丢过东西」= 读入时记下的这几种：`uvDropped`、`foreignPaintSlots`（这两种再存盘就真去掉了）。`paintUnplaced`、`orphanPaintTextures` 不丢（原样带回）。【定】更早的 `danglingTextureRefs`、`danglingShelfRefs` 也是「再存盘就去掉」，要不要一起算进来？我建议算（同一类）。
- 做法：`format-notes.ts` 那张表旁边加一张「会丢东西」的名单（守卫：每个键都要表态丢 / 不丢）。打开时有 → 会话记「还没点头」：自动保存 / 切后台落本机 / 崩溃快照照拍（快照不动原文件）……但**不写这份文件**；人按存 → 先弹面：「存（丢掉那几处）/ 另存为一份新的 / 先不存」，点了「存」之后才放开。

### 七 zip
- index.html 里 zip.js 是 classic defer 脚本、排在主模块前面 → 主模块执行时 `window.zip` 已经在。守卫：index.html 里 zip 那一行在主模块之前；内核拷来的 zip.js 和三维 vendor 的那份逐字节相同（现在相同，哈希 39f3a868…）；存盘那条路第一步先查 `globalThis.zip` 在不在，不在 = 明说存不了，不往下编。

### 八 测试 / 探针 / 样本（对着「不能破的规矩」）
- node（内核测试那两个垫片：zip、DOMParser；放在不叫 .test 的工具文件里引）：随机几张画（几层、有透明、有橡皮擦过的洞）存 → 读 → 热起来，每层像素逐字节相同；没动过再存，文件逐字节相同；钉在同一刻（编码那一下 await 的空档里画一笔、切一刀：文件里是钉的那一刻，之后仍算改过，再存才带上）；编码中途抛（注入）：这一轮失败、上一份文件不动、内存里的画不动；撤销栈存盘前后一样、还能撤对；不带画的文件写出来和 v0.19.22 逐字节一样；画布比坐标高（空白 / 有内容两种）；尺寸不对的文件当孤儿。
- 浏览器探针：读一份十张画的文件，全部显示出来之后活着的画板数 = 0、量每张的常驻；冷的显示和热起来之后逐像素相同；落笔撞上冷的画：提示行、没有丢笔；崩溃快照带画 + `paintStale` 的那句话。
- `scripts/old-reader-check.mjs` 再跑一遍；冻样本加「画板比坐标高」那一份（两层真画的那份 1-2½ 已经有）。

### 九 停下来报的那几条，现在的情况
1. 内核钉不住一张画那一刻：钉得住（`exportData` 冻结拷贝），不改内核。
2. 编码没完就当存好了：没找到（见二）。
3. 冷的画整张解开会卡：量了（见〇），排队一张一张；要不要上 worker 等你定。
4. 「存了但其实没存上 / 读了但少了却没说」：新建没画过的画（`ora: null`）以前是「不许写盘」，这次编空白的那份；冷的画原字节带回；尺寸不对的当孤儿并说；丢过东西的文件要点头才存。我没再找到别的口子，交审时再对一遍。
