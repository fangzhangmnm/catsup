## 「全量」有两层（Opus 核代码，给计划书用）

1. **键表**：改 `controller/keymap.ts` 一个文件。帮助页、工具提示、键名芯片都从它生成，自己跟上。
2. **键盘起手**：硬表面现在**没有**这套。`Editor.startModal` 第一句就是 `mode.id !== "freeform"` 返回 false；手势层（中途 X / Y / Z 锁轴）也只在自由建模压上来（`layersOf`）。所以只做第 1 层时，硬表面按 G = 拿起移动工具，还要再按下去；Blender 的「G、X、打数、回车」接不上。要真吃下肌肉记忆得做第 2 层，它碰的是硬表面每把工具的手势，不止键表。

**影响面（数过的）**：39 个探针文件用到键盘（直接按工具字母的有十几处：g × 6、l × 4、h × 2、a × 2……）；`test/keymap.test.ts` 冲突守卫（迁完这张表应该接近清空，这就是验收线）；代码里带键名的文字（正则搜到 18 处，含注释，如「按 G」「（J）」；正则不全，要人工过一遍）；轮换组 `TOOL_CYCLES`（E / X / R / T 四组要重新找家）；`main.ts:1423` 弧的 A 轮换。

## 没拍（已列给 user，11-03）

1. **F 和补洞**：F = 画线，那 10-29 想要的「F = 补洞」放哪？Opus 建议：**没选区 = 拿起画线工具；选着一圈开口的边或两个点 = 补上 / 连上**。这正好就是 Blender F 的意思（两点连边、一圈补面），一个键不打架。
2. **硬表面的 K**：硬表面没有单独的刀。Opus 建议：**K 和 F 在硬表面都落到画线工具**（画线本来就切开面，user 10-29 也这么说过），以后真有硬表面刀再分。
3. **Tab**：Blender 里是进出编辑模式。这边 10-28 拍了不做物体模式（对象层设计稿），「Tab 进出组件」10-28 也否过（`FM153` 读法没通过，v0.15.43 记「那条不做」）。Opus 建议：**这个不跟**；除非 user 周末的体验改了想法。
4. **键盘起手要不要搬到硬表面**（上面第 2 层）。Opus 建议：**要，分两期**，第一期键表，第二期起手；否则「全量」只算名义上全量。
