> created 20261104 by Claude Fable 5.1 · as-of v0.18.31。起因 = 单面 / 双面第四版审查收尾时 OBJ「都留还是都下」那一问（计划书 §9.2½ ④）。

## Fable 的看法（11-04 夜）

**不是 dilemma，是两个角色被当成一个。**

| 角色 | 格式 | 保什么 | 丢什么 |
|---|---|---|---|
| 交付 + 文件底座 | glTF（.catsup = glb 换皮） | 材质 / 贴图 / PBR / 层级 / 实例 / 单位，引擎和网页查看器都吃 | 只有三角形。自家文件把多边形存在 `CATSUP_mesh` / `CATSUP_brep` 里，坑只在「给 Blender 看」时露出来；Blender 没有读多边形扩展的标准入口，这条补不了 |
| **建模往返的第一公民** | **OBJ** | 多边形原样、平滑组（= 软边 / 硬边）、UV、基本材质 + 贴图路径；纯文本、无 SDK、谁都读；Blender 的 OBJ 读写是原生 C++ | 实例（每份摊平）、PBR 参数——建模往返不需要 |
| 不要 | FBX | — | Autodesk 私有二进制；Blender 自己的读写是逆向的一座山；多出来的动画 / 骨骼我们不用 |
| 以后看 | USD | 多边形 / 实例 / 材质全，Blender 4 支持好 | 规格太大，现在不是第一公民的料 |

「互相导入才是 king」同意：king 就是 **CatsUp ↔ OBJ ↔ Blender 这条环**。验收也按环：模型 → OBJ → 读回来指纹一样；再 → Blender 无头跑一遍 → OBJ → 读回来还一样（开 Blender 要先问 user，家规）。glTF 导入照留——从 Blender 拿带贴图和实例的成品用它更好。

## 「做好」= 下一张 OBJ 单的清单（没拍之前不动）

- 导出：写多边形不写三角；**按侧出面**（OBJ 的面单面；两侧都出 = 两张反向的面，Blender 看得到、「合并重合反向面」修复工具能收回）；软 / 硬边写平滑组 `s`；MTL 写颜色 + 贴图（`map_Kd`）；贴图没法嵌 → 导出打成一个 zip（obj + mtl + 图）；每个物件一个 `o`；Z-up ↔ Y-up 在文件边界换；单位米（OBJ 无单位，Blender 默认米）。
- 导入：读 MTL 和贴图；平滑组 → 软 / 硬边；每面材质；Y-up 换回 Z-up；进来直接成网格体（照现在的 glb 导入路）。
- 测试：往返指纹（几何 + 材质 + 两侧）；Blender 环（需要 user 同意开 Blender）。
