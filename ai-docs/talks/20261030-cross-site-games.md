# 讨论：跨站点把场景交给第三方游戏（验证纪元）

> created 20261030 by Claude Opus 5.5 · as-of v0.18.7 · 账本 Tron 纪元 T202

## 10-30 · 能不能、安不安全
- **user 原话**：「验证纪元：帮我科普一下跨站点。就是能不能你输入一个网址甚至是上传一个html，然后catsup把场景glb发给它，然后跳转过去。最好还能跳回来继续编辑，但是运行游戏的时候catsup得内存显存能清的多空就多空，或者就是页面跳转了。这样安全吗可行吗。就是第三方写的游戏。然后游戏最好浏览器权限不要太阉割。比如webxr必须要有，woker之类也大概率要。科普。」「最好是还能拿回来遥测」
- **答**：新标签页 + 页面间互发消息（postMessage）交场景；回来 = 游戏发「玩完了」或切回标签；CatsUp 交接时退 VR、还显存；遥测走同一条通道；游戏永远不能和 CatsUp 同一个域名（上传的 html 放家族专门的「游戏」子域名）；发之前弹窗写明发给谁；游戏是独立顶层页 = VR / worker 能力全；把场景发给第三方网址 = 外发，按「外接服务先开白名单」那条家规由 user 定规则。

## 10-30 · 为什么不是 XSS、本地网页、怎么通信
- **user 原话**：「游戏还是不懂，为什呢那不是xss？用户开本地网页怎么算？他们如何通信？」「或者其实就是普通的post？但那是服务器端的啊」
- **答**：XSS = 别人的代码跑进 CatsUp 自己的域名（能读 OneDrive 登录、本机模型）；交接时游戏在另一个域名，浏览器砌墙，只有 CatsUp 主动递过去的数据（场景字节、遥测数字）过墙，收信核对来信域名、只当数据读、不当代码跑。postMessage ≠ HTTP POST：两个标签页之间在本机浏览器内存里递，不经服务器。坑：要多线程的游戏开「跨源隔离」会剪断标签页之间的把手 → 只能退回「下载 glb 拖进游戏」。本地网页三种：本地服务器（localhost）= 普通网站能通信；双击打开的 html（file://）= 没真域名、CatsUp 打不开、认不出 → 不支持；上传 html 到 CatsUp = 绝不能在 CatsUp 域名下开（那就是 XSS），放「游戏」子域名。
- **状态**：科普，不排期（验证纪元）。
