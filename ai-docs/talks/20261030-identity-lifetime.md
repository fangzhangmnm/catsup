## 10-30 · 为什么删实例会有删组件定义的风险
- **user 原话**：「可能需要fable系统的审核一下hierarchy纪元的东西。也许有数据架构的问题。不过你先看。为什么删实例会有删组件定义的风险？这个风险就不应该有。你看一下这是什么系统性的问题。一共有几层瑞士奶酪？」「为什么炸开会删除组件。我们没有一个中心化的按引用计数的东西吗？学blender。然后贴图什么也一样。但是wishlist，可以强行删有引用找不到谁在引用的东西。但是我们需要一个中心化的资源管理器？然后到时候也有这种引用和孤儿管理面板。可以先记wishlist，你先非常认真小心地做。到时候fable审核」「这样，我们先写一个。然后高中时代让fable重写一个，因为反正那时候流加载什么的」「无人使用的材质会悄悄残留。这个现在小学时代能修复吗。」「反正就是要么被引用要么被素材库引用。和blender的逻辑一样」「能改成guid吗 然后物体之类的同理，定成家规」「不要用序号」
- **查到的**：删实例本身不删；炸开把最后一份炸掉时删定义（两处），合并不删 = 生死没有统一的主人；测试还钉着删。8 层奶酪 4 层挡住 4 层漏（细节在纪元账本 I10 / I11）。
- **状态**：**拍了**——活着 = 被引用或被素材库收着（Blender 逻辑）；文件里条目用 GUID 不用序号 = 家规（家族 CLAUDE.md）。**落地** v0.18.3：炸开不删定义 + 守卫 + 资源页（清点 / 孤儿 / 清理没人用的组件）。材质清理等 GUID（Fable，周账 F-137 ㉑）。愿望单：强行删还被引用的、引用和孤儿面板完整版。

## 10-30 · GUID 现在全量做了吗
- **user 原话**：「guid而不是递增数字，现在我们全量做了吗？」
- **Opus（代码核过）**：没有，只立了家规。现在组件定义是递增编号（`scene.ts nextDef++`），文件里组件按在列表里的位置引用；组、实例也是递增编号；材质按序号。换 GUID = 改文件格式（要迁移 + 冻结样本），按分工归 Fable 先定（周账 F-137 ㉑）。
- **状态**：没做，等 Fable。

## 10-30 · 老文件的根叫什么
- **user 原话**：「老文件的顶层组件是文件名，现在是四位hash了对吧」
- **Opus（代码核过）**：都不是。v0.18.3 以前层级里根那一行显示的是文件名（作品名）；v0.18.3 起显示根自己的名字，而所有文件（新的老的）根的名字都是程序起的占位「model」，按「没起名」淡色显示。新组件才是四位码。要不要让没起名的根也显示四位码（和别的组件一样），等 user。
- **user**：「没起名的根，要不要也和别的组件一样显示四位码 同意」
- **状态**：拍了，**v0.18.17 落地**：新建 / 开机空白 / 打开老文件时，根还叫程序占位 model 的当场起一个四位码（照旧淡色 = 没起名）。老文件打开后没存过之前，每次打开码都不一样；存一次就定下来。
