- **Opus 答**：硬表面的面都有边界，真无限要在几何核里引入「无限远的点」，动根基、不建议；Minecraft 超平坦 = 默认处处平地 + 只存动过的块。
- **状态**：**拍了（原则）**：地形不归硬表面兜；地形（体素〔像素块 / marching cubes 平滑〕、高度图……）**默认无穷大、自适应分块，用户不管大小，除非显式指定**。

- **Opus 的看法**（对话里同一份）：
  - **总原则提案「树只装东西，不装规则」**：①物件 = 一个位置 + 一个身体（种类）+ 几个属性，一物一体（不像 Unity 一个 GameObject 挂 N 个组件）；②影响全局的设置是某个原子的属性（根的属性），不是树里单独的节点；③物件之间的引用一律用永久编号（GUID 家规），对方没了只降级显示「缺了」、不崩；④显示开关只管显示，永远不当逻辑。
  - **环境（天空 / 太阳 / 经纬度）与后处理**：Godot 式（环境是一种身体、可有范围）好处 = 一切皆物、组件能带着自己的环境走、能做局部范围；坏处 = 多个时谁赢要有混合规则、删它画面变 = 「删一个某个系统变了」、藏它 = 用显示开关改画面（正是 user 讨厌的）。Unity 式（全局设置 + 体积）好处 = 一处、删不掉、不占层级、SketchUp 也是模型信息里一处；坏处 = 设置散在场景 / 光照 / 项目 / 体积几处、组件拷到别的文件带不走环境。建议：天空 / 太阳 / 经纬度 = 作品的（实验室已拍「材质归物体 / 光归场景 / 画法归视图」），做成**根组件的属性**——根 = 普通组件，所以一个组件单独打开用它自己的环境、被摆进别的模型时它的环境不起作用（Godot 主场景的 WorldEnvironment 同理），局部范围以后做成可选的「范围」身体、不是必须；后处理 = 画法 → 归视图（画风兜底）。天空盒跟作品走（日落场景就是日落），画风可以不画它（线稿 / 1-bit），视图可以临时换个时段看看但不写回作品。滑坡：Godot 路滑向「树变成程序」；Unity 路滑向「到处藏着全局设置、面板旋钮机」。
  - **化身**：骨架 = 化身身体里面的东西（像网格体的点，进去才看到），不进层级；glTF 规定骨头是节点，导出时变成节点树 = 交付格式的事（同「导出时把组烤进网格」），我们自己的文件里骨架住在化身里、读回来收回去。动画控制器放化身里 = 原子（拷走照样动、删了只是它死）；多个化身共用动作 = 动作资源被引用（组件那套）、换骨架共用要骨骼映射表；放外面（一个控制器驱动一群）= 群体 / 过场方便，但交叉引用：删控制器全僵、删化身控制器悬空 = user 讨厌的那种。建议：会动的本事归化身（引用动作资源）；编排（过场 / 时间轴）是另一个原子，按永久编号引用化身，缺了显示缺了不崩。
  - **「生成的东西不进场景树」**：大方向对，关键是分清编辑态和运行态——层级 = 作品（作者摆的原子），游戏跑起来生成的是运行状态，不进作品的树（Unity 跑起来层级冒一堆 Clone 就是混了）。可能错的两处：①想把运行结果留下（模拟堆好的箱子）要一个「收进作品」的动作；②调试运行状态要一张单独的「运行时清单」，不是层级。有这两座桥理想就站得住。
  - **相机**：同意禁止「相机物件」。真正的相机只有一个、归视图；作品里只有机位（一个视角）和镜头轨（机位串成的曲线 + 节奏），整条镜头轨 = 一个身体。例外：监控画面投到电视这种 = 屏幕身体自己的属性（从哪个机位看），不是满地相机；分屏 = 视图的事。
  - **灯 / 锚点集**：同意 user 的担心（灯组是一个身体 → 编辑硬表面时挪不了灯），两个解：①进灯组挪灯时照样吸附外面的几何（推断读整个世界）；②「台灯」= 一个组件里装硬表面体 + 灯组，挪台灯灯跟着走 = 原子。赞成「锚点集」做成一种身体（一串带朝向的坐标点），按用途分：灯组 / 路点 / 镜头轨 / 探针（光照探针、LPV）/ 出生点……选、挪、转、对齐、吸附、复制、阵列只开发一次。注意：路径 / 镜头轨有顺序 → 又碰到「有序表」（文件记顺序，Fable 那批）。
  - **继承实体还是特例**：都不是继承，是组合——所有物件一样（位置 + 一个身体 + 属性），区别全在身体种类；灯 = 锚点集的一种；相机不存在（只有镜头轨）。叫法冲突就此解：「物件」= 世界里摆的任何东西，「种类」= 它装的身体；没几何、只有位置的东西 = 只有一个点的锚点集（挂点），不另起一个叫「实体」的种类。
  - **组件与引用 / 往游戏引擎滑**：我们的「组件」= SketchUp 组件 = Unity 的 prefab；Unity 的 Component 是「挂在物体上的行为」，往游戏引擎滑会打架。可选：先保留「组件」（对外文档注明 ≈ prefab），等真有行为系统再定（改叫法不迁旧数据）。守住 SketchUp 的禅：同一组件的几份完全一样，只有位置（+ 名字 / 图层 / 藏）不同，想不一样就「做成唯一」，**不做 prefab 覆盖**（Unity 最丢禅的地方：看不出哪份偷偷改过、apply / revert、嵌套 / 变体）。
  - **Unity 会丢的禅（清单）**：①物体挂一堆组件、组件间互相拖引用 → 删一个满屏「Missing」；②prefab 覆盖；③场景设置 / 光照设置 / 项目设置 / 体积四处放配置；④运行时生成的东西冒进层级；⑤active / hidden 当逻辑开关；⑥检查器几百个字段。对应 CatsUp 护栏：一物一体 / 永久编号引用、缺了只降级 / 不做覆盖 / 设置是原子的属性 / 运行态不进作品 / 显示开关只管显示 / 窗口四样。
  - **显卡代价**：user 定了 = 高中、大学（烘焙、剔除、预计算）。
- **状态**：讨论中，**没拍**（地形原则那条除外）。
