> 相关：IK 那份第四、六、十轮（动捕：跳舞教学视频、原视频要留）；参考窗（`@internal/reference-window`，CatsUp 是它的宿主之一）；动画曲线（时间轴）。

## 10-30 夜 · 开题
- **user 原话**：「比起动捕更重要的是视频overlay」
- **拍了**：视频叠加排在动捕前面。
- **Opus（没拍）**：
  - **为什么它更根本**：动捕是让机器照着视频摆；叠加是让人照着视频摆（转描）。动捕出来的结果也得叠在视频上才看得出对不对，所以叠加是动捕的地基，先做它不白做。MMD 圈的「扒舞」就是这么干的：MMD 能把视频垫在背景里，人一帧帧对着摆（Opus 记得 MMD 有「背景视频」功能，没核）。
  - **现有的**：CatsUp 收的参考窗库 0.5.0 已经有视频卡片（上一帧 / 播放 / 下一帧 / 进度条 / 快捷键），视频默认只放内存、存档不带字节、下次把同名文件拖回来补回原位。所以「旁边放一个视频看」现在就有。
  - **缺的四样**：
    1. **跟时间轴同步**：拖时间轴，视频跟着到对应那一帧；播动画，视频一起播。要设：视频从哪一秒对上动画的第 0 帧（偏移）、快慢（教学视频常有慢放段）、帧率换算（视频 30 / 60 帧，动画自己的帧率）。
    2. **放在哪**，三种（可以都要）：
       - 旁边：参考窗里同步播（最简单，现有的加同步）。
       - 叠在画面上：半透明盖在视口上，像洋葱片——要相机对得上视频的机位才能描。
       - 立在场景里：一块平面立在角色后面 / 侧面（Blender 参考图 / Maya 图像平面那种），转视角时它是场景里的东西。
    3. **左右对调**：镜面拍的教学视频（IK 那份第六轮）。
    4. **相机对上视频**：叠在画面上那种要先把相机摆到和视频同一个机位、同一个焦距。SketchUp 有「照片匹配」（拉几根线对准照片里的透视），可以照那个做一个视频版；粗对就够，人眼描。
  - **iPad 上的坑**：网页里的视频按时间跳帧在 iOS 上不一定准、不一定快（Opus 没核）。逐帧对着 K 要求「拖到哪就是哪一帧」，可能要先把视频解成一串小图缓存起来——这个放骨骼动画实验室先量。
  - **改库要批**：同步时间轴如果加进参考窗库（而不是 CatsUp 自己包一层），那是内部库加功能 = 升小版本，要 user 批（家规）。
  - 视频存哪：照参考窗现在的规矩（只放内存、不进存档、同名拖回来补）就和「视频太胖别撑云同步」对上了；动捕那份「原视频要留在本机」以后也可以走同一条。
