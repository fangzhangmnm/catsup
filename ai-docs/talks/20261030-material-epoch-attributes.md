  比如我可能做一个少女终末旅行的1bit游戏，我会标注什么地面是雪什么地面是钢板
  然后这个attribute要和material 联动吗是一个送命题，或者就用material读？
  但是你明白我意思，表面tab上面我们可以assign各种自定义的点 线 面attribute，然后我们所有builtin的都一视同仁。可以删。所以其实软边之类的归表面，只是sketchup里面借用了罢了
  然后不用的不自动丢引用，灰了用户删。或者自定义的不灰。你可以assign 自定义的flag，有一些可视化，这个都是表面tab的事情，会有各种不同的overlay
  然后material也一样，你换了一个shader之后，原来的不用的slot灰但是显示，可以折叠在手风琴里面，但是不能藏起来不能删」
- **整理出来的要点**（Opus 按原话归纳，供下一轮逐条聊，不是拍板）：
  1. 几何本体只有点的位置；其余一律是「属性」（属性 = 挂在点 / 边 / 面上的一整列数据）：法向、UV（多套）、顶点色、硬边 / 软边标记、蒙皮权重、长草密度、自定义标签……
  2. 属性可丢、整列丢：能从物体设置算出来的（法向、自动 UV）就不存；不用的硬边标记整列删掉省空间。
  3. 内建属性和自定义属性一视同仁：都能在物件面板的「表面」页看见、都能删；自动生成的（如自动 UV）也披露，只是默认折叠。
  4. 改语义 = 复制成新的再删旧的，不做「重新指派」（重新指派会偷偷做类型转换：取灰度 / 取某个通道 / 套 gamma 曲线，复制时让人明着选）。
  5. 不用的属性不自动丢：变灰、等人删；自定义的不灰（是用户自己的意图）。
  6. 「表面」= 给点 / 线 / 面指派各种属性 + 各种可视化（叠加显示）。软边、硬边这些本来就是表面的事，SketchUp 只是借用了。〔第一次记成「物件窗口里的一页」是误读，第二轮 user 更正 = 已有的表面工作台，见下〕
  7. 材质同理：换了着色器以后，原来用不上的参数槽灰着但照样显示，可以折进手风琴，不能藏、不能删。
  8. 例子：做一个《少女终末旅行》式的 1-bit 游戏，给地面标「雪」「钢板」——自定义的面属性。
  9. 送命题：属性要不要和材质联动？还是材质自己去读属性？
  10. 剧透（绘制纪元，user 说想法还在变、先记账）：UV 强制像素对齐（pixel perfect）、不强求 2 的幂；加几何之后只做一次「像素对齐的重排」；生成合并贴图时防渗色（anti-bleeding）和带透明时的外扩边（flange / padding）是家规级的必须，不是选项。

## 10-30 · 素材架上放的是引用还是拷贝

- **user 原话**：「素材架上放的应该是引用而不是拷贝吧。我们讨论一下pro和con，只有跨文件拷过来才是拷贝」
- 前情：同日 user 的远景原则是「禁止引用外面的文件……vendor is copy, not reference」（`20261030-materials-color.md` 远景那条）——那是说**作品**从素材架拿东西 = 拷贝进作品；这里问的是**素材架自己**：架子上那一格是指向原物的引用，还是一份拷贝。
- **user 答**：「放引用 关键是你可以整体调色。就是调整所有引用，对齐的事情，引用就是为了对齐，都一致，而不是调了这个那个忘了」
- **状态**：**拍了 = 架子上放引用**。推论（Opus）：架子上那一格指着原物，原物改了架子上看到的就是新的，不会有一份过期的拷贝；从架子拿进**别的文件** = 拷贝（远景那条「vendor is copy」不变），拿走之后原物再改，已经拷走的不跟着变。和家规「生死按引用」对上：被架子收着 = 被引用 = 活着，没有面在用的材质只要标了素材也不算孤儿。原物所在的文件被删了、架子那格怎么显示（Blender 是「素材丢了」）= 数据安全，交 Fable。

- **Opus 答送命题**：
  - 「哪个面用哪个材质」**本身就是一列面属性**（就叫「材质」），和别的属性一视同仁、归表面工作台。
  - 它存的是小编号，但编号只是代号：每个组件带一张**槽表**（0 = 红砖，1 = 钢板……），这张表就是 user 说的 enum；界面上永远只显示名字和颜色，不显示 0 / 1 / 2。CatsUp 现在就是这样存的（面 → 槽号 → 组件的槽表），这一层合规；欠账在下一层：槽表指向材质时还是「文件里第几个材质」，要换 GUID（Fable 那批）。Blender 同理：面上的 material_index 是光秃秃的整数，但物体身上带着槽表；合并两个物体时 Blender 合并槽表、重排编号 = 「拷贝的时候合并」。
  - 送命题原本问的是：**自定义标签（雪 / 钢板）和材质要不要连起来**。三种做法：
    - **A 两列分开 + 一个「按标签上材质」的动作**（做一次，结果写进材质那一列）。好处：看到的就是存的；导出给别的软件天然对（glTF 没有「按标签挑材质」这回事）；改标签不会偷偷改样子。坏处：规则改了要再跑一次；两列可能对不上（标了雪、刷的却是钢板）→ 表面工作台叠加显示「对不上的面」。
    - **B 材质自己去读标签**（标签一改样子跟着变）。好处：改一处全对齐。坏处：材质变成一段程序、多了看不见的依赖（「删一个某个系统变了」那种）；导出时还是得烘成 A。
    - **C 标签就是材质**（「雪」就是一个材质，顺便带走路声音之类的字段）。好处：只有一列。坏处：「长什么样」和「是什么」绑死——同样是雪地想要两种颜色、或者两种地样子一样走路声不同，就得复制材质。Unity 把物理材质和渲染材质分开就是这个原因。
    - **Opus 推荐 A**：动作做完烘进状态（和「历史不存在，只有被打歪的原子」一致）；B 留 wishlist；C 不做。
  - 自定义标签自己也是「编号 + 对照表」（雪 = 0、钢板 = 1，表跟着文件走），跨文件拷时合并对照表。两个文件各有一个叫「雪」的算不算同一个（按 GUID 合并还是按名字合并）= 交 Fable。存**数值**的属性（长草密度、蒙皮权重、顶点色）不是编号，不受这条管。
- **user 答送命题**：选 A（两列分开 + 「按标签上材质」的动作，做一次、结果写进材质那一列），并给了原则：「聪明。对，就是我们能变成修复类的都不用自动geometry shader，只有确实手感需要自动的mirror和subdiv才是，但是那也只是在mesh上，在brep还是手动。这样是最稳定的。要自动以后geometry node纪元再说」
- **状态**：1–5 拍了；**送命题拍了 = A**。原则（user 原话归纳）：**能做成「修复」式动作（做一次、烘进状态）的，一律不做自动、实时的几何处理**；只有手感上确实要实时的——镜像、细分——才自动，而且只在网格体上；硬表面体照旧手动。理由 = 最稳定。要「自动」，以后几何节点纪元再说。B（材质实时读标签）跟着进几何节点纪元，C 不做。

## 10-30 · 算出来的列：面板里怎么露、存不存
- **Opus 推荐**：物件窗口里折叠一个「算出来的」小节，灰着、写明怎么算的（如「自动 UV：按世界铺，1 格 = 1 m」）；不给「删」（现算的，删了下一帧又算出来）；想改就改它的来源（材质的铺法、默认平滑），或者用「烘成画出来的」动作拷成一列手画的再调。
- **user 原话**：「我的推荐 可以，但是如果是不用存的内存内现算的也许就不用存？」
- **Opus（代码 + 契约核过）**：对，本来就不存——CatsUp 自己读回来的那部分数据里没有法向、没有 UV，打开时现算（09-20 user 就拍过：「autoUV 不存」「平滑 → 逐边 smooth 位……角度阈值是工具不存」，契约第五 / 六轮）。面板里露的只是「怎么算的」这句话 + 内存里现算的结果，不进文件。唯一的例外是同一个文件里**给别的软件看的那份**（三角形 + 有平滑边处的法向 + 有贴图处的 UV）：为了 Blender / OneDrive 预览 / Windows 3D 查看器能直接打开，CatsUp 只写不读（契约 §4，user 09-20「省流」「第三方查看器尽量 wysiwyg」）。要「烘成画出来的」时才第一次真进文件，那时它已经是画出来的了。
- **顺带对上的老账**：09-20 契约第五轮 user 拍过「马里奥 64 式面 tag → id + 名称表（id 身份、name 显示），每元素一个 tag id」——就是今天的「自定义标签列 + 编号只能是对照表的代号」，09-20 那份设计直接接得上。
- **一处说法对不齐（记着）**：09-20 写的是「autoUV 不存、**算法版本化**」（改了算法、老文件还用老算法）；10-30 v0.18.15 改自动 UV 朝向时 user「不用念旧」= 没版本化、老文件跟着换。不存的代价就在这里：算法一改，老文件的样子跟着变。Opus 建议以后照 10-30 的口径（不版本化），哪次改动 user 觉得老文件的样子要保住再单独版本化。
- **状态**：面板露法拍了（折叠、灰、写明算法、不给删、给「烘成画出来的」）；不存 = 本来就是；算法版本化的口径等 user 一句话。
