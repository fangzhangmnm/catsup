## AI 的更正

计划书 §15.1-B 写的「用目标那条，**不比内容**（user 11-04 拍）」说过头了：user 11-04 同意的是「之后再贴同一组件只多摆一份」，那句没有谈两边内容不一样时怎么办；「不比内容」是 Fable 加的。10-30 否决的是「内容哈希当身份 / 去重」，身份照旧是 GUID，比内容只回答「同一个条目两边分叉了没有」，不和它打架。

## 对抗分析：无条件覆盖哪里会出事

1. **同一个模型里的旧剪贴板**：拷组件 → 接着改它 → 贴一下：覆盖 = 刚改的全被拷贝时的旧版盖掉，每一份都变，还没有提示。→ 同一个模型不覆盖（11-04「同一文件内不变」本来就这么说）。
2. **分不清谁新**：文件里没有版本号。A 拷到 B、两边都改过，拷回 A 就盖掉 A 这段时间的改动。没有共同祖先，机械上判不了谁对。→ 只能摆事实问人（哪几个组件、摆了几份、两边各几张面）。
3. **连带**：贴甲，甲里摆着乙，乙在这份模型里还被丙用着：覆盖乙，丙也变。不带乙，甲就不是修好的样子。SketchUp 社区也报过嵌套组件重载后变成 `B#1`、别的份没跟上。→ 整个闭包一起算、弹窗列清。
4. **一个一个选会造环**：源里 甲→乙，目标里 乙→甲。整包用拷来的不会成环（闭包自成一体、源本身无环）；只更新甲、留下目标的乙就成环。→ 一次贴只选一种处理，不逐行勾。
5. **材质**：同 GUID 颜色不同。更新会改到这份模型里所有用它的面，包括不相干的组件；不更新，贴出来的组件就不是修好的样子。→ 跟着组件一起算、弹窗列清（待 user 拍）。**层不覆盖**：可见性是看法不是内容，默认层更不能动。
6. **站在要被覆盖的组件里面贴**：上下文链断掉、东西贴进一个可能变成孤儿的定义。→ 这种情况拒，说「先退出来」。
7. **断开（break link）**：摆放本来每次都是新的；真正要断的是**定义**。断开 = 内容不一样的那些定义、以及摆着它们的上层，都铸新 GUID（不然上层还指着旧的）；内容一样的子组件继续共用。
8. **「内容一样」机械判得了吗**（node 实测，v0.18.34）：直接比序列化不行：一笔没改的组件存盘重开后顶点 / 边 / 面顺序变了，逐字不等 = 会误报「不一样」。规范化（坐标按 µm、边按两端、面按环、属性跟着面走、材质换成 GUID，再排序）之后：没改 = 相等；存盘重开三次 = 相等；改一笔 = 不等；400 张面 4.4 ms。原型只覆盖硬表面根池，组 / 参考几何 / 网格体 / 坐标架还要补。只在跨模型、同 GUID 时才算。
9. **别家怎么做**：SketchUp（社区经验，没找到官方说明）拷贝不更新，更新走专门的 Reload，所有份一起变。InDesign 载入样式遇到同名：用拷来的定义（改掉用它的文字）/ 自动改名留两份，并排显示两边定义（Adobe 手册，CS3 / CS4 版）。

## AI 的方案（等拍）

| 情况 | 做什么 |
|---|---|
| 同一个模型里贴 | 只多摆一份，用现在的版本，不问 |
| 跨模型、这份模型没有 | 带原身份新建，不问 |
| 跨模型、有、内容一样 | 只多摆一份，不问（11-04 那句） |
| 跨模型、有、内容不一样 | 弹一次，列清哪些组件 / 材质、各摆了几份、两边几张面：**用拷来的更新**（默认）/ 留这份模型的，只多摆一份 / 断开，贴成新组件 / 取消 = 不贴 |

## Fable 审（2026-11-04 夜，Claude Fable 5.1；user「你看一下这个思路怎么样，你也好好想一下」；代码没动）

- **骨架同意**：四格 + 一次贴只选一种处理。理由比上面还硬：家族同步红线（`MyPWAPatterns/docs/MASTER.md` §A）= 无 LWW、冲突必 surface；两边内容不一样就是冲突，弹窗是同一条红线用到组件上。
- **改 ①：比内容的构造要反过来**。原型是挑字段比（允许列表）→ 以后加字段（贴图 / 动画正是下一波）漏进比较 = 两个不一样的组件判「一样」→ 静默贴成这里的版本、拷来的改动没了、没提示。要改成：整份 `DefinitionDoc` 逐字比，只对已知「存盘重开会乱序」的部分（顶点 / 边 / 面 / 环的顺序）做排序规范化，其余一律逐字；漏字段的后果变成「多问一次」。不加坐标公差（那是猜；写盘怎么量化就怎么比）。规范化器可以另当测试谕示。
- **改 ②：弹窗不能说「从别的模型拷来的」**。`clipboard.set(p, docEpoch)` 记的是第几次 `Editor.loadScene`，同一文件重开也加一；所以「同一模型」那格实际 = 「同一次打开」。拷 → 重开同一文件 → 改组件 → 贴：会弹窗，默认「更新」= 旧版盖掉刚改的。弹得对（分歧就该问），但文字只能说「拷来的版本和这份模型里的不一样」；两边事实要列够。以后给文档一个文件身份（gallery 条目 id）再分「同一文件重开 / 真的别的模型」，不急。
- **补 ①：材质独立开关**。组件不能逐个勾是因为会成环；材质不引用任何东西、不会成环 → 弹窗 = 「组件：更新 / 留这里的 / 断开」+「材质也跟着 ☑（默认勾）」。选「断开」时内容不一样的材质也铸新 GUID（贴出来是源的样子、不碰这份模型别的面）。
- **补 ②：弹窗多列两样事实**：要更新的定义有几份锁着（更新会改到锁着的实例；披露不拦）；只在素材架上、没摆的也列（「摆了 0 份，在架上」）。
- **补 ③：撤销是安全网不是替代**：paste 是 scene 级快照，一步退回更新连带的所有份；只在没存盘关掉之前有效。
- **站边**：① 弹窗（不是事后撤销）；② 材质跟组件、带开关。**新增待拍**：导入素材撞同一组件内容不一样 → 同一弹窗同一默认「更新」；user 若认为导入本意是上架不是修模型、想默认「留这里的」，说一句。
- 没问题的部分：同模型只多摆、跨模型没有就新建、内容一样只多摆、站在要被更新的组件里拒、层永不覆盖、断开 = 断定义不是断摆放。「拷出去修拷回来其他份跟上」走「跨模型、内容不一样 → 更新」那格，成立。
