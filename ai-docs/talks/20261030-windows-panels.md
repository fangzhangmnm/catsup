## 10-30 · 抽屉还是浮窗、要不要停靠（think critically）
- **user 原话**：「手游里面氪金商城和资源管理是分开来的吧。但是问题是手游他们是同一个全屏页面的tab，我们这里一个是抽屉一个是浮窗，能帮我think critically吗，还是氪金商城也做成浮窗？像老网游那样？也许这样更不容易挡东西，或者干脆浮窗都能dock成抽屉？但是会不会太复杂？我不太喜欢blender的窗口管理系统 帮我think critically」「不过先这么做，做完之后还是希望你能认真回答一下。想一下catsup的nature，其实我确实是unity和blender和sketchup和bodypaint合租的怪物。但是有需要procreate级别的zen，而不是一个超多面板旋钮的机器」
- **Opus 的看法**：①按「看的是什么东西」分窗，不按「从哪个软件学来」：视图 / 物件（唯一的检查器）/ 物品栏（模型里有什么 + 素材）/ 参考，四颗钮封顶，新功能先找现有窗的一页；②Procreate 的禅 = 默认只有画布 + 细栏、面板是挂在钮上的弹层、唯一常驻底部条是动画时间轴 → CatsUp 全浮窗，唯一的抽屉留给时间轴；③不做用户停靠（Blender 坡），手机竖屏自动变底部一张；④手游全屏页能那样是因为世界暂停，CatsUp 画布得活着 → 只学「一个入口里面分页」；⑤风险 = 窗口一锅粥 → 一键藏窗。
- **状态**：**①③ 拍了**（「我建议按「你在看什么东西」分，只有四样……同意」「不做用户停靠，布局由设备定。同意」）；② 已落（v0.18.5 只有浮窗）；⑤ 落地 v0.18.6。

## 10-30 · 主菜单要不要开一个「窗口」页签
- **user 原话**：「一键藏起所有窗 这个和参考窗要不要主菜单专门开一个tab就是开关各种窗口，windows，还是你觉得没毕业,think critically，思考的时候记得先看一眼屏幕截图」
- **看了截图**：层级 + 视图 + 参考三扇一开右半边就挤、参考窗压在视图窗下面；主菜单现有 文件 / 模型 / 设置 / 帮助 四页；一键藏窗只有手势 / 键、界面上找不到。
- **Opus 的看法**：还没毕业，先不开页签——①窗口家族还在变（素材页、时间轴、可能的待办清单），现在开一页过几天就要改；②一页只放 4 行太薄，而且每扇窗已经有自己的钮 = 两条路开同一扇窗；③真正缺的是两件「找不到」的事：一键藏窗没有看得见的入口、窗口拖丢了（拖到屏幕外 / 被压住）没地方找回来。所以先在现有的页里加两行就够：「藏起所有窗（四指轻点 / \）」「窗口都放回原位」；等窗口家族定了（四样 + 素材 + 时间轴）再看要不要一页。
- **状态**：没拍。
- **user 追问（同轮）**：「或者windows还是应该跟着视图？主要是他们应该跟着主菜单还是视图，两个抽屉的语义是什么」
- **Opus 的看法**：两个抽屉的语义——**主菜单（左上 ☰）= 作品和 app**：这份作品（新建 / 打开 / 保存 / 导出 / 锁）、模型级的事、这台设备的设置、帮助，和画面无关；**视图（右上）= 你这一眼看到什么**：画风、屏幕、选中色、单位显示，不改作品内容。「哪些窗开着、一键藏起、窗口放回原位」= 屏幕上摆着什么、按设备记、不进作品 → 属于视图那一侧（Procreate 的全屏也是「看」的动作；参考窗钮本来就挨着视图钮）。所以建议跟视图：视图窗加一节「界面」两行（藏起所有窗 / 窗口都放回原位），不进主菜单。
- **状态**：没拍。
- **user 10-30 第二轮**：「天空、太阳、经纬度归作品。 其实这个就是右边那个视图吧，是不是以后全局的画风都是它调，包括帧率，渲染细节，正是因为它会很胖，所以我才想驱逐其他的东西，但这样的话单位可能不应跟归它。以及右边视图最常用的就是换预设玩，所以必须浮窗而不是menu」「两个「抽屉」的语义 / 单位和高亮画法归谁」
- **Opus**：视图 = 画面怎么看（画风预设、屏幕、帧率、渲染细节、高亮画法），会很胖，所以只放这些；单位跟作品（文件里本来就存单位制 / 吸附长度）→ 建议挪进根物件的物件窗口（「模型信息」那一摊：单位 + 以后的天空 / 太阳 / 经纬度）；视图常驻浮窗（已经是）。
- **user 10-30**：主菜单「模型」页里的东西都不该在那（截图）→ **落地 v0.18.9**：整页撤，主菜单 = 文件 / 设置 / 帮助。
- **状态**：单位挪家没拍 → 见下一节（user 10-30 拍了：进 ☰）。

## 10-30 · 文件和根物件分清；☰ = 文件设置 / 偏好 / 手感，视图 = 看效果
- **user 原话**（逐条）：「我觉得文件和根物体还是分清，根物体不能带场景元数据。光照单位什么的跟着glb文件走，不是根物体！ 然后统一，现在就把单位搬到菜单里面 / 天空、太阳、经纬度 反而应该跟着视图，视图改名。视图 = tweak and see the visual effect。后处理什么都在，甚至材质也是这个位置。但是逻辑上可以分开来」「所以文件是文件设置，preference，手感，视图就是eye candy」「单位搬进根物件的物件窗口 不同意！我说了根物件和其他物件完全等价！所以说根物件也应该有自己的名字，而不是用作品名！根物件就是物件。没有任何特殊。可以随便挂。如果数据契约有问题，我可以立刻escalate fable」「试用这里ui谜语人了我建议是放在尺度参考同一行，看哪里这个label也去掉，就是两个下拉框」（附截图：单位页「尺度参考 · 看哪些」「试用（这台设备记住）· 最多 3 条」）

## 10-30 · 视图窗改名「渲染」；太阳 / 天空归它，材质和灯单独
- **user 原话**：「视图窗改个什么名 渲染？画风也行。渲染是不是语义对。因为以后性能之类的图形学也调。然后太阳光照是不是也归这个，但是材质和灯光单独？相当于blender的世界材质？」
- **Opus**：「渲染」对：以后画质 / 性能档 / 曝光这些图形学旋钮都住这，「画风」只是其中一项、太窄。太阳 / 天空 / 时刻 / 经纬度归它 = Blender 的「世界」属性（环境光、天空）+「渲染」属性合在一个窗；材质（每张面刷什么）和灯（摆在世界里的物件）是作品内容，各走自己的地方（材质编辑器、灯 = 物件）。灯用物理量存之后，渲染窗要有「曝光」（像真相机），不然真实亮度的灯一会儿全黑一会儿全白。
- **状态**：**拍了 + 落地 v0.18.15**（窗口和钮都叫「渲染」）；太阳 / 天空进渲染窗 = 以后做。
