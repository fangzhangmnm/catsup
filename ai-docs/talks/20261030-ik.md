## 10-30 晚 · 开题
- **user 原话**：「待会要讨论fbik和其他ik的方案。我也在想pro和con，但是根据我们数据契约不变，其他吃书的思路，我觉得可以有多种不同的ik方案，然后数据是一样的。可以换着编辑。」「MikuMikuMoving这个就是fbik的，算是我们的前辈，我们不是第一个吃螃蟹的人」
- **Opus 的看法（预习，给待会那轮用）**：
  - **同意主干**：数据 = 每根骨头的本地转动（FK），IK 只是编辑工具，写的也是 FK，就像建模工具写的是点的位置。好处：数据契约不变；glTF 的动画本来就只有转动 / 位移，导出零翻译；解算器换着用、以后加新的都不碰文件。
  - **最该讨论的一条坏处 = 两个关键帧之间**：两帧都用 IK 摆好了（脚踩在地上），中间按 FK 转动插值，脚会滑、手会离开桌面。业界（Blender / Maya）是把 IK 的目标点也存成动画，每一帧都重新解，这样解算器就成了数据含义的一部分，换解算器动作就变了。MMD 也是这样：动作文件里存 IK 骨头的位置，播放时用它固定的解法每帧解。
  - **一种中间做法**（没拍，供讨论）：除了 FK，再存「目标」，只写要什么、不写怎么解，比如「这只脚第 a 到第 b 帧钉在这个点」（接触 / 钉子）。哪个解算器都必须满足它，满足的方式可以不同；导出时烘成每帧 FK。这样「数据一样、换着编辑」大体还成立，代价是多了一类目标数据，格式归 Fable 定。

## 10-30 晚 · 第二轮：user 在 Blender 里 K 的是 IK
- **user 原话**：「嗯blender我反而是K ik，关键是插值怎么办，如果只是摆pose还好，不过其实我的精度做几个pose然后线性插估计就够用了。」（接着的「先key pose，然后二阶微扰」「不同的插值方案是不一样的」记在 `20261030-animation-curves.md` 第二轮）

## 10-30 夜 · 第三轮：全身 IK 动画师用得多吗？会不会伤 K 帧
- **user 原话**：「然后讨论fbik，这个在动画师里面这个用的多吗 / 我比较担心这个反而比较伤k帧，因为如果你拉一下手屁股动了。但是你知道做行走动画是先把重心调好，再折腾手的sub-primary然后是secondary的 / 所以就是community里面是不是只有过程动画，ragdoll才会用fbik？ / 现在大厂的态度是什么」
- **Opus（凭记忆，截至 2026 年中，没核；要准的话去调研）**：
  - **手 K 的主流不是全身 IK**：Maya 里手 K 角色，大多用绑定师做的控制器——每条胳膊 / 腿一个 IK 手柄，能和 FK 来回切；脚有一套踮脚 / 抬跟的控制；重心一个控制器。拉手只动这条胳膊，屁股不动。user 担心的正是全身 IK 在手 K 里不受欢迎的原因：分层做（先重心、再四肢、再二次动作）时，它会把已经调好的那层拽歪。
  - **全身 IK 用得多的地方**（不只是程序动画和布娃娃）：
    1. 动捕清理和重定向：MotionBuilder / Maya 的 HumanIK，全身 IK 是它的本行。
    2. 运行时的程序动画：脚贴坡、手扶墙、看向。这些多数其实是两节骨头的 IK，用全身的少。
    3. VR 化身：头 + 两只手三个点推出全身（Unity 的 Final IK 里那套、VRChat 全身追踪）。
    4. 摆关键姿势：Cascadeur 整个工具就是围着「拽几个点、全身自动摆好、显示重心」做的，而且是给手 K 用的；MikuMikuMoving 也是这一路。
    5. 布娃娃其实是物理不是 IK；「主动布娃娃」= 物理去追一个目标姿势。
  - **治「拉手屁股跟着动」的标准做法 = 钉子 + 硬度**：MotionBuilder 里身体每个部位可以钉住位置 / 转动，还有「全身跟着动」和「只动这一节」两种模式；Cascadeur 也是先钉住不想动的点。钉住屁股 = 拉手只动胳膊和脊椎。正好对上 user 的行走流程：重心那层调好就钉住，再折腾手。
  - **大厂现在的态度**：
    - Epic：UE5 的 Control Rig 有全身 IK 解算器，Epic 在推「在引擎里直接 K 动画」；游戏运行时走动作匹配（UE 5.4 起，从一大堆动捕里挑最合适的一段接上）。
    - 3A 过场和大片：还是 Maya 控制器绑定 + 大量动捕；全身 IK 主要在动捕那条线上。
    - 新方向是「学出来的」：Cascadeur 用神经网络从几个点补全整个姿势；Ubisoft La Forge 做过学出来的补间（给关键姿势，AI 补中间帧，2020）——这正好是我们「插值方案」里的一种。
    - 拿视频动捕（不穿动捕服）：Move.ai、Rokoko、DeepMotion 这些在商业化。
- **Opus 的提案（没拍）**：
  1. **默认 = 局部 IK**：拉手只解这条胳膊（两节骨头有现成的解析解），屁股永远不动；分层 K 帧不被打扰。
  2. **全身 IK = 明着换的一种解法**，用来摆关键姿势。身体部位上有钉子开关；开全身 IK 时默认钉住屁股和两只脚（拉手只动胳膊 + 脊椎 + 头）；想要「够远处、身子跟着倾过去」就拔掉屁股的钉子。
  3. **钉子就是第一轮那个「目标 / 钉子」数据**，不另发明；换解法不换数据（user 的主干照旧）。
  4. **重心看得见**：摆姿势时画出重心落在地上的点 + 两脚之间能站稳的范围（Cascadeur 那种），「先把重心调好」有东西可看。

## 10-30 夜 · 第五轮：Cascadeur 科普；先摆再钉、拖核心动全家、框选拖；只管点扭转对不对
- **user 原话**：「Cascadeur 科普」「我现在的想法是先摆，摆好了把核心钉住，以及可以做成hierarchy的拖核心动全家，以及可以框选然后拖」「顺便，fbik是基本只用管点，扭转基本都会比较正确对吧？」
- **Cascadeur 科普（Opus 凭记忆，截至 2026 年中；版本号和年份没核）**：
  - 谁做的：Nekki（做《暗影格斗》那家），起先是给《暗影格斗 3》做动画的内部工具，2019 年前后公开；有免费版，Windows / Mac / Linux。定位 = **手 K 的角色动画**，AI 帮忙、不替人做主。
  - **自动摆姿势（AutoPosing）**：身上一圈点（手、脚、手肘、膝盖、胯、胸、头……），拖几个点，神经网络把其余的补成自然的姿势；每个点可以单独关掉自动、自己定。= 学出来的全身 IK。
  - **自动物理（AutoPhysics）**：画重心的轨迹、着地点（支点）、跳起来时重心的抛物线；按物理算一个修正版放在旁边一层，人对照着挑 / 混。= 「先把重心调好」有东西可看。
  - **二次动作**：一个滑条给选中的部位加跟随 / 延迟 / 晃动。
  - **补间**：给关键姿势，AI 补中间帧（较新的版本）。
  - **「反烘焙」**：把动捕那种每帧都是关键帧的动作抽稀成少数关键帧，好让人手改——正好是我们动捕那条线的最后一步。
  - **快速绑定**：人形骨架一键生成它的控制点（Mixamo 那一路的思路）。
  - 和我们的差别：它是桌面大软件、写实向；我们是低模、iPad、glTF / VRM 原生。它几样功能正好各自对上我们这周聊的：全身 IK、重心、二次动作、插值方案、动捕抽稀。
- **user 的摆法（倾向）**：先自由摆 → 摆好了把核心钉住 → 拖核心动全家（按层级）→ 也能框选几个点一起拖。
- **Opus 的读法（没拍）**：
  - **三个操作其实是一条规矩**：「拖谁，谁的子孙跟着走；钉住的不走；夹在中间的关节自己弯。」
    - 什么都没钉、拖胯 = 整个人平移（层级的「拖核心动全家」）。
    - 脚钉住了再拖胯往下 = 腿自己弯 = 蹲下（行走 / 蹲起的标准动作）。
    - 核心钉住后拉手 = 只动胳膊和脊椎，效果就是局部 IK。~~所以第三轮「默认局部 IK、全身 IK 另开一个模式」可以不要了，一个解法 + 钉子就够；第三轮「开全身 IK 默认钉屁股和脚」也让位给 user 的顺序~~（第七轮作废：user 要几种 rig 切换，局部 IK 和全身 IK 都留）。
    - 框选几个点一起拖 = 这几个点当一块硬的一起走，其余的解。
  - 钉子要看得见（点上一个钉子标记），一点就开 / 关；钉子就是第一轮那个「目标 / 钉子」数据。
- **只管点，扭转对不对（Opus）**：**大体对，但扭转正是「点」给不出来的那一维**，靠三样兜：
  1. **关节极限**：膝盖只能往一个方向弯、手肘差不多也是，所以腿和胳膊弯的方向基本不会错。手肘往外还是往里撇（肩到手那根轴上绕一圈都行）点手腕定不了——但手肘本身也是一个点，拖它就定了。
  2. **从上一个姿势出发、改得最少**：解算器只在现在的姿势上做最小的转动，原来没扭的就不会突然扭，所以通常看着是对的。坑 = **跟走过的路有关**：同样的点、拖的顺序不同，扭转可能不同；拖很多次以后小臂 / 脊椎的扭转会慢慢攒歪。关节的扭转极限（人体模板里有）能把它拦在合理范围；学出来的那种（Cascadeur）会往「自然」拉。
  3. **手、脚、头要朝向**：一个点没有朝向——手心朝哪、脚掌平不平、脸看哪，只拖点给不出来。要么这几个末端带一个能转的把手，要么多给点（脚尖 / 指尖），Cascadeur 是两样都有。
  - 路飞那种拧好几圈：点永远给不出来（解算器只走近路），要手动转、走越狱。

## 10-30 夜 · 第六轮：动捕的两个场景；iPad 拍视频有多胖
- **user 原话**：「动捕可能大概率的场景还是用户网上去下小姐姐跳舞的教学视频然后直接丢吧，或者自己diy的话应该也是录好了多个选项可以一个一个试？说起来ipad ios拍视频有多胖？」

    - 礼数：MMD 圈本来就有「照着跳舞视频扒动作」的文化，分发扒出来的动作时会写原舞者 / 编舞、有的要先征得同意。app 不管、不拦；导出时能填出处就行（同 VRM 带作者 / 许可那条）。
  - **场景二：自己录，录好几条一条条试**。在 app 里直接用摄像头录，~~每条只留骨架轨迹、不留视频~~（第十轮更正：原视频要留，分层存）：
    - 骨架轨迹很小：33 个点 × 每点 4 个数 × 30 帧 / 秒 ≈ 每分钟 1 MB 上下（不压缩），视频的几十分之一；录十条也不占地方。
    - 一条条试 = 录歌的「多条挑着拼」：前半段用第 2 条、后半段用第 3 条，接缝处混一下。
    - 隐私顺带解决：视频不落盘、不外发，只剩骨架。
  - **iPad / iPhone 拍视频多胖**（iOS 相机设置里写的大概数，凭记忆没核；高效 = HEVC，兼容 = H.264）：
    | 规格 | 高效（每分钟） | 兼容（每分钟） |
    |---|---|---|
    | 720p 30 帧 | ~40 MB | ~45 MB |
    | 1080p 30 帧（常见默认） | ~60 MB | ~65 MB |
    | 1080p 60 帧 | ~90 MB | ~100 MB |
    | 4K 30 帧 | ~170 MB | ~350 MB |
    | 4K 60 帧 | ~400 MB | ~400 MB |
    | ProRes 4K 30 帧 | 约 6 GB | — |
    - 一段 30 秒的舞 1080p ≈ 30 MB，4K 60 帧 ≈ 200 MB。动捕的小模型只看 256 像素上下的小图，**4K 白胖**，1080p 甚至 720p 就够。
    - 从相册挑视频进网页，iOS 有时会先「准备 / 压缩」一下，要等一会儿（没核）；在 app 里直接录就没有这一步。

## 10-30 夜 · 第九轮：先只做一个全身 IK；局部 IK 是不是它的退化；插值在 FK 还是 IK 目标上做
- **user 原话**：（引第五轮 Cascadeur「自动物理」那段）「这些也都可以玩，但是一开始我们做一个FBIK就行了，以及为什么普通IK不是FBIK的一种退化（钉几个）」「以及，用ik bone做插值和用FK做插值有什么优劣」
- **拍了**：一开始只做一个全身 IK。自动物理（重心轨迹 / 支点 / 抛物线 / 修正版一层）、二次动作滑条、AI 补间这些以后在骨骼动画实验室里玩。
- **局部 IK 是不是全身 IK 的退化（Opus）**：**是**，跟「Ptex 是自动 UV 的退化」一个道理——把这条胳膊以外的一切都钉死，全身 IK 剩下要解的就正好是局部 IK 那道题。业界分开做，是因为下面三个前提常常不成立；我们自己写，可以让它们成立：
  1. **钉子要能钉转动，不只钉位置**：只钉屁股的位置，胸还能转，拉手时脊椎会扭。局部 IK =「这条链以外全部钉死（位置 + 转动）」，所以不是「钉几个」，是「一键钉一大片」——界面上可以做成一个预设：「只放开这条胳膊」。
  2. **钉子要是硬的**：很多全身 IK 把钉子当「尽量满足」（带权重），钉住的地方会微微漂；局部 IK 是保证不动的。我们的钉子做成硬的，就没差别。
  3. **手肘往哪撇的偏好两边要一样**：两节骨头的局部 IK 有现成的精确解，手肘朝向由一个「手肘指向点」明着定；全身 IK 是一步步逼近，手肘朝向按「改得最少」挑。偏好一样，答案就一样。
  - 所以做法（没拍）：先只写全身 IK 这一个解法；局部 IK 那个 rig = 全身 IK + 自动钉住这条链以外的一切。以后要快，再给「两节骨头」加一条精确解的快路，但要和全身 IK 在同样的钉子下给出同一个答案（瑞士奶酪：一条测试对拍）。
- **插值：在 FK 上做 vs 在 IK 目标上做（Opus）**：
  | | 在 FK 上插（每根骨头的转动在两帧之间插） | 在 IK 目标上插（手 / 脚的目标点在两帧之间插，每帧重解） |
  |---|---|---|
  | 着地 / 接触 | ✗ 两帧之间脚会滑、手会离开桌面，要靠多 K 帧压住 | ✓ 目标点不动，脚就一直在那 |
  | 弧线 | ✓ 转动插出来天然是弧（甩胳膊、跟随好看） | ✗ 目标点直线插，手走直线、像机器人；要另外把目标的路径弯起来 |
  | 换 rig / 换解法 | ✓ 中间帧不变——和「数据一样、换着编辑」一致 | ✗ 中间帧取决于解法，换解法动作就变 |
  | 中间会不会跳 | ✓ 不会 | ✗ 手肘 / 膝盖可能半路翻面；目标够不到时膝盖「啪」地伸直 |
  | 拧好几圈（路飞） | ✓ 能存 | ✗ 目标点表达不了扭转圈数 |
  | 导出 glTF | ✓ 原样（glTF 只认转动 / 位移） | ✗ 要逐帧烘 |
  | 算力 | 很省 | 每帧解一次全身 IK |
  - 业界手 K 行走的老规矩：**腿用 IK、胳膊用 FK**——脚要钉地，胳膊要甩出弧线。这说明两种插值是按部位、按时段选的，不是全局二选一。
  - **Opus 推荐（没拍）= FK 插值 + 钉子**（第一轮的中间做法）：先按 FK 插出中间帧，再只在有钉子的时段、有钉子的部位，用全身 IK 把它拉回钉子上。这样弧线来自 FK，着地来自钉子；换 rig 时没钉子的部分中间帧完全不变，有钉子的部分「要什么」不变、「怎么满足」可能有一点差别（解法冻住的话就完全不变，见曲线那份第三轮）。
  - 「在哪个空间插」可以当成插值方案的一部分写进文件（每段 / 每个部位一个闭集选项，编号 = 对照表的代号），以后想要「这只手走直线去按按钮」就给那段选「目标空间」。
