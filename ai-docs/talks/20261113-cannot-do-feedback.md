# 讨论：做不了的时候怎么告诉用户（菜单灰不灰、失败的提示）

> created 2026-11-13 by Claude Fable 5.2 · as-of 三维开发版 v0.19.66
> 状态：**愿望单，不排期**。user：「到时候处理的时候好好想一下」。下面的分析是统筹的初步看法，user 没表态。

## user 原话（2026-11-13）

「以及wishlist，没法炸开的时候菜单项应该灰色，而且失败的时候应该有更明显的提示而不只是状态栏。这个问题反应了什么系统性的ux设计和ui设计问题以及架构问题？到时候处理的时候好好想一下」

## 起因

user 在自己的文件 a12b 里，选中画过的面点「建组件」，没成；他一度以为是选了全部触发的护栏，又以为是硬表面的毛病。实际是「带着画的面现在还不能分出去」那道护栏（`src/scene/paint.ts paintMoveBlocked`）。菜单里「建组件」是亮着的，原因只出现在状态栏。来龙去脉在 `talks/20261113-empty-kind-and-new-component.md`。

## 统筹的初步看法：它反映了五件事

1. **「能不能做」有两处在判断，对不上。** 菜单亮不亮看的是一套条件（`canMakeComponent()`：有没有选中东西）；真正的拒绝在执行那一步里面（`ops.ts` 里的 `refusePaintMove`）。菜单说能，点下去才说不能。根子：每个动作没有一个统一的「现在能不能做、不能是为什么」的问法。修改锁那次把「锁着时什么能动」收成了一张表、各层都查它，这里是同一个病。
2. **所有反馈只有状态栏一条通道。** 成功的话、顺手的提示、被拒、出错，都写进同一行字，轻重不分。被拒是用户明着做了一个动作却没成，应该出现在手边，并且说出路（家族已有的原则：UX 误导 = 数据安全缺陷；别让用户被踢下去）。
3. **做不了的项是灰着、藏起来、还是点了再说，没有统一规矩。** 现在有的藏、有的亮着点了再拒、层级面板里有的灰着。iPad 上没有悬停，「灰着加原因」的原因得直接看得见。
4. **一个新功能让一批旧动作悄悄失效。** 画进来之后，分、并、炸开、复制、做成唯一、转种类都被拦，但物体上没有任何标记说「它现在有这些限制」。
5. **物体是哪一种不够显眼。** user 把自由建模里建的方块（网格体）当成了硬表面。

## 到时候要想的（没定）

- 每个动作一个「为什么现在不能做」的问法，菜单、快捷键、执行都问它；它返回的那句人话就是灰着时显示的原因和被拒时说的话。
- 反馈分几档、各出现在哪：顺手的提示、被拒、出错。
- 灰着、藏起来各用在什么情况。
- 因为功能没做完而加的限制，在物体上要不要有看得见的标记。

## 同一天稍后：小弟拿 a12b 复现，查出来是谎报成功

- 实际显示：状态栏写「建了组件『ab12』：6 张面，嵌在这一层里……」，而场景和历史都没变，6 张面还选着。
- 经过：`editor.ts makeMeshComponentStep` 提交 `separateObject`，被「带画不能搬」拒，护栏把原因写进状态栏；但这个函数不看提交成没成，接着又写了一句成功，把原因盖掉。
- 这不属于上面「到时候整套想」的范围：家规「界面不许谎报成功」是硬的。统筹定：现在就修，在「一步」那一层收口——一步里有提交被拒，这一步整个不算，结束时状态栏一定是被拒的原因。diff 统筹审（撤销那一层的收尾）。菜单灰掉、更明显的提示照旧留在愿望单。
- 统筹更正自己对 user 说的话：先说「听着像真的毛病」，读了文件又说「不是新毛病，是护栏加提示不明显」，后一句说错了一半——带画分不出去是还没做，谎报成功是真毛病。

## 小弟查「一步」那一层的现状（11-13）

- 护栏拒绝（比如「这些面上有画」）：不落半步——这一步里之前提交的会回滚、之后的跳过、选区退回。漏的只有状态栏（假的成功）。
- **锁着的拒绝（演示锁、物件锁）：会落半步。** 它们拒了直接返回，不回滚、不把这一步标成失败。一步里有好几条提交时（比如合并那种宏），前面的已经落进场景，锁着的那一条跳过，后面的照做，最后还写成功的话。比假话更重。
- 改法（统筹批了，只动 `editor.ts`）：锁着的拒绝和护栏拒绝走同一个口——回滚这一步、标失败、后面不做、记原因；收尾时状态栏写第一次失败的原因。
- 统筹要他另查三处：失败的一步不该清掉重做；不该让文件变成「改过、要存」；画板要跟着退回去。
- 同类的「提交之后不看结果接着写成功」在 `editor.ts` 里有 7 处（建组件、强行对称开和关、镜像关、焊接、藏、全部放回），有了收尾的规矩都不会再说假话。
- diff 发统筹审。

## 「一步全有或全无」的 diff，统筹审（11-13）

- 小弟改了：锁着的拒绝和护栏拒绝走同一个口（整步回滚、标失败、后面不做）；收尾时状态栏写第一次失败的原因；建组件那一处被拒就返回。
- 他照统筹要求查的三处里，两处原来就是坏的，一起修了：
  - 重做：原来提交一开头就清重做，哪怕这一条被拒、什么都没改。改成第一条成功的提交先把重做「停放」，成功收尾才真丢，失败回滚就放回去。
  - 「有没有改动」：原来失败的步也让改动号加一，文件变成改过、触发自动保存；一步做到一半时会话还能看到中间状态。改成另起一个只给会话用的改动号，一步成功收尾才加一。
  - 画板那一头本来就对。
- **统筹退回两处**：
  1. 放回停放的重做时，如果这一步开始前没有重做，代码直接返回，没有把失败那一步的前半截从重做里丢掉——按一下重做，半步就回来了。这是这次改出来的。
  2. 停放的东西没有规矩保证不活过一步：提交可以发生在一步之外，那时停放了没人收；之后再有一步失败，会把一份对不上的旧尾巴接到历史末尾。要的规矩：没有一步开着的时候停放的一定是空的，并在开一步、撤销、重做、装载时检查。
- 另要他确认：锁着的拒绝改成整步不算之后，「锁着的跳过、别的照做」的动作（修复、全选删除、全部藏、全部放回）还对不对。
- 一起改：「新建平铺的画」被拒还写「建好了」。
- 根的名字不跟文件名：唯一的一条路是存盘时拿文件名盖掉根的名字，批了去掉；导出给别的软件的顶层节点也改叫根自己的名字。

## 「一步」第二版，统筹审过（11-13）

- 两处都改了：放回停放的重做之前先无条件丢掉失败那一步的半截；提交多一个「在不在一步里」，不在就当场丢、不停放；开一步、撤销、重做、装载四处检查停放的是不是空的，漏了就丢掉、计数、记一条。
- 小弟补探针时发现上一版探针②是假绿，而且假绿的原因正是那个毛病（半截留在重做里被重做了回来）。已改成先明着断言「进这一步前确实有重做」。
- 深度 0 的提交现在不存在（只有几个直接拿 History 用的单元测试会这么调）。修复、全选删除、全部藏起来 / 放回来都是提交之前就把锁着的筛掉，不受影响。
- 通过，跟这一版发。这一版带：一步全有或全无、「画画」改名「绘制」、两颗图标、画布小窗靠左、根的名字不跟文件名、「新建平铺的画」被拒不再说建好了。自动标接缝的新做法不带（没有进度和取消），和第 3 刀一起发。

## 被拒的原因走不抢焦点的通知条（user 11-13）

user：「动作被拒时整个不算、状态栏写原因，不再说假的成功。 这个其实应该是那个非抢占的弹窗？不过不要用error」

- 「那个非抢占的弹窗」= 软件里现成的通知条（`src/app/ui/notice.ts`，四个级别：中性、提示、警告、错误）。
- 定：一步被拒时，原因除了写状态栏，同时用通知条弹一条；级别用中性，不用警告、不用错误（被拒不是出错）；瞬态、不带按钮、同一个原因原地更新。真的出错照旧走原来的级别。跟这一版一起做。
- 这就把愿望单里「失败时要有比状态栏更明显的提示」先做了一半；「菜单项灰掉、原因写在菜单上」那一半还在愿望单里。
