# 讨论：像素风友好的「拉直」UV（lowpoly 有机体）

> created 20261030 by Claude Opus 5.5 · as-of v0.18.19
> 状态：user 提的方向（「建议我们也发明」），细节没拍。图形学科研 → Opus 做。
> 相关：`20261030-bodypaint-kernel-uv.md`（一套 UV、只平移、像素不变；第二轮末尾有小红帽 UV 的实测）。

## 10-30 晚 · 开题
- **user 原话**：「顺便说到小红帽，其实这种lowpoly，你看一下uv，都是要拉直的。建议我们也发明一个可以做pixel art friendly的有机体拉直的uv」
- **小红帽 pose1 的 UV**（Opus 看的）：头发、裙子、袖子、兜帽这种「一圈一圈的四边形带」都拉成矩形、列宽一样（裙子 4 列）；脸是正面投影、不拉直；一半 UV 边横平竖直；岛的边不在像素格上；颜色画出岛外一圈。
- **Opus 的看法**：
  - 岛分两种：**带子**（胳膊、腿、身子、裙子、头发片：一圈圈四边形）拉成矩形；**贴花**（脸、徽章这种要在上面画五官 / 图案的）按投影保形状。小红帽本来就是这么分的。
  - **像素友好 = 比小红帽多走一步**：矩形的角落在整数像素上；每一列、每一行的宽度是整数像素（按 3D 边长 × 像素密度取整，同一圈上要一致 → 一个带整数约束的小优化）；只平移、不旋转（接贴图那条的打包）。这样格子正好压在像素上，画像素画不会斜。
  - 现成的近亲（Opus 记得的，没核）：Blender「跟随活动四边形」（把一圈四边形摊成直格子）、几个「拉直 / 矩形化」插件；学术上「边界优先摊平」（2017，能指定岛角是 90° → 摊成矩形）、「整数格映射」（2013 前后，让参数化的线落在整数格上——落在整数格 = 像素对齐）。
  - 三角形、极点（五条边汇一处）、带子的分叉处没法拉直，留成小的不规则岛，或在岛里允许局部歪一点。小红帽那团挤在一起的小三角就是这种地方没人管的样子；自动做时要保证每个三角至少有几个像素。

## 10-30 夜 · 第二轮：Klee 是另一种（涂鸦）
- **user 原话**：「klee我反而比较vibe，因为是涂鸦，不是像素级别的小贴图，你看一下是不是这样」
- **Opus 看了**（user 2023 的 Klee 工程，在本机检疫桶，没进仓）：是这样。四张分开的贴图（衣服 / 脸 / 头发 2048²、包 1024²），后来又烘成一张 2048² 的总图（文件夹里有 VRChat 那边常用的烘焙插件的产物，= user 说的「rebake 繁琐」那一步）。UV 是有机的自动 / 切缝展开，岛弯弯曲曲、各种角度转着摆，很多零碎小岛，**没有拉直**；画法是软笔刷的渐变涂抹，看得到笔触，不在像素级。小红帽是另一种：256² 一张图、带子拉直成矩形。
- **读法（Opus，没拍）**：UV 有两种风格——**像素风**（拉直、整数像素、最近邻，小红帽这类往这边走）和**涂鸦风**（有机展开、保角、高分辨率、线性采样，Klee）。两种都能用「打包只平移不旋转、像素不变」那套；涂鸦风禁转岛会让打包稍微松一点，代价是多一点空白。自动展开时按物件（或按区域）选风格。

## 10-30 夜 · 第三轮：保角不对；吸附到像素选角还是中心
- **user 原话**：「顺便，我对〔人名略：本仓公开；一位做计算共形几何的学者〕表示一句学术嘲讽。conformal在这里不是合适的东西。因为反而会把密度最高的地方的像素密度压低。不过也许他后来有什么好想法了。反正到时候我们好好科研一波」「然后我希望是snap to pixel的，你觉得是corner还是center」
- **Opus 的看法**：
  - **保角为什么不对**：保角展开只保角度、不管面积，伸出去的部分（手指、鼻子、发梢）会被缩得很小——正好是最需要细节的地方像素最少。我们要的目标是「按密度分面积」：先定每块该有多少像素（密度），再让展开尽量照这个面积来，角度歪一点可以接受。近亲（Opus 记得的，没核）：「尽量刚性」展开（2008，角度和面积一起顾）、Blender 新版的「最小拉伸」展开（好像是 4.3 加的）、带锥点 / 切缝来减变形的做法。拉直那一路则两样都不是——它要的是对齐整数格。真做时 Opus 调研一波。
  - **吸附到像素：推荐角，不是中心**。理由：
    1. 像素 i 占的是 [i, i+1) 这一格，**角 = 整数坐标**。UV 点落在角上，岛的边正好是像素边，每个像素要么整个在岛里、要么整个在外；画像素画时像素的边和模型的边对齐（picoCAD 那种干净）。落在中心（i + 0.5），岛的边会把边上一排像素劈成两半，最近邻采样时边上那排只露半格。
    2. 上一轮定了 UV 存像素坐标：落在角上 = 存的就是整数，没有小数误差。
    3. **中心只在一种情况用**：一个面整个缩成一个点、只取一个颜色（低模常见的「调色板贴图」：每个面的 UV 全挤到调色板某一格的中心）。那时点要落在中心，免得采到隔壁颜色。
  - 所以：铺画的岛 → 角；「这个面就一个颜色」 → 那一格的中心。

## 10-30 夜 · 第五轮：别的行当怎么对付「极点」；不用 UV 的做法；Nanite
- **user 原话**：「继续聊〔科研那边，略〕，学术或者数值相对论碰到这种带pole的脏拓扑怎么办？还是其实就是不用贴图（数组）？或者它在图形学就是gaussian splatting和nanite？nanite是不是比较接近我的理念只不过没人用它做过low rez?」
- **Opus（科普 + 看法，没拍）**：
  - **极点去不掉，只能选放哪**：闭合的网格，各顶点的「角亏」（360° 减去围着它的角之和）加起来恒等于 720°（球那种拓扑；离散的高斯—博内）。展平时这些弯曲必须有个去处：摊开（= 拉伸变形）或集中到切缝 / 锥点。**低模的弯曲只住在顶点上**：胳膊、腿、裙子那一圈圈四边形带上的点，角之和接近 360°（几乎是可展开的平的），所以拉直几乎不变形；角亏大的地方（极点、帽子顶、分叉）就是缝和锥点该去的地方。「脏拓扑」其实是弯曲集中的地方。
  - **物理 / 数值计算那边**：① **地图册**（流形 = 多张互相重叠的坐标片 + 片之间的换算）——贴图的「atlas」这个词就是从这来的，UV 岛 = 坐标片、缝 = 换算。数值相对论用多片网格（立方体投到球面的六片、阴阳两片）躲开经纬网格的两极；气候模型也用立方球。② **不用数组**：谱方法用球谐函数的系数表示场，基函数处处光滑，两极不特殊（相对论里多块谱方法的代码就这么做）。③ **等面积像素**：天文用的 HEALPix 把球切成面积全相等的像素——正好是「密度」那个目标，和保角相反。④ 真正的奇点（黑洞里面）是挖掉不算（excision）或特殊处理（puncture）——有点像我们留着不管的孤儿。
  - **图形学里「不用 UV」的做法**：迪士尼的 Ptex（每张面自带一小张图，完全不展开，密度可以按面给）；网格颜色（颜色存在点 / 边 / 面的细分格上）；顶点色；三维的哈希格 / 体素；高斯泼溅（外观存在空间里的一团团高斯上，没有面也没有 UV）。Ptex 最接近「用户不碰 UV」，但游戏引擎和 glTF 不吃它——所以我们的做法相当于「里面像 Ptex 一样不用管，导出时烘成一张图集」。
  - **Nanite**：管的是几何不是贴图——把网格切成一百来个三角的小簇、按层级挑，让屏幕上一个三角大约一个像素；贴图照样用普通 UV + 虚拟贴图（按屏幕需要只载入用得到的那几页）。和 user 理念像的地方 = **细节跟着屏幕像素走**（「统一像素密度会死！远山vs手里的精致小刀」）。低分辨率：原理上把屏幕设成 160×144，它就会自动挑很粗的簇——但那是「误差最小的模糊几何」，不是设计过的低模刻面；低模的美是人定的，不是误差函数定的。有没有人拿它做过低分辨率，Opus 不知道。贴图那边对应 Nanite 的是虚拟贴图，再往前是 id 的 MegaTexture（Rage，2011：整个世界每一寸都是独一份的画，引擎自动管载入）——那才更接近「每个原子独一份 + 自动管理」。

## 10-30 夜 · 第六轮：边界项；为什么要连起来；纸艺；非流形自动拆；缝让人标
- **user 原话**：「高斯–博内定理 要接住小红帽还得加上boundary term。而且碰到非manifold一样死」「你是说底模直接全炸碎？」「那么为什么以前艺术家画贴图非要连起来，不连起来的话continuity有多少artifact」「等等，是不是反而这里纸艺大师是我们的朋友」「这个工作流反而可以有，以后可以导出折纸图谱，进wishlist」「等等，所以有没有算法可以把非manifold，比如一个杨桃，给自动拆开来。因为我们之前说了连seam都尝试最大流或者更对口的算法自动推理一下seam」「以及pixel肯定是需要手工展平的，逃不了的。智能算法顶多算一下怎么割刀，但其实人类标edge property也就三分钟」
- **Opus**：
  - **边界项**：对。带开口的网格是「内部顶点的角亏 + 边界顶点的转角（180° 减去它那几个角之和）= 360° × 欧拉示性数」；小红帽 125 条开口边（裙摆、披风、头发片）都在边界项里。好消息是开口本身就是弯曲的出口：开口的圆锥（裙子）不用切就能摊平。非流形（一条边挨 3 张以上的面）定理不管——要先拆成流形再说。
  - **不是全炸碎**：上一轮说「里面像 Ptex 不用管」是指用户体验；烘出来的图集还是该连的连。
  - **为什么艺术家非要连**（不连的代价）：① 在 PS 里一笔不能跨岛画——**我们在视图里画、贴图像素自己去取色，这条理由对我们不存在**；② 每个岛要一圈防渗的边，岛越碎边越多，低分辨率下边能吃掉一大块（256² 的图、上百个一张面的小岛，边比岛还大）；③ 缝两边被双线性 / mipmap 各自过滤，远看是一条线；④ **像素风**：缝两边的像素格对不上，像素图案在缝上错一下——这是像素风要连的主要理由（拉直的带子让一圈像素行绕胳膊连续）。结论：能摊平的带子连起来，弯曲集中处切开，不炸碎。
  - **纸艺大师是朋友**：对。纸模展开（Pepakura、Blender 的纸模导出插件）= 只沿边剪开、每张面形状一点不变（零拉伸），剪到不重叠为止——正好是「低模的零变形 UV」：每张面的像素都不歪，密度天然一致。冷知识：「每个凸多面体能不能只沿边剪成一整片不重叠的展开图」是至今没解决的数学问题（丢勒问题）；凹的会失败，就多剪几片。user 10-26 说过「没有smooth的小红帽的折纸非常舒服……以后玩256 tri折纸是神器」。**导出折纸图谱进愿望单**（画好的贴图跟着展开图一起印出来，折一个实体小红帽）。
  - **非流形自动拆**（杨桃：几片棱在中轴上汇成一条挨好几张面的边）：标准做法 = 绕着那条边按角度给面排序，相邻两张两两配对、按朝向配对，把边复制成几条，每对自成流形（「切开再缝合」这类论文，2001 年前后；Opus 记得，没核）。CatsUp 网格内核本来就会碰到这种边（以前「loopCut: edge has 4 faces」那个报错）。
  - **自动推缝**：有专门的算法——「缝长度最短、变形不超过某个上限」一起优化的那类（2017–2018，Autocuts / OptCuts 之类，Opus 记得，没核），也有图割一类。
  - **缝让人标**：同意。像素风的展平逃不了手工，算法顶多建议在哪割；人在表面工作台给边刷一个「缝」属性，三分钟。缝 = 一列边属性（和软边 / 硬边手标同一套），不另开 UV 页签；展平、拉直、吸到像素角、只平移打包全自动。和愿望单里「缝（UV 切线）标记（DT66）」是同一条。
- **同轮拍了**：user「拍：ptex也是一个方案，或者是我们自动uv的一个退化情况」。读法（Opus）：每条边都当缝 → 每张面自己一个岛 = Ptex 那样；照样走「像素角对齐 + 只平移打包」，所以不另起一套。代价是防渗边多、像素格在每条边上都可能错开；适合给乱的、非流形的、拆不开的部分兜底，或者纯色面。

## 10-30 夜 · 第七轮：没人标缝时全自动；展平后自相交；按面积比例拉直
- **user 原话**：「折纸、杨桃这种非流形能不能自动拆开、缝让人标就够了 有缝的话blender也能自动拆，我说的是人不标的情况」「以及还有就是拆的很干净但是展平的时候自相交了。这个也需要grill」「然后还有就是自动按面积比例拉直，这个我真的想做，也许我也得当一回〔人名略：本仓公开；上文那位学者〕」
- **Opus（没拍；Q1–Q3 等 user）**：
  - **没人标缝时**，分三步全自动：
    1. **先拆非流形**（~~纯拓扑、确定的、不用猜~~ **错，见第九轮更正**）：挨着好几张面的边，绕着它按角度排序、两两配对、复制成几条边。杨桃的每片棱自成一块。
    2. **再找缝**：低模的弯曲集中在角亏大的顶点上 → 把这些点用最短的边路径连起来（一棵树），沿树切开，每块就能摊平（Seamster 一类，2002，Opus 记得没核）。路径的代价按「看不看得见」加权：优先走已经标了硬边的边（法线本来就断，缝藏在里面）、凹进去的折、背面 / 腋下 / 内侧。另一条路是先按「近似可展」分块再展（D-charts 一类，2005）。
    3. **低模专用捷径**：先认出四边形带（一圈一圈的环），每条带沿最不显眼的一条纵边切开 → 拉成矩形；帽子 / 极点 / 三角扇剩下的成小岛；实在乱的退化成 Ptex（每面一岛）。小红帽拼回四边形后是 237 面里 54 个四边形，带子不算多，三角多 → 小岛会不少。
  - **拆得干净但展平后自相交**：分两种——局部翻面（三角形翻过来）和整体重叠（一条长带绕回来压到自己）。「最小拉伸」那类算法保证不翻面，但不保证整体不重叠；有专门防边界重叠的变体（2015 前后，没核）。拉成矩形的带子本身不会重叠，重叠只会出在「不拉直、照形状展」的岛上。
  - **按面积比例拉直**（user 真想做的那题，Opus 的起步想法）：一条带子拉成矩形网格，第 j 列宽 w_j、第 i 行高 h_i，每格面积 = w_j × h_i，要它尽量正比于 3D 里那张四边形的面积 A_ij。取对数就变成 log w_j + log h_i ≈ log A_ij + 常数——「行效应 + 列效应」的最小二乘，有现成的闭式解（各行平均 + 各列平均 − 总平均），再按总像素预算取整（最大余数法），保证整数像素。难点是**锥形**：胳膊上粗下细，一个矩形里同一列上下等宽，粗处挤、细处拉，这个误差算得出来 → 超过阈值就横着再切一刀，分成几段矩形。
  - **要 user 拍的**：
    - **Q1 自动缝优先藏哪**：推荐「已有硬边 > 凹折 > 背面 / 内侧」，按看不看得见加权。
    - **Q2 展平后重叠了怎么办**：A 再切一刀（纸艺做法，推荐默认）；B 多容忍一点拉伸；C 故意让镜像的左右两半重叠、共用同一块像素（省一半画布，低分辨率很香，但两边就不能画不一样）——C 可以当镜像物件的选项。
    - **Q3 锥形的带子**：A 一个矩形（列宽取平均，有变形）；B 误差超过阈值就横切成几段矩形（推荐）；C 梯形（不变形但像素格斜了，像素风不要）。

## 10-30 夜 · 第九轮：更正——非流形配对不是确定的
- **user 原话**（配截图：地面一个正方形分成左右两张面，中缝上立一堵墙 = 一条边挨三张面）：「先拆非流形。 这步纯看拓扑，结果是确定的，不用猜：一条边挨着好几张面时，绕着它按角度排序，两两配对，再把这条边复制成几条。杨桃的每片棱会各自变成一块。 不同意，你这个对双面才成立要么下面两个一对要么上面吃掉一块下面」
- **Opus**：user 对，第七轮那句错了。
  - **只有当成双面时才唯一**：每张面有正反两侧，绕着那条边，相邻两张面朝向同一个空隙的那两侧配一对（三张面 → 三个空隙 → 三对），这样总是唯一的——这是实体建模里「围出一个个空间」的看法。
  - **贴图是按面不按侧**（单面），三张面挨一条边：要么地面左右两张连成一块、墙单独；要么墙和某一边的地面连成一块、另一边地面单独。奇数张总有一张落单；偶数张也照样是选择题。拓扑本身给不出答案。
  - **这个选择影响的只是缝开在哪**：三张面怎么配都能展开，区别是贴图上哪两张是连着的。所以可以用启发式选，选错了代价也只是一条缝的位置。推荐顺序（没拍）：① 同一个材质 / 同一个区域的配一对；② 标了平滑的配、标了硬边的分；③ 最平的延续配一对（夹角最接近 180°，截图里就是地面左右两张）；④ 还分不出就随便选、照样能展开。
  - 也连着单面 / 双面那份讨论：材质是双面的那张薄片，按「侧」处理时两侧可以各自归不同的块。
