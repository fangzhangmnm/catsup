# 讨论：像素风友好的「拉直」UV（lowpoly 有机体）

> created 20261030 by Claude Opus 5.5 · as-of v0.18.19
> 状态：user 提的方向（「建议我们也发明」），细节没拍。图形学科研 → Opus 做。
> 相关：`20261030-bodypaint-kernel-uv.md`（一套 UV、只平移、像素不变；第二轮末尾有小红帽 UV 的实测）。

## 10-30 晚 · 开题
- **user 原话**：「顺便说到小红帽，其实这种lowpoly，你看一下uv，都是要拉直的。建议我们也发明一个可以做pixel art friendly的有机体拉直的uv」
- **小红帽 pose1 的 UV**（Opus 看的）：头发、裙子、袖子、兜帽这种「一圈一圈的四边形带」都拉成矩形、列宽一样（裙子 4 列）；脸是正面投影、不拉直；一半 UV 边横平竖直；岛的边不在像素格上；颜色画出岛外一圈。
- **Opus 的看法**：
  - 岛分两种：**带子**（胳膊、腿、身子、裙子、头发片：一圈圈四边形）拉成矩形；**贴花**（脸、徽章这种要在上面画五官 / 图案的）按投影保形状。小红帽本来就是这么分的。
  - **像素友好 = 比小红帽多走一步**：矩形的角落在整数像素上；每一列、每一行的宽度是整数像素（按 3D 边长 × 像素密度取整，同一圈上要一致 → 一个带整数约束的小优化）；只平移、不旋转（接贴图那条的打包）。这样格子正好压在像素上，画像素画不会斜。
  - 现成的近亲（Opus 记得的，没核）：Blender「跟随活动四边形」（把一圈四边形摊成直格子）、几个「拉直 / 矩形化」插件；学术上「边界优先摊平」（2017，能指定岛角是 90° → 摊成矩形）、「整数格映射」（2013 前后，让参数化的线落在整数格上——落在整数格 = 像素对齐）。
  - 三角形、极点（五条边汇一处）、带子的分叉处没法拉直，留成小的不规则岛，或在岛里允许局部歪一点。小红帽那团挤在一起的小三角就是这种地方没人管的样子；自动做时要保证每个三角至少有几个像素。

## 10-30 夜 · 第二轮：Klee 是另一种（涂鸦）
- **user 原话**：「klee我反而比较vibe，因为是涂鸦，不是像素级别的小贴图，你看一下是不是这样」
- **Opus 看了**（user 2023 的 Klee 工程，在本机检疫桶，没进仓）：是这样。四张分开的贴图（衣服 / 脸 / 头发 2048²、包 1024²），后来又烘成一张 2048² 的总图（文件夹里有 VRChat 那边常用的烘焙插件的产物，= user 说的「rebake 繁琐」那一步）。UV 是有机的自动 / 切缝展开，岛弯弯曲曲、各种角度转着摆，很多零碎小岛，**没有拉直**；画法是软笔刷的渐变涂抹，看得到笔触，不在像素级。小红帽是另一种：256² 一张图、带子拉直成矩形。
- **读法（Opus，没拍）**：UV 有两种风格——**像素风**（拉直、整数像素、最近邻，小红帽这类往这边走）和**涂鸦风**（有机展开、保角、高分辨率、线性采样，Klee）。两种都能用「打包只平移不旋转、像素不变」那套；涂鸦风禁转岛会让打包稍微松一点，代价是多一点空白。自动展开时按物件（或按区域）选风格。

## 10-30 夜 · 第三轮：保角不对；吸附到像素选角还是中心
- **user 原话**：「顺便，我对〔人名略：本仓公开；一位做计算共形几何的学者〕表示一句学术嘲讽。conformal在这里不是合适的东西。因为反而会把密度最高的地方的像素密度压低。不过也许他后来有什么好想法了。反正到时候我们好好科研一波」「然后我希望是snap to pixel的，你觉得是corner还是center」
- **Opus 的看法**：
  - **保角为什么不对**：保角展开只保角度、不管面积，伸出去的部分（手指、鼻子、发梢）会被缩得很小——正好是最需要细节的地方像素最少。我们要的目标是「按密度分面积」：先定每块该有多少像素（密度），再让展开尽量照这个面积来，角度歪一点可以接受。近亲（Opus 记得的，没核）：「尽量刚性」展开（2008，角度和面积一起顾）、Blender 新版的「最小拉伸」展开（好像是 4.3 加的）、带锥点 / 切缝来减变形的做法。拉直那一路则两样都不是——它要的是对齐整数格。真做时 Opus 调研一波。
  - **吸附到像素：推荐角，不是中心**。理由：
    1. 像素 i 占的是 [i, i+1) 这一格，**角 = 整数坐标**。UV 点落在角上，岛的边正好是像素边，每个像素要么整个在岛里、要么整个在外；画像素画时像素的边和模型的边对齐（picoCAD 那种干净）。落在中心（i + 0.5），岛的边会把边上一排像素劈成两半，最近邻采样时边上那排只露半格。
    2. 上一轮定了 UV 存像素坐标：落在角上 = 存的就是整数，没有小数误差。
    3. **中心只在一种情况用**：一个面整个缩成一个点、只取一个颜色（低模常见的「调色板贴图」：每个面的 UV 全挤到调色板某一格的中心）。那时点要落在中心，免得采到隔壁颜色。
  - 所以：铺画的岛 → 角；「这个面就一个颜色」 → 那一格的中心。

## 10-30 夜 · 第五轮：别的行当怎么对付「极点」；不用 UV 的做法；Nanite
- **user 原话**：「继续聊〔科研那边，略〕，学术或者数值相对论碰到这种带pole的脏拓扑怎么办？还是其实就是不用贴图（数组）？或者它在图形学就是gaussian splatting和nanite？nanite是不是比较接近我的理念只不过没人用它做过low rez?」
- **Opus（科普 + 看法，没拍）**：
  - **极点去不掉，只能选放哪**：闭合的网格，各顶点的「角亏」（360° 减去围着它的角之和）加起来恒等于 720°（球那种拓扑；离散的高斯—博内）。展平时这些弯曲必须有个去处：摊开（= 拉伸变形）或集中到切缝 / 锥点。**低模的弯曲只住在顶点上**：胳膊、腿、裙子那一圈圈四边形带上的点，角之和接近 360°（几乎是可展开的平的），所以拉直几乎不变形；角亏大的地方（极点、帽子顶、分叉）就是缝和锥点该去的地方。「脏拓扑」其实是弯曲集中的地方。
  - **物理 / 数值计算那边**：① **地图册**（流形 = 多张互相重叠的坐标片 + 片之间的换算）——贴图的「atlas」这个词就是从这来的，UV 岛 = 坐标片、缝 = 换算。数值相对论用多片网格（立方体投到球面的六片、阴阳两片）躲开经纬网格的两极；气候模型也用立方球。② **不用数组**：谱方法用球谐函数的系数表示场，基函数处处光滑，两极不特殊（相对论里多块谱方法的代码就这么做）。③ **等面积像素**：天文用的 HEALPix 把球切成面积全相等的像素——正好是「密度」那个目标，和保角相反。④ 真正的奇点（黑洞里面）是挖掉不算（excision）或特殊处理（puncture）——有点像我们留着不管的孤儿。
  - **图形学里「不用 UV」的做法**：迪士尼的 Ptex（每张面自带一小张图，完全不展开，密度可以按面给）；网格颜色（颜色存在点 / 边 / 面的细分格上）；顶点色；三维的哈希格 / 体素；高斯泼溅（外观存在空间里的一团团高斯上，没有面也没有 UV）。Ptex 最接近「用户不碰 UV」，但游戏引擎和 glTF 不吃它——所以我们的做法相当于「里面像 Ptex 一样不用管，导出时烘成一张图集」。
  - **Nanite**：管的是几何不是贴图——把网格切成一百来个三角的小簇、按层级挑，让屏幕上一个三角大约一个像素；贴图照样用普通 UV + 虚拟贴图（按屏幕需要只载入用得到的那几页）。和 user 理念像的地方 = **细节跟着屏幕像素走**（「统一像素密度会死！远山vs手里的精致小刀」）。低分辨率：原理上把屏幕设成 160×144，它就会自动挑很粗的簇——但那是「误差最小的模糊几何」，不是设计过的低模刻面；低模的美是人定的，不是误差函数定的。有没有人拿它做过低分辨率，Opus 不知道。贴图那边对应 Nanite 的是虚拟贴图，再往前是 id 的 MegaTexture（Rage，2011：整个世界每一寸都是独一份的画，引擎自动管载入）——那才更接近「每个原子独一份 + 自动管理」。
