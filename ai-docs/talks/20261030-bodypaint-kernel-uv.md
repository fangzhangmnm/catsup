# 讨论：贴图内核搬家 + UV 像素对齐 + 换 UV 无损

> created 20261030 by Claude Opus 5.5 · as-of v0.18.19
> 状态：**拍了**：不结婚直接生孩子；整个画画内核搬过来、改成适合 CatsUp 的（不是 WeebPaint 的 256 池）、接上撤销；UV = 像素对齐；**换 UV 时贴图无损搬过去，第一天就保证**。**没拍**：「无损」靠什么保证（下面 Opus 的读法）。
> 相关：素材稿 `../20261030-marriage-bodypaint-stash.md`（给 Fable 出设计稿用；它 §1 里 Opus 早先「只拷无状态的算法」那条已被这轮更正）；方向稿 `../20261024-design-weebpaint-marriage-bodypaint.md`。

## 10-30 晚 · 开题
- **user 原话**：「贴图关键是要把不结婚直接生孩子，整个内核要搬家抄袭过去，还要做成适合catsup的而不是256池，然后undo也要接上」「uv就是我说的像素对齐，然后换uv的适合贴图无损搬过去。这个第一天就要保证」
- **Opus 核的现状**：WeebPaint 的画布切成 256×256 的小块，放在一个 256 MB 的显存池里，按文档坐标排。CatsUp 要的是每一层贴图有自己的 UV 和分辨率（user 10-24「每个layer有独立的分辨率和uv」）。CatsUp 的撤销是部件注册表（每种东西登记自己的撤销部件，共用 128 MB 预算），渲染这边有「显存一本账」那条待办（素材稿）。
- **Opus 的看法**：
  - **更正素材稿 §1**：Opus 早先说「只拷无状态的算法，不拷 WeebPaint 的文档 / 图层 / 存储」。user 这轮定的是整个内核搬家抄过来，再改成适合 CatsUp。读法：笔刷、混合、选区、变换、小块存储这些整体抄过来；「文档 = 一张大画布」那一层换成「一层 = 一张贴图（自己的 UV + 分辨率）」；显存不再自己开一个 256 MB 的池，并进 CatsUp 的一本账；撤销 = 画画登记一个自己的撤销部件（存改过的小块），和建模共用预算。每个抄过来的文件记上「从 WeebPaint 哪个版本的哪个文件」。
  - **「换 UV 无损」只能靠结构保证，不能靠重采样**：贴图像素从一套 UV 搬到另一套，形状或大小一变就得重采样，按采样定理就不可能逐像素无损。能保证的有两条：
    1. **每层留着自己的 UV**（user 10-24 的设计本来就是这样）：模型换 UV，旧的层不动，像素一个不改，显示时照旧按它自己的 UV 贴。只有人主动「合并图层 / 烘焙」才重采样，而且要说出来。
    2. **岛只是整像素平移、转 90°、镜像**：这几种搬法逐字节无损，可以直接改像素位置，不留旧 UV。
  - **第一天的守卫（提案）**：换 UV → 换回去，像素逐字节一样；换 UV 后渲染出来的样子和换之前逐像素一样（第 1 条的情况）。
  - **改拓扑时**：面没了的那部分旧层像素照样留着（孤儿），不偷偷删；面的身份跟着血缘传（同 GUID 那批）。
  - **分工**：搬家和改造 Opus 做（图形学）；层的 UV 身份、撤销部件、显存一本账的契约归 Fable。

## 10-30 晚 · 第二轮：一套 UV、打包不旋转、只平移、像素不变
- **user 原话**：「平移不用重采样，我现在的方案是有一个不依赖多重uv的。多重uv先set inactive 算作脑洞罢了。关键是其实现代硬件无所谓power of two吧。然后uv有unwrapping和atlas packing，只要我们atlas packing不旋转。那么加了物件就是加一点canvas size就可以了。所以甚至用不到多重UV。只要平移就不是从采样，然后拓扑变了多一个面也许就看看能不能新的atlas然后看看我们的绘制和mipmap算法能不能把缝给接住。我们自己画mipmap」「反正人类不这么做是因为rebake繁琐。我们这个全量自动化，只要保证pixel不变就行了」
- **Opus**：
  - 同意，比第一轮 Opus 说的「每层留自己的 UV」简单：一套 UV，打包只平移不旋转，换布局 = 整像素平移 = 逐字节无损，加物件 = 画布加大一点。**多重 UV 降成脑洞、不活跃**（第一轮那条，和 10-24 方向稿的「每层独立 UV」一起）。
  - **UV 存像素坐标**：glTF 里 UV 是 0–1 的比例，画布一加大，所有数都要重算（像素没动，数字全变）。所以文件里和内存里 UV 存「第几个像素」，只在渲染和导出时除以画布尺寸。和「数据存 SI，显示换」同一个形状，加画布 = 零改写。
  - **UV 一旦画上东西就是数据**：自动展开是现算的；可是一旦有像素画在上面，UV 就得存下来、不再重算，不然展开算法一改进像素就对不上了。和 10-30「想保住现算结果 = 烘成数据」是同一条。
  - **非 2 的幂**：WebGL2 和现代显卡完全支持（mipmap、平铺都行）。导给真老的机器（要 2 的幂）时，导出往右下补空白到 2 的幂；补像素不改已有的，仍然无损。
  - **拓扑变了、多一个面**：已经画过的面的 UV 钉死，只给新面展开、边贴着旧岛（钉点展开，常见算法都支持）；贴不下或会重叠，就新开一个小岛、多一条缝。只挪顶点不改拓扑时像素不变，但模型上看到的画会被拉伸——这是「像素不变」的代价，Blender 也一样。
  - **缝和自己画 mipmap**：岛和岛之间留一圈边，里面填「缝对面那一侧的颜色」（沿缝延展，不是简单往外扩），双线性采样和低级 mipmap 才不会在缝上露底色。自己画 mipmap = 每个岛在自己的范围里缩、再沿缝填边，不让邻居岛的颜色渗进来。
  - **整理贴图**：只平移的重新打包也无损 → 可以有一个「整理贴图」动词，随时把空洞挤掉，像素一个不变。
  - **状态**：方向拍了（一套 UV、不旋转、只平移、像素不变、自己画 mipmap、多重 UV 不活跃）；上面这些细节 = Opus 的读法，没拍。
- **Opus 看了小红帽 pose1 的 UV**（user「你看一下uv」；文件 = user 10-29 传的 glb，没进仓）：一张 256×256 的图集、一个材质；采样是线性 + mipmap（不是最近邻：这只小红帽是手绘柔和风，不是严格像素风）；约 15 个岛；863 条 UV 边里 438 条横平竖直（51%）。头发、裙子、袖子、兜帽被拉成矩形或等宽的列（裙子 4 列一样宽），脸是正面投影、没拉直（留着形状画眼睛）；颜色都画出岛外一圈（手工留的边）；岛的边不在像素格上（比如裙子左边在第 134.25 像素）；白色那块里有一小团挤在一起的小三角。拉直接着记在 `20261030-pixel-uv-straighten.md`。

## 10-30 夜 · 第三轮：小红帽的斩杀线
- **user 原话**：「小红帽的斩杀线是我需要第三方图或者我自己画的眼睛套索复制之后screen space拍到脸上然后还需要调几次位置，然后最好有weebpaint级别的笔把一些糊的地方描干净」「我当时是blender和procreate之间导入了很多遍然后用procreate那个没有像素精确，有bug的3d绘制做的。你知道ipad上传文件有多痛苦吗？所以只有一个小红帽」
- **Opus 的读法**：斩杀线 = 一条完整的动作链，五步：
  1. **拿到眼睛**：第三方的图，或自己画的。进门：参考窗（已有）/ 素材规划里留了接口的「扒取窗口」/ 导入图片 / 粘贴；iPad 上从「照片」「文件」拿、或分屏拖进来（Edge 里能不能拖要真机验）。
  2. **套索复制**：WeebPaint 的套索（选区笔）。
  3. **屏幕空间拍到脸上**：复制出来的那块浮在 3D 视图上，落下时每个贴图像素算自己投到屏幕哪、去浮层上取颜色（6 月定的「贴图像素去屏幕上取」）。
  4. **调几次位置**：浮着的时候能挪 / 转 / 缩，模型上实时预演；落定 = 烘进像素、一步撤销。WeebPaint 的浮动变换就是这个。
  5. **WeebPaint 级的笔描干净**：内核搬家过来的笔刷，在模型上画或在 UV 平面上画。
- **两处要讨论（没拍）**：
  - 浮着的时候转视角：浮层贴着屏幕（Blender 的「模板」那样，转了视角浮层不动、投到模型的位置变）还是贴着模型表面（转视角它跟着脸走）？
  - 拍在哪：3D 视图里按屏幕投影拍（直观，但会重采样），还是在 UV 平面里直接贴到脸那个岛上（像素精确，适合像素风的眼睛）。两种可以都要，用同一个浮动变换。
- **一个巧合**：小红帽的脸那个岛本来就是正面投影（第二轮实测），从正面拍眼睛几乎是一比一，几乎不变形——当年 Procreate 能凑合用大概也是因为这个。别的角度、弯的部位（脖子、袖口）才会真拉伸。
- **离斩杀线还差的地基**（Opus 核的现状）：网格体还没有 UV 那一列属性；导入 glb 时材质 / UV / 贴图全丢（Tron 账本 T90，「最小导入器」）；贴图层数据 + 撤销部件 + 显示；内核搬家（笔刷、套索、浮动变换）；屏幕投影落笔。顺序大概就是这个。
- **为什么值**：user 当时在 Blender 和 Procreate 之间来回导入很多遍、用的是没有像素精确还有 bug 的 3D 绘制，iPad 传文件又痛苦，所以只做了一个小红帽。同一个 app 里画完 = 「结婚」的全部意义（10-24「我渴望的就是画贴图不切app。仅此而已」）。
