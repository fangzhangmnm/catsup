## 10-30 夜 · 开题
- **user 原话**：「klee当时我也是加了零件开新的贴图空间，最后烘培成一张大贴图的，所以可能我的思路确实是对的，可以降低你画贴图前需要定下来geometry的压力。然后你能get吧就是我在ai时代之前的疼点就是没法进下一步因为are you sure you want to lock the design. 然后之前小月相和要不要在catsup里面玩也都是为了能先跑起来，再回来改，回到pipeline的任何一步，敏捷开发不是waterfall」
- **Opus 的看法**：
  - **get 到了**：传统流程每进一步都要先「锁定上一步」——画贴图前几何定死、绑骨前贴图定死、K 动画前骨架定死；回头改 = 下游全部重做，所以人不敢往下走。Klee 那次 user 已经在用「加零件就开新的贴图空间、最后才烘成一张」绕开它；我们把「最后烘一张」自动化（打包只平移、画布加大一点、像素不变），画贴图之前就不用先锁几何。
  - **和 Blender 的解法不一样**：Blender 治「锁定」靠非破坏的修改器栈 = 存历史。我们不存历史（「历史不存在，只有被打歪的原子」），靠的是**下游的数据经得起上游改**——原子被打歪了还是好的。
  - **代价 = 每一列属性都要经得起每一种几何改动**。上游改了什么、下游怎么不坏：
    | 回去改 | 下游的东西 | 怎么不坏（Opus 的读法） |
    |---|---|---|
    | 几何（加面） | 画好的贴图 | 旧岛钉死，新面贴着旧岛展开，贴不下开新岛；画布不够就加大 |
    | 几何（挪点） | 画好的贴图 | 像素不变，模型上的画被拉伸（代价，照实说） |
    | 几何（删面） | 画好的贴图 | 那块像素留着当孤儿，不偷偷删 |
    | 几何（加点 / 加面） | 蒙皮权重、区域标签 | 新点的权重从邻居插值；区域标签和材质一样跟着面的血缘走 |
    | 骨架（加骨头、换精度） | 动画 | clip 按 GUID 指骨头；缺了的骨头显示「缺了」，不崩 |
    | 骨架（挪骨头、调朝向） | 动画 | 动画存在「标准化的人形姿势」里，骨架微调不改动作（VRM 1.0 好像就是这么规定 T 姿势的，Opus 记得，没核） |
    | 比例（腿变长） | 动画 | 只存 FK 的话脚会浮 / 会滑；存了「脚钉在这里」这类目标就能重解贴地（IK 那份的中间做法多了一条理由） |
    | 贴图 | —— | 下游没东西依赖它 |
  - **架构上的推论（给 Fable 的代码架构）**：现在 CatsUp 里属性怎么跟着走是分散写的（面材质按事件血缘继承、边手标在挤出时带过去……每个功能各写各的）。要「随时回去改」不变成屎山，需要**一层统一的属性**：每一列属性登记自己挂在哪（点 / 边 / 面 / 面角）和每种改动下怎么跟（照抄父亲 / 按权重插值 / 标「缺了」/ 丢）；几何算子只报「这个新东西是从哪几个旧东西来的、各占多少」，所有列由属性层一次处理完。加一种新属性 = 登记一行，不碰算子。Blender 也是这个形状（属性挂在域上 + 每个算子按规则插值）。
  - **披露**：上游一改让下游坏了一点（孤儿像素、缺了的骨头、被拉伸的画），说出来、给去处，不静默（家规「默认 + 披露」）。

## 10-30 夜 · 第二轮：关键是没有心理负担
- **user 原话**：「流程不锁定的关键是回到上一个pipeline没有心理负担」
- **Opus 的读法**：心理负担来自两件事——怕下游白做了、不知道这一改会坏掉什么。所以光「数据经得起改」还不够，还要三条：
  1. **改之前就看得到代价**：回到上一步动手时，预演里直接显示会碰到下游的什么（「这一刀会让脸上那块画拉伸」「这根骨头删了，2 段动作里它会显示缺了」），不是改完才发现。
  2. **改完一步撤回**：回上一步的每个改动都是一步撤销，撤回去下游原样（撤销栈本来就管这个，贴图 / 权重 / 动作都要登记进撤销部件）。
  3. **下游永远不被静默毁掉**：坏了的留着当孤儿、标「缺了」，等人处理；不偷偷删、不偷偷重算。
- **状态**：理念拍了；三条是 Opus 的读法，没拍。
