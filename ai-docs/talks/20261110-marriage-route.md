- **这轮 user 定了的**（原话里直接有的）：
  - 先规划整个结婚纪元，再动手。
  - 路子 = 不结婚直接生小孩 = 抄画画那边的代码，并且保证可移植。
  - 这一轮的毕业条件 = 能在模型上画贴图，最基本的，手感不差。
  - 要求 = 加新功能的复杂度不随已有功能涨，最好越后面越方便；衡量办法之一 = 加一个功能要读的代码量不越来越多。

- **Fable 读了两边代码之后的看法**（详见设计稿）：
  - 画画的后端已经自成一体（约 1.7 万行，只依赖自己和四个 vendor 库，几乎零界面接口）；工具引擎约四千行也零界面，只是文件还在界面那一层。
  - 成本不涨靠一条规矩：工具只认识一块平面（笔画台），三维只写「推」「拉」两个口。
  - 两边用逐字节同一份内核（正本在画画仓，三维机械拷贝）。这条改了 10-30「独立的小孩、可以冷落」的说法 → 要 user 拍。

## 11-10 深夜 · 第四轮：笔和橡皮是不是该按空间做
- **user 原话**（语音转的字，照抄）：「你再帮我想一下笔，就我们最核心的笔和橡皮，因为我之前只考虑了视图和 UV，没有考虑空间。会不会空间其实才是最优的？也可以解决，就是说近垂直的表面会一笔画很大，这是视图的问题。会不会我们一开始就按空间来做才是最好的？那这样的话就不能用我那篇二零一二年论文里面的思路了，得好好想想。但可能有专门的好的办法。」
- **Fable 的答（设计稿第四⅞节，提案，没拍）**：
  - 是，一开始就按空间做。一支笔是三件事：手怎么走在屏幕上（手感代码不动）；每个笔尖的中心由屏幕打射线落到模型上；笔尖盖住多大在空间里量（每个贴图像素按自己在模型上的位置到中心的距离算浓淡）。中心线和按视图做一样，变的只是笔尖在表面上占多大。
  - 2012 的思路还在：仍然遍历贴图像素、反查来源；来源从屏幕上的笔画图换成空间里的笔。笔尖是公式不是图，所以没有重采样。
  - 好处：斜面不拉长；不用判断看不看得见（第一笔不再需要那一套）；没有深度打架；任何缩放下按贴图分辨率锐利；可以只吃和落笔处连着的面；对称、VR、多物件都顺。丢掉的只有「屏幕上处处一样粗」。
  - 专门的办法：从落点那张面沿共用边找球碰得到的面；对每一对「笔尖 × 面」在贴图上画一个小矩形，像素用这张面自己的公式算空间位置。
  - 核过的事实：画画内核的手感数学全在 CPU 上出笔尖列表（`backend/gl/gl-stamp.ts` 头注释「手感红线安全」），显卡只算逐像素的浓淡和累积；所以只换后一半。显卡接口不用加东西。
- **user 拍了**（原话）：「还是遍历贴图像素、反查来源。只是来源从「屏幕上那张笔画图」换成了「空间里那支笔」。 赞，你是天才，拍，这个是canonical」。按空间做定了，是正本。
- **还开着（不挡开工，Fable 先按建议做，做出来 user 试了再定）**：一笔之内大小在物体上不变还是每个笔尖按屏幕重算；拐角另一边吃不吃；只吃连着的面默认开不开；斜处线变细是不是要的手感（要试）。

## 11-10 深夜 · 第八轮：笔按真实笔刷的物理来想

- **Fable 的读法（设计稿第四⅞节末；没拍）**：一支笔三件事——碰（笔尖是空间里有形状有软硬的东西，贴图像素问「我陷进去多深」）、给（带多少颜料、碰多实）、留（颜料在表面上流和干）。球 = 最简单的「碰」。扫漆换「碰」和「给」，渍洗换「留」（最简单的按「这里凹多深」算，不真模拟流动），刷毛 = 很多根小笔尖。第一天留口（每一下交出若干有形状的小东西；贴图像素能查位置、朝向、凸不凸、凹多深；三段规则分开），实现只做球。真的流动和刷毛弯曲是模拟，不在这一轮；流动到时候也要过「铺法换掉，结果不变」。

## 11-10 深夜 · 第十轮：薄层之后内核能不能原样用；选区是重灾区
- **user 原话**：「（引：得到的还是贴图格子里的一张薄层，之后合进图层、橡皮、锁透明、选区、撤销、边画边看，全用内核现成的。）think critically. 选区可能是重灾区」
- **Fable 查的结果（设计稿第四⅞节「薄层之后」；没拍）**：
  - 内核把画布当一整张连着的图，贴图是一块块拼的。操作分两种：只看一个像素的安全；要看旁边像素的在贴图上一用就错。
  - 安全：薄层合进图层、橡皮、锁透明、混合、透明度、图层结构、撤销、边画边看；选区的存、挡、加减交反、填、清；逐像素调色。
  - 不能用内核的：选区怎么圈（多边形栅格）、蚂蚁线（会在缝上描线）、羽化 / 扩缩 / 平滑 / 描边、魔棒 / 找连着的区域 / 线稿填色、模糊类滤镜、挪图层 / 翻转 / 旋转画布、浮层放下时的高级取样（沿整行整列预处理的那种会穿过别的块）。
  - 又查出三件：写入要多一道「画布的形状」（不然全选 / 反选再填会把贴图上的空地填脏，空地以后分给新面）；补边不存图层，只在合成图和导出图上做；在贴图上做平滑取样也算找邻居，原件要先补过边。
  - 守卫：内核每个动作在一张表里标「只看一个像素 / 看邻居」，三维这边默认只能调前一种。

- **user 原话**：

  - 「（引 Fable：只认一套三角形……）我们3d rendering的话是四边形是有变形的啊，这样不就不和opengl一直吗？」（「一直」= 一致，语音）

- **Fable 的答（设计稿第四⅞节三小节；没拍）**：
  - 和显卡一致：显卡只画三角形，四边形上那道折是它真画出来的；我们照它用同一套三角形、同样的插值，所以一致。不一致的反而是把四边形当一整张光滑面算。准确的规矩 =「只认最后显示出来的那套三角形」。面全是平的时怎么切都一样，最干净（硬表面体）。
  - 查出一个没定的问题：切法现在按空间形状现算，挪点时不平四边形的对角线会跳，画过的面里的画会跟着跳 → 建议画过的面切法钉死、和贴图坐标一起存。**等 user 拍。**

  - 速度（数字都是估的）：一帧七件事；贵的四处 = 射线（相机停下来时按屏幕分格）、长笔画（定型的只画一次）、大软笔（只画碰到的三角形的外框，要真机量）、补边和缩小图（只做改到的那块）；落笔不卡（提前建好）；抬笔读回按块分开；跟不上时宁可慢半拍也不画假的预演。
