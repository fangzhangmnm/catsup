- **这轮 user 定了的**（原话里直接有的）：
  - 先规划整个结婚纪元，再动手。
  - 路子 = 不结婚直接生小孩 = 抄画画那边的代码，并且保证可移植。
  - 这一轮的毕业条件 = 能在模型上画贴图，最基本的，手感不差。
  - 要求 = 加新功能的复杂度不随已有功能涨，最好越后面越方便；衡量办法之一 = 加一个功能要读的代码量不越来越多。

- **Fable 读了两边代码之后的看法**（详见设计稿）：
  - 画画的后端已经自成一体（约 1.7 万行，只依赖自己和四个 vendor 库，几乎零界面接口）；工具引擎约四千行也零界面，只是文件还在界面那一层。
  - 成本不涨靠一条规矩：工具只认识一块平面（笔画台），三维只写「推」「拉」两个口。
  - 两边用逐字节同一份内核（正本在画画仓，三维机械拷贝）。这条改了 10-30「独立的小孩、可以冷落」的说法 → 要 user 拍。

## 11-10 深夜 · 第四轮：笔和橡皮是不是该按空间做
- **user 原话**（语音转的字，照抄）：「你再帮我想一下笔，就我们最核心的笔和橡皮，因为我之前只考虑了视图和 UV，没有考虑空间。会不会空间其实才是最优的？也可以解决，就是说近垂直的表面会一笔画很大，这是视图的问题。会不会我们一开始就按空间来做才是最好的？那这样的话就不能用我那篇二零一二年论文里面的思路了，得好好想想。但可能有专门的好的办法。」
- **Fable 的答（设计稿第四⅞节，提案，没拍）**：
  - 是，一开始就按空间做。一支笔是三件事：手怎么走在屏幕上（手感代码不动）；每个笔尖的中心由屏幕打射线落到模型上；笔尖盖住多大在空间里量（每个贴图像素按自己在模型上的位置到中心的距离算浓淡）。中心线和按视图做一样，变的只是笔尖在表面上占多大。
  - 2012 的思路还在：仍然遍历贴图像素、反查来源；来源从屏幕上的笔画图换成空间里的笔。笔尖是公式不是图，所以没有重采样。
  - 好处：斜面不拉长；不用判断看不看得见（第一笔不再需要那一套）；没有深度打架；任何缩放下按贴图分辨率锐利；可以只吃和落笔处连着的面；对称、VR、多物件都顺。丢掉的只有「屏幕上处处一样粗」。
  - 专门的办法：从落点那张面沿共用边找球碰得到的面；对每一对「笔尖 × 面」在贴图上画一个小矩形，像素用这张面自己的公式算空间位置。
  - 核过的事实：画画内核的手感数学全在 CPU 上出笔尖列表（`backend/gl/gl-stamp.ts` 头注释「手感红线安全」），显卡只算逐像素的浓淡和累积；所以只换后一半。显卡接口不用加东西。
- **user 拍了**（原话）：「还是遍历贴图像素、反查来源。只是来源从「屏幕上那张笔画图」换成了「空间里那支笔」。 赞，你是天才，拍，这个是canonical」。按空间做定了，是正本。

## 第二十四轮（11-10 夜）：角上的数、按三角形插值，是不是图形学里的标准做法

user：「你这个三角形，角点，这个是标准的图形学里面的做法吗」

Fable 的回答（函数名和选项名凭记忆，没有现查）：

- **和标准一样的**：数存在面的角上（Blender 的 loop / face corner，USD 和 OpenSubdiv 的 face-varying，OBJ 的 `f v/vt/vn`，文献里的 wedge）；切面时新角的值按位置在旧面里插值（Blender `BM_loop_interp_from_face`）；细分时贴图坐标走直线不跟着平滑（OpenSubdiv 的 linear face-varying，Blender「UV 平滑 = 无」）；贴图每格记属于哪个三角形、位置现算（烘焙器在贴图坐标空间里光栅化出编号图，块边往外多归几格 = padding）。
- **我们自己的取舍**：
  1. 插值在显示用的那套三角形上做。Blender 对多边形用广义重心坐标（mean value coordinates）。平的、没拉伸的面上两者相同；不平或拉伸的面上有差别，而且这种面切开后面里面仍可能轻微变形，哪种算法都避不开。
  2. 「没有值」用 NaN。Blender 每个角永远有坐标。
  3. 并面时两边对不上就整张清空并说出来。Blender 让每个角留着原来的坐标、不提示。等铺法能让相邻的面在画布上也相邻，就和别人一样留得住。
- 「每个操作必须交代来历」是工程纪律，不是理论上的区别。

## 第三十九轮（11-11 下午）：空隙能不能减、自动展开 0.1

**user 原话**

**查到的现状**

- 归属表：每格归最近的那块画布多边形，块外面 2 格以内取块边上的颜色，再远没人要；没画过的地方是材质底色。
- 铺法：一张面一块，留 4 格。

**Fable 的说法（不是 user 说的）**
- 空隙为谁留：放大最近邻只需要块外 1 格填着边上的颜色（防浮点误差）；mipmap 每降一级一格变 2 × 2，隔 g 格大约保 log2(g) 级；我们串的只会是隔壁那块的颜色或底色，没有黑边。所以能减：留的格数 = 画布边长 ÷ 256（128、256 留 1，512 留 2，1024 留 4 和现在一样，2048 留 8）。往外填色的范围保持 2 格，和铺的空隙分开，不改文件格式。
- 大头不是空隙，是一张面一块。展开的几种做法：一张面一块（Lightmap Pack，零拉伸、最浪费）；按朝向连成片再压平（Smart UV Project，简单、片少、斜面被压短）；沿边摊开（纸模，零拉伸但弯的地方成花瓣）；标缝解方程（LSCM / xatlas，活大）；从视角投影（画脸用，单子上已有）。
- 0.1 做「按朝向连成片」：和种子面夹角小于 45° 的连着的面归一片，朝种子的方向压平；不许重叠；只有一张面的片和旧铺法逐位相同。每张面仍有自己的公式，所以切面、镜像的继承规则不用动；片里面相邻的面共边，那条边不再是接缝。
- 粗算：小红帽 291 张面在 256 见方，现在每张面约 60 格，新铺法约 140 格；128 见方从几格到三十来格。真数让小弟量。
