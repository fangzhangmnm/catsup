- **这轮 user 定了的**（原话里直接有的）：
  - 先规划整个结婚纪元，再动手。
  - 路子 = 不结婚直接生小孩 = 抄画画那边的代码，并且保证可移植。
  - 这一轮的毕业条件 = 能在模型上画贴图，最基本的，手感不差。
  - 要求 = 加新功能的复杂度不随已有功能涨，最好越后面越方便；衡量办法之一 = 加一个功能要读的代码量不越来越多。

- **Fable 读了两边代码之后的看法**（详见设计稿）：
  - 画画的后端已经自成一体（约 1.7 万行，只依赖自己和四个 vendor 库，几乎零界面接口）；工具引擎约四千行也零界面，只是文件还在界面那一层。
  - 成本不涨靠一条规矩：工具只认识一块平面（笔画台），三维只写「推」「拉」两个口。
  - 两边用逐字节同一份内核（正本在画画仓，三维机械拷贝）。这条改了 10-30「独立的小孩、可以冷落」的说法 → 要 user 拍。

## 11-10 深夜 · 第四轮：笔和橡皮是不是该按空间做
- **user 原话**（语音转的字，照抄）：「你再帮我想一下笔，就我们最核心的笔和橡皮，因为我之前只考虑了视图和 UV，没有考虑空间。会不会空间其实才是最优的？也可以解决，就是说近垂直的表面会一笔画很大，这是视图的问题。会不会我们一开始就按空间来做才是最好的？那这样的话就不能用我那篇二零一二年论文里面的思路了，得好好想想。但可能有专门的好的办法。」
- **Fable 的答（设计稿第四⅞节，提案，没拍）**：
  - 是，一开始就按空间做。一支笔是三件事：手怎么走在屏幕上（手感代码不动）；每个笔尖的中心由屏幕打射线落到模型上；笔尖盖住多大在空间里量（每个贴图像素按自己在模型上的位置到中心的距离算浓淡）。中心线和按视图做一样，变的只是笔尖在表面上占多大。
  - 2012 的思路还在：仍然遍历贴图像素、反查来源；来源从屏幕上的笔画图换成空间里的笔。笔尖是公式不是图，所以没有重采样。
  - 好处：斜面不拉长；不用判断看不看得见（第一笔不再需要那一套）；没有深度打架；任何缩放下按贴图分辨率锐利；可以只吃和落笔处连着的面；对称、VR、多物件都顺。丢掉的只有「屏幕上处处一样粗」。
  - 专门的办法：从落点那张面沿共用边找球碰得到的面；对每一对「笔尖 × 面」在贴图上画一个小矩形，像素用这张面自己的公式算空间位置。
  - 核过的事实：画画内核的手感数学全在 CPU 上出笔尖列表（`backend/gl/gl-stamp.ts` 头注释「手感红线安全」），显卡只算逐像素的浓淡和累积；所以只换后一半。显卡接口不用加东西。
- **user 拍了**（原话）：「还是遍历贴图像素、反查来源。只是来源从「屏幕上那张笔画图」换成了「空间里那支笔」。 赞，你是天才，拍，这个是canonical」。按空间做定了，是正本。

## 第二十四轮（11-10 夜）：角上的数、按三角形插值，是不是图形学里的标准做法

user：「你这个三角形，角点，这个是标准的图形学里面的做法吗」

Fable 的回答（函数名和选项名凭记忆，没有现查）：

- **和标准一样的**：数存在面的角上（Blender 的 loop / face corner，USD 和 OpenSubdiv 的 face-varying，OBJ 的 `f v/vt/vn`，文献里的 wedge）；切面时新角的值按位置在旧面里插值（Blender `BM_loop_interp_from_face`）；细分时贴图坐标走直线不跟着平滑（OpenSubdiv 的 linear face-varying，Blender「UV 平滑 = 无」）；贴图每格记属于哪个三角形、位置现算（烘焙器在贴图坐标空间里光栅化出编号图，块边往外多归几格 = padding）。
- **我们自己的取舍**：
  1. 插值在显示用的那套三角形上做。Blender 对多边形用广义重心坐标（mean value coordinates）。平的、没拉伸的面上两者相同；不平或拉伸的面上有差别，而且这种面切开后面里面仍可能轻微变形，哪种算法都避不开。
  2. 「没有值」用 NaN。Blender 每个角永远有坐标。
  3. 并面时两边对不上就整张清空并说出来。Blender 让每个角留着原来的坐标、不提示。等铺法能让相邻的面在画布上也相邻，就和别人一样留得住。
- 「每个操作必须交代来历」是工程纪律，不是理论上的区别。

## 第五十一轮（11-12 上午）：「低配」是一个看法，不是硬指标；Fable 批判着想了一遍

> 记的人：Claude Fable 5.2。

**起因**：第五十轮 Fable 把 user 的话记成了「2048 是必量的一档」，回复里也说「都必量」。

**user 原话**：「也不是非说必须吧，而是说就是对于认真的，就不是像我们这种业余做一些比较轻量级，而是认真的来说，我觉得万面模型和两 K 贴图算是低配。 你批判性的想一下是不是这样」

**Fable 的回答（四条；user 还没回应，下面都只是 Fable 的看法）**：

1. 「2048 的贴图算低配」这一半站得住：做电脑和主机游戏的资料里，一般的东西用 2048、主角用 4096。要打折的是手绘风、手机游戏、Quest 上的 VRChat 形象这几类，1024 到 2048 就是正常配置；这几类离「直接在模型上画」的软件最近。
2. 「一万面」要看说的是什么：一个角色，在电脑和主机上一万面是低的那一头；在手机上按通用的指南已经偏高；一件道具，一万面算多；一整个场景，一万面很小。靠手一张一张面搭的单个物件很少过几千面，上万的面一般来自导入、细分、同一个组件摆很多份。
3. 两个数不该绑成一档：贴图多大取决于表面多大、要多细，跟面数没关系。在三维软件里它们压的是两条路：画布大小压画画那条路（每画一下、抬笔），面数压三维那条路（点选、把笔落到面上）。量的时候分开量。
4. 更能区分业余和认真的是「同时有多少张」：认真做的一个角色通常好几套贴图，每套除了颜色还有法线、粗糙度，再乘上图层。「一张 2048 画得顺」只是一半，另一半是已经放到「高中」那一轮的「很多张 2048 同时在」。

**核过的数（11-12 查网页）**：

- VRChat 电脑版：三角形不超过 32,000 是最好一档，32,001 到 70,000 是第二档，超过 70,000 直接掉到最差一档（官方创作者文档 https://creators.vrchat.com/avatars/avatar-performance-ranking-system ）。Quest 版：7,500 / 10,000 / 15,000 / 20,000 四档（VRChat 维基 https://wiki.vrchat.com/wiki/Avatar_Performance_Ranking ）。

**查到的事实**：

- 现在只有网格体能画。硬表面不能画，11-11 第四十轮答过：面没有稳定的来历。
- 平铺的画和自由的图是按材质铺的，硬表面的面也能涂（v0.19.61 的样本就是盒子上的两张面）。
- 网格体的画是跟着部件的定义走的，摆出来的每一份共用同一张画。复用这件事网格体已经有。
- Elf Haven 烘好的那份 glb：一个物件、35795 个三角形、一张 1024² 的图，颜色和光烘在一起，图只用了 46%，每个单位长度约 180 个像素。它没有复用，也没有单独的光照层：是成品的样子，不是制作时的样子。原件 .blend 这台机器读不了（没有 Blender），所以「分部件、有复用」在 Elf Haven 上没法核。

**统筹批判着想的（都是统筹的看法，没验证，user 没表态）**：

1. 「硬表面的画」其实是三件事，值和代价差得很远：
   - 复用的那一层：平铺的画已经能涂上去。缺的是在一张面上把它挪、转、缩。
   - 低分辨率的光照：它归「摆在哪」，不归材质、也不归部件（同一个部件摆在两处，光不一样）。现在的文件格式里没有这个位置。它有一个好处：分辨率低，形状改了可以按空间位置重新采样着搬，不用追面的来历。所以硬表面上最先做得成的「独一份」其实是它。但烘光要有一个算光的东西。
   - 独一份地画（涂鸦、脏迹、招牌）：难在硬表面的面一画线就裂、一擦线就合、一推拉就长大。
2. 一个候选做法：**画住在面所在的那张平面上，不住在面上**，面只是平面上的一个窗口。面裂、合、长大都不用搬画；画画内核的图层本来就是按需要才占格子的。它正好是 11-11 说的墙上涂鸦。代价：这是另一套结构（不是排法加贴图坐标）；弯的硬表面（很多小平面拼的圆柱）不适用，那种该走网格体加接缝；导出给别的软件时要另烘一张；面整体挪动、转动时画要跟着平面走，还是要有平面的来历。只是候选。
3. 这三件合起来，一张面的样子就是一摞层：平铺的底、独一份的层、光照层，各有各的铺法。这就是 user 说的比标准材质 uber 得多的那个东西。所以硬表面的画不该在材质设计之前单独做。
4. 顺序反了的风险，先记四条：
   - 文件格式这一头留了余地：材质的通道是一摞贴图、贴图表示什么是开放的、铺法的形状是开放的。
   - 风险在软件里的假设：「一个材质 = 一个颜色加最多一张图，画就是那张图」、画的合成图把材质的颜色烘了进去、一张画对一个材质对一个部件的一套坐标。这些在软件这一层，能重写。
   - 眼前最容易踩的是任务清单里的「材质面板第一版」：轮到它时只做看得见、能拿掉、能清理，不在这一版里定材质的结构。
   - 「排法成为独立条目、画跟着面走」是几何那一头的事，不受影响。
5. 统筹没做的：没有重读渲染实验室，也没有重读早期的材质设计。这件大，需要好好设计、来回几轮，照 user 说的先记账，等材质纪元真正开工时做。

**定下来的**：都不做，只记账。Elf Haven 加进展开贴图开发时试用的模型清单（建筑一类）。任务清单加一条「材质纪元开工前统筹过一遍渲染实验室和早期材质设计」。
