## 查到的事实（统筹读代码）

1. 物体的种类只有两种：硬表面（`brep`）、网格体（`mesh`）（`src/scene/body-kind.ts`）。一个物体（组件的定义；根也是一个）只有一个种类。2026-10-24 定的是：多种并存、明着互转、不自动转；「组件是管理方法，一个组件里面可以有 brep，也可以有别的」。
2. 带着画的面，下面这些全被同一道护栏拒（`src/scene/paint.ts paintMoveBlocked`，话是「这些面上有画：带着画的面现在还不能并进别的物件、分出去、做成唯一、复制粘贴、炸开或者转成硬表面（这个功能还没做）」）。
3. 所以 user 碰到的两处都是这道护栏，**不是因为选了全部的几何**：根有画 → 转不回硬表面（`castDefinition`）；选中带画的面「新建组件」→ 在网格体里这一步其实是把面分出去成新物件（`separateObject`），带画被拒。
4. 网格体里「新建组件」只有两条路：选的是面 = 把面分出去；选的是组件 = 包成一个新组件（`wrapInMesh`）。没有「新建一个空的子组件」。分出来、包出来的新组件，种类都是网格体。
5. 所以在画过的网格体根里想加硬表面的东西，只能绕：造一个方块 → 做成组件 → 转成硬表面。
6. 没核到：被这道护栏拒的时候，界面上那句话 user 看没看到（user 的说法是「没用」）。交小弟报。

## 统筹的批判（都是看法，user 没表态）

**眼前的麻烦是三件事叠在一起，不是一件：**

1. 没有「新建空的子组件」。最直接的缺口。
2. 画挡住了一切重组（分出去、并进来、复制、转种类）。这是「画跟着面走」那张单（施工单十八）要解的：做完之后分、并、复制都不用重画；转成硬表面 = 先问「画会丢，转不转」。
3. 种类是物体一出生就定死的属性。user 的提议针对的是这一件。

**user 的提议：空的没有种类，有了东西才有，删光变回空。统筹赞成方向，理由：**

- 种类本来是内容的性质，不是容器的性质（和 10-24 那句是一路的）。空的容器硬要有种类，是实现漏到了用户面前。现成的例子：网格体里把几个组件包成新组件，新组件其实没有自己的几何，却被塞了一个「空的网格体」当种类。
- 新文件、新组件第一下用什么工具就是什么，不用先选，也选不错。
- 删光变回空，走错了能回头。现在种类不对又有画，就卡死。

**要想清楚的边界和风险：**

- 「空」怎么算：没有面？点和线算不算？硬表面里的辅助线、参考几何算不算？子组件不该算（它是容器里的东西，不是这个物体自己的几何）——只装子组件的物体就是「纯容器」。
- 自动变种类合不合 user 的原则（自动只许拦、不静默）：空 → 有种类，是 user 第一下动作的直接结果，是明着的；删光 → 变回空，是自动的，但那时已经没有东西可丢，说一句就行。
- 挂在种类上的东西在变回空时怎么办：画、贴图坐标的表、材质槽、镜像设置、平滑默认。照「生死按引用」，画不该跟着没，成孤儿留着。
- 撤销：种类的变化要跟着撤销走。
- 文件格式：种类写在定义上（缺 = 硬表面，只在不是硬表面时写）。统筹倾向「空」不是存进去的第三个值，而是算出来的状态（没有几何就是空），这样旧版本读新文件不受影响。这是格式上的事，归统筹，和施工单十八一起排。
- **这个提议解决不了 user 最开始那个麻烦。** 画过的网格体里想加硬表面，种类已经不是空了，还是得建子组件。所以真正的问题是更大的那个：一层里能不能同时放两种内容。
  - 统筹倾向不混：两种内核守的规矩不一样（硬表面会自动合面、补面，网格体不动），混在一层里选择、工具、撤销都要分两套。
  - 替代：一个物体一个种类不变，但「在这里新建一个空的子组件、进去建模」要轻到不觉得是绕路；根想从网格体变成容器时，能把这一层的东西一步包成子组件（带画的面要能包 → 又回到施工单十八）。
- 根的特殊：根也是一个物体。根有画又想加硬表面，最自然的结果是根变成纯容器，原来的几何下沉成一个子组件。

**排法（建议，没定）：**

- 现在不动。
- 「新建空的子组件」和「空的没有种类」是一回事的两面，一起设计、一起做，可以排在施工单十八之前或之后，和它不冲突。
- 「画挡住重组」等施工单十八。
- 「一层里混两种内容」「实体种类」归远景，和材质纪元开工前那次批判性审视一起想。

## 换一个物体当根（11-13）

**统筹的想法（user 还没回应）**：

- 根和别的物体是同一种东西，只是文件里有一个指针说它是入口。它特殊在没有「摆出来的那一份」：选不中、包不进组件、挪不走、炸不开。别的物体走错了能包一层，根不能，所以会卡死。
- 缺的动作是「给根包一层」：新建一个空的物体当新的根，原来的根整个变成它下面的一个子物体，位置不动。
  - 原来的根身份（GUID）不变，面一张没搬，所以画、贴图坐标的表、镜像设置原样跟着。不用等施工单十八。
  - 不改文件格式：多一个定义、多一份摆放、入口指针换一下。
  - 是把现成的动作补全：选中几个子组件能包成新组件（`wrapInMesh`），唯独根因为选不中包不了。
- 要想清楚的：新的根是什么种类（眼下倾向硬表面，和新文件一样；「空的没有种类」做了之后就是空）；名字（新根拿文件名，原来的根另起名）；挂在根上的东西（坐标轴、辅助线、原点……）归谁，没读代码，要先清点；反过来的动作（根只有一个子物体、自己没有几何时能去掉这一层）；撤销算一步。

## 空物体叫什么、长什么样（11-13，等 user 定）

统筹的建议（user 还没回）：

- 名字就叫「空物体」（user 自己顺口说的词）。想过又放下的：「物体」（最像 Unity 的基类，但放进句子里会绕）、「容器」（它要长出几何时就不是容器了）、「节点」（太工程师）、「组」（已经被硬表面里的组占了）。

- 不学 Blender 把它画成一副坐标轴杵在场景里：平时什么都不画，只有选中它或者进到它里面时才显示原点；有子物体时点子物体就能选到它。

## 系统地查：写到盘上的和人做的不一样的所有地方（11-13）

user：「它违反的是一条更一般的规矩：存盘只该把软件里的东西原样写出去 系统的查一下 这个其实和auto 版本迁移的问题一样」

- 统筹的理解（已对 user 说，等他纠正）：存盘改名字，和「打开老文件 → 自动升成新格式 → 存回去」是同一类——人没要求改，软件替人改了文件里的东西。所以要查的是全部这一类，不管发生在存的时候还是读的时候。
- 交小弟清点（只查不改）：写的那一头（存盘、自动保存、崩溃快照、另存、导出、跨文件粘贴）；读的那一头里读进来就不一样、下次存盘会写回去的；外加实际跑「打开 → 不动 → 存盘，字节变不变」。每一处分三类：人做的东西的意思变了；意思不变只是换一种存法；软件自己算出来的东西。
- 规矩的草稿（清点完再定稿）：文件里人做的东西只有人的动作能改；软件能自己动的只有「同一个意思换一种存法」和「它自己算出来的东西」；打开老文件不动盘上的文件，人改了、存了才按新格式写。
- 别的 app：家族周账记一条，碰到哪个 app 再对。

## 存盘一路的清点：小弟先交了写的那一头（11-13）

十四条。统筹的初步分类：

- **改了人做的东西**：① 根的名字拿文件名盖（已去掉）；② 指向不存在的定义的摆放，写的时候丢掉；③ 指向不存在的材质的槽，写成空。②③是存盘时悄悄清东西，先不改，等小弟查清它们什么情况下出现、照原样写出去读的那一头会怎样、现在丢的时候有没有记录。统筹倾向「不许悄悄丢」。
- **要先知道事实的**：网格设置和尺度参考是这份文件自己的还是设备上的（后者 = 把设备的状态写进文件）；只转视角、挪窗，文件算不算改过、会不会被自动保存写盘。
- **意思不变、只是写法**：空的素材架不写；画里全空白的行裁掉、没画过的写一份空白；点和面在文件里重新连续编号。
- **软件自己算出来的**：缩略图、合成图、崩溃快照、generator 和给别的查看器的 bake、导出。
- 读的那一头和「打开 → 不动 → 存盘字节变不变」的实跑还没做，排在这一版发了之后，结果写成一页。

## 系统清点的结果（11-13；全文 `ai-docs/20261112-save-faithfulness-audit.md`，小弟写，已推给 user）

**好消息**：软件自己存出来的文件，打开 → 什么都不动 → 再存，只差缩略图和两处版本串，别的每一段字节都一样。打开不算改过，不触发自动保存；只转视角也不算。413 份冻样本（49 个格式版本）在真软件里逐份打开，全部打得开，没有一份被当成改过。自动升级旧格式这一头：打开老文件不动盘上的文件。

**查出来的问题和统筹的裁定**：

1. **人改的没写出去**（方向反过来的那种）：换单位制、吸附长度、硬表面吸附开关、网格住哪个面 / 显不显示、尺度参考开关、清空尺度参考，这六样存在文件里，改了却不算改过——不自动保存、崩溃影子不写、离开前不问。只改这些就关掉，改动悄悄没了。裁定：改成算改过，先做一个小版本，diff 统筹审。画风、屏幕、参考窗位置、☰ 停在哪页是有意不算改过的「看法」，不动。
2. **读的时候悄悄修掉悬空的引用**（只有外来的、手改的、坏的文件会碰到）：材质槽指向不存在的材质 → 变成默认；组或实例的父亲指向不存在的组 → 变顶层。读的时候不记、不提示，存回去原来的值就没了。裁定：各记一条、打开时提示一次；修法不改。
3. **写盘时的两处兜底**（摆放指向不存在的定义就滤掉、悬空的材质槽写空）：照现在的代码走不到，真走到了是悄悄丢。裁定：走到了要留痕，存盘的结果里带上丢了几个。
4. 参考窗的位置存盘时会被夹到顶栏下面：桌面态，只记不动。
5. 老版本样本存回去的差（重铸 GUID、去掉 doubleSided、颜色换成线性、补贴图表……）都是换写法或软件自己算的东西，不动。

**规矩定稿**（照清点的结果，统筹）：

- 文件里人做的东西，只有人的动作能改；人改了的东西，一定要算改过、一定写得出去。
- 软件能自己动的只有两样：同一个意思换一种存法；它自己算出来的东西（缩略图、合成图、版本串）。
- 打开文件不动盘上的文件，不算改过。
- 读的时候修掉的、写的时候丢掉的，不许悄悄做：要记、要说。

## 给根包一层：设计定稿（11-13 晚，统筹；清点 = `ai-docs/20261112-root-inventory.md`）

**目标**：根除了「文件的入口指针指着它」之外，在数据上和别的物体没有区别。清点出来现在不一样的有三处：坐标架住在场景上而不住在自己身上；认不出的内容按「第几个定义」认根；存盘拿文件名盖名字（已去掉）。

**定的**：

1. **老文件打开时不包。** 包一层是 user 点的动作，不是迁移；打开不动盘上的文件（存盘那四条规矩）。所以不存在「两种结构并存」：根就是入口指针指着的那个物体，以前、以后都是这一个意思。
2. **先把根的特殊收到读写的门口，文件格式不变**（做在包一层之前）：
   - 坐标架：内存里根也住自己的那一份（和别的定义一样）；读文件时从 `document.axes` 放进去，写文件时照旧写回 `document.axes`。过了门口，运行时不再有「如果是根」这一支。
   - 认不出的内容的携带（根的硬表面几何里认不出的部分、根节点的 extras）：改成按 GUID 跟着那个定义走，不按「第几个」。
   - 要先查清的一件：不是根的定义，它的硬表面几何里认不出的内容，现在带不带回。不带 = 另一个口子（旧版本存回去会毁掉新版本写的东西），先报统筹，不顺手改。
3. **包一层这一下**：新根 = 新的硬表面物体（以后 = 空物体）、新 GUID、四位码的名字；旧根整个成为它下面的一份摆放，位置不动，GUID 不变，名字不变。新根的坐标架抄旧根的。**看得见的东西一样都不变**：视图、坐标轴的位置、导出时的原点。撤销算一步。
4. **反过来：去掉这一层。** 根自己没有几何、没有辅助线、没有组，只摆着一个子物体时可用；别的时候做不了并说原因。没有这个动作，包错了存盘之后就回不去。
5. **缺省的落点**（指令没写落在哪、粘贴、导入、素材架取东西的检查）：一律 = 当时的根。新写的指令都明写落在哪。
6. **不另加规则的几处**：空白新模型的判定不改（包过一层就算有内容，偏保守，不会被悄悄丢）；旧根成了普通物体之后可以上素材架；导出会多一层节点，照实导出。

**排法**：在「画跟着面走」之后。开工前统筹把上面写成施工单；第 2 条的门口那两处 diff 统筹审。

## 空物体怎么表示（11-13 晚，统筹定格式上的那一半；名字和样子仍等 user）

- **不存。** 「空」是算出来的：这个物体没有自己的几何，而且没有换种类就会丢的东西（贴图坐标的表、镜像设置、指着它的画）。文件里照旧只有硬表面、网格体两个值，旧版本读新文件不受影响。
- 满足上面条件的物体，下第一笔时按当时的工作台变成那一种，不问（没有东西可丢）；删光之后自然又满足条件。
- 删光了几何但还挂着画或贴图坐标的表：不算空，照旧是网格体，那些东西留着（生死按引用）。
- 只记账，不做（user：「放在合适的时候做」）。和「新建 / 加入分开」「没有新建空的子组件」一起做。


## 11-13 夜：改了方向——强类型；「空物体」是一个种类；种类只靠明着的「切换种类」改

added by Claude Fable 5.2 2026-11-13。**这一节盖过上面「空的没有种类，有了东西才有，删光变回空」那个方向**（那是 user 当天早些的提议、统筹当时赞成的）。

user 原话（按先后）：

- 「不过这些都是ux的问题，你帮我系统的设计一下。关键就是如何在一个脏的有东西的物体里面新建新的不同类别的物体，这个我们一直没有正视」
- 「你批判性地想一下，是一个空的子物体，没有种类，然后你切不同的边际模式好，还是一开始先定好种类好？……也许空的物体还是带有种类比较好，不然的话会比较失控，特别是以后。我们的物体种类多的时候……然后空物体本身也是一个种类，就是因为我们后来说还是不要静默转换嘛，就是相当于切换种类，还是让用户来切换。然后是我们有一个专门的切换种类的按钮，应该就是在这个物体选项里面，就我们不是有个转回应表面体吗？我们到时候把它变成一个系统的切换种类，也包括空物体，然后会告诉你说会有什么损失。」（「边际模式」= 编辑模式，「转回应表面体」= 转回硬表面，语音）
- 「对，我现在是比较建议空物体是一个种类，但是物体的种类，包括你删光的时候不会自动变换，而是你必须得手动选。就是我们是还是做强类型语言，而不是弱类型语言。然后就相当于如果我们想切换工作流的话，我们会有一个 explicit 的类型转换，然后我们是尽量把它做得漂亮一点，就是尽量无损一点。」

定下来的（user 的话）：

1. **强类型**：物体的种类在新建时定；之后只有明着的「切换种类」能改；删光几何，种类不变。
2. **「空物体」是一个种类**，和硬表面、自由建模并列。
3. **「切换种类」** 做成物体选项里一个系统的动作（现在只有「转成硬表面 / 转成网格体」），也能切到空物体；切之前说清会丢什么；尽量做成无损。
4. **新建物体时当场选种类**（硬表面、自由建模、空物体）。在一个已经有东西的物体里要另一种类的东西 = 新建一个那种类的子物体，不碰原来的。

统筹的看法和加的（user 没逐字说）：

- 统筹改了主意。早先赞成「空的没有种类、第一下用什么工具就是什么」，想错了：那是静默转换；选择没有省掉，只是藏进了「挑工作台」那一下；种类多了以后（灯、相机、曲线）很多种类没有「第一笔」可言。
- 「空物体」= 自己没有几何、只装子物体。给根包一层时新的根就是它；网格体里把几个组件包成新组件，新组件也该是它（现在被塞了一个空的网格体当种类）。
- 人在空物体里拿起画线、拉出这类工具：工具不能用、说原因，旁边给两个出口（在这里新建一个子物体 / 把它切换成某个种类）。不自动转。统筹问了，user 回的是「对」开头的那一段，统筹读成同意。
- 「尽量无损」的一个办法：有东西的物体切换成空物体时，不删几何，把几何原样下沉成它的一个子物体（种类照旧）。这一步不丢东西，而且正好就是「给根包一层」，两件事是同一个动作。已说给 user，user 还没回。
- 同一天读代码看到的两处要一起改：拒绝的话「这些面上有画」在「整个物体画过、这几张面没画」时说得不对；把面分成新物件时，画布对照表被原样抄给新物件，害得没画的新物件也转不了种类。
- 新长出来的面先不带画，笔或油漆桶碰到时按连成一片给（user 同意）。这一条归画那边，和这里一起排。

排法：统筹提的是刀做完之后就做这一件（卡建模），user 没明说行不行。文件格式会动一处（种类里多一个「空物体」），写施工单时单独摆给 user 定。
