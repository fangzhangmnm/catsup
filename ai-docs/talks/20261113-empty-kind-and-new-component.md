## 查到的事实（统筹读代码）

1. 物体的种类只有两种：硬表面（`brep`）、网格体（`mesh`）（`src/scene/body-kind.ts`）。一个物体（组件的定义；根也是一个）只有一个种类。2026-10-24 定的是：多种并存、明着互转、不自动转；「组件是管理方法，一个组件里面可以有 brep，也可以有别的」。
2. 带着画的面，下面这些全被同一道护栏拒（`src/scene/paint.ts paintMoveBlocked`，话是「这些面上有画：带着画的面现在还不能并进别的物件、分出去、做成唯一、复制粘贴、炸开或者转成硬表面（这个功能还没做）」）。
3. 所以 user 碰到的两处都是这道护栏，**不是因为选了全部的几何**：根有画 → 转不回硬表面（`castDefinition`）；选中带画的面「新建组件」→ 在网格体里这一步其实是把面分出去成新物件（`separateObject`），带画被拒。
4. 网格体里「新建组件」只有两条路：选的是面 = 把面分出去；选的是组件 = 包成一个新组件（`wrapInMesh`）。没有「新建一个空的子组件」。分出来、包出来的新组件，种类都是网格体。
5. 所以在画过的网格体根里想加硬表面的东西，只能绕：造一个方块 → 做成组件 → 转成硬表面。
6. 没核到：被这道护栏拒的时候，界面上那句话 user 看没看到（user 的说法是「没用」）。交小弟报。

## 统筹的批判（都是看法，user 没表态）

**眼前的麻烦是三件事叠在一起，不是一件：**

1. 没有「新建空的子组件」。最直接的缺口。
2. 画挡住了一切重组（分出去、并进来、复制、转种类）。这是「画跟着面走」那张单（施工单十八）要解的：做完之后分、并、复制都不用重画；转成硬表面 = 先问「画会丢，转不转」。
3. 种类是物体一出生就定死的属性。user 的提议针对的是这一件。

**user 的提议：空的没有种类，有了东西才有，删光变回空。统筹赞成方向，理由：**

- 种类本来是内容的性质，不是容器的性质（和 10-24 那句是一路的）。空的容器硬要有种类，是实现漏到了用户面前。现成的例子：网格体里把几个组件包成新组件，新组件其实没有自己的几何，却被塞了一个「空的网格体」当种类。
- 新文件、新组件第一下用什么工具就是什么，不用先选，也选不错。
- 删光变回空，走错了能回头。现在种类不对又有画，就卡死。

**要想清楚的边界和风险：**

- 「空」怎么算：没有面？点和线算不算？硬表面里的辅助线、参考几何算不算？子组件不该算（它是容器里的东西，不是这个物体自己的几何）——只装子组件的物体就是「纯容器」。
- 自动变种类合不合 user 的原则（自动只许拦、不静默）：空 → 有种类，是 user 第一下动作的直接结果，是明着的；删光 → 变回空，是自动的，但那时已经没有东西可丢，说一句就行。
- 挂在种类上的东西在变回空时怎么办：画、贴图坐标的表、材质槽、镜像设置、平滑默认。照「生死按引用」，画不该跟着没，成孤儿留着。
- 撤销：种类的变化要跟着撤销走。
- 文件格式：种类写在定义上（缺 = 硬表面，只在不是硬表面时写）。统筹倾向「空」不是存进去的第三个值，而是算出来的状态（没有几何就是空），这样旧版本读新文件不受影响。这是格式上的事，归统筹，和施工单十八一起排。
- **这个提议解决不了 user 最开始那个麻烦。** 画过的网格体里想加硬表面，种类已经不是空了，还是得建子组件。所以真正的问题是更大的那个：一层里能不能同时放两种内容。
  - 统筹倾向不混：两种内核守的规矩不一样（硬表面会自动合面、补面，网格体不动），混在一层里选择、工具、撤销都要分两套。
  - 替代：一个物体一个种类不变，但「在这里新建一个空的子组件、进去建模」要轻到不觉得是绕路；根想从网格体变成容器时，能把这一层的东西一步包成子组件（带画的面要能包 → 又回到施工单十八）。
- 根的特殊：根也是一个物体。根有画又想加硬表面，最自然的结果是根变成纯容器，原来的几何下沉成一个子组件。

**排法（建议，没定）：**

- 现在不动。
- 「新建空的子组件」和「空的没有种类」是一回事的两面，一起设计、一起做，可以排在施工单十八之前或之后，和它不冲突。
- 「画挡住重组」等施工单十八。
- 「一层里混两种内容」「实体种类」归远景，和材质纪元开工前那次批判性审视一起想。

## 换一个物体当根（11-13）

user：「第二层：有画就什么重组都做不了 好，所以是因为还没实现啊，那就没事了，不过这时候就是确实如何换一个物体当根而不是这个物体卡死在这里，可以好好想想」

**统筹的想法（user 还没回应）**：

- 根和别的物体是同一种东西，只是文件里有一个指针说它是入口。它特殊在没有「摆出来的那一份」：选不中、包不进组件、挪不走、炸不开。别的物体走错了能包一层，根不能，所以会卡死。
- 缺的动作是「给根包一层」：新建一个空的物体当新的根，原来的根整个变成它下面的一个子物体，位置不动。
  - 原来的根身份（GUID）不变，面一张没搬，所以画、贴图坐标的表、镜像设置原样跟着。不用等施工单十八。
  - 不改文件格式：多一个定义、多一份摆放、入口指针换一下。
  - 是把现成的动作补全：选中几个子组件能包成新组件（`wrapInMesh`），唯独根因为选不中包不了。
- 要想清楚的：新的根是什么种类（眼下倾向硬表面，和新文件一样；「空的没有种类」做了之后就是空）；名字（新根拿文件名，原来的根另起名）；挂在根上的东西（坐标轴、辅助线、原点……）归谁，没读代码，要先清点；反过来的动作（根只有一个子物体、自己没有几何时能去掉这一层）；撤销算一步。
- 没选的另一条路：规定根永远是容器、几何都住在子物体里。没选，因为简单的文件会平白多一层。
- 和第十八张单的关系：这个不是过渡办法，十八做完它照样有用（十八管的是面在物体之间搬，这个管的是谁当入口）。
- 排法（统筹的打算，user 可以否）：展开贴图接进「开始画」之后、施工单十八之前。做之前小弟先清点挂在根上的东西并报方案；入口指针那一处统筹审。

## 空物体叫什么、长什么样（11-13，等 user 定）

user：「空物体的名字叫什么？我不喜欢blender的轴。unity就是gameobject基类。你觉得应该叫什么」

统筹的建议（user 还没回）：

- 名字就叫「空物体」（user 自己顺口说的词）。想过又放下的：「物体」（最像 Unity 的基类，但放进句子里会绕）、「容器」（它要长出几何时就不是容器了）、「节点」（太工程师）、「组」（已经被硬表面里的组占了）。
- 不当成第三个种类：硬表面、网格体是「里面装了什么」，空物体是「还没装东西」。层级面板里不画种类的图标（或者一个中性的小圆点）；在里面动了第一下就显示成那一种，删光了图标又消失。文件里不存「空」这个值，没有几何就是空。
- 不学 Blender 把它画成一副坐标轴杵在场景里：平时什么都不画，只有选中它或者进到它里面时才显示原点；有子物体时点子物体就能选到它。

## 「新建」和「加入」（11-13，愿望单）

user：「以及新建某种类型的空物体也需要wishlist，哈哈我这句话自相矛盾，就是我想开一个某种画法的子物体该怎么办，也许这个比加入mesh更重要，我觉得可以名字区分为新建和加入」

- user 的提法：两个动作用名字分开。「新建」= 开一个新的子物体；「加入」= 往当前这个物体里加几何。「新建」可能比「加入」更重要。
- 统筹的读法（user 没确认）：不矛盾。「新建 › 硬表面 / 自由建模」= 建一个空物体、进去、切到对应的工作台；它此刻是空的，画下第一笔才成为那一种。种类是打算怎么画，落到物体上是第一笔的事。
- 这正是前面记的「没有新建空的子组件」那个缺口；user 在 a12b 里绕的那一圈（造方块 → 做成组件 → 再转）就是因为只有「加入」没有「新建」。
