# 讨论：动画曲线（时间轴的关键）

> created 20261030 by Claude Opus 5.5 · as-of v0.18.19
> 状态：**开着**。user：曲线要「发明」，会反复想。已拍的边界：只编辑每个 clip 自己的时间轴、没有全局时间轴；编排（过场）是另一种身体（`20261030-world-things.md`）。

## 10-30 晚 · 开题
- **user 原话**：「时间轴关键是要把animation curve发明出来，我可能要内耗很多次」
- **Opus 记的地基（不是方案）**：
  - 已有的几家：Blender / Maya 的贝塞尔曲线（每个关键帧两个把手）、TCB 曲线（张力 / 连续 / 偏移三个旋钮）、阶梯（定格动画、日式「一拍二」）。
  - **导出的硬边界**：glTF 的动画只认三种插值——线性、阶梯、三次（每个关键帧带进出切线）。任何分段三次的曲线都能一点不差地写成第三种；我们发明的曲线只要落在分段三次里，导出就无损，不然只能逐帧采样烘出去。
  - **转动是另一个岔路**：人好编的是欧拉角（三条曲线），glTF 存的是四元数。欧拉曲线导出要采样，四元数又几乎没法手编。这个岔路发明曲线时要一起想。

## 10-30 晚 · 第二轮：先 key pose 再二阶微扰；插值方案不一样
- **user 原话**：「但是关键是一般的动画流程是先key pose，然后二阶微扰吧。这么说洋葱片，打点算曲线我们也都需要我们是可以好好创新，不用照着blender，可以多看看图形学论文」「所以不同的插值方案是不一样的」
- **Opus**：
  - 这就是传统动画的「姿势到姿势」：先关键姿势 → 再加过渡姿势 → 再调间距（缓入缓出、跟随、重叠）。user 说的「二阶微扰」= 后两步。洋葱片（前后几帧半透明叠着看）、运动轨迹（手 / 头在空间里画出的弧线，打点看间距）都是这一步的工具。
  - 图形学里可以看的方向（Opus 记得的，没核；做的时候 Opus 调研）：时空约束（1988，把动画当优化问题解）、动作线摆姿势（2013，画一根线定整个人的姿势）、时空草图（2015，画一笔轨迹出一段动作）。
  - **插值方案进文件**：每段（或每个关键帧）用哪种插值 = 一个闭集选项，写进文件（编号 = 对照表的代号，按家规）。按 10-30 定的「兼容管数据、不管衍生算法」：插值是现算的，算法以后改进了，老动画的中间帧会跟着变，不并存两套；想保住某段的样子 = 烘成逐帧关键帧。Opus 提一句（没拍）：插值和自动法向不太一样，它决定的是 user 看过、认可过的动作；不过照规矩，烘一下就能保住。
  - 导出：glTF 只认三种插值，别的方案导出时烘（逐帧，或拟合成三次）。

## 10-30 夜 · 第三轮：「不版本化」那条可以商量
- **user 原话**：「"兼容数据、不管衍生算法、不并存两套、不版本化，想保留的结果就烘成数据" 这个可以negotiable」
- **Opus**：那「插值算法发出去就冻住、改进 = 加一个新方案（新编号）」又回到桌上，作为一个选项（没拍）。好处：老动画的中间帧永远不变，不用靠烘焙保。坏处：几套插值并存，就是 user 怕的屎山。不过插值是很小的纯函数（关键帧进、某一时刻的值出），并存几份的代价比并存几套渲染器小得多。哪些算法值得这样冻，要逐个商量。

## 10-30 夜 · 第四轮（指路）：插值在 FK 里做还是在 IK 目标上做
- 讨论在 `20261030-ik.md` 第九轮（user「用ik bone做插值和用FK做插值有什么优劣」）。和这份有关的一条（Opus，没拍）：「在哪个空间插」（FK / 目标空间）可以当插值方案的一个维度写进文件，每段 / 每个部位一个闭集选项；Opus 推荐默认 = FK 插值 + 钉子把着地拉回来。

## 10-30 夜 · 第五轮：反烘焙必须要——狗咬坦克的修复理念搬到动画
- **user 原话**：（引 IK 那份第五轮 Cascadeur「反烘焙：把动捕那种每帧都是关键帧的动作，抽稀成少数几个关键帧，方便人手改。这正好是我们动捕那条线的最后一步。」）「这个必须要，wishlist，不就是我们说的狗咬坦克的修复理念吗！把baked和collapse all的变成human editable的，然后你还可以手动选一些语义帧」
- **拍了**：反烘焙要做，进愿望单。人可以手动选「语义帧」（自己点哪几帧是关键）。
- **Opus**：
  - 对上狗咬坦克那句「坦克被狗咬了一口不应该作为需要回炉重做的理由」：烘过的动作（每帧一个关键帧）不该是死路，要能变回人能改的少数关键帧。
  - **每帧烘过的动作从哪来**（都是它的病人）：动捕；二次动作烘成的关键帧（二次动作那份的「烘成关键帧再手 K 修」）；想保住某段样子烘下来的（第二轮）；**导进来的 glb**——Blender 导出 glTF 默认逐帧采样，user 自己在 Blender 里 K 的小红帽动画，导进来就是烘过的，反烘焙之后才能接着改（anti-abandonware）。
  - **语义帧 = 人钉的关键帧**：人点的那几帧（着地、最高点、过渡姿势……）一定成为关键帧；算法在这之上再补几帧，直到和原动作的差距小于一个看得见的阈值。人点的是「硬的」，算法补的是「软的」（可以删）。
  - **整个人一起出关键帧**：手 K 是姿势到姿势，所以所有骨头共用同一组关键帧时刻，不是每根骨头各抽各的（各抽各的数学上更省，但人没法按姿势改）。
  - 顺带：着地的时段识别出来写成钉子（IK 那份第九轮「FK 插值 + 钉子」），抽稀以后脚也不滑。
  - 也连着「历史不存在，只有被打歪的原子」：反烘焙的产物就是普通的关键帧 + 钉子，不留「这是从哪段烘焙反推来的」历史。
