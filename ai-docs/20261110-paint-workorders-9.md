## 先读这一条（11-10 夜改，Fable）：没有「画布三角形」，只有「画布多边形」

写这一页时我默认了「一张面切成哪几个三角形只由贴图坐标决定」。小弟做 1-3a 时实测不成立：切法由点的位置和环的起点决定，镜像过去的面、挪过点的面，对角线可能正好相反。1-3a 第三节已改成下面这样，本页凡是写「画布三角形」的地方都照此读：

- 归属的单位是**画布多边形**（一张面在画布上的多边形；贴图坐标完全相同的面并成同一个）。每格归最近的画布多边形。
- 每格有一个**取样点**：格子中心在多边形里面就是中心，在外面（块边上多归的格子）就是中心在这块多边形上最近的那一点。
- 一格在某一张面上的空间位置 = 这张面自己显示用的三角形里、在贴图坐标上离取样点最近的那个，用它的公式在取样点上算。
- 所以第三节的名单是「画布多边形 → 这颗笔尖碰到的、对着它的那几张面（各带自己的三角形）」；第四节第 2 步是「对着这一格的每张面，各按上一条算位置，取离球心最近的距离」。
- 第三节的余量照旧（块边上的格子拿到的是边上的位置，所以三角形本身没碰到球时这些格子不会在球里；余量可以减到一个格长，量着定）。

## 要达到什么

user 定的（正本）：**笔和橡皮，轨迹在屏幕上，笔尖在空间里。**

```
屏幕上的点 → 滤抖、压感（内核，0-6）→ 平滑好的中心线（屏幕上）
          → 【这一张：落成路】打射线，落到模型上，变成空间里的一条路
          → 走步（内核，0-6，按路自己的长度）→ 笔尖列表（空间里的球）
          → 【这一张：每颗笔尖碰到哪些三角形】
          → 【这一张：标准答案】每一格吃多少，CPU 上按定义直接算
          → （1-4b：显卡上画成薄层，和标准答案对拍）
```

这一张做三样纯计算的东西，加一个把它们串起来的小控制器。

## 一、先说几个定下来的规矩

1. **全部在世界坐标里算。** 同一个定义可以摆好几份，每份有自己的摆放（可以带缩放）。一笔画的是「某一份摆放」的表面：三角形的顶点、位置公式都先乘上那一份的摆放，变成世界坐标。别的摆放共用同一张画，自然跟着有。
2. **目标**：这一笔可以画的东西是调用的人给的一张名单，每一项 = 一份摆放 + 它那个定义上的一张画（哪一套贴图坐标、哪张贴图）。名单里可以有好几项（多选多画）。
3. **被挡住的不画。** 射线打中的必须是眼睛看到的第一张面。名单之外的东西挡在前面，算没打中。「前面有没有别的东西挡着」由调用的人给一个函数来问；这一张的测试里给假的。
4. **藏起来的面**当它不存在：不挡、不吃、连通也不从它过。**不走这张画的面**（比如脸上的金属耳环）挡得住射线、连通可以从它过，但是不吃。
5. **背对着眼睛的面照吃**，只要球碰得到、而且和落点连着。笔在空间里，和从哪看没有关系。不想要的人用下面的「拐角」选项。
6. **笔的大小**：第一次打中的那一刻，屏幕上的直径 × 落点那里一个屏幕像素在空间里的大小 = 空间里的直径。定死，这一笔之内不变。「一个屏幕像素在空间里多大」由调用的人给一个函数（它知道相机）。
7. **路的单位**（0-6 的 `unit`：路的坐标里一个贴图格有多大）：名单里最密的那一项的名义值，也就是那份摆放的缩放 ÷ 那一套坐标的密度。落笔时就知道，不用等打中。
8. **一格在空间里多大**（下面叫格长）：每个空间三角形一个数 = 根号下（它在世界里的面积 ÷ 它在画布上的面积）。只在第三节「球够不够得着」留余量时用。
9. **浓淡只看空间里的距离。** 我核了内核的笔尖边缘曲线（`soft-shaders.ts` 的 `stampAccum`）：它只看「距离 ÷ 半径」和硬度，不带单位，也没有另加一格的软化；硬度是一的笔就是「格子中心在圆里就涂」的硬边。所以空间里直接把世界里的距离和半径交给它，不用换算成格数。设计稿里写的「边缘软化按当地一格的大小」不对，以这里为准。

## 二、落成路（0-6 的 `PathPlacer` 的实现）

**输入**：平滑好的中心线（屏幕上的点和压感，前多少个不会再变）；一个函数「屏幕上一点 → 打中了什么」。

**「打中了什么」的三种回答**：打中目标（哪一项、哪个空间三角形、世界里的位置）；打中了但不是目标（挡住了，或者那张面不走画）；什么都没打中。后两种下面统称没打中。

**输出**：一条路（0-6 的 `StrokePath`，三维）。路上只有打中的点。

**做法：在屏幕上对半分。** 对中心线上相邻的两个点 A、B：

- 两头都打中：量它们在世界里的距离。不超过步长上限 → 这一段就是路上的一段。超过 → 取屏幕上的中点（压感取两头的平均），打一条射线，分成两段各自再看。
- 分到屏幕上不到 1/256 个像素还超过上限 → **这里断开**（笔从一处跳到了另一处，比如从胳膊跳到了身子）。
- 一头打中、一头没打中：同样对半分，一直分到 1/256 个像素，路在最后一个打中的点上断开。这样线会一直画到轮廓边上。
- 两头都没打中：屏幕上超过 2 个像素就对半分着找（中间可能有一条细的东西），不超过就算了。
- **步长上限** = 这一笔定下来的半径（不随压感变的那个）的一半和一个路的单位，两个里大的那个。
- 1/256 是这么来的：笔在屏幕上至少一个像素大，所以步长上限至少是四分之一个屏幕像素在落点那里的大小；分到 1/256 个像素还超过它，说明表面比 89 度还斜，或者真的跳了。两种都当断开。

为什么这样分得出「连着」和「跳了」：连着的表面再斜，屏幕上分一半，世界里的距离也跟着减半，总能分到上限以内。真的跳了的地方，怎么分都有一段不变短。不需要另定一个「多斜算太斜」的角度。

代价：很斜的表面上，一小段屏幕上的线要打很多条射线（世界里的长度 ÷ 步长上限）。平的地方其实不用分这么细；这个省法留给 1-6，这一张先量出来。

**其它规矩**：

- 每条射线的落点是射线和三角形求交，双精度。打的是 1-3a 的那一套三角形，用 1-3a 的索引。
- 确定性：同样的输入，路逐位相同。
- **定型的部分不重算**：中心线前面不会再变的那些点对应的路，算过一次就留着，路的 `frozenCount` 跟着涨，只增不减。每次只重算尾巴。
- 一段里射线的条数有上限（默认 4096）。到了上限：剩下的当成断开，并且在统计里记一笔。
- **落笔时没打中**：先把输入的点攒着。第一次打中时定大小、开始这一笔，把攒着的点按原来的时间补给内核。一直没打中 = 这一笔什么都不发生。

## 三、每颗笔尖碰到哪些三角形

**输入**：一颗笔尖（世界里的球心和半径）；它在路上夹在哪两个点之间（用笔尖带着的「走了多远」去路上找）；目标的三角形和它们怎么相邻。

**输出**：这颗笔尖要画的「画布三角形」的名单；每一个下面挂着它在世界里对应的那几个空间三角形（镜像的两半、复制出来的面，会有好几个空间三角形对着同一个画布三角形）。

**做法：从落点往外找。**

- 起点 = 夹着这颗笔尖的那两个路上的点各自打中的三角形。
- 从起点出发，沿着公共的边往外走。一个三角形和球相交（球心到三角形最近的点的距离 ≤ 半径 + 余量）→ 收下，接着看它的邻居。不相交 → 不收，也不从它往外走。起点自己不相交时，往外多看一圈。
- 余量 =（1-3a 的归属表往块外面延出去的格数 + 1）× 这个三角形的格长。原因：块边上的格子中心在三角形外面一点，它们的位置是公式往外延出去的值，三角形本身没碰到球时，这些格子仍然可能在球里。
- 这样找到的是「球碰到的、而且和落点连着的那一片」。贴着身子的胳膊、鼻子后面的脸颊，离得近但不连着，不会被蹭到。
- **相邻**：两个三角形有一条公共的边（两个公共的点，按网格体的点的编号认）。同一张面切出来的三角形之间也算。只在同一份摆放里走，不跨到别的摆放。
- **拐角的选项**（笔刷的设置，一个角度，默认不限）：朝向和起点三角形差得比它多的三角形不收，也不从它往外走。
- 收下的三角形里，所在的面不走这张画的，从名单里去掉（连通已经用过它了）。

三角形怎么相邻的那张表，每份摆放建一次，网格体变了才重建。

## 四、标准答案：每一格吃多少

这是定义，也是 1-4b 显卡那一半要对拍的东西。写成普通的函数，不碰显卡。

**一颗笔尖 × 一个画布三角形 × 一格**：

1. 这一格归不归这个画布三角形（1-3a 的归属表）。不归 = 不吃。
2. 这一格对着的每个空间三角形（第三节挂在这个画布三角形下面的那几个），用它自己的位置公式算出格子中心在世界里的位置，量到球心的距离。**取最近的那个距离**。同一颗笔尖对同一格只算一次。
3. 把这个距离和笔尖的半径（都是世界里的长度）交给内核的笔尖边缘曲线（和画画软件同一份），得到这一格有多浓；再乘这颗笔尖的浓度。距离不小于半径 = 不吃。

**一笔之内怎么攒**：照内核的两种，和画画软件一样。取最大：每一格留各颗笔尖里最浓的。叠加：按笔尖的先后一颗一颗盖上去。

**内核那条曲线在 CPU 上的那一份**：内核的软件显卡里有它的 JavaScript 写法。施工单（六）加了一条，让它导出成一个函数；这一张直接调。到时候没有就停下来说。

## 五、串起来的小控制器

放在 `src/paint/`。它拿着：目标的名单、相机给的两个函数（打射线、一个屏幕像素多大）、内核的「一笔的手感」（0-6）、笔的设置。对外只有：按下、移动、抬起、取消，和「现在的笔尖列表、每颗笔尖的名单」。

- 这一笔开始时把相机给的东西记下来，一笔之内不变（操作期间锁视角是界面那一张的事；这里只保证自己不会用到变了的相机）。
- 它不碰图层、不碰显卡、不知道撤销。1-4b 在它后面接上薄层和档口。

## 六、放在哪、门

- 新代码放 `src/paint/` 下，不放进 `src/paint/kernel/`。不 import three、不碰页面。可以 import 内核里 0-6 的类型和那条曲线。
- `npm test` 全过，`tsc` 干净。全套测试的时间加之前、加之后各量一遍；过一分钟停下来说。

**测试（随机的都固定种子）**：

1. **路贴着表面。** 球、圆柱、一张波浪形的面：路上每个点都在表面上（到最近三角形的距离是零）；相邻两点的距离不超过步长上限；配上 0-6 的走步，相邻两颗笔尖在世界里的距离等于那一步的间距（误差不超过弦和弧的差）。
2. **斜面不断。** 一张平面，从正面、60 度、85 度、89 度各画同一条屏幕上的线（笔在屏幕上四个像素大）：路都不断开；斜的时候路更长，笔尖更多，相邻笔尖的距离不变。每种角度打了多少条射线，写进记录。
3. **跳了会断。** 前后两个离得远的盒子，一条线横着画过去：路在两个盒子之间断开，断口两头之间没有笔尖；「走了多远」不含那一段。
4. **画到轮廓边上。** 线从模型里面画到外面：路的最后一个点离轮廓不超过 1/256 个屏幕像素对应的距离。线从外面画进来、落笔时没打中：进来之后正常画，大小是第一次打中时定的。
5. **被挡住的不画。** 目标前面放一块不是目标的板：板挡住的那一段，路是断开的。
6. **定型。** 一笔边画边取：路的前 `frozenCount` 个点和下一次取的逐位相同；`frozenCount` 只增不减；定型的那一段没有重新打射线（数射线的条数）。
7. **连着的才吃。** 两张离得很近但不相连的面，笔画在一张上，球够得着另一张：另一张不在名单里。把两张面用一条边连起来：在名单里。
8. **和笨办法一样。** 随机的网格体和随机的笔尖：第三节找出来的名单 = 笨办法（所有和球相交的三角形里，和起点连着的那一片）。
9. **镜像和复制。** 强行对称的网格体，笔尖压在中缝上：两半的空间三角形挂在同一个画布三角形下面，每一格只算一次，取的是最近的距离。复制出来叠在旁边的面同理。
10. **拐角的选项。** 方盒子的棱上，选项设成 45 度：侧面不吃；不限：侧面吃。
11. **铺法换掉，结果不变。** 同一个模型两份铺法：1-3a 铺的那一份；把它每一块各自拉伸、歪斜、缩放到密度差十倍的另一份。画同一笔。在表面上随机取点，各自查那一点所在的格吃了多少，和「直接拿这一点所在格的中心位置按定义算」的值相同（差不超过万分之一）；两份铺法在同一个表面点上的值，相差不超过「这一点和它所在格的中心之间」浓淡本来的变化（按格长和曲线的斜率估上界）。硬度是一的笔另测一遍：线在模型上的宽度，两份铺法只差各自的一格。
12. **藏起来的面、不走画的面**：第一节第 4 条各有断言。
13. **速度**（写进记录，不设及格线）：一万个三角形的模型上，一帧 40 条射线花多久；一千颗笔尖、每颗碰到五十个三角形，找名单花多久；标准答案不用快。

**守卫**：打射线求落点全仓只有 1-3a 那一处；球和三角形求最近点只有一处；标准答案里那条曲线是内核导出的那一个，不许自己抄一份算式。

`api/` 重新生成；流程图文档加一节「空间里的一笔（计算的那一半）」；升一个末位版本。

## 七、碰到这些就停下来报

- 0-6 做出来的 `PathPlacer`、`StrokePath`、`StrokeTips` 和这里假设的不一样。
- 对半分在某种表面上分不出「连着」和「跳了」（比如刀刃一样薄的边上）。
- 落笔没打中时攒点再补，内核的滤抖结果和「一开始就开始」不一样。
- 笔尖在路上夹在哪两个点之间，用「走了多远」找不准（断开的地方、原地停顿的地方）。
- 你觉得起点要多于两个，或者连通要跨摆放。
- 测试 11 对不上。

## 这一张不做的

显卡上画薄层、定型层和尾巴层、档口、抬笔落层（1-4b）；像素笔（1-5）；射线按屏幕分格这类提速（1-6）；指针事件、锁视角、界面（1-7）；涂抹和模糊（第 5 段）；笔的倾斜和转向（接口等用到时再加）；笔尖中心在模型外面时找最近的表面（以后）。

**第七节先核的**：0-6 的 `PathPlacer` / `StrokePath` / `StrokeTips` 和这里假设的一样（`place(cx, cy, cp, count, frozenCount)`、`breakBefore`、`frozenCount`；笔尖 = 位置 + 大小 + 浓度 + 走了多远）。「笔尖在路上夹在哪两个点之间」没用「走了多远」去找：内核的 `forEachTip` 本来就交出「第几段」，直接用（统筹 11-10 说过段号直接用）——断开、原地停顿都不用另想。落笔没打中时攒点再补：攒的点从第一个开始、按原来的时间喂，滤抖结果和一开始就开始一样（同样的点、同样的时间；测试 4 的第二条）。刀刃那样薄的边、起点要多于两个、连通要跨摆放：都没碰到。**测试 11 对上了。**

**做了什么**（全在 `src/paint/`，不碰显卡、不进界面、不 import three）
1. `space-target.ts`：名单里一项 = `{ 网格体, 摆放（3 × 4，可带缩放）, 那一套贴图坐标, 密度, 画布, walks(面) }`；`walks` 由调用的人给（这一层不认识材质，1-3b 的 `paintUvOf` 在场景那一层）。每项建一次：1-3a 的格子（定义坐标）+ 归属表 + 世界三角形 / 世界法向 / 格长（根号下世界面积 ÷ 画布面积）+ 相邻表（公共的边按点编号认，同一张面切出来的也算）。打射线 `rayHit`：世界射线换进各项的定义坐标（方向不归一化，t 两边相同）交给 1-3a `castRay`，各项取最近；那张面不走画、或名单外的东西挡在前面 = 「打中了但不是目标」。路的单位 `pathUnit` = 各项「摆放的缩放（行列式的立方根）÷ 密度」里最小的。
2. `space-path.ts`：照第二节原样。步长上限由控制器给（半径的一半和一个路的单位里大的那个）；1/256 像素、2 像素、一对点 4096 条射线都是参数（默认值照施工单）。定型：定型的中心线点打过的射线记着、定型的相邻对落成的路记着，`frozenCount` 只增不减，每次只重算尾巴。
3. `tip-reach.ts`：照第三节。起点 = 夹着这颗笔尖的那两个路上的点打中的三角形（段号 −1 = 起点那一颗只有一个）。余量 =（归属表往块外延的格数 gap / 2 + 1）× 这个三角形的格长。球和三角形求最近点 = `sphereTriDist`（Ericson 那一段），全仓（src/paint 里）一处。
4. `tip-truth.ts`：照第四节。②按 11-10 夜改的读：对着这一格的每张面各用 1-3a `positionOnFace` 算位置、乘摆放、取离球心最近的；③硬芯 = 硬度 × 半径（和二维笔尖同一个夹法 0 … 0.999），曲线 = 内核 `soft-shaders.ts` 导出的 `stampFalloff`。攒：取最大 / 叠加（a + v·(1 − a)）。
5. `space-stroke.ts`：小控制器，对外 `down / move / up / cancel / tips() / path()`；相机给的函数开始时记下来、一笔之内不变。
