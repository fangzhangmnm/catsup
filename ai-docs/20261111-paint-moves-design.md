## 二、现在的样子和它的毛病

- 一张画 = 贴图表里的一行。这一行的 `layout` 记着 `{ definition, uvSet }`：我铺在哪个物件上、用它的哪一套贴图坐标。
- 一套贴图坐标 = 那个物件的网格体里的一行（名字、画布宽高、密度）加上每张面每个角上的一列数。
- 规矩：一张画只属于一个物件。别的物件的面换不到这张画上；带着画的面并进别的物件、分出去、做成唯一、复制粘贴、炸开，全部明着拒绝（`scene/paint.ts paintMoveBlocked`）。

毛病：「画属于哪个物件」记了两处（画记着物件，物件记着那一套坐标），面一搬家两处都要改；原来的 1-3d 打算每次搬家都把坐标、贴图、材质复制一份换新身份。那样做合并要拷整张画，分出一小块也要拷整张画，而且几个物件永远没法合用一块画布。

## 三、改成什么

**画布是中心。面只是在某块画布上占了一块位置；物件不拥有画。**

说法对照：一块画布 = 一张 atlas（一批面排在同一张图里）；铺法 = packing。对 user 说「一张画管一组面」时 user 问过「一组面是什么意思？你没有做atlas和packing？」——以后直接说 atlas。

- 画布 = 贴图表里的那一行。宽、高、密度记在它自己身上，不记在物件里。它不再记「我属于哪个物件」。
- 面在画布上的位置 = 面的角上的那一列数，这一列用画布的身份号认。它长在面身上，面被切、被镜像、被搬到别的物件里，它都跟着（角上的列本来就是这么设计的）。
- 材质指着画布（照旧）。一张面走不走某张画 = 它的材质指着那块画布，而且它角上有那一列。
- 画布活多久 = 按引用（家规，学 Blender）：还有材质指着它、或者素材架收着它，就活着；没人指了进「没人用的」清单，清掉了文件才变小。

后果：

- 一个物件可以有好几张画（现在就可以）；**一张画也可以被好几个物件的面合用**（现在不行）。
- 搬家不用动画。默认永远是共用，要各一份是明着的动作。

## 三½、把各种用法过一遍之后的修正（11-11 傍晚）

user：「不过如果是指定贴图大小的话，后面自动涨也不好」「think critically, systemically, and in future long vision, imagine user cases like different modeling tasks, building, kitbashing, artist, aaa pbr probs, anime figures, n64 characters, ...」

| 用法 | 它最在乎什么 | 要我们有什么 |
|---|---|---|
| 建筑 | 大平面、真实尺寸的砖和木纹，上面零星有招牌、涂鸦 | 按真实尺寸平铺的图（已有：自由的图 + 物理尺寸）；涂鸦 = 贴在表面上的单独物件 |
| 拼装零件 | 每个零件带着自己的图来，并在一起不重画，最后合成一张 | 一个物件多张 atlas；统一密度；合成一张图 |
| 手绘画师 | 预算是「这个东西给一张 2K」，脸比脚细，软笔和图层 | 定大小；一片可以比别的细；从视角铺；小窗里画 |
| 写实道具 | 颜色、粗糙、金属、法线好几张图共用一套排法 | 排法和图分开，一套排法挂好几张图 |
| 动漫手办 | 脸一张细的、身体粗的，眼睛不能对称 | 多张 atlas；把几张面从对称里分出来；光泽那一槽 |
| N64 角色 | 32、64 见方的小图好多张，大量镜像重复，色数有限 | 更小的档；合用；限色；以后的顶点色（角上的列本来就装得下） |
| 像素风场景 | 全场景每一格一样大 | 文件级的默认密度 |

**修正一（改了第三节）：中心是「一套排法」，不是「一张图」。** 第三节把两样并成了一样（「画布 = 贴图表里的那一行」），写实道具那一行说明不能并。改成三层：

- **排法**（一套贴图坐标）：文件里独立的条目，有自己的身份号；宽、高、密度、定住的是什么、哪一版排法排的，都记在它身上。面的角上的那一列用**排法**的身份号认。
- **图**：挂在一套排法上（贴图行指着排法，不指物件）。一套排法可以挂好几张图（颜色、光泽……）；图的分辨率可以是排法的整数分之一。
- **材质**：每个槽指一张图（照旧）。

第三节别的话照旧成立，只是把「画布」读成「排法和挂在它上面的图」。user 看到的「一张 atlas」= 一套排法连同它的图。

**修正二：每套排法记着定住的是什么。**

- 定密度：一格多大不变，画布跟着内容长大缩小，全程静默。
- 定大小：画布不变；放得下就静默重排；放不下不许自己涨，明着问一次（变粗重铺 / 放大画布 / 另开一张）。建模长出来的新面放不下时先留着没位置（照底色显示），上方正中的按钮照现在的规矩露出来。
- 手工：钉住的、导入时自带的，什么都不自动动。

**修正三：密度有文件级的默认值**（文档设置里一个数；新开的排法默认用它；像素风、N64 要的是整份文件一个数）。

**修正四：同一套排法里的一片可以比别的细**（每片一个倍数；定大小时按权重分地方，定密度时这一片乘倍数）。user 的手工展开里不同部位密度差 10 倍，就是这个。先留位置，以后做。

**展开保守、排法放开（user 11-11 傍晚）**：听完「夹角放宽到 70° 能多一成多的格子，但斜面会被压到三分之一，先留在 45°」之后：「同意，因为到时候我们说的横平竖直的转开，我们是要单独找个时间一起好好讨论一下。现在我是说，你 pack 的时候可以尽量优化，用优秀的算法，但是你展开的时候可以先用保守。」「横平竖直的像素展开」。所以：怎么把面压平（展开）先保守，夹角留 45°；怎么把片排进画布（排法）可以尽量用好的算法，反正是静默、无损的。**「横平竖直的像素展开」是一个单独的题目，等 user 找时间一起讨论，Fable 不先定。**

**修正五：导出时的要求和平时分开**（2 的幂、留多宽的边、合成一张，都是导出那一下现算的）。**档往下加** 16 / 32 / 64。

## 四、各个动作怎么办

| 动作 | 现在 | 改成 |
|---|---|---|
| 并进别的物件、炸开 | 拒绝 | 面带着角上的列过去，画不动。结果那个物件里有好几张画，各管各的面 |
| 分出一部分、建组件 | 拒绝 | 同上。分出去的和留下的合用同一块画布，各占各的位置 |
| 做成唯一 | 拒绝 | 几何各一份，画合用。要画也各一份，另点「给这几张面单独的画布」 |
| 同一个物件里复制几张面 | 拒绝 | 副本和原来的占同一块位置：画一个，两个都变（和开着对称一样）。提示行说一句 |
| 同一份文件里再摆一份 | 合用 | 照旧 |
| 跨文件粘贴 | 拒绝 | 画布跟着载荷按值过去。目标文件里已经有同一个身份号而内容不一样 = 走身份层现成的弹窗（更新 / 留这里的 / 断开） |
| 转成硬表面 | 拒绝 | 先问：画会丢，转不转。硬表面的面没有稳定的来历，这一条不变 |

**共用是 user 定的（11-11 下午）**：问「同一个物件里复制几张画过的面，副本和原来的是共用同一块画布，还是各一份」，user：「component已经处理好了实例化了，嗯我建议共用。对，如果需要make unique需要用户手动指定，编辑的时候模式是一起画，就和对称一样」。所以：复制、分出去、做成唯一一律合用；画的时候合用的那几处一起变；要各一份只有用户手动点「给这几张面单独的画布」这一条路，不自动拷。

## 五、一个底层动作：按面把画搬过去

每张面在画布上有自己的公式（面上的一点 ↔ 画布上的一点）。所以「把这张面上的画，从旧画布的旧位置，搬到新画布的新位置」可以按面做：对新位置里的每一格，算出它在面上是哪一点，再到旧位置上取颜色。每个图层各做一遍。

这一个动作有五个用处，做一次：

1. **换大小（resample）**：同一批面，按新的密度重铺一遍，再搬。
2. **重新铺紧**：画布上有人走了、空出了地方，或者想换成连成片的铺法，重铺再搬。
3. **合成一张图**：几块画布上的面铺进一块新画布，搬过去，旧的没人用了。导出给游戏引擎之前用。
4. **给这几张面单独的画布**：选中的面铺进一块新画布，搬过去。合用的、对称的想分开都走它。
5. （以后）**改贴图坐标时连画一起挪**。

取样两种：保持硬边（最近的一格；整数倍放大不损失）、平滑。缩小是有损的，做之前说清楚。

**换地方存可以静默，重采样必须用户手动（user 11-11 傍晚定的线）**：「不过还是比较scrutiny你的统一密度这个和 Atlas 不一样，Atlas 可以静默排，因为它本质上只是一个数据结构。MipMap 显示会有问题，是我们算法的问题。但是用户的语义，它的数据，你只是相当于把你一部分像素换了个地方存，所以它可以静默重排。但是说，如果是重采样的话，不应该静默，而是用户手动设置。」

| 上面的用处 | 哪一类 | 能不能静默 |
|---|---|---|
| 重新铺紧、裁小画布 | 换地方存（整格平移、转 90°、翻转） | 能 |
| 合成一张图 | 换地方存：各片原样搬进新图，**各自保持自己的密度**，不用统一 | 无损；是用户点的指令（图和材质的数目变了） |
| 给这几张面单独的画布 | 换地方存 | 无损；是用户点的指令 |
| 换大小、统一密度 | 重采样 | 不能：只在用户手动点时做 |
| 改贴图坐标时连画一起挪 | 整格平移、转 90° = 换地方存；缩放、转任意角度 = 重采样 | 后一种要明着做 |

所以「合成一张图」和「统一密度」是两条指令：拼装零件并在一起、合成一张都无损；统一密度是单独的、想要才点的。合出来的图里各片密度不同是正常的（user 的手工展开里就差 10 倍）。

**排得紧之后缩小显示时串色，是显示算法的事**（同一句里 user 说的）：不拿它当理由打扰用户，也不为它把排法放松。做法归显示那一层：缩小图按岛做——每个岛先把边上的颜色往外填，再往下缩；这是现算的派生物，不动用户的像素。**改成愿望单，等真正看到串色再想**（user 同日）：「有道理啊，就是更好的mipmap算法，这个可以到愿望单里……我的建议是等真正看到串色了再去想，因为我们最后还是导出游戏引擎，所以我们还是按照标准做，要游戏引擎能接住比较好。」Fable 的意思是简单的那一种（每一层缩小图排列不变，只是缩之前把每个岛边上的颜色往外填一圈 = 行业里的边缘填充，导出的是一张普通的图，引擎照常生成缩小图）；user 一度理解成「不同层级用不同的排列」，那是另一个主意，标准引擎接不住，不做。导出的那一份可以按引擎惯用的宽度重新留边（重排无损），和平时排得多紧无关。

**重排可以静默（user 11-11）**：「按包围盒排 对这个是以后需要高级packing算法的」「以及packing是可以静默的。除非uv编辑pin了」。读法（Fable，报给 user 了，没回）：静默的重排只做**整格平移**——一个像素都不损失，撤销只要记「谁挪了多少」、不用记像素；要缩放、要转任意角度的会损失像素，仍然是明着的动作（换大小）。以后改贴图坐标时被人钉住（pin）的片，静默重排不碰。高级的排法（片和片互相嵌着放）排在「重新铺紧」里做。

**坐标的单位是格，不是零到一的比例（现状，1-3a 起就是；`src/paint/layout.ts` 头注释）。** user 11-11 自己推到了这一条并且很看重：「所以！！！！！！packing用的是像素坐标，不是百分比坐标」「现在改还来得及吗」「所以你加东西了之后只是1024*1024变成了1300*1300，但是每一个岛的像素还是一样的」「比如升级版本的时候可以自动repack用更好的算法」「然后以及是repack之后可以用小一点的图尺寸」。这条是下面几件事的底子，**以后不许改成比例**：

- 加面只是画布变大，已有的岛一格不动（现在是往下加高）。
- 重排 = 岛按整格挪，像素原样搬，无损。
- 重排之后画布可以裁小（改宽高），不损失像素；宽高不必是 2 的幂、不必是正方形。
- 换了更好的排法，旧的画可以直接重排，重排前后模型看起来一样。
- 给别的软件看的那一半（glTF 的 TEXCOORD）必须是零到一的比例：那是存盘时现算的派生物，不是正本。

**贴图坐标完全静默（user 11-11 傍晚定，推翻了 Fable 上面加的「只是打开文件不动它」）**：「为什么，我反而觉得是可以顺手重排」「用更优化的算法」「只有用户确实有需要手工指定uv的意图了才是」「我一开始设计的理念就是uv完全静默，用户不知道，不需要焦虑uv空间管理」。

所以：重排当成读文件时的格式迁移——在内存里悄悄做，**不标脏、不单独写文件**，等用户下次因为自己的改动存盘时顺带存下去；锁着的文件照旧一个字节都不写。Fable 原来担心的只是「打开就让文件变脏」，这样就没有了。

user 同日确认这个读法：「把重排当成读文件时的格式迁移……就之前不太优化的方案变成优化的重排方案。」做法上是懒的：不是一打开文件就把每张画都解开重排（画多了打开会变慢，家规启动速度优先），而是哪一套排法第一次被用到（醒过来）时迁那一套；用户看到的效果一样。

内部的保险（用户看不到；Fable 定的）：

1. 只按整格挪，不损失像素。
2. 在这张 atlas 醒过来、这一次打开还没落笔之前做（不弄乱画的撤销记录）。
3. 挪完逐个岛核对像素和原来一样才采用；对不上 = 保留旧的、记一笔调试日志。防新排法有 bug 把画弄坏。
4. 每张 atlas 记着自己是哪一版排法排的；只有存着的版本比本版老才重排，旧版本的 app 不把新排法退回去。
5. 用户表达过手工指定意图的不动：以后在小窗里钉住的岛；导入的模型自带的贴图坐标（那是别人手工展的，而且常常有意叠着放）。

**创建画布时两种指定方式（user 同日）**：「所以这么说的话，创建画布的时候也应该有像素密度和贴图大小两个指定方式？」——对。按一格多大（密度）是更根本的那个：铺法本来就能直接吃密度、画布大小跟着算，每张 atlas 也一直记着密度；不同物件的格子一样大是像素风的基本功。按总大小是抠总像素时用的。面板上两组都给（施工单十六第四节）。

撤销：这一步换掉的是整块画布的像素，不走一格一格的差量——旧画板整块留着当这一步的「之前」，撤销就是换回去。占的内存算进撤销的额度，太大就先问（家规：慢的、贵的先问，不悄悄不做）。

## 五½、贴图坐标存整数、整数在角点（11-11 傍晚；Fable 的建议，全家规范等 user 定）

user：「给你一个送命题，我们贴图坐标的保存要不要做非规范的做法，就是存整数的像素值，而不是存浮点值和相对uv的浮点值。」「如果你用贴图坐标做别的事情的时候，这个时候实际上语义上是违规的，你应该用别的 attribute。就是我会觉得说，我们贴图坐标必须整数、像数，这个是个全家的硬规范。以及这样的话，整数到底是应该是在中心还是在角点？你能帮我好好的想一下吗？」

量到的事实：user 自己的小红帽（检疫仓 `littlered.glb`）的坐标不在整数格上——乘 256 之后只有 2.4% 落在格点上（0.02 格以内），离最近格点的中位数 0.28 格，基本均匀散开。所以这是新立的规范，导入的模型会受影响。

**建议：存整数；整数在像素的角上**（像素 (i, j) 是从 i 到 i+1、从 j 到 j+1 的那个方块，中心在半格上；原点左上角、纵轴朝下，照旧）。

为什么值得：

- 整格平移、转 90°、整数倍放大之后还是整数：重排和整数倍放大永远无损。
- 「哪一格归哪张面」可以用纯整数算，不靠误差容限，所有设备和版本算出来一样；相邻的面共用整数的点，拼得严丝合缝。
- 像素风的本义：面的角落在像素的角上，横平竖直的面正好盖住整数个像素。PS1 的贴图坐标就是每个顶点两个整数。
- 语义干净：贴图坐标只表示在图上的位置；别的数用别的列（角上的列本来就能装别的种类）。
- 文件更小。

为什么是角点：

- 现代显卡和 glTF 的约定：零到一是从图的这条边到那条边，像素中心在半格上。整数在角点 = 导出时坐标除以宽，不加减半格。
- 横平竖直的面：角点制下边压在像素的缝上，没有像素被两张面分着用；中心制下边穿过一排像素中心，最常见的情况最含糊。
- 放大：角点制坐标乘 2 就对；中心制要加减半格。
- 像素中心永远在半格上，不会正好落在顶点上，横平竖直的边上也不会有。
- 中心制适合「一个顶点一个采样值」（高度图、光照图），那些归「别的列」。

四条配套规矩（不带这几条会出事）：

1. 切一刀长出来的新点，坐标取到最近的格点；画不动、不重采样。代价：这附近贴图在模型上最多错开半格；建模的格距是一格的整数倍时没有误差。
2. 取整之后没有面积的面（比一格还小）算没有位置，在小窗里标出来。
3. 导入的模型自带的小数坐标不强行取整：当成「外来的坐标」原样带着，是另一种列；user 点「收编」时才取整，明着做。
4. 展开算出来的是小数，最后一步取整（同一个位置的点取到同一个格点）。让这一步不产生误差 = 「横平竖直的像素展开」，等 user 单独讨论。

落地：和「排法成为独立条目」那一轮一起改格式（现在存的是小数的格数）。先让所有产出坐标的地方都取整 + 守卫「贴图坐标列里的数都是整数」，再把文件里换成整数，最后（可选）把归属表改成纯整数算。

**同日再修正（user 两句话之后）**：

user：「小红帽不是，可能是因为 Blender 不支持，但我实际上是想这样的。不过这么说也对，因为我们到时候重排的时候，只要保证位移是整数就可以了。不过如果我们想重旋转的话，倒是需要格点是整数，有九十度旋转翻转。」「关键是我们随时要防御，我们必须非常防御性的想，我们用户画好之后会进行一些点的挪动，甚至是一些比较大的改动，增加删除，拓扑改动都有可能。」

- **更正上面「为什么值得」的第一条**：无损重排不靠整数坐标。平移只要位移是整数格；转 90° 和翻转只要转的中心、翻的线在格点上；面的角是不是整数都无所谓。整数坐标换来的是横平竖直、归属用纯整数算、语义干净这三样。
- **改掉配套规矩第 1 条**（「切一刀长出来的新点取到最近的格点」）：切一刀用户期待画一点不变，取到整格会让新点附近的贴图错开最多半格，像素风的大格子上看得见。改成：
  - 坐标存的全是整数，**单位是 1/1024 格**（和归属表取样点的量化同一个数）；整格的点 = 1024 的倍数。
  - **铺出来的、重排之后的、收编之后的坐标必须是整格**——这是规范的样子。
  - **建模时派生出来的点按原来的公式继承，可以落在格子中间**——切一刀画的样子完全不变。这些点在小窗里标出来，下一次重铺时归整。
  - 归属照样是纯整数运算；重排照样无损。
- 别的三条配套规矩照旧。

**第三版（user 同日又想了一遍之后）**：

user：「切一刀长出来的新点，坐标取到最近的格点。让我很犹豫，这个确实是得重新想一下，因为我后来新的说法是，只要我们保证重排的时候它的位移是整数就可以了，就其实取整的目的就不是很重要了。但是确实有整数的话会比较舒服。所以说怎么办？你帮我想想，因为说如果为了取整导致你这个。均匀排列的东西有一点点不对齐的话，我觉得可能有些人会晕动。就是比如说一个墙，如果说它会有一个比较周期性的抖动的话，我觉得，比如说你快速放的时候，人能看出来。不过也不一定，也许他误差非常小。」

- 取到整格确实会出 user 担心的抖动：误差最多半格；像素风里一格在屏幕上十几二十个像素，半格 = 十来个屏幕像素；一面墙每隔一段切一刀，每个新点偏得不一样 = 均匀图案上周期性的错位。所以不取整格。
- **定下来的建议**：
  1. 坐标存成整数，单位 1/1024 格（没有小数、运算精确、各设备一样）。
  2. 切出来的点、展开出来的点按公式算在该在的位置，只量化到 1/1024 格（误差不到 1/2048 格；一格占 30 个屏幕像素时 = 0.015 像素；和平常用小数存的误差同一个量级）。
  3. 重排只做整格的位移、转 90°、翻转——无损靠这一条，和面的角在不在整格上无关（user 自己推出来的）。
  4. **「面的角正好落在整格上」不是全局规范**（撤掉上面第二版里「铺出来的、重排之后的坐标必须是整格」那句）：它只是横平竖直那种展开法想要的性质，等 user 专门讨论那个题目时再定。
- 如果立全家规范，建议的条文只到：「贴图坐标的单位是格，不是零到一的比例；存成整数，不存小数。」不写「必须是整格」。

**状态**：Fable 的建议（整数、角点、单位 1/1024 格；整格不是硬规范）。user 在犹豫、让 Fable 想；立不立全家规范、条文怎么写等 user 定，定之前不进家规。

## 五¾、防御：画好之后再改几何（11-11 傍晚）

user：「关键是我们随时要防御，我们必须非常防御性的想，我们用户画好之后会进行一些点的挪动，甚至是一些比较大的改动，增加删除，拓扑改动都有可能。」

总的一条：**改几何永远不许悄悄毁掉或者改变画。** 默认是像素原样不动、坐标跟着面走；密度偏了、拉伸了、没位置了，明着标出来；要损失像素的修正，用户明着点才做。

| 改动 | 坐标 | 像素 | 之后看到什么 |
|---|---|---|---|
| 挪点、整体缩放 | 不变 | 不变 | 画跟着面拉伸；小窗里标「这几张面密度偏了」，给「摆正重铺」（有损，明着点） |
| 切割、环切、细分 | 子面按原来的公式继承（可以落在格子中间） | 不变 | 画的样子完全不变 |
| 挤出、插入、倒角、新建 | 新面没有位置 | 不变 | 新面是底色；定密度的自动找地方，定大小的放不下就留着、明着说 |
| 删面 | 那些面的没了 | 不变 | 画布上空出地方，下次静默重排收回 |
| 合并面、溶解边（两张面在画布上相邻） | 并成一块 | 不变 | 不变 |
| 同上，但两张面在画布上不相邻 | 新面重铺 | 按面搬过去（有损） | 做之前说一句 |
| 重新布线这类找不到来历的 | 全部重铺 | 按空间位置从旧模型搬到新模型（有损） | 做之前问 |
| 对称 | 另一半共用 | 不变 | 不变 |

**第二个底层动作：按空间位置搬画。** 找不到「这张面是从哪张面来的」时，新排法里的每一格算出它在模型表面上的位置，到旧模型的表面上最近的那一点取颜色。它是所有拓扑大改的保底；第五节的「按面搬」是有来历时的精确做法。

**两道机械的防线**（和「排法成为独立条目」那一轮一起做）：

1. 每条改网格的指令登记它对画做了什么（坐标不变 / 按公式继承 / 新面没位置 / 面没了 / 要搬画），漏登记 = 测试红。照 `src/mesh/mirror-ops.ts` 那张分类表的做法。
2. 随机乱改的探针：在画过的模型上随机做几百步建模操作，每步之后核对——没被碰的面像素逐位相同；每张走画的面坐标都在画布里；除了有意合用的（对称、复制），没有两张面在画布上叠着；撤销回去逐位相同。照 `probe-undo-fuzz` 的做法。

## 七、画布小窗

长远是一个窗三种用法：看 → 在上面画（迷你 WeebPaint；像素风的精确活在二维里做最自然）→ 改贴图坐标。扒取贴图、导入带贴图的模型以后也用它。

立意（user 11-11，听完「一张画 = 一张 atlas、现在的 packing 是最笨的那种」之后）：「嗯有了uv查看器之后我就心理有数了」「我们还是需要透明诚实，虽然是高级功能用户一般不会动」。读法（Fable）：小窗是摆真相的地方——哪张面在哪、谁和谁合用一块、哪里空着、每格归谁，直接看得见；默认行为（合用画布、对称照镜子）发生的那一下说一句；高级的开关放在小窗和材质面板里，一般人不用碰，但不藏。

- 它归认识画画内核的那个共享面板库。内核本来就是二维画布引擎，小窗只是把画板的结果再摆出来一次，和三维里的永远同步，不另存东西。
- 面的轮廓线由三维这边递给它（画布上的折线 + 点中了哪张面的回调）。内核不认识三维，这条界线不动。
- 第一版只看：画布、面的轮廓、三维里选中的面和小窗里的一起亮（两个方向）、放大到看得见格子、每格归谁的调试视图、这张画多大占多少。**排在「开始画」那张单后面紧接着做**：后面的展开、搬家、换大小都要靠它看对不对。
- 画布成了中心之后，小窗里看到的就是「这块画布上所有物件的所有面」，不用再问是哪个物件的。
- **小窗也能开平铺的那种图**（user 11-11 傍晚）：「小窗还有个好处就是，你想画些二维贴图，比如说像砖墙啊、材质啊，你可以正常的二维的画，而不用切weebpaint上。然后最好是你画的时候实时可以看到3d」。平铺的图没有面的轮廓，只是一张图；画的时候三维实时跟着变（两边本来就是同一份结果）。归「小窗里能画」那一步。

## 八、很多张画同时在的时候

- 画板按画布登记（现在就是）。画布不属于物件之后，「这块画板歇不歇」= 还有没有面走它。
- **只醒着正在编辑的那个物件用到的画板**（user 11-11 定：「对，就是只wake在编辑的物体，我们以后做多物体编辑，现在还是当前物体啊」）：它们占着画画那一套（内核的显示目标、显卡上的图块、每格的表）；别的物件的画只留给渲染器的那张显示图。当前物件有好几张 atlas 时，那几块都醒着；一块画布被别的物件合用不影响它醒不醒。几块画板合用一个图块额度。多物件一起编辑以后再做。先量再做，数在流畅那一批里量。
