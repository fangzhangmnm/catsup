## 要达到什么

数据格式第 4 版定的：**画是一种材质**。对一个物件点「开始画」，程序做三件事：给要画的面铺一套贴图坐标；建一张贴图和一个接着它的材质；把这些面的材质换成它。之后改模型，新长出来的面如果走的是这个材质，在长出来的那一步就铺好。

这一张把这些做成指令，能撤销、能重放、有测试。做完之后**没有任何界面入口**（入口是 1-7 的事），画也还显示不出来（1-3c）、画不上去（1-4）：走画的面现在照材质自己的底色显示，这本来就是现状（`colorMapIn` 对分层的贴图返回空）。

## 先说一条总规矩：存盘落地之前，造得出画的入口不进普通界面

贴图坐标进文件是 1-2½，画的字节进文件是 1-8。在那之前，带着画的文件存不下来。所以：

- 这一张的指令只有测试、探针、重放够得着。
- **写盘碰到下面两种情况就抛，写明原因，不许悄悄丢**：网格体带着贴图坐标（`uvSets` 不空）；分层的贴图没有字节（见第三节）。这两处抛分别由 1-2½ 和 1-8 换成真的写。加一条守卫测试钉住「现在是抛」。

## 一、网格体上多一张表：有哪几套贴图坐标

- 网格体的身体（现在是 `{ kind: "mesh", kernel, materialSlots }`）多一张表 `uvSets`：GUID → 一行。
- 一行 = `{ guid, name, width, height, pxPerM }`。宽高是画布的格数（整数）；`pxPerM` 是铺的时候用的密度。条目不可变，改 = 换一个对象（和贴图表一样）。
- 它和内核里**同一个 GUID 的那一列**（1-2 做的，每个角两个数）是一对。以这张表为准：内核里每角两个数的列不一定都是贴图坐标（以后别的用途也走列）。
- **规矩（进场景的自检，和 `check()` 一起跑）**：表里每一行，内核里有同 GUID、每角两个数的列；这一列上有值的角都落在画布里（横 0 到宽、纵 0 到高）。
- 撤销：这张表跟着场景的骨架快照走（浅拷），内核里的列跟着整表互换走（1-2 已经做了）。
- 表的先后没有意思。

## 二、「这个材质是不是画」只有一个问法

放在 `format/document.ts`，紧挨着 `colorMapIn`，两个加在一起是全仓问「这个材质的颜色那一槽是什么」的全部入口：

- `paintIn(贴图表, 材质)`：颜色那一槽的第一张，内容是分层的，而且 `layout` 是 `{ definition, uvSet }` 两个 GUID 字符串 → 返回 `{ texture, definition, uvSet }`。别的情况返回空。
- `layout` 现在的类型是 `unknown`、原样带。形状不认识的照旧原样带，当它不是画。
- **「这张面走不走画」**（场景上的一个方法）：面的材质过 `paintIn` 不是空，`definition` 就是这张面所在的定义，这个定义的 `uvSets` 里有那一套 → 走画。差一样都按普通材质（底色）算。
- 守卫：`src/` 里除了这个文件，不许有第二处去读贴图的 `layout`。

## 三、分层的贴图可以还没有字节

- `TextureContent` 的分层那一种改成 `{ kind: "layered"; ora: Uint8Array | null }`。
- 空 = 新建的画，还没有编过码。读文件读进来的永远有字节。
- 理由：编码要靠画画内核、而且是异步的，指令是同步的；新建的画在第一次存盘时才有字节（1-8）。
- 资源页、清理、粘贴这些读 `ora` 的地方跟着改；空的照样显示成灰色占位。

## 四、三条指令

指令的写法照现在 `ops.ts` 的规矩（面怎么指、GUID 放在指令里好让重放得到同一个身份）。

### 1. `startPaint`：开始画

**交进来**：哪个网格体；哪些面；三个新的 GUID（这一套贴图坐标、贴图、材质）；三个名字；材质的底色；密度（可以不给）。

**做的事**（一步撤销）：

1. 网格体的 `uvSets` 加一行，内核加同 GUID 的一列。
2. 用 1-3a 的铺法给这些面铺上。没给密度 = 1-3a 的默认（1024 见方，找放得下的最大密度），找出来的密度记进这一行。
3. 贴图表加一行：分层的、没有字节、`value` 是颜色、`layout` 指着这个定义和这一套。没有 `sizeM`。
4. 材质表加一个材质：给的名字和底色，颜色那一槽指着这张贴图。
5. 这些面的材质换成它（走 `paintFaces` 现在那条路，槽表照常追加）。

**拒绝（什么都不改，说清原因）**：不是网格体（硬表面）；一张活着的面都没有；三个 GUID 里有已经存在的；铺不下（1-3a 返回的原因：哪张面、要多大）。

### 2. `meshLayoutPaint`：给走画但还没有位置的面补一块

**交进来**：哪个网格体。

**做的事**：这个网格体上每一套被画用着的贴图坐标，找出「走这张画、但角上还没有值」的面，用 1-3a 的「给新面补一块」铺上。已经铺好的角一个数都不变。画布不够就往下加高（256 的倍数），`uvSets` 那一行换成新的高。

- 加到上限（默认 4096）还放不下：**不拒绝、不抛**。放得下的照铺，放不下的面留着没有值，返回「有几张面在画布上放不下」。这些面照底色显示。建模的那一步不能因为画布满了就做不成。
- 所以规矩是：**走画的面要么有位置，要么是这一步明着报出来放不下的。** 不许有第三种（悄悄没铺）。
- 「画布上哪里空着」：只要有面在这一列上占着那一块，就不算空，不管那张面现在走不走这张画。
- 确定性：同样的网格体得到同样的结果（面按编号的先后铺）。
- 找「还没有位置的面」不许每次扫全部的面：靠内核的改动日志只看这一步动过的面。量一下一万面和四万面的网格体上、动了十张面时这一步各花多久（两个数应该差不多；造模型加上量，总共不超过半分钟），写进记录。

### 3. `paintFaces`（现成的，改两处）

- 把面换成一个画的材质，而这张画是别的定义的 → 拒绝，说清原因。
- 把面从画的材质换成别的 → **角上的数留着不清**。这张面不再走画，不显示、以后也不吃笔；它在画布上的那一块留着。再换回来，还是原来那一块，画还在。清掉旧的块是以后「整理」那个动作的事。

## 五、每一步做完的收尾

规矩要在每一步做完时成立，不靠各个算子自己记得。照强行对称现在的做法（`editor/mirror-force.ts`：提交前记版本号，提交后看改没改、补一条指令进同一步）：

- 一条指令提交之后，内核版本号变了的网格体，如果它有画，而且有「走画但没有位置」的面 → 在**同一步**里补一条 `meshLayoutPaint`。撤销时一起撤。
- 「放不下」的那句话接到提示行上（和强行对称的那几句同一个出口）。
- **并面丢了画也在这里说**（11-10 夜补）：1-2 做了「这一步里有几张面在某一列上丢了值」的数（`takeDroppedFaces()`），现在没人读。收尾时拿走这个数，不是零就在提示行上说「有几张面的画没带过来」。加一条测试。
- 预演（拖动中的影子）不补：新面在松手前照底色显示。

**和强行对称一起时**，要成立的三条：

1. 被丢掉的那一半不占画布（不给马上要被删的面铺）。
2. 两半在画布上是同一块：只铺留着的那一半，镜过去的面照抄（1-2 定的）。
3. 全在同一步里，一次撤销回到原样。

做法你定。一个可行的顺序：选好以哪半为准之后，先给留着的那一半补 `meshLayoutPaint`，再对称化；这一步里有新铺的面时，即使形状已经对称也补一次对称化，让镜过去的那一半抄到数。

**先查清一件事再动手，报给我**：现在开着强行对称时，只给一半的面换普通材质，另一半跟不跟着换？什么时候跟？画的材质照普通材质现在的行为走，不为画另开一套。

## 六、这一张先拒绝的（等「画跟着面搬家」那一张）

下面这些动作碰到走画的面，数据上要连贴图坐标、贴图、材质一起复制一份并换新的身份，其中复制画的内容要等存盘那一张。所以这一张先明着拒绝，原因写「带着画的面现在还搬不了」：

- 把一个物件并进另一个（`mergeObject`）。
- 把一部分面分成新物件。
- 把组件变成独立的。
- 复制、粘贴（含跨文件）带着走画的面。

拒绝的判断只有一个函数，这几处都调它。**整个物件一起复制成同一个定义的另一份摆放（实例）不受影响**：它们本来就共用同一张画。

内核那一层 1-2 已经让角上的数跟着整面搬了；这一张拒绝的是场景这一层。

## 七、门

1. `npm test` 全过，`tsc` 干净，截图基线不变。全套测试的时间加之前、加之后各量一遍；过一分钟停下来说。
2. **测试 A：开始画。** 做完之后：`uvSets` 多一行，贴图表多一行，材质表多一个，这些面走画，每个角有位置，自检没有毛病。撤销之后这五样全部回到原样（逐位）；重做再回来（逐位）。同一条指令在副本上重放，结果逐位相同。
3. **测试 B：改了模型新面自动铺上。** 在画过的面上各做一遍：挤出、倒角、内缩、环切、刀、细分、复制面。每一步做完，没有「走画但没有位置」的面；原来有位置的角一个数都没变（细分、内缩这类按 1-2 的规矩继承的另算）；撤销一次回到这一步之前。
4. **测试 C：画布加高。** 一直加新面到画布放不下：高按 256 的倍数涨，已有的角不变。到上限之后：放不下的面没有值，返回的张数对，建模的那一步照样做成了。
5. **测试 D：换走再换回来。** 面从画换成普通材质再换回画：角上的数和原来逐位相同，没有新占一块。
6. **测试 E：强行对称。** 上面第五节的三条各有断言：丢掉的那一半没占过画布（画布上被占的面积和只铺一半时一样）；两半的面在画布上的三角形相同；一次撤销回到原样。
7. **测试 F：拒绝的那几处。** 第六节每一种都试，拒绝之后场景一个字节不变。别的定义的画换不上来。
8. **测试 G：存盘现在是抛。** 带着贴图坐标的网格体、没有字节的分层贴图，写盘各抛一次，原因写得明白；不带这两样的文件写出来和现在逐字节一样。
9. **守卫**：读 `layout` 的只有一处；`uvSets` 只经这一张的两条指令加和改；拒绝的判断只有一个函数。
10. `api/` 重新生成；流程图文档加一节「开始画和新面自动铺」，写清每一步碰多少东西；升一个末位版本。

## 八、碰到这些就停下来报

- 1-2 或 1-3a 做出来的形状和这里假设的不一样（列按 GUID 认、每角两个数、没有值 = NaN；铺法有「给新面补一块」的入口，返回放不下的原因）。
- 收尾补的那条指令和强行对称的先后理不顺，或者要改 `mirror.ts` 里对称化本身。
- 某个建模动作做完之后，新面的材质不是从旁边的面带过来的，而是别的来路，导致它该不该走画说不清。
- 撤销的骨架快照带不上 `uvSets`。
- 第六节之外，还有别的动作会把走画的面带到别的定义里去。

## 这一张不做的

显示（1-3c）；贴图坐标进文件（1-2½）；画的字节进文件、画板（1-8）；界面入口、默认画哪些面（1-7）；删掉没人用的贴图坐标的指令和资源页上的那一节（1-7）；画跟着面搬家（第六节那几种）；整理画布、重新生成一套。

**和施工单不一样的地方**

1. 网格体换材质是新指令 `meshPaintFaces`（你 11-10 改的）；硬表面 `paintFaces` 只加「换成画 = 拒」。
2. 拒绝的地方多了炸开网格体组件、网格体转硬表面（你同意的），还有拷贝时就拒（为了剪切）。
3. paintIn 返回的字段叫 `textureDoc`，指令里叫 `textureGuid` / `materialGuid` / `names.paint`（老守卫不许「点 texture」）。
4. uvSets 写盘的抛放在 `documentFromScene`，不在 `definitionToDoc`：后者也是条目仓库的读面，粘贴对账、变成独立的都走它，放那里会让同一份文件里贴整个物件也炸。
5. 1-3a 的 `layoutAppend` 里面重写了（外面的规矩不变）+ `partial`。
6. **「两个数应该差不多」只做到一半**：找没位置的面那一项是平的，整步收尾四万面约是一万面的三倍（见上）。要整步也平，得给每个网格体留一份随改动日志增量维护的占位表，而且收尾补的那条指令进撤销不能再拷整个内核——这两样我没做，你定要不要。
7. 强行对称下的「开始画」在提交前就被改写成只给留着那半的面（History 里记的就是改写后的那条，重放得到同一个结果）。

**不放心的**

- 同一份文件里粘贴、而那个定义在目标里内容不一样被选了「断开」（换新身份）：贴出来的那份的面带着画的材质，但画指着原来的定义 → 照底色显示，不拒。概率小，记一笔。
- 强行对称只在「这一步有走画没位置的面」时才会让两半同一块；开强行对称之前两半已经各铺了各的，开了之后不会自动并成一块（开关强行对称是 meta 指令、不收尾）。要不要在开强行对称那一下统一，你定。
- `takeDroppedFaces` 的数会被同一步里后面那条网格体指令的「影子换真身」换掉；现在收尾一开始就先拿走。以后谁在收尾之前同一步里再提交网格体指令，要记得这件事。
- 编辑器那一层（拷贝拒绝的提示行、收尾接在 commitIn 里）只有守卫和探针兜着，没有专门的编辑器级单测。
