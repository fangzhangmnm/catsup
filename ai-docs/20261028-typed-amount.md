## 1. 要不要 Fable 改设计：不用

键表（`src/controller/keymap.ts`）本来就是分层的：每次按键从现状算出压着哪几层，从顶往下找。加一个模式 = 加一层。数值小窗（VCB）已经是同样的做法：它那一层只有一条「`*` + 它说要才要」的绑定。打数这一层照抄。

## 2. 行为（照 Blender）

| 按 | 结果 |
|---|---|
| S（键盘起手，有选区）→ Z → 0 → 回车 | 沿物体自己的 Z 缩放 ×0 = 压平，一步撤销 |
| G → X → 1.5cm → 回车 | 沿 X 挪 1.5 cm（单位在最后打；不打单位 = 当前显示单位） |
| R → Z → 90 → 回车 | 绕 Z 转 90° |
| E 0.5 / I 0.1 / Alt+S 0.02 | 挤出 / 插入（倒角）/ 沿法线，打的是长度 |
| 退格 | 删一个字；删空了 = 回到照鼠标走 |
| 回车 / 点一下 | 定（和「点一下落定」同一条） |
| Esc | 只取消这次操作，选区留着（自由建模；硬表面的 Esc 照旧） |
| 打到一半按 X / Y / Z | 照旧锁轴（单位里没有这三个字母） |

拖着没松时也能打：松手按打的数落定。回车只管「点一下落定」那种手势（键盘起手 / 点了一下在等下一点）。

## 3. 一个读法（和单位文本框同一个深模块）

`src/editor/units.ts` 的「量」本来管长度和速度（存 SI、显示跟用户选的单位、什么单位都接），单位文本框（工具条 / 马后炮的数）用它。这次加两种量：

- `angle`：存弧度，打 / 显示按度（`30`、`-45°`、`30deg`、`30度`、`0.5rad`）
- `factor`：倍数，无量纲（`0`、`1.5`、`-1`、`50%`）

加一个函数 `quantityKey(tag, buf, key)`：这个键能不能接进这一段量的文字。规则：数字、小数点、正负号永远能进；单位那几个字只在已经有数之后才进。长度是 m c i n f t ' " 空格 /，角度是 ° d e g r a，倍数是 %。X / Y / Z 永远不进。

编辑器读打的数只调 `parseQuantity`。单位文本框调的也是它。哪个键能进只调 `quantityKey`。

## 4. 谁管什么

- **工具**只声明 `typedQuantity`（自己收哪种量），只问 `ctx.typed()`（打的数，没打 / 看不懂 = null → 照鼠标）。移动 / 沿法线是长度，旋转是角度，缩放是倍数，挤出 / 插入是长度。
- **编辑器**住打的字：一次手势一份，手势没了在 `closeStep` 里清。它答两件事：这个键要不要（`gestureTypingWants`），打进来怎么办（`typeIntoGesture`）。回车 = `confirmGesture`（同点一下）。状态行一直显示「打数：…▏」，和预演读数并排。
- **键表**加 `TYPING` 层（`gesture:typing`），压在手势层上面，只有一条 `*`，问 `c.typingWants`。
- **app**（`main.ts`）把 `typingWants` 接到编辑器，动作 `gesture.type` 转给编辑器。

## 5. 每把工具怎么用打的数

- 移动：锁着轴就沿那根轴走这么长。没锁就沿目前拖出来的方向，锁着面时取面里那个方向。还没有方向，读数提示「先锁一个轴或者拖出个方向」，不动。
- 旋转：绕锁着的轴转，没锁就绕视线。
- 缩放：锁轴就只沿那根轴，锁面就只在面里，什么都不锁就三轴一起。
- 挤出：锁轴就沿轴。面沿法向，边和点沿各自的垂直方向。
- 插入 / 倒角：打的是宽度。

## 7. 没做 / 以后

- 硬表面的工具没接（SketchUp 的打数是「做完再打」，走数值小窗）。
- 表达式（`1+2`、`/2`）没接；`parseQuantity` 加了，这里自动有。
- 触屏上怎么打：键名芯片 / 数值小窗那套数字键盘还没接到手势中。
