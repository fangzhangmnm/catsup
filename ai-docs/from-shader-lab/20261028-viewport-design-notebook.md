- **现状：GB 和卡西欧是怎么做的**（AI 核过代码，10-28）：
  - 屏幕层：同一个后处理着色器、同一个分支（`lab/app.js` 的「没有背光的单色反射屏」），只换三个数：不通电的颜色、通电到底的颜色、像素缝的宽度。
  - 屏幕不量化：它把输入按亮度算成**连续**的通电程度（通电 = 1 − 亮度），再在两个颜色之间插值。方块机那块屏同样按亮度连续地点亮。
  - 量化在风格那一层：「GB 真实屏幕」「卡西欧」「卡西欧 · 灰度引擎」「俄罗斯方块机」四个预设都是复古着色器，各用一种色板模式——GB 四档（按亮度分四档）、黑白（按亮度一刀切）、灰度引擎（交替刷屏 + 慢液晶的解析纹波）。扁平版的 GB / 卡西欧是平涂着色器 + 调色板（带朝向分阶护栏）。
  - 所以现在的兜底 = 按亮度连续映射：写实、Tron 放到 GB 屏上，出来是连续的灰，不是四档。「屏幕强制色板」还没实现。
- **屏幕正交以后对别的有什么限制**（AI 的读法，未拍）：
  1. 分辨率：风格得能画进任意大小的缓冲（已经能）；跟着屏幕像素走的东西要按低分辨率换算——解析描边换像素描边（已做）、细件保底宽度、Tron 的线宽和辉光半径。
  2. 色板：屏幕真的强制四档 / 黑白以后，不认识色板的风格会出断层——渐变变台阶、辉光和抗锯齿的半透明边变成一块块、几个面落进同一档融在一起（10-26 扁平 GB 加朝向分阶护栏就是为这个）。今天不抖动，所以只能靠风格自己挑档，或者外壳按亮度硬切。
  3. 时间：屏幕自带残影 / 余辉，风格自己的时间效果（Tron 余辉、脉冲）会叠两次；自动旋转在慢液晶上糊。
  4. 亮度：反射屏假定的是环境光，风格自带的曝光 / 色调映射会被再压一遍（第 31 版 GBA 补光就是这个：游戏颜色本来画亮了补偿，3D 渲染没有补偿，暗两遍）。
  5. 几何：屏幕变形要鼠标逆变换（2.6）；编辑叠加层叠在屏幕前还是后（2.4）；真机大小 + 机框会让编辑时的视口变小。

- **倾向 → 定了一半**（user「我也觉得色板应该是shader自己根据几何算的，根据screen pixel算反而很多东西看不见」）：屏幕只交出「这块屏有哪几档」；落进哪一档由风格的着色器按几何算（朝向、明暗、边、零件），不在屏幕那一步按像素亮度硬切——按亮度切会把面和面、零件和背景的区分切没。外壳按亮度硬切只当没办法时的最后一档兜底。
- **等 user 教**：四色色板怎么挑档（user「四色的色板我可以优化一下，你的方案比较保守，以后我可以教你」）。现在的做法是朝向分阶护栏：一盏钉在画面左上的光，按平滑法线分三阶，再加一点模型自己的深浅。

- **倾向**（user「某些色彩太少的屏幕，其实就是gb casio 方块，不接受屏幕像素。需要着色器兜着。强行覆盖可以让用户做实验 / 然后其他的屏幕可以接像素。然后用户可以调gamma之类的」）：屏幕分两种——
  - 色彩太少的（GB、卡西欧、方块机）：不接任意风格的像素，要风格的着色器自己兜住色板；用户硬要覆盖也行，算做实验。
  - 其他的（GBA、NDS / PSP 的 TFT、CRT 电视 / 显示器）：接像素，用户可以调 gamma 之类的。先把 gamma 调好（10-28 量过：同一张写实放上去，平均亮度（线性）比无屏幕低——CRT 电视 −35%、CRT 显示器 −14%、TFT −13%、GBA −43%；CRT 的扫描线、荫罩、暗角是在编码后的值上乘的，不守能量）。
- **矢量显示器是特例**（user「矢量显示器是完全另外一回事……算了，no，矢量显示器接不住线稿……反而就是当做一个需要单独照射器的特例吧」）：它不是一块像素屏，要自己的「照射器」（电子束按线画）；不接任意线稿风格。

- **复古着色器里几种色板是怎么做的**（AI 核过代码，答 user 10-28 的三问）：
  - 卡西欧黑白：不借模型颜色（底色浅灰）；逐顶点打光，太阳固定在世界里（强度 0.75、环境 0.3）；亮度过 0.5 是白、不过是黑；再描 1 像素黑线（外轮廓 + 深度跳变）。可读性就靠三样：太阳把面分成白 / 黑、描线把轮廓和前后层次分开、不抖动。**没有朝向分阶护栏**：转到背光的角度整个模型几乎全黑、只剩线；侧光时同朝向的面全白、融成一片——这多半就是 user 说的「casio不好看」。
  - 合租：是。GB 四档、卡西欧黑白、卡西欧灰度引擎是复古着色器里同一段代码的三个分支——前面的光照、亮度一模一样，只有最后一步分档不同（GB 四档 = 亮度 × 3 四舍五入；黑白 = 亮度过 0.5；灰度引擎 = 同四档、再加慢液晶的纹波）。屏幕那一层 GB 和卡西欧也合租一个分支。改一处三个都动。
  - NDS：也是复古着色器，借模型颜色；两阶卡通光（逐顶点算，环境 0.55 + 太阳 0.5 ×「朝光够不够」）、最近邻、贴图上限 128、每通道 6 位（18 位色）、不抖动；1 像素描边（固定深灰和「近邻 × 0.42」各占一部分）；256×192、带背光的 TFT。今天没改它的预设；第 36 版改了共用的描边判法，和第 35 版比，熊 / 小红帽 / 坦克各只差 40–78 个像素。
- **做了**（第 37 版）：GB 真实屏幕、卡西欧灰度引擎接上朝向分阶护栏 + 最暗那档给明暗用（和扁平 GB 同一套）；卡西欧黑白还没接（等 user 教四色映射时一起定）。

- **做了**（第 41 版，gamma）：接像素的屏的扫描线、荫罩、晕、暗角、像素缝改在线性光里乘、按平均归一。同一张写实（320×240）的平均亮度：CRT 电视 −29% → −15%（剩下的是真有的暗角，四角暗三成）、CRT 显示器 −10% → −4%、TFT −20% → −4%、GBA −43% → −41%（台灯下的色调曲线是 user 要的，没动）。加了「屏幕 gamma」滑杆，只管接像素的屏。
- **矢量显示器下线**（user「矢量显示器sunset,移动到tron 复古里面，加显示器」）：街机显示器框给了「青 Tron · 复古」；矢量屏那套着色器代码留着。

- **描边归谁**（user「描边应该归谁」；AI 的答，待拍）：归风格（着色器那一层），用公用件实现（实验室的 `ShaderLab.pixelOutline`，扁平的「像素描边」和老主机的 NDS / GB / 卡西欧共用）。理由：
  1. 它要几何：深度跳变、零件边界——只有画几何的那一步才有（NDS 真机的 edge marking 也是 GPU 按多边形 ID 画的，是主机的渲染，不是屏幕〔凭记忆〕）。
  2. 它要挑颜色：落进色板哪一档、同色系加深——这就是「怎么落进色板」，上面定了归着色器。
  3. 各风格的线不是一回事：Tron 的线就是画面；雕塑是可开关的淡叠加；像素画是 1 像素深色；NDS 是主机硬件的描边。
  4. 屏幕只给分辨率和色板（「1 像素宽」从这里来）。
  5. 编辑器的选中描边、线框、gizmo 是另一层（本节上面），不归风格。
- **做了**（10-28，第 36 版）：像素描边按深度跳变检测、默认开（透视下 1/z 对屏幕仿射，按对面那格外推到邻居，斜地面不出假线）；扁平 GB 最暗那档也给明暗用一点（user「4色的时候深色也让明暗用一点」）。已知：关卡地面上的矮台阶描成虚线（高度差落在阈值附近）。

- **做了**（第 37 版，user「像素描边有两种预设，一个是可爱扁平sokpop细的，一个是黑线的更加清晰的gba 或者pixel art系的」）：描边公用件加「压暗多少」和「取两侧暗的那一侧」；「像素描边」= 软的（同色相 × 0.72），新加「像素描边 · 黑线」（取暗的一侧 × 0.25，近黑）。

- **定了**（user 10-28）：选中的面——Tron 就是换颜色（Clu 的橙）；铸铜用雕塑那一档的方案（很淡的线框 + 点叠在上面，选中的照常显示）；GB 和像素风还没想好。

  - 描边不靠模型大小：像素描边的判据是相对深度（邻居近 4% 以上、外推差 3% 以上），按「离相机多远」缩放，不按「东西多大」——整个场景放大十倍，判出来一样。近远平面固定 0.2 / 30。
- 到了 GTA VCS 那种城里编辑一个房子，会出问题的（AI 的读法，未拍）：
  1. **按整个模型算的服务**：一张深度图盖整座城，房子只分到几个像素——遮蔽和影子没了。要改成跟着相机 / 选中的那一块（级联影子、只烘选中物体周围）。
  2. **材质里的长度**：半透、层纹、倒角现在是「模型半径的几分之几」，城里的房子和桌上的手办会按同一个比例透光。该写成物理单位：玉的透光距离是毫米级、FDM 层高 0.1–0.3 毫米、倒角几毫米；文件告诉我们一个单位是多少米（CatsUp 存档有单位）。那样玉做的房子就几乎不透光——物理上本来如此。
  3. **描边**：判据是屏幕空间、相对深度的，本身不怕尺度；怕的是深度精度——近远平面差几万倍时远处深度挤成一团，相对 4% 的跳变量不准。近远平面要按视野动态取，或者换线性深度 / 反向 Z。
  4. **「关注尺度」**：编辑一个房子时真正要的尺度是「选中的那个东西多大」，不是整个场景多大——服务的范围、噪声的频率、LOD 都可以锚在它上面。
- **user 拍了**（10-28）：
  1. 按整个模型算的服务改成跟着相机 / 选中物体那一块算（级联影子、只烘选中物体周围）——**同意**。
  2. 物理单位——本来就是物理单位起家的；但实验室现在的「自动特征长度」（把模型缩到半径 1 再按比例算透光、倒角、层纹）是**有意的「自动 miniature」**，和移轴一个道理：lookdev 的是微缩模型的样子（user「我们lookdev的是miniature,一开始做自动特征长度就是为了这个……其实和移轴一样，本质是自动miniature」）。房子在实验室里效果不好，是因为它被当成了微缩模型看。→ 两种都要：「真实尺寸」（物理单位）和「自动 miniature」（按模型大小缩放），后者是实验室现在的默认。

### 2.14 线的颜色：往粉白走，还是往黑清晰走
- 起因：user「线稿的颜色是不是按照材质颜色智能选的。这么说的话其实也有往粉白走和往黑清晰走两种。现在新的色稿不知道为什么小红帽不好看了，但是熊和场景都好看，先不要急着改，思考一下为什么」。
- 现状（AI 核过代码）：「像素描边」的线色 = 挨着的、离相机近的那一格的颜色 × 0.42（同色相压暗，在编码后的值上乘）；GB、卡西欧是固定色。
- 对比图（小红帽 / 被诅咒的熊 × 纯色像素 / 只描外轮廓 / 加深度跳变）看出来的，AI 的读法，按可能性排，**没改代码**：
  1. × 0.42 落在两条路的正中间：暗色乘完近黑（熊的棕、场景的深绿，线清楚）；浅色乘完是灰、褐（白裙一圈中灰、粉皮肤一圈褐粉、金发一圈橄榄褐）——既不黑也不粉，是发脏的那一段。小红帽大部分是浅色。
  2. 内部的线画在远的那一侧、用近的那一侧的颜色：红斗篷压在白裙上 → 白裙那格上一道暗红，读成「渗色」不是「线」。v36 加深度跳变以后才有，所以是「新的」不好看；熊和场景相邻的颜色接近，看不出来。
  3. 小红帽的贴图自己画了线和光（斗篷白边、眼睛、花纹），几何线再叠一层就打架；熊的贴图是毛和明暗，没画线。
  4. 小红帽层叠多（斗篷、裙、头发、两条腿），三百个三角里深度跳变多，内部线又多又短。
- **更正**（user「你渲染的太大了，我渲染的比较小，第三人称远视角」）：上面那四条是凑近截的图（镜头距离 2.4）；按远视角（距离 6、9）重截后，读法改成：
  1. **线的分量**（最主要）：远看小红帽只有几十个像素高，手、腿、发尾只有 1–2 像素粗，外面再包一圈 1 像素（放大后 3 屏幕像素）的线，细的部分就只剩线、看不出颜色。熊是大块的，线只占外面一小圈。
  2. 线色 × 0.42 对浅色是灰褐（同上），远看整个人发灰；熊是暗色，线近黑、清楚。
  3. 脸被压住：小红帽的贴图分辨率都给了脸和眼睛（建模历史 §2⅞），远看脸只有几个像素，帽子和头发的外轮廓线正好贴着它。
  4. 内部线远看只多几个像素，影响小——「不好看」主要不是 v36 的深度跳变，是像素描边这种画法放在细瘦、浅色的角色上。
  - 和 2.12「尺度」接上：线的分量要跟着东西在屏幕上有多大走——远了、细了就减线 / 变淡（线的 LOD）。
- 验证法（未做）：只换线色为固定近黑 → 看 1 占多少；只关内部线 → 2、4 一起消失。
- 两条路的做法（AI，未拍）：往黑清晰 = 两侧取暗的那一侧再压到近黑（动画线稿）；往粉白 = 往白里提（贴纸描边）；「智能选」= 按材质明度决定往哪边走。

### 2.15 线色和屏幕边的结论（第 39 版做了）
- **线色**：中间那档（同色相压暗一点）不要——它落在填色和背景之间，看着像抗锯齿的毛边（user「反而是现在的淡线版本有抗锯齿的难看感」）。线要么明确往黑（「像素描边」= 黑线，扁平门面），要么明确往白（粉白、纯白 1 / 2 像素都试过）——**定了：只留黑线**（user「白的不行，放弃，就留黑线稿，这个最可爱」）。AI 的读法：线和填色、背景要拉开明度差，落在两者之间就会被眼睛当成边缘的过渡。
- **屏幕的四角 / 边**（按工艺，数值凭常识估）：CRT 已有暗角（电视三成半、显示器一成半）；带背光的 TFT 侧入式背光，四角暗一成左右；反射屏自己不发光、没有光学暗角，但屏凹在塑料窗下，光从左上来，窗框唇边在上沿、左沿投一条软影；卡西欧嵌得深（user「卡西欧我记得屏幕嵌入蛮深的」），影子更宽更深。

### 2.18 标准管线（universal / standard，慢慢整理）
- 起因：user「对，我们现在可以慢慢整理出来universal/standard管线」「过曝应该是视口而不是材质对吧」。
- **倾向**（AI 的读法，user 说「对」的是方向，层的细节还没逐条拍）：一帧从前往后分三层——
  1. **相机**：曝光、炫光（辉光 + 星芒，亮部才有）、色调映射（ACES）。曝光属于视口 / 相机，预设只「建议」一个值；材质不管过曝。
  2. **风格**：怎么画（材质、线、平涂、复古主机的硬件特征）。
  3. **屏幕**：分辨率、色板、物理显示（像素格、反光、扫描线、残影）。
- 第 48 版做到的（AI 核过代码）：炫光是公用件 `ShaderLab.glare`（核心库），水晶和表面两个着色器都调它，参数一份定义（辉光、星芒、几道、亮部门槛）；相机这一层现在还是每个着色器自己调，没有拆到外壳。
- Tron 的回答（user「tron反而觉得暗了，你做bloom了吗」）：Tron 有自己的多级辉光，一直有；第 40 版把屏幕外面统一改成中灰，发光的画面放在中灰中间被衬得发闷，所以看着暗。第 48 版改成按观看条件：反射屏（GB、GBA、卡西欧、方块机）在亮房间看，四周中灰 #4d4d4d；自发光的（CRT、背光屏、Tron）在暗房间看，四周深灰 #151515。
- 现状（user 问「其他的材质是全量接同一个高光管线吗」，AI 核过代码）：表面着色器的所有预设都走同一段代码，炫光的开关和强度是预设上的参数；第 49 版开着的只有金属（首饰黄金、白银、铂金、钢铁雕塑和它的切面版、黄铜和它的切面版），其它是 0。平涂、硬边线、老主机不走这个公用件（Tron 有自己的辉光）。
- **定了方向**（user「对的」）：照「曝光、炫光归相机」，炫光是视口的一个开关，所有走 HDR 的预设一起开，谁发光由亮部门槛决定——哑光的东西本来就到不了门槛，自然不亮。
- **user 的担心**：「我就是怕一下srgb调好的放进去会很闪。我建议是二次元（shadeless）的材质有没有办法逃」。AI 的办法（等 user 拍）：
  1. 门槛是线性 HDR 的单位、大于 1；二次元 / 平涂这种按 sRGB 调好的画面输出的是显示值，最白也就是 1，本来就到不了门槛。
  2. 再加一道明的：每个材质声明自己是「按场景算光的」（写实、金属、玻璃）还是「按屏幕调色的」（二次元、平涂、shadeless）；后一种在亮部那一遍写一个「不进炫光」的遮罩，亮部乘上它。
  3. 反过来，二次元里真要发光的地方（发光的眼睛、魔法）用自发光遮罩单独点名进炫光——二次元风格的游戏也是这么做的：辉光看自发光遮罩，不看亮度。
- **定了**（user「嗯和我想的一样，做」），第 51 版做了：
  - 画面栏「炫光」开关（默认开），表面和剥层玻璃的所有预设一起受它管；预设上的辉光、星芒是建议强度，表面着色器的相机默认是辉光 0.25、星芒 0.1；低分辨率档自动不开。
  - 公用件的浮点图 alpha = 遮罩：1 按场景算光（乘曝光、色调映射、过门槛才发光）；0 按屏幕调色（原样上屏，不进炫光）；负数 = 按屏幕调色但点名发光（不看门槛，按 −alpha 进炫光）。炫光叠在按屏幕调色的像素上用滤色，不冲爆。
  - 用上的：2014 SSAO 白模的模型写 0（它上屏的是遮蔽值本身）。点名发光那条路做好了，实验室里还没有模型带自发光的信息，第一个真用户是 CatsUp（文件里的材质语义）。
- **全家统一的路线**（user「全家统一一下，我们慢慢收」；AI 排的顺序，等 user 拍）：① 表面、剥层玻璃（第 51 版，已经走公用件）；② 平涂、老主机、最省、线稿画进同一张浮点图、写遮罩 0——结果和现在一样，但相机这层（曝光、炫光、色调映射）只剩一处；③ Tron 的辉光改成「线写负数遮罩、点名发光」，和公用件合一（Tron 是门面，要对比着改）；④ 相机这层挪到外壳，插件只管画。
- **开着**：相机这一层什么时候从各着色器挪到外壳（等所有着色器都输出线性 HDR 才能挪；平涂、硬边线、老主机现在直接出显示值）。

### 2.19 半透明分两类：焊死的 / 分层的
- **定了**（user「可能分一下什么是分层玻璃有内部多层结构好看，什么是虽然有点transcluent但是里面假设焊起来好看」）：
  - **焊死的**：玉、翡翠、琥珀、蜡、牛奶玻璃、树脂、光固化（表面着色器里 `trans > 0` 的全部）——几个零件拼起来的模型当一整块实心，里面埋着的零件不透出来。
  - **分层的**：剥层玻璃（水晶、冰、紫水晶、钻石、彩色玻璃）——一层层表面都画出来，里面的结构就是看点。
- **第三类：有面没实体**（user「糖纸只有一层，和肥皂一样，然后肥皂不带色彩。这个确实是一种新的模态就是有面没实体」）：肥皂膜、糖纸——每张面就是一层没有厚度的膜，不量厚度、不吸收；肥皂膜本身无色，颜色全是薄膜干涉。第 49 版的肥皂泡走剥层玻璃的「膜」模式，就是这一类（每层表面当一张膜）。糖纸只有一层（开放的面，不是闭合的壳）。
  - AI 补的接点（等 user 拍）：CatsUp 文件里要能分「闭合的实体」和「只是一张面」——同样一个球，当实体是玻璃球、当面是肥皂泡；开放的面（一张纸、一块布、糖纸）本来就只能当面。焊死的半透要量厚度，只对闭合实体有意义。
- 做法（第 48 版，AI 写的）：厚度取两个估计里小的那个——「最远背面 − 正面」（零件重叠算对，但零件之间的空气也算进去）和「所有背面深度之和 − 所有正面深度之和」（空气不算，但重叠处算两次）；两个都不比真实厚度小。以前量「到最近一层背面」，最近的背面常是埋在里面的零件。
