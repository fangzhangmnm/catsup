# 代价估算：水晶、Tron 和 CatsUp 现状、基础版比，在 Quest / PC / iPad 上

> created 20261026 by Claude Opus 5.5。user 10-26：「做好之后评估一下他们和catsup的现状和最乞丐版的shader比，在meta quest, pc, ipad上面代价是多少」「可以把代价估算写到html里面」。
> 名词（user 同日纠正）：「乞丐版的意思应该就是每个模式和预设的matcap或者别的近似优化，你那个应该叫基础版」。所以本文的「基础版」= 一遍几何平涂的基准；「乞丐版」= 每个模式自己的便宜近似（matcap、两遍直画等），做好后各占一行。
> 页面「代价」栏就是这份的活版本：估算表跟着当前参数变；到真机上打开，那一栏还会显示实测帧间隔，浏览器支持时也显示 GPU 计时。

## 怎么算的

- **只算两样**：
  - 显存带宽：每像素搬多少字节 × 像素数，加上顶点读取；
  - 每次切换渲染目标的固定开销。

  不算运算量，因为手机和 Quest 上瓶颈通常是带宽。水晶 6 层每像素大约 900 次运算，在 Quest 3 上：窗口模式约占算力的 3%，XR 约占 20%（推测），所以不算它问题不大。
- **两种 GPU**：
  - 普通 GPU（PC）：每遍的颜色、深度、多重采样都要写回显存；
  - 分块 GPU（Quest、iPad、手机）：一遍里的东西留在片上，只写最后那张。全屏后处理在两种 GPU 上一样贵，分块省不掉。
- **每像素字节数**（半精度颜色按 8 B 算），由各插件的 `cost()` 报：
  - 基础版：普通 GPU 12 B / 分块 4 B，1 遍几何；
  - 水晶 K 层：普通 GPU 约 58K + 22 B，几何 K 遍、切 2K + 2 次渲染目标；
  - Tron：普通 GPU 约 320 B（4× 多重采样的两张颜色加深度），分块约 58 B，几何 2 遍（含被挡住的边）、切 16 次（辉光四级各三次）。
- **顶点读取**：按 CatsUp 倾向的格式算：索引网格约 15 B / 三角形，带边信息的数组约 40 B / 三角形。实验室自己用的三角形汤是 288 B / 三角形，是 7 倍多，所以 CatsUp 照实验室的格式接会更贵。
- **设备**：带宽取公开规格峰值的一半左右当「实际能用的」。全部是量级估计，没在真机上测。

| 设备 | 假设 |
|---|---|
| Quest 窗口 | Quest 3 浏览器里的 2D 窗口，1280×720、像素比 1、72 Hz；峰值约 51 GB/s，按 25 算；分块 |
| Quest XR | Quest 3 WebXR 沉浸，两只眼各约 1680×1760、72 Hz；同上 |
| PC 独显 | RTX 3060 级，峰值 360 GB/s，按 250 算；画布 1580×950、像素比 1 |
| PC 核显 | Iris Xe 级，和内存共用，峰值 68 GB/s，按 30 算；笔记本像素比 1.5 |
| iPad M | iPad Air / Pro，M1 峰值 68 GB/s、M2 100 GB/s，按 50 算；1180×820、像素比 2；分块 |
| iPad A | 基础款（A13 / A14），峰值约 34 GB/s，按 17 算；1080×810、像素比 2；分块 |

## CatsUp 现状（CatsUp 自述，v0.14.61，10-26）

- WebGLRenderer 开了 antialias（默认缓冲多重采样），powerPreference 是 high-performance；
- `setPixelRatio = devicePixelRatio`，**不封顶**；
- 面用自写的 ShaderMaterial：顶点色乘一盏跟相机走的方向光，亮度 = 0.66 + 0.34·|n·L|，没有高光、阴影、PBR；
- 线：线宽 1 用 gl.LINES；线宽 > 1 用三角形粗线（LineSegments2）加剪影判定；高 DPI 设备默认线宽 1.5，走粗线；
- 没有后处理；覆盖层在同一遍里画；
- **按需渲染**：有变化才画，只有步行模式和 XR 才连续跑；
- 基准：全合并坦克约 3.3 万三角、2.4 万条线。

表里按「默认缓冲 4× 多重采样 + 一遍面 + 一遍线」建模：普通 GPU 40 B / 像素，分块 8 B / 像素。

## 结果（毫秒 / 帧，预算：Quest 13.9、其余 16.7）

| | Quest 窗口 | Quest XR | PC 独显 | PC 核显 | iPad M | iPad A |
|---|---|---|---|---|---|---|
| 基础版 | 0.3 | 1.1 | 0.1 | 1.4 | 0.4 | 0.9 |
| CatsUp 现状 | 0.4 | 2.0 | 0.3 | 4.6 | 0.7 | 1.8 |
| Tron（青 Tron） | 3.8 | 15 | 2.2 | 36 | 5.3 | 13 |
| 水晶 2 层（2014 水晶坦克，当时叫「2014 原味」） | 5.5 | 31 | 1.0 | 16 | 10 | 27 |
| 水晶 6 层（水晶） | 14 | 84 | 2.5 | 43 | 28 | 73 |

读法：

- CatsUp 现状和基础版是一个量级，哪里都不成问题，何况它不动就不画。
- **Tron** 在分块 GPU 上还行：多重采样留在片上，主要花在辉光的四级模糊上。在 PC 核显上最差（普通 GPU，多重采样整片写回）。Quest XR 超预算一点。
- **水晶**是全屏多遍的典型：每多一层，就多一遍几何加一遍全屏合成，分块省不掉。只有 PC 独显能随便开；iPad、Quest 要靠「手机」画质（两遍直画，见下）。
- **最便宜的杠杆**，按效果排：
  1. 降像素：像素比封顶，或者用低分辨率档。像素数按平方算，iPad 从像素比 2 降到 1.5，代价乘 0.56；
  2. 少几层：水晶 6 → 2 层，代价约乘 0.37；
  3. 关辉光：Tron 少 12 次渲染目标切换；
  4. 不动就不画：CatsUp 已经在做。

## 手机画质：2014 年手游技美里，哪些今天还赚

user 10-26：「做一个mobile的高度优化版，想一想2014年的手游技美有多卷。不过如果legacy反而会伤现在设备的性能也不用那么极端」。

| 手法 | 今天 | 为什么 |
|---|---|---|
| 不用离屏缓冲、不做全屏后处理 | 还赚 | 分块 GPU 的瓶颈在带宽，每一遍全屏都是一整屏读写 |
| mediump / fp16 | 还赚 | 手机 GPU 上半精度吞吐还是翻倍 |
| 透明物体「先背面、后正面」两遍，代替深度剥离 | 还赚 | 背面用乘法混合把身后压暗（层数越多越暗，当厚度用），正面加反射；不读回帧缓冲 |
| 反射用球面图 / matcap，一次贴图读取 | 还赚 | 就是 2014 年那份作业的做法 |
| 掠射角的彩虹渐变假装色散 | 还赚 | 一个函数，不读贴图 |
| iPad 上少用 discard | 还赚 | 苹果 GPU 一 discard 就丢掉隐藏面剔除 |
| 分块 GPU 上开多重采样 | 还赚 | 片上解析，几乎免费 |
| 顶点色烘遮蔽 | 还赚 | 不占贴图 |
| 为了避开「依赖读取」，把 UV、菲涅耳挪到顶点着色器 | 今天亏 | 这类读取现在不慢了；3 万三角形逐顶点算，插值量比逐像素还大，低模上还会出插值瑕疵 |
| 16 位颜色缓冲 | 不需要了 | |

## 怎么在真机上看

在 Quest 浏览器、iPad Safari 打开发布版，切到要看的覆写，看「代价」栏第一行：

- **帧间隔**：被屏幕刷新率封顶，所以只能看出「掉没掉帧」。
- **GPU 计时**：只有浏览器给 `EXT_disjoint_timer_query_webgl2` 时才有，桌面 Chrome 一般有，Safari 和 Quest 多半没有。
- **对照**：同一台设备上切到基础版，就是这台设备的地板。
