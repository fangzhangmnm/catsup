## 一、显示（层级显示施工单第三节）

### 1. 各档现在画了什么（图 1–6）

| 图 | 场景 | 正在编辑的这一层（A 自己的几何） | 这一层的子物体（B、C） | 外面的（地、S、A 的分身） |
|---|---|---|---|---|
| 1 | 根层、线稿 | 根的散几何（地）= 深色线 | S、A、A 的分身、B、C 全部深色线 | —— |
| 2 | 进 A、硬表面、线稿 | 深色线，没有点 | **深色线，和 A 一模一样**（分不出哪层能改） | 整块淡掉：面淡、线淡（`faceDim` / `edgeDim`） |
| 3 | 进 A、选中 B | 同上 | B 整个子物件的面和边都换成选中色 | 同上 |
| 4 | 进 A、像素描边 | 黑描边 + 线 | 黑描边 + 线（和 A 一样黑） | 线是灰的（淡掉），地的外轮廓仍是黑描边（后处理描边对谁都画） |

结论：画风不带线（写实、铸铜、剪纸）时，「只有能改的那一层有线」**已经成立**（`render3.ts` 1047 行 `showL = 有线 && (画风 edges === "all" || 这一层是正在编辑的)`）。要改的是带线的画风：线稿、像素描边、1-bit、Tron（`preset/index.ts` 里 `edges: "all"` 的四种）。

### 2. 粗线现在标什么
**不是选中**（user 记的是选中）。粗线 = SketchUp 式的轮廓线：悬空的边、只挂一张面的边界边、两侧面朝向相反的剪影边，比内边粗约一倍（总宽不超过 5 设备像素；`render3.ts` 67 行 `profileAdd`）。选中的边是同样粗细、换成蓝色（`edgeSelected`）；悬停 / 将删是红色（`edgeHot`）；检查是橙色。

### 3. 「画风要求显示线框」现在对应什么
只有画风表里的一个字段：`material.edges` = `"all"`（线稿、像素描边、1-bit、Tron）或 `"none"`（剪纸、写实、铸铜）。没有单独的开关。另有「线稿粗细」= 设备像素线宽（1 / 1.5 / 2 / 3），和画不画无关。

**要统筹定的一处（核心）**：默认的「线稿」画风（建模时的默认看法）算不算「画风要求显示线框」？
- 算：默认看法里外层和子物体照旧有线，能改的那一层只多出顶点小圆点——user 嫌的「分不出在哪一层」在默认看法里基本不变。
- 不算（我倾向这个，照施工单标题「只有现在能直接改的才显示线框」）：线稿画风的线就是编辑用的线，只画在能改的那一层；像素描边 / 1-bit / Tron 的线算画风要求的，照画，能改的那一层加顶点小圆点。Blender 物体模式里别的物体也不画网格线，只有正在编辑的那个画。
- 你不回我就按「不算」做，记进施工记录。

### 4. 点、碰、只看这个
- 单击：这一层的几何 = 点到的元素；这一层的子物体 = **整个直接子物体**（`editor.ts classify → topChild`）；外面的、分身 = 什么都不是（单击 = 清掉选区）。框选走同一个分类器（`selecting.ts`）：外面的不进框。
- 悬停：只亮这一层的面 / 边；**移到子物体上不会整个亮**（没有子物体的悬停高亮）。
- 双击：点在子物体上 = 进去；点在空处 **或外面的东西上** = 退一层（`hierarchyTapAt`；手指双击同语义）。
- 「只看这个」（左上面包屑右边的钮）：这一层和它里面的之外整个不进世界——不画、不吸、点不中（`world-view.ts insideContext`，构造世界时就跳过）。

### 5. 照规矩改会碰的画线代码
- `src/minccino/providers/three/render3.ts` 1047 行 `showL`：现在只看 placement 的 `tier`（= 正在编辑那一层）和画风 `edges`。
- `src/editor/stream-provider.ts` 157 行：placement `tier: s.active && this.editing ? 1 : 0`（这一档也决定共面时谁在前，`DEPTH.face` / `faceOther`）。
- `src/editor/editor.ts` `vertDotsView` / `softEdgesView`（只在自由建模）：顶点小圆点、平滑淡线。硬表面没有顶点小圆点，「画风带线时能改的那一层 = 顶点小圆点」要给硬表面也接上。
- `src/editor/highlight.ts` 淡出标记（`dimSlots`）。
- 后处理描边（像素描边 / 1-bit 的 `post.pixelOutline`）是整张图的，不分槽——它算画风要求的线，不动。

### 6. 二½ 那张表的现状：谁 × 哪一档 → 怎么办

档（照统筹猜的四档）：① 这一层自己的几何 ② 这一层的子物体（连它里面的）③ 外面的（外层几何、兄弟、不相干的）④ 同一个组件摆在别处的分身（含它里面的）。

| 行 | ① 自己 | ② 子物体 | ③ 外面 | ④ 分身 | 现在拿什么判 |
|---|---|---|---|---|---|
| 画编辑用的线 | 画 | 带线画风 = 画；不带 = 不画 | 带线画风 = 画（进了物件时淡）；不带 = 不画 | 同 ③ | placement `tier`（= `s.active && editing`）+ 画风 `edges`（render3） |
| 画编辑用的点（顶点小圆点、平滑淡线） | 只自由建模画 | 不画 | 不画 | 不画 | `view.activeSlot()`（editor `vertDotsView`） |
| 淡出 | 不淡 | 不淡 | 进了物件时淡（根层不淡） | 淡 | `insideContext`（editor `draw` → `dimSlots`） |
| 共面时谁在前 | 前 | 后 | 后 | 后 | placement `tier`（render3）；拾取打平时 `pick.ts preferActive`（`activeSlot`） |
| 点一下 | 元素 | 整个直接子物体 | 没有 | 没有 | `slot.active` + `topChild`（比链前缀） |
| 框选 | 元素 | 整个直接子物体 | 不进 | 不进 | 同上（classify） |
| 双击 | 无事 | 进去 | 退一层 | 退一层 | 同上 |
| 悬停 | 元素亮 | 不亮 | 不亮 | 不亮 | 悬停只记活动池的本地编号（editor `hoverEdge` / `hoverFace`） |
| 吸附 | 吸，最优先 | 吸，远近 1 | 吸，远近 1（父母 / 兄弟）或 2 | 分身本身 1（兄弟实例）、它里面的 2；手势中分身在手里 = 不吸 | `tier`（`world-view.ts tierOfSlot`，求解器 `TIER_EPS` / `TIER_DIST`）+ `overridden` |

现在各处各算各的地方（二½ 第 4 条要列全的）：
- `world-view.ts`：`active`（排槽时算）、`inContext`（同一条链 = 同一个定义；**没人读**，我搜到的读者为零）、`tier`（`tierOfSlot`）、`insideContext`（只看这个 + 淡出）、`twin`（分身在手里）。
- `editor.ts`：`classify`（`slot.active` + `topChild` 自己比链前缀）、`draw` 里的 `dimmed`（直接调 `insideContext`）、`vertDotsView` / `softEdgesView` / `breakTicks` 等（`activeSlot()`）、`emptyMarkers`（自己比 `chain.join("/")`）、`selectedPoolFrames`（`overridden`）。
- `stream-provider.ts`：placement `tier` = `s.active && editing`。
- `pick.ts preferActive`：`slotOf(fid).index === activeSlot().index`。
- `solver.ts`：`tier` 只用来排远近。
- `activePool()` 有一百处左右，大部分是「指令落在哪」，不是「怎么对待别的槽」，不算这张表的事；`defOfContext` 同理。

### 7. 分身（正在改 A 时，别处的 A）
- 画：淡掉（不在 `insideContext` 里），带线画风照画淡线；手势中它画的是预演（跟着一起变，`twin`）。
- 点：点不中（classify = 没有）；双击它 = 退一层。
- 吸：吸得到，远近 1（兄弟实例）；手势中当「在手里」，不吸、不挡、点不中（防自己吸自己）。
- 它算不算「能直接改的」：改 A 就是改它（同一个定义），但它不在你站的那条链上。统筹拿去问 user。

## 二、进出和挪

- **进一层**：双击子物体（鼠标 / 手指同一条 `hierarchyTapAt`）；选中后右键「进入编辑」；层级窗口里双击一行。进的时候查：锁着的不让进；那种身体没有工作台的不让进（说为什么）。
- **退出来**：手势外、没选区、没锁时按 Esc = 退一层（锁着时第一下只解锁）；双击空处或外面的东西 = 退一层；右键空白「退出一层」；左上面包屑点哪一级就退到哪一级（`exitTo`）。退出来时刚才那一层被选中。
- **点外面的东西**：单击 = 清选区、什么都不发生；双击 = 退一层。
- **层级窗口**（`app/hierarchy-window.ts`）：一行一个物件，组不进树；点名字 = 走到它挂的那一层并选中它；双击 = 进去；小眼睛 = 藏 / 显；「…」/ 右键 = 物件菜单（和画布右键同一张表）；第二页「资源」= 组件 / 材质 / 贴图清点和清理；拖一行 = 换父亲或同层排序。
- **把东西挪到别的层**：
  - 物件：层级窗口拖动 = `moveInstance`（世界位置不变、GUID 不变、一步撤销）；能拖进别的组件（放在那个组件的根上，不进组）；拦：放进自己里面、锁着的、会被斜切的。注意：拖进一个摆了好几份的组件 = 每一份里都多了它（它成了那个定义的一部分），现在没有提示。
  - 几何、组：只有剪切 → 走到那一层 → 粘贴（原位）这一条路。
  - 组不能在层级窗口里拖（组不进树）。

## 三、新建和种类

### 1. 现在能造出子物体 / 组 / 组件的路
| 路 | 造出什么 | 种类怎么定 |
|---|---|---|
| 建组（Ctrl+G） | 组（硬表面体里的 group，不是物体） | 只在硬表面体里有 |
| 建组件（G / 右键） | 新组件，把选中的几何 / 组 / 子物件包进去 | 跟着所在那一层：硬表面里 = 硬表面；网格体里只能包子物件（面走「分开」），新组件 = **空的网格体**（`ops.ts wrapInMesh`） |
| 分开物件（网格体里选面建组件） | 新的网格体组件，摆在同一层 | 网格体 |
| 粘贴 | 载荷里的组件原样；散几何贴进对不上的种类 = 先问「转成 X 再贴 / 不做」 | 载荷带着；对不上先问 |
| 导入 glb | 节点树 → 组件 | 有网格的 = 网格体；空节点 = 空的硬表面定义 |
| 素材架取下 / 摆实例（`placeInstance`） | 已有定义的又一份 | 定义自己的 |
| 复制（Ctrl 拖、复制组） | 又一份 / 组的拷贝 | 同原来 |
| 做成唯一 | 新定义（拷一份） | 同原来 |
| 根 | 新文档的根 = 空的硬表面体 | 硬表面 |

**没有**「在这一层新建一个空的子物体」的路；右键「新建 ›」和「拉出」是往**当前这一层自己的网格体**里加几何，不新建物件。

### 2. 种类在哪一刻定、哪些地方会改它
- 定：定义造出来那一刻（上表）。
- 明着改：物件设置「转成网格体 / 转回硬表面体」（`object.toMesh` / `object.toBrep` → `castDefinition`，提示行披露丢什么；什么都不选 = 转你所在的这一层，**这一层的所有分身一起变**）。
- 先问再改：炸开跨种类（「转成 X 再炸 / 不做」，`explode.cast`）、合并跨种类（`mergeObject.cast`）、粘贴散几何跨种类。
- 悄悄改：我没找到悄悄改种类的路（v0.16.29 工作台下拉转种类 v0.16.37 撤了；删光几何种类不变）。导入时「有网格 = 网格体」是导入那一刻的定，不算改。

### 3. 「空」现在怎么表示
没有「空」这个种类。代码里有两种「空」：
- `Scene.isBare(def)` = 硬表面身体、零个点、零个组、零个子实例 → 画成一个小三轴（`emptyMarkers`，导入的空节点就是这个）。
- 只装子物件、自己没几何的定义：硬表面里只选子物件建组件 = 一个零几何的硬表面定义；网格体里同样操作 = **零几何的网格体**（施工稿说的「被塞成空的网格体」只有 `wrapInMesh` 这一处）。这两种在界面上和普通物件一样，工作台照常给全套工具。

### 4. 物体窗口现有的每一行从哪来（`app/object-window.ts`）
- 「物体」页：第一行「设置的是谁」（`describeTarget`）；对称 / 镜像面（只网格体，写死在 object-window.ts）；放置表 `objectWindow` 面上的指令（转换种类、细分、默认平滑 ›，来自 `editor/objects/` + `mesh-edits/` 的登记）；机器面板（修复，`machine-window.ts MACHINES`）。
- 「元素」页：元素属性表（属性地基轮的只看版）。

## 四、文件格式

- 种类写在定义上：`CATSUP_definitions` 7.0，`DefinitionDoc.kind?: "brep" | "mesh"`，**缺省 = 硬表面，只在不是硬表面时写**（`scene-doc.ts definitionToDoc`）。网格体定义另带 `mesh` 载荷，同时照样带 `brep: 空`、`groups: []`、`instances`（网格体能挂子物件）。
- 实例：`{ guid, definition（定义的 GUID）, parent（组的 GUID 或 null）, xform, name?, locked?, layer?, hidden? }`。
- **读到不认识的种类 = 整份拒开**：`read.ts` 233 行 `definition N kind "…" is not supported by this version`。所以给种类加一个值，老版本打开新文件会整份打不开。
- 「空物体」成为一个种类，文件里最少要动的（只列选项）：
  - A. `kind` 加一个值（比如 `"empty"`）：老版本整份拒开（上一条）；要不要按大版本处理归你定。空物体的定义照样带 `instances`，不带几何载荷。
  - B. 不加值，读的时候按「硬表面、零几何」认成空：这是靠内容猜种类，和「种类是强类型、新建时定」冲突（删光几何的硬表面就分不清了）——列出来只是为了说明它不成立。
  - 两种都要处理：现在零几何的硬表面定义（导入的空节点、只装子物件的组件）和 `wrapInMesh` 造的零几何网格体，在新格式下是什么——这是「老文件的约定」，照家规 #9 不能进门时悄悄改种类。
- 「创建父物体」：**文件里不用加东西**。新父亲 = 一个新定义 + 在原来那层摆一份它，原来那个物件的实例搬进新定义（`moveInstance` 已经能做，GUID 不变）。现成的 `makeComponent` 指令也能只包子物件。要动的是新父亲的种类（空物体 = 上面那个格式问题）。根的那一半（给根套一个父亲 = 换根）要动 `rootIndex` / 根的 GUID，这是施工稿第七节第 5 步说的「根的特殊收到读写的门口」，那两处 diff 照你说的过你。

## 五、顺带看到的

- `PoolSlot.inContext` 没有读者，可以在收「关系只算一处」时一起拿掉或并进档里。
- 层级窗口把物件拖进摆了好几份的组件时，所有份一起多出它，没有提示（物件管理那一轮可能要一句提示）。
- 根层（没进任何物件）时不淡出任何东西，所有组件都和散几何一样画线——「能直接改的」在根层是散几何，子组件按规矩也不该有编辑用的线。
