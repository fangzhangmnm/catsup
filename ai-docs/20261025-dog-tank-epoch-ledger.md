### 3.1 各条的现状和要定的点（AI 看法，没拍）

**DT1 指令注册表**
- 现状（核过）：「指令」散在五处——`src/app/main.ts` 的 keydown（工具键表 + 一串 if：G / Ctrl+G / Ctrl+A / Shift+Z / Delete…）、`HudModel.edits()`（选区动作：右键菜单 / 上下文条 / VR 手腕面板三个渲染器共用，`selection-actions.ts`）、☰ 和视图菜单、`tool-config.ts` 的工具动作、Editor 上的方法（makeGroup / explodeSelection / zoomExtents…）。底下的 `ops.ts` 有 37 种可序列化 op（撤销、复现包都吃它）。拖手势的工具另有 `ToolHandler`（≈ Blender 的 modal operator）。总账 A3「动词注册表」（2026-09）说的是工具手势那层，已被 0.13 刀 ② 的 `tools/` 搬迁做掉。
- 形状候选：一张表，一条 = `{ id, 名字, 图标, 快捷键, 什么时候可用（poll：模式 / 选区 / kind）, 参数表, 执行 → Op }`；右键菜单、☰、快捷键、以后的搜索、修复面板、数 op（GTA 毕业考要数）都只读这张表。工具 = 表里的一种条目（「切到这个工具」），手势仍走 `ToolHandler`。
- **形状要求（user 拍）**：「面板里也可以配置，所以能不能做成blender一样一个命令是一个类似函数的东西，你面板喂，而不是查面板。以及注意性能」——
  - 一条指令 = 一个函数：`(作用域, 参数) → Op`（Blender 的 operator + properties）。参数是显式传进来的值；对话框、修复面板、右键菜单、以后的搜索、快捷键都只负责凑参数、调用它。**指令永远不去读面板 / UI 状态。**
  - 白得的：预演 = 拿同一组参数在克隆上调一次；修复面板 = 一串（指令, 参数）按顺序调；复现包 / 数 op = 记下（指令 id, 参数）就能重放；作用域也是参数（DT5：刮到的 / 选中的 / 物体里全部）。
  - 性能（AI 列的注意点，没拍）：只碰作用域里的池（结算机已是 O(影响域)）；一个池里所有顶点一次 `moveVertices` 批量挪，不逐点提交；组件按定义去重，一个定义只处理一次，不按实例数重复；预演在参数变动时重跑要防抖，并且只克隆被碰到的那几个内核，不克隆整个场景。
- 谁做：**拍了 = Opus 做，周二 Fable 审**（user「指令注册表可以做，周二让fable scrutiny就行」）。顺序：提案 .h（落 ai-docs，家族 API .h 规矩）→ user 过目 → 表 + 五处搬迁 → 修复指令（DT4 / DT5 / DT7）作为最早的几条进表。

**DT2 brep vs mesh** —— **拍了（user「DT2不同意……」，见 §3 表）：本纪元不碰 mesh，导入直接成 brep。** 下面是 AI 当时的读法，user 不同意，留档不执行。
- 待做（接线）：外来 glb（没有 `CATSUP_document` 的，现在 `read.ts:57` 拒开）/ 三角汤 → 直接进 brep。要定的细节（做的时候再问）：进成根上的散几何还是自动包一个组（sticky 几何会和已有的东西粘）；外来网格的 UV / 顶点法线不进 brep（brep 不存每角 UV），导入时说明丢了什么（同 `castsTo.loses` 的写法）。
- 现状（核过）：mesh 只有数据形（`positions / indices / triMaterial / materialSlots`，契约稿另写了可选 `uvs / normals`），`modes: []` 不能编辑；只通 brep → mesh 一个方向（`brepToMesh`）。
- brep 接得住的：三角汤的拓扑（每个三角都是平的，SU 导入网格就是三角 + 软边 / 隐藏边；CatsUp 有软边和平滑组）。
- brep 接不住（或者一进门就改了它）的：① 脏的外来数据原样——brep 进门就结算，重叠的贴花三角、穿插面会被切开 / 合并，残骸还没决定怎么修就被改了；② 每个角上的属性——UV、顶点法线 / 颜色（契约稿：「mesh = 显式 UV……别的软件进来的『被拉伸的贴图』只能住这里」；GTA mod 毕业考要把带 UV 的 Rhino 放回游戏）。
- 1 mm 的怕可以在 brep 里解，不用 mesh：现在挪点让面不平 → autofold 折出新的硬缝；折不了（结点多边形 k ≥ 4 还不平）→ BURST，面没了只剩边框。候选 = 「可逆的折」：折缝是软的，点挪回平面时自动消失。这是内核契约，归 Fable。
- AI 建议（没拍）：本纪元 brep 是唯一能编辑的；mesh 不做编辑，只当托盘装 ①② 这两样，显式 cast 成 brep 才能改；不变 vertex driven（不吃书）。「永远」先不拍——有机建模（Blender 模态）那条 10-24 说过是另一个内核。

**DT3 / DT6 修复模式 vs 修复面板**
- AI 看法：面板比模式合适。模式 = 换一套工具 + 换鼠标理解方式（`src/editor/mode.ts` 已有接缝）；修复指令都是「选好范围 → 设参数 → 看预演 → 一次应用」，不需要换鼠标。像 SU 第三方插件 CleanUp³ 那样一个面板勾几步，一次预演，一次应用 = 一个 `batch` op = 一次撤销（`batch` op 已有）。步骤按固定顺序跑（先吸格点，再焊断口——吸完会冒出新的共线断口）。
- 每一步同时是 DT1 表里的一条，所以右键菜单 / 以后的搜索也能单独叫它。

**DT4 吸到格点**
- 名字候选：「吸到格点…」（界面已有「吸附」「格点」两个词；带省略号 = 点了弹对话框）；内部 id `snapToGrid`。
- 对话框：含不含子物体；吸多少（默认 = 文档的格距 / 细分）；坐标系 **拍了 = 默认按物体自己的轴吸（定义坐标），世界格点是选项**（理由：组件实例转了 30°，按世界格点吸会改它的定义，同一组件的别的实例就离格了）。同样的参数在修复面板里也能配（DT1 的「面板喂参数」）。
- 预演（核过）：工具有预演（`Editor.computeLive` 把活动池的内核克隆一份跑工具）；**对话框式指令、跨好几个选中物体的预演没有通路**（只克隆活动池那一个内核）。→ 周账请 Fable 看：「任何 Op 都能预演」（History 本来就存 Scene 克隆，把 Op 跑在 Scene 克隆上画出来，应用 = 同一个 Op）。
- 面破（核过 `kernel.moveVertices`）：顶点被吸走时内核会 ① 两个点落到同一格点 → 合并（短于半格的边消失）；② 面不平 → autofold 折出新硬缝；③ 折不了 → BURST 面没了。候选：预演里报数并高亮「会合并 N 点 / 折 M 张面 / 破 K 张面」，破面的默认由 user 定：照吸并标出来 / 那几个点不吸 / 折缝用软边。不硬拦。
- **破面拍了**：不破；折缝默认软边，「高级」里可选硬边（user「估计没人用」）。预演照样报「合并 N 点 / 折 M 张面」。
- 落地要补的一处（核过 `src/kernel/autofold.ts`）：autofold 找「极大共面段」折，结点多边形 k ≥ 4 还不平就返回 null → 调用方 BURST。「不破」= 这时要有退路：全三角化（三角永远是平的，不会失败），对角线同样是软边。这是内核行为，周二请 Fable 一起看（只在这条指令里换退路，还是全局换）。

**DT9 看得见的微折软边**
- 为什么是最差情况（核过）：推拉对曲面上的一片是拒绝的（0.10「推拉曲面一片拒绝（先硬化）」）；一张面被悄悄折成两片软边相连，看起来是一张平面，推拉却推不动，用户不知道为什么。

**DT5 焊上断口**

**DT7 make faces planar**
- 前提（核过）：CatsUp 内核里每张面永远是平的（共面容差 10 µm）。所以「不平的面」在内核里长这样：一张本来的面被 autofold 折成几片平面，片和片之间是折缝边，二面角很小。make planar = 把这样「几乎共面」的一组片拍到同一张平面上；拍完之后折缝变成共面的内线——这就是要点 ③「擦不擦内线」的对象（擦 = 软边橡皮「共面 → 删边并面」那一套）。
- **要点 ① 拍了**：角度 = 油漆桶的「锐角阈值」（`tool-config.ts:163 sharpDeg`，默认 20°，每台设备记）——同一个量、同一个默认。
- **要点 ② 拍了**：平滑组整体算一张面、组里的软边不算内线；理由**不是**「弯得超过护栏」。user：「也许比我想的简单，不用flood fill，只是把所有小于角度的硬边干掉就行」。
- **算法读法（AI，按 user 这句）**：指令作用的对象 = 范围里**夹角小于阈值的硬边**。软边从来不是候选，所以平滑组自动不碰，不用特例。要拍到同一张平面上的那组面 = 经由这些候选边连起来的面（连通分量；就是 DT10 的「分组」）；每组按众数平面拍平，再按选项擦掉这些边（擦了两边就并成一张面）。
- **边角情况拍了（和 AI 读法相反）**：一条夹角很小的硬边，一边是平面、一边是平滑组里的一片——user「和你相反，我想的就是这条边会被吃掉，面和平滑组的第一个面融合，加入平滑组」。即这条边照样是候选；平面和挨着的那一片拍到一张平面上、并成一张面，成为平滑组的一员。（做的时候再问一句：「擦内线」选项关着时这条边怎么办——留硬边，还是改软边入组。）
- **零破面拍了**：user「确保不要有任何面破，如果有，说明我们算法可能想错了」。落地 = 这条指令的不变量：输出的面事件里 BURST 必须是 0，单测钉死；运行中真出现 → 整步拒绝 + 复现包 + 报错，不静默应用（算法错了的信号，不靠兜底盖住）。同一条不变量也套在 DT4（DT4 已拍「不破」）。
- 要点 ④ 拍到哪张平面（AI 读法）：众数 = 组里已经落在同一张平面上（10 µm 以内算同一张）的顶点最多的那张平面，其余点挪上去——user 的例子里大家在 0.5、一个在 0.51，结果就是 0.5；中位数 = 每个点到平面距离取中位数的稳健拟合；平均数 = 最小二乘。
- AI 补的一个坑：组边界上的点也属于组外的面（邻居墙），沿法线挪它，邻居墙就不平了 → 又是 autofold / 破面（同 DT4 的三种结果）。候选：边界点如果只有一条通往组外的边，就沿那条边滑（邻居墙仍然在自己的平面上）；不止一条才沿法线挪，并在预演里报数。
- 和 DT4 的先后：先吸格点再拍平，拍平可能把点挪离格点；先拍平再吸格点，吸格点又可能把面弄不平。众数平面如果本来就在格点上，两者不冲突。面板的步骤顺序要 user 定。

**DT10 共用的 flood fill 深模块**
- 现状（核过）：同一个「从面出发、按规则跨边灌」的循环抄了三份——`src/editor/paint-flood.ts surfaceFaces`（只过软边）、`src/editor/surface-assign.ts facesForAssign`（过软边或夹角 ≤ 阈值 / 过任何边）、`src/editor/editor.ts selectExpand` 三击（连通体：经边和顶点走，包括没面的线）。`paint-flood.ts` 头注释还写着 single / smooth / sharp / connected / pool 五种模式，那张表 10-24 已经搬去 `surface-assign.ts`，注释过期。
- 形状候选（没拍）：一个纯函数模块，两个动词——「从种子灌」（油漆桶、选择用）和「把一片面全部分组」（user「flood fill divide」：修复用，DT7 的每组拍平、以后别的修复指令）；跨不跨一条边由一个判定函数决定，现有的几种规则（软边 / 软边或夹角 ≤ 阈值 / 任何边 / 夹角小于阈值的硬边）各是一个现成的判定。三击连通体走的是边 + 顶点的图，作为第三个动词放在同一个模块里。
- **还要第三种：按「侧」灌**（user 拍的读法）：DT8 之后一张面有正反两个表面，油漆桶灌的单位是「某张面的某一侧」，不是面。跨一条边时，从 A 的哪一侧走到 B 的哪一侧，看两张面的环在这条边上走的方向（环边带 `forward`，核过 `face-lifecycle.ts:287`）：方向相反 = 法线同向，+ 侧接 + 侧；方向相同 = 法线反向，+ 侧接 − 侧。圆柱这样能分正反的曲面只灌满一侧；莫比乌斯环转一圈回来正好翻到另一侧，所以两侧都灌满（user 的例子）。
- 验收：油漆桶三档、选择单双三击行为零变化（现有单测 / 探针里碰到的那几项）；按侧灌在莫比乌斯环上灌满两侧、在圆柱上只灌满一侧（同晚做的样本见 §6）。
