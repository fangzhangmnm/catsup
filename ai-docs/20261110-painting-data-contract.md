## 一、三样东西，各管各的（第 3 版）

> 第 3 版（11-10 深夜，user 看完第 2 版）改了三处：意思从贴图上挪到槽上；贴图坐标有身份、可以有很多套，单品的画和它照着画的那一套硬绑定；一套贴图坐标就是一块画布，同一块画布上可以有好几张贴图。旧版本拒绝打开带贴图的物件：user 同意（「大版本号可以，我们不需要太念旧」）。
> 第 2 版（user：「为什么他们是两个不同的类型，而不是同一个类型的不同多态」）：画和贴图合成一种条目。

| 东西 | 它是什么 | 它知道什么 | 它不知道什么 |
|---|---|---|---|
| **贴图** | 一张图 | 像素（原图，或者分层的）；装的是哪种数；真实尺寸；（可选）是照着哪一套贴图坐标画的 | 自己被拿去当什么用 |
| **贴图坐标**（可以有很多套） | 物件每个角上的一列数，也是一块画布 | 每个角在画布上的位置；画布多大、多密 | 画布上画了什么 |
| **槽** | 物件或材质上的一张小表 | 「颜色用哪张贴图」「长草用哪张贴图」…… | 贴图里面的事 |

### 贴图

- 文件里一张「贴图」表，一行一张，有自己的身份号。现在嵌在材质里的那张图搬进这张表。
- **内容是两种形态之一**：原图（导入的字节，一个字节不动）或分层（画画软件的开放格式，图层、草稿层、蒙版都在里面）。原图上第一次动笔就变成分层的，原图成为最底下一层。**指着它的那些槽不用动**，所以导入的图随时可以拿来画，不用你重新接线。
- **装的是哪种数**（贴图自己的性质，三种）：
  - 颜色：正常地画。
  - 一个数（0 到 1）：比如粗糙度、长草的密度、刷怪的概率。画的时候是深浅，显示时可以套一条色带看。
  - 标签：比如「雪 / 钢板」。存的是编号，旁边必须带一张对照表（编号是谁），没有对照表的编号不合法（家规）。只能用硬边的笔和填色画，不能模糊、不能平滑取样，因为两个编号之间没有「中间」。
- **真实尺寸**：自由的图自己带（老规矩）；照着贴图坐标画的图，尺寸跟那一套坐标走。
- **是照着哪一套贴图坐标画的**（可选的一格）：
  - 有这一格 = **单品的画**。它和那一套坐标硬绑定，离开那套坐标这些像素就没有意义。
  - 没有这一格 = **自由的图**。可以平铺，可以给材质用。
  - 这就是「单品的贴图」和「可以刷的材质」的全部区别。它们是同一种东西，不是两种身份。

### 贴图坐标：可以有很多套，每一套是一块画布

user 11-10 深夜：「单品的画，它应该是和贴图坐标硬绑定的，因为你贴图重新生成了，你这个画就没有任何意义了……如果你要重新生成 UV 的时候，你旧的 UV 还是会保留的，然后会问你说要不要把画给重新拷过去。但是……不应该有画之后 UV 就锁定，因为你拖一个角，稍微拖拖这种修改还是允许的……有点像就是你这个物件关系图里面的引用……你画会引用这个 UV，那它就会一直在这里，不会被删掉，不会被清掉。然后你生成的 UV 是新的 UV……贴图坐标可能会有很多个」。

- 一套贴图坐标有自己的身份号和名字，一个物件可以有好几套。
- **一套坐标就是一块画布**：它定了画布多大、多密（每米多少像素）。你关心的密度就挂在这里。
- **同一块画布上可以有好几张贴图**：颜色一张、长草一张、粗糙一张，它们共用同一套格子。这是「以后有多张贴图怎么办」的默认答案：不用多套坐标，多张贴图铺在同一套上。
- 需要另一套的情况：想要另一种密度（刷怪概率一米一格就够，不用跟颜色一样密）；或者重新生成了一遍。
- **生死按引用**：被贴图引用着的那一套不会被删、不会被清。没有贴图引用的，在物件的属性列表里灰着，你可以删。
- **三种改法，分清楚**：

| 你做了什么 | 贴图坐标 | 画 |
|---|---|---|
| 拖一个角微调 | 在原来那一套上改 | 像素不动，画在模型上跟着挪一点 |
| 整理（只平移，把空洞挤掉） | 在原来那一套上改 | 像素跟着整块平移，无损 |
| 建模（切面、长新面……） | 每一套都按同样的规则跟着变 | 切出来的小块继承，新面是空白 |
| **重新生成** | **新出一套，旧的留着** | 问你要不要把画拷过去。拷 = 重新采样出新的贴图，绑在新的那一套上；旧的画和旧的那一套都还在，直到你自己删 |

- 10-30 定过「一套、多重 UV 降成脑洞」。那时说的是「每个图层各用一套」，现在仍然不做那个。今天说的「很多套」是另一回事：是整块画布的另一个版本或另一种密度。

### 槽：意思写在用它的那一方

user 11-10 深夜：「我一开始的想法是意思是槽，你可以指定贴图……如果你想用同一张贴图同时管多个通道、多个语义怎么办？如果你不想复制他们的话。」

- 物件和材质上各有一张小表：通道的名字 → 哪张贴图。
- 意思写在这张表上，不写在贴图上。所以同一张贴图可以同时接到好几个通道，不用复制。
- **通道的名字是开放的**，不只是渲染器认识的那几个：
  - 渲染器认识的：颜色，以后的粗糙、发光……它本来就有一张语义通道的登记表。
  - 你自己起的：长不长草、刷怪概率、地面是雪还是钢板。渲染器不认识它们，照样存、照样能画、照样导出；读它们的是游戏那边的逻辑。
- 同一个名字可以是「每张面一个数」，也可以是「一张贴图」。面上的标签（表面工作台那一套）和贴图上的标签是同一种东西，只是细到面还是细到像素。
- 物件的槽只能接「照着这个物件自己的贴图坐标画的」贴图；材质的槽只能接自由的图。
- 物件的贴图叠在材质给的值上面：画过的地方用物件的，没画的地方透出材质的。

## 二、几条规矩

- **指着贴图的物件，每一套贴图坐标都覆盖所有的角。** 新长出来的面在长出来的那一步，每一套上都铺好。
- **同一个组件摆好几份，共用贴图。** 把组件变成独立的时候，它的贴图坐标和贴图跟着复制一份。
- **第一版只做「颜色」一个通道、一套贴图坐标。** 上面说的多套、多通道、一个数、标签，这一版只把格子留对，不开入口。材质的贴图能画，也是到材质窗口那一段再开。
- **新建贴图坐标时的默认密度**：按物件的大小算，让画布大约是 1024 见方。你可以改。改密度 = 重新生成一套。
- **画布有上限**：受显卡限制（iPad 上一般是 4096 或 8192）。快到上限时提前告诉你。
- **存盘的大小**：分层的贴图比几何大得多。没改过的贴图，存盘时直接用上一次编好的字节。
- **给别的软件看的那一张**：材质的贴图 = 它自己（分层的写合成结果）。物件的颜色贴图 = 合成结果再叠到每张面的材质底色上、补过边。别的通道第一版不写进标准的那一半。

## 三、定了的一件事：旧版本打不开带贴图的物件（user 同意）

- 旧版本不认识角上的贴图坐标。让它打开，你在里面切一刀，那一列还是旧的，存回去画和模型就对不上了，而且是悄悄坏的。
- 所以带贴图坐标的网格体在文件里盖新的大版本号，旧版本拒绝打开并明说要更新。没有贴图坐标的文件不受影响。
- user：「大版本号可以，我们不需要太念旧。现在我们这个东西连宣发都没宣发。」

## 四、我自己定了、你没逐条说过的

- 贴图坐标用小数存（单精度），单位是像素。
- 贴图只带「装的是哪种数」，不带通道的名字（上面说了理由）。
- 画布的大小和密度归贴图坐标那一套管，不归贴图。同一套上的贴图大小永远一样。
- 物件的槽只接自己的画，材质的槽只接自由的图。
- 现有文件里嵌在材质里的图，打开时搬进贴图表、现给一个身份号。两个材质用了一模一样的图也是两条，不按内容合并。
- 贴图表如果被更新的版本写过、当前版本不认识：不拒绝打开，原样带着，按合成图只读显示。

## 五、形状（提案 `.h`，实现中变了要回写）

```ts
// —— 顶层扩展（可选）：CATSUP_textures 1.0。空 = 不写这个扩展。major 比本版新 → 不拒开（同 desk / references / shelf）。
export type TextureContent =
  | { kind: "image"; mimeType: string; bytes: Uint8Array }   // 原图：导入的字节，一字不动
  | { kind: "layered"; ora: Uint8Array };                    // 分层：画画内核 encodeOra 的字节（本层不解释）
/** 装的是哪种数（数据自己的性质；决定能用什么笔、能不能模糊 / 平滑取样）。1.0 只写 color。 */
export type TextureValue =
  | { kind: "color" }
  | { kind: "scalar" }                                       // 0..1
  | { kind: "tag"; table: { id: number; guid: Guid; name: string; color: [number, number, number] }[] };   // 编号只是对照表的代号（家规）
export interface TextureDoc {
  guid: Guid; name?: string;
  value: TextureValue;
  content: TextureContent;
  /** 自由的图：真实尺寸（米）。老规矩：每张图必须带长度尺度。照着贴图坐标画的图不写这个键（尺寸跟那一套坐标走）。 */
  sizeM?: [number, number];
  /** 单品的画：硬绑定到哪个定义的哪一套贴图坐标。有 layout 就没有 sizeM，反之亦然；两个都有或都没有 = 文件坏了。 */
  layout?: { definition: Guid; uvSet: Guid };
}
export interface CatsupDocument { /* … */ textures: TextureDoc[] }

// —— 槽：通道的名字 → 贴图。名字是开放集（渲染器 material/ 登记表里的，或用户自己起的）；本层不解释、认不出的原样带回。
export type ChannelSlots = Record<string, Guid>;
export interface MaterialDoc { guid: Guid; name: string; color: [number, number, number];
  channels?: ChannelSlots }          // 只许指自由的图（没有 layout）；铺法 = 平铺。以前的 texture = channels.color
export interface DefinitionDoc { /* … */
  channels?: ChannelSlots }          // 只许指 layout.definition = 自己的贴图

// —— CATSUP_mesh 2.0（major）：带 uvSets 的网格体才盖 2.0，没有的照旧盖 1.2
export interface UvSetDoc {
  guid: Guid; name?: string;
  width: number; height: number;     // 画布，像素
  pxPerM: number;                    // 密度
  /** 每个角一对坐标（像素单位，f32 成对；长度 = 2 × loopVert.length；和 loopVert 同序）。覆盖所有的角。 */
  loopUv: Float32Array;
}
export interface MeshDoc { /* … */ uvSets?: UvSetDoc[] }     // 列表顺序没有语义
```

- **校验（读取时，不猜）**：`loopUv` 长度不对 → `fail`。贴图的 `layout` 指向不存在的定义或 `uvSet` → 这张贴图当孤儿留着，`readNotes` 记一笔，不拒开。同一套 `uvSet` 上的分层贴图画布大小和 `width × height` 不一样 → `fail`。槽指向的 GUID 不在表里 / 种类不对（物件的槽指了自由的图）→ 当这个槽空着，`readNotes` 记一笔。
- **`ImageAsset` 退役**：材质不再装图。内存里 `scene/scene.ts Material.texture` 改成 `channels`。全仓读 `.texture` 的地方约 20 处（`format/write.ts` 7、`editor.ts` 3、`render3.ts` 2、`pool-mesh.ts` 2、`ops.ts` 2、`main.ts` 2、`scene-doc.ts` 2、`read.ts`、`resources.ts`、`stream-provider.ts`、`paste-actions.ts` 各 1）。渲染器的贴图缓存键从「材质对象」换成「贴图条目 + 它的版本号」。
- **角上的列是通用的**：网格体内核里「角上的一列数」做成通用的东西，贴图坐标是它的一种，可以有任意多列。新建面时交代来历（`addFace(from)`）之后，每一列按同一段代码继承。以后角上的别的属性（按面画的顶点色、拆开的法线）也走它。
- **拍子**：
  - `CATSUP_textures` 1.0：新扩展。
  - `CATSUP_material` 1.2 → 1.3（minor）：多一个键 `channels`。标准那一半（`baseColorTexture` → 图）照写，老读者读到的和现在一样；它存回去贴图的身份号会换一个，内容不丢（提示一次）。材质的槽指着**分层**的贴图时这个材质盖 2.0（major）：老读者会丢图层。第一版不开这个入口，拍子先定下。
  - `CATSUP_definitions` 7.1（minor）：`channels` 键。
  - `CATSUP_mesh` 2.0（major，user 同意）：带 `uvSets` 才盖；没有的盖 1.2，字节和现在逐字一样。这是「写入器只写当前拍」的例外，写进 `migrate/index.ts` 头注释。
- **glTF 标准那一半**（`bake.ts` / `write.ts`）：材质的颜色贴图照现在写。物件的 `channels.color`：烘出来的 primitive 带 `TEXCOORD_0`（= 像素坐标 ÷ 画布宽高），用一个现生成的 glTF material（`baseColorTexture` = 合成图 over 每张面的材质底色、补过边）；这个 material 不带 `CATSUP_material`，读的时候跳过。别的通道 1.0 不进标准那一半。
- **引用和孤儿**（`scene/resources.ts` 那一套）：贴图被槽、素材架引用就活着；贴图坐标被贴图的 `layout` 引用就活着。没人引用 = 孤儿，列出来、能删，不许哪个动词顺手删。「重新生成」只新建，不删旧的。跨文件粘贴、把组件变成独立的：贴图坐标和照着它画的贴图一起按值拷、铸新 GUID、`layout` 重新对上。
- **存盘的字节缓存**：`content` 的字节由宿主按「这张贴图的版本号没变就复用上次的」给；格式层不管。

## 六、迁移和样本

- `CATSUP_definitions` 7.0 → 7.1：加可选键，不用迁移函数。
- `CATSUP_mesh` 1.2 → 2.0：STEPS 里登记一条空迁移（1.2 的形状是 2.0 的子集）。
- `CATSUP_textures` 1.0：新扩展，登记进 `FORMAT`、`CATSUP_EXTENSION_ORDER`、`extensionsUsed`（有才列）。
- `CATSUP_material` 1.2 → 1.3：读老文件时把嵌着的图搬进贴图表（`migrate/material.ts`）。
- 冻样本：一个没有贴图的文件；一个材质带原图的老文件（读进来贴图表里有一条、标准那一半的字节不变）；一个定义带一套贴图坐标和一张两层的颜色贴图的文件；一个定义带两套贴图坐标、其中一套没有贴图引用的文件（确认孤儿读得进、写得回）。`node scripts/freeze-format-fixtures.mjs`。
- 守卫：定义带自己贴图的文件用上一版的读取器读，必须是 `FormatTooNewError`，不是静默打开；src 里除了格式层和贴图表的访问口，不许有第二种「一张图」的类型（`ImageAsset` 只许参考卡片用，或者删掉）。

## 七、没定的

- 蒙版存在 ORA 里的哪（归内核，0-8 那张工单定）。
- 一张贴图的某一个分量当一个通道用（比如红色那一路当粗糙）。现在是一张贴图整张接一个通道，可以接多个；按分量拆以后要再加。
- 物件的贴图和材质的值怎么叠，颜色以外的通道还没定（颜色 = 盖在上面）。
- 标签贴图怎么画（硬边、不模糊）归内核的动作分类表管，具体的笔到做的时候定。
