## 一、文件里多出三样东西

1. **「画」这一类条目。** 文件里新增一张表，一行是一份画。每份画有自己的身份号，和组件、材质一样，名字只是显示。
2. **物件指向自己的画。** 组件定义上多一个可选的格子：「我的画是哪一份」。没画过的物件没有这一格。
3. **网格体的每个角上多一列贴图坐标。** 存的是「第几个像素」，不是 0 到 1 的比例。只有有画的物件才有这一列。

一份画里面装着：

| 内容 | 说明 |
|---|---|
| 身份号、名字 | |
| 宽、高（像素） | 画布会随着物件长出新的面而变大，所以不是固定的 |
| 密度（每米多少像素） | 这是你唯一要关心的技术量。家里的老规矩是「每张图必须带长度尺度」，画带的就是它 |
| 意思 | 这份画是「表面的颜色」。登记的是意思，不是渲染器的哪个槽（你提醒的旧话）。渲染器那边本来就有一张「语义通道」的表，颜色是其中一个，每个通道可以是一个数，也可以是一张图；一份画就是「颜色」这个通道的图 |
| 分层的源文件 | 画画软件的那种开放格式（ORA），原样装进去。图层、草稿层、以后的蒙版都在它里面。取出来画画软件能直接开 |
| 给别的软件看的那一张 | 合成好的一张图，已经叠在材质的底色上、补过边。Blender、Windows 预览看的是它。我们自己读文件时不用它，每次存盘时重新生成 |

## 二、几条规矩

- **有画的物件，每个角都有贴图坐标。** 第一版以物件为单位：一个物件一旦有了画，它所有的面都铺好、都存。新长出来的面在长出来的那一步就铺好、存上。（以后可以细到「没画过的面先不存」，那是省空间的事，不改含义。）
- **画叠在材质上面。** 没画的地方是透明的，透出材质。第一版材质只支持纯色当底；底下是平铺贴图的情况（砖墙上画苔藓）放到「接住现成的」那一段。
- **同一个组件摆好几份，共用一份画。** 和几何一样。
- **材质也可以有画**（你定的：通用的东西可以做成材质）。形状已经留好：画这张表不分主人，材质也可以指向一份画。这一条第一版不做，到材质窗口那一段做。
- **密度的默认值**：新建一份画时，按物件的大小算一个密度，让整张画大约是 1024 见方。你可以改。改密度等于重新采样，会明说。
- **画布有上限**：受显卡限制（iPad 上一般是 4096 或 8192）。快到上限时提前告诉你，不是到了才报错。
- **存盘的大小**：一份画比几何大得多（一张 2048 见方、几层的画是几 MB）。没改过的画，存盘时直接用上一次编好的字节，不重新编码。

## 三、要你定的一件事：旧版本打不开带画的文件

- **这是什么**：旧版本的三维软件不认识「角上的贴图坐标」这一列。如果让它打开一个有画的文件，它不知道有这一列，你在里面切一刀，面和角都变了，那一列还是旧的。存回去之后，画和模型就对不上了，而且没法恢复。
- **所以**：凡是带画的网格体，在文件里盖一个新的大版本号。旧版本看到这个号会拒绝打开，并且明说「要更新才能打开」。和 11-04 定义表升大版本时是同一种做法。
- **影响谁**：你别的设备上如果还开着没更新的旧版本，要刷新一下才能开这些文件。没有画的文件不受影响，旧版本照开。正式版的用户打不开开发版存的带画的文件，直到正式版也更新。
- **不这么做会怎样**：旧版本能打开，但只要在里面动过模型再存，画就废了，而且是悄悄废的。
- 我的建议：盖大版本号。

## 四、我自己定了、你没逐条说过的

- 贴图坐标用小数存（单精度）。边界上的点落在像素角上是整数；面被切开后中间新出来的点是小数。
- 没有画的物件，文件和现在逐字节一样。
- 「给别的软件看的那一张」是每次存盘现做的，不是正本；正本是分层的源文件。
- 画这张表如果被更新的版本写过、当前版本不认识：不拒绝打开，原样带着，画先按那张合成图显示、不能改。这和参考窗、素材架现在的做法一样。

# 以下给施工

## 五、形状（提案 `.h`，实现中变了要回写）

```ts
// —— 顶层扩展（可选）：CATSUP_paintings 1.0。空 = 不写这个扩展（抠）。major 比本版新 → 不拒开（同 desk / references / shelf）：
//    原字节进 carry.extensions 原样写回、readNotes 记一笔、这些画只读显示。
export interface PaintingDoc {
  guid: Guid;                       // 身份；名字只是显示、可重名
  name?: string;
  width: number; height: number;    // 像素；整数
  pxPerM: number;                   // 密度（每米多少像素）；> 0。家规「每张图必须带长度尺度」落在这
  channel: string;                  // 语义通道 id（渲染器 material/ 的登记表）；1.0 只写 "color"；认不出的原样带回
  ora: Uint8Array;                  // 分层源文件（画画内核 encodeOra 的字节，原样；本层不解释）
  /** 不进 PaintingDoc：给别的软件看的那一张是写入时现做的（合成 over 材质底色 + 补边），读取时不读回。 */
}
export interface CatsupDocument { /* … */ paintings?: PaintingDoc[] }   // 列表顺序没有语义

// —— CATSUP_definitions 7.1（minor：加可选键）
export interface DefinitionDoc { /* … */ painting?: Guid }              // 这个定义的画；只在有时写

// —— CATSUP_mesh 2.0（major）：有画的网格体才盖 2.0，没有的照旧盖 1.2
export interface MeshDoc { /* … */
  /** 每个角一对贴图坐标（像素单位，f32 成对；长度 = 2 × loopVert.length；和 loopVert 同序）。只在定义有画时写。 */
  loopUv?: Float32Array;
}
```

- **为什么 mesh 要 major**：老读者不认 `loopUv`，照 minor 语义会原样带着它（`carry`），而 `loopVert` 被它改过 → 两列对不上、无法恢复。三级语义里这是「不可兼容 → 拒开」。
- **「有画才盖 2.0」是「写入器只写当前拍」的一个例外**，要在 `migrate/index.ts` 头注释和 `encodeMeshItem` 里写明：`FORMAT.CATSUP_mesh` 记 2.0；写的时候 `loopUv` 缺 → 盖 1.2 的拍子（字节和现在逐字一样）。冻结样本两种都要有。
- **读取**：`loopUv` 在、长度不对 = 文件坏了，`fail`，不猜。定义有 `painting` 但 mesh 没有 `loopUv`、或者反过来 = 同样 `fail`。`painting` 指向的 GUID 不在表里 = 这个定义当没有画，`readNotes` 记一笔，不拒开。
- **glTF 标准那一半**（`bake.ts` / `write.ts`）：有画的定义，烘出来的 primitive 带 `TEXCOORD_0`（= 像素坐标 ÷ 宽高），材质用一个现生成的 glTF material（`baseColorTexture` = 那张合成图，`baseColorFactor` = 1）。合成图 = 每个贴图像素 over 它所属的面的材质底色，再补边。这个现生成的 material 不带 `CATSUP_material`，读的时候跳过。
- **存盘的字节缓存**：`PaintingDoc.ora` 由宿主按「这份画的版本号没变就复用上次的字节」给；格式层不管。
- **引用和孤儿**：画被定义引用（以后被材质、素材架引用）就活着；没人引用 = 孤儿，进现有的「引用和孤儿」那一套（`scene/resources.ts`），不许哪个动词顺手删。跨文件粘贴带着画走（按值拷、铸新 GUID），和材质同法。

## 六、迁移和样本

- `CATSUP_definitions` 7.0 → 7.1：加可选键，不用迁移函数。
- `CATSUP_mesh` 1.2 → 2.0：STEPS 里登记一条空迁移（1.2 的形状是 2.0 的子集）。
- `CATSUP_paintings` 1.0：新扩展，登记进 `FORMAT`、`CATSUP_EXTENSION_ORDER`、`extensionsUsed`（有才列）。
- 冻样本：一个没有画的文件（确认字节和上一版逐字一样）；一个有一份画、两层的文件。`node scripts/freeze-format-fixtures.mjs`。
- 守卫：有画的文件用上一版的读取器读，必须是 `FormatTooNewError`，不是静默打开。

## 七、没定的

- 材质指向一份画时 `CATSUP_material` 怎么盖拍子（到材质窗口那一段定；同样要防老读者）。
- 蒙版存在 ORA 里的哪（归内核，0-8 那张工单定）。
- 多个通道（粗糙、发光）各一份画，还是一份画里多个通道。现在只有颜色，先不定。
