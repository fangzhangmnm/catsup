## 一、三样东西，各管各的（第 3 版）

> 第 4 版（11-10 深夜）：**每张面只走一样，就是它的材质；画是一种材质。** 去掉了「物件的贴图叠在材质上、没画的地方透出材质」。user：「你面一个面设置了材质，就是材质；设置了画，就是画，而不是没画的地方透出材质……关键是你这个面走什么？」槽只在材质上，物件上不再有槽。合并物件时各带各的材质和各自那一套贴图坐标过来。
> 第 3 版（11-10 深夜，user 看完第 2 版）改了三处：意思从贴图上挪到槽上；贴图坐标有身份、可以有很多套，单品的画和它照着画的那一套硬绑定；一套贴图坐标就是一块画布，同一块画布上可以有好几张贴图。旧版本拒绝打开带贴图的物件：user 同意（「大版本号可以，我们不需要太念旧」）。
> 第 2 版（user：「为什么他们是两个不同的类型，而不是同一个类型的不同多态」）：画和贴图合成一种条目。

| 东西 | 它是什么 | 它知道什么 | 它不知道什么 |
|---|---|---|---|
| **贴图** | 一张图 | 像素（原图，或者分层的）；装的是哪种数；真实尺寸；（可选）是照着哪一套贴图坐标画的 | 自己被拿去当什么用 |
| **贴图坐标**（可以有很多套） | 物件每个角上的一列数，也是一块画布 | 每个角在画布上的位置；画布多大、多密 | 画布上画了什么 |
| **槽** | 材质上的一张小表 | 「颜色用哪张贴图」「长草用哪张贴图」…… | 贴图里面的事 |

### 贴图

- 文件里一张「贴图」表，一行一张，有自己的身份号。现在嵌在材质里的那张图搬进这张表。
- **内容是两种形态之一**：原图（导入的字节，一个字节不动）或分层（画画软件的开放格式，图层、草稿层、蒙版都在里面）。原图上第一次动笔就变成分层的，原图成为最底下一层。**指着它的那些槽不用动**，所以导入的图随时可以拿来画，不用你重新接线。
- **装的是哪种数**（贴图自己的性质，三种）：
  - 颜色：正常地画。
  - 一个数（0 到 1）：比如粗糙度、长草的密度、刷怪的概率。画的时候是深浅，显示时可以套一条色带看。
  - 标签：比如「雪 / 钢板」。存的是编号，旁边必须带一张对照表（编号是谁），没有对照表的编号不合法（家规）。只能用硬边的笔和填色画，不能模糊、不能平滑取样，因为两个编号之间没有「中间」。
- **真实尺寸**：自由的图自己带（老规矩，而且归贴图不归材质）；照着贴图坐标画的图没有这个数，也没有密度。
- **是照着哪一套贴图坐标画的**（可选的一格）：
  - 有这一格 = **单品的画**。它和那一套坐标硬绑定，离开那套坐标这些像素就没有意义。
  - 没有这一格 = **自由的图**。可以平铺，可以给材质用。
  - 这就是「单品的贴图」和「可以刷的材质」的全部区别。它们是同一种东西，不是两种身份。
  - 用了单品的画的材质，只能给这个物件自己的面用（下面「每张面只走一样」）。

### 贴图坐标：可以有很多套，每一套是一块画布

user 11-10 深夜：「单品的画，它应该是和贴图坐标硬绑定的，因为你贴图重新生成了，你这个画就没有任何意义了……如果你要重新生成 UV 的时候，你旧的 UV 还是会保留的，然后会问你说要不要把画给重新拷过去。但是……不应该有画之后 UV 就锁定，因为你拖一个角，稍微拖拖这种修改还是允许的……有点像就是你这个物件关系图里面的引用……你画会引用这个 UV，那它就会一直在这里，不会被删掉，不会被清掉。然后你生成的 UV 是新的 UV……贴图坐标可能会有很多个」。

- 一套贴图坐标有自己的身份号和名字，一个物件可以有好几套。
- **一套坐标只管「走它的那些面」**：哪些面的材质用了照着这一套画的贴图，这一套就覆盖哪些面的角；别的面在这一套上没有位置，也不占画布。
- **一套坐标就是一块画布**：它定了画布多大，另外记着一个「铺的时候用的密度」（见下面「尺寸和密度归谁」）。
- **同一块画布上可以有好几张贴图**：颜色一张、长草一张、粗糙一张，它们共用同一套格子。这是「以后有多张贴图怎么办」的默认答案：不用多套坐标，多张贴图铺在同一套上。
- 需要另一套的情况：想要另一种密度（刷怪概率一米一格就够，不用跟颜色一样密）；或者重新生成了一遍。
- **生死按引用**：被贴图引用着的那一套不会被删、不会被清。没有贴图引用的，在物件的属性列表里灰着，你可以删。
- **三种改法，分清楚**：

| 你做了什么 | 贴图坐标 | 画 |
|---|---|---|
| 拖一个角微调 | 在原来那一套上改 | 像素不动，画在模型上跟着挪一点 |
| 整理（只平移，把空洞挤掉） | 在原来那一套上改 | 像素跟着整块平移，无损 |
| 建模（切面、长新面……） | 每一套都按同样的规则跟着变 | 切出来的小块继承，新面是空白 |
| **重新生成** | **新出一套，旧的留着** | 问你要不要把画拷过去。拷 = 重新采样出新的贴图，绑在新的那一套上；旧的画和旧的那一套都还在，直到你自己删 |

- 10-30 定过「一套、多重 UV 降成脑洞」。那时说的是「每个图层各用一套」，现在仍然不做那个。今天说的「很多套」是另一回事：是整块画布的另一个版本或另一种密度。

### 槽：意思写在用它的那一方

user 11-10 深夜：「我一开始的想法是意思是槽，你可以指定贴图……如果你想用同一张贴图同时管多个通道、多个语义怎么办？如果你不想复制他们的话。」

- 材质上有一张小表：通道的名字 → 哪几张贴图（从下往上的一摞；第一版只放一张）。**物件上没有这张表**（第 4 版）。
- 意思写在这张表上，不写在贴图上。所以同一张贴图可以同时接到好几个通道，不用复制。
- **通道的名字是开放的**，不只是渲染器认识的那几个：
  - 渲染器认识的：颜色，以后的粗糙、发光……它本来就有一张语义通道的登记表。
  - 你自己起的：长不长草、刷怪概率、地面是雪还是钢板。渲染器不认识它们，照样存、照样能画、照样导出；读它们的是游戏那边的逻辑。
- 同一个名字可以是「每张面一个数」，也可以是「一张贴图」。面上的标签（表面工作台那一套）和贴图上的标签是同一种东西，只是细到面还是细到像素。
- 一个槽里的一摞，可以混着放自由的图和单品的画：自由的图平铺，单品的画按它那一套坐标铺，从下往上一层层盖。更花的叠法（相乘、按遮罩混）是以后材质那边的事。
- **这就是游戏引擎里细节贴图、贴花、光照图那一套**（user 11-10 深夜：「不同的贴图按照不同的坐标放，然后……材质把它们给融合起来，对吧？这不是很常见的吗？」）。和引擎不一样的两点：用身份号指那一套坐标，不用第几号；贴图坐标只当贴图坐标用，别的数据是另一列有自己名字的属性，不往坐标通道里塞（user：「有时候贴图坐标也会被滥用做别的语义，当然这个样子我们就得用别的语义，不是贴图坐标」）。

### 每张面只走一样：它的材质。画是一种材质（第 4 版）

user 11-10 深夜：「我反而觉得，就是说，你面一个面设置了材质，就是材质；设置了画，就是画，而不是没画的地方透出材质。然后没材质的地方透出画，虽然对耳环这些东西比较合理，对装饰品比较合理，但我觉得也有点怪怪的。关键是你这个面走什么？不过实际上，大部分建模的时候都是会分成不同的物体，只是说我们有些时候会把不同的物体给合在一起，对吧？这个是我们要兜得住。」

- **一张面长什么样，只问一个地方：它的材质。** 这是现在就有的东西（每张面记着自己用哪个材质）。
- **「画」就是一种材质**：它的颜色那一槽接的是「照着这个物件的贴图坐标画的贴图」。你对一个物件点「开始画」，程序做三件事：给要画的那些面铺一套贴图坐标；建一张贴图和一个接着它的材质；把这些面的材质换成它。
- **没画的地方露出的是这个材质自己的底色**（材质本来就有一个颜色），不是别的材质。
- **耳环、皇冠**：那些面的材质是「金属」，就是金属。它们不走画，在贴图坐标上没有位置，也不占画布。笔碰到它们不吃颜色。
- **把一张面从金属改成画**：这张面在那一套坐标上还没有位置，当场给它铺一块。和新长出来的面一样。
- **把几个物体合成一个**（要兜得住的那件事）：每个物体带着自己的材质、自己那一套贴图坐标、自己的画过来。合完之后这个物件有两套坐标、两个画的材质，各管各的面。不重新采样，不重排。以后想压成一张画布，是一个明着做的动作。
- **从一个物件里分出一部分**：分出去的面带着材质走；它们用到的贴图坐标和画跟着复制一份。
- **砖墙上画苔藓**：一个材质，颜色槽里叠两张，下面是平铺的砖，上面是照着这面墙的坐标画的苔藓。
- **头发片、睫毛**：画的材质自己的底色设成透明，没画的地方就是镂空。
- 你之前说的「画属于物件」仍然成立：这个材质接着单品的画，只能给这个物件用，跟着物件走、跟着物件复制。它在这个物件的材质列表里是一行，不用你单独去管。

### 尺寸和密度归谁（user 11-10 深夜问的）

user：「单品的贴图的话，它就没有像素密度这个概念了。然后你再想一下材质的贴图的话，像素密度也许应该归贴图，而不是材质？」两句都对：

- **自由的图（材质用的那种）：真实尺寸归贴图，不归材质。** 「这张砖墙的照片拍的是一米见方」是这张图自己的事实。归了贴图，所有用它的材质尺寸自动一致，改一处全对齐。现在文件里这个数恰好是写在材质上的，搬贴图表的时候一起搬过来。个别材质想故意把图铺大一倍，那是用法，以后在槽上加一个倍数，默认是一。
- **单品的画：贴图自己没有密度。** 它的每个像素在哪，完全由贴图坐标决定，而且脸那一块可以比身子密。
- **那一套贴图坐标上记着一个「铺的时候用的密度」。** 它是一个设置，不是贴图的性质：自动铺的时候按它定每块多大；以后新长出来的面也按它铺。你 10-30 说的「用户只关心密度」，在界面上对应的就是这个数。

## 二、几条规矩

- **走画的面，每个角在那一套贴图坐标上都有位置。** 新长出来的面如果材质是画，在长出来的那一步就铺好；改成走画的面，在改的那一步铺好。
  - 11-10 夜补（施工单（八））：唯一的例外是画布加到上限还放不下的面。它们留着没有位置，照材质的底色显示，那一步明着报「有几张面在画布上放不下」；建模的那一步不因此做不成。
  - 面从画的材质换成别的材质：它在画布上的那一块留着不清，换回来画还在。清掉旧的块是以后「整理」的事。
- **同一个组件摆好几份，共用贴图。** 把组件变成独立的时候，它的贴图坐标和贴图跟着复制一份。
- **第一版只做「颜色」一个通道、一套贴图坐标。** 上面说的多套、多通道、一个数、标签，这一版只把格子留对，不开入口。材质的贴图能画，也是到材质窗口那一段再开。
- **新建贴图坐标时的默认密度**：按物件的大小算，让画布大约是 1024 见方。你可以改。改密度 = 重新生成一套。
- **画布有上限**：受显卡限制（iPad 上一般是 4096 或 8192）。快到上限时提前告诉你。
- **存盘的大小**：分层的贴图比几何大得多。没改过的贴图，存盘时直接用上一次编好的字节。
- **给别的软件看的那一张**：每个材质的颜色贴图 = 那一摞合成的结果叠在材质自己的底色上（单品的画再补过边）。因为画就是材质，这在标准格式里就是普通的「材质 + 贴图 + 第几套坐标」，别的软件直接认。别的通道第一版不写进标准的那一半。

## 三、定了的一件事：旧版本打不开带贴图的物件（user 同意）

- 旧版本不认识角上的贴图坐标。让它打开，你在里面切一刀，那一列还是旧的，存回去画和模型就对不上了，而且是悄悄坏的。
- 所以带贴图坐标的网格体在文件里盖新的大版本号，旧版本拒绝打开并明说要更新。没有贴图坐标的文件不受影响。
- user：「大版本号可以，我们不需要太念旧。现在我们这个东西连宣发都没宣发。」

## 四、我自己定了、你没逐条说过的

- 贴图坐标用小数存（单精度），单位是像素。
- 贴图只带「装的是哪种数」，不带通道的名字（上面说了理由）。
- 画布的大小和密度归贴图坐标那一套管，不归贴图。同一套上的贴图大小永远一样。
- 槽只在材质上。接了单品的画的材质，只能给那个物件的面用。
- 现有文件里嵌在材质里的图，打开时搬进贴图表、现给一个身份号。两个材质用了一模一样的图也是两条，不按内容合并。
- 贴图表如果被更新的版本写过、当前版本不认识：不拒绝打开，原样带着，按合成图只读显示。（11-10 深夜写施工单时收窄：第一版先按材质的底色显示，不去读给别的软件看的那张合成图；要等真有更新的大版本才会碰到，到时候再补。）

> 11-10 深夜补：第一张照这份做的施工单是 `20261110-paint-workorders-2.md`（贴图成为独立的条目）。写它的时候定了几处这里没写细的，以那一页为准：
> - 文件里图的字节用 `{ "bufferView": N }` 指（不用图片下标），标准那一半的图片指同一个 `bufferView`，字节只存一份。原因：老版本原样带回不认识的扩展时只会改 `bufferView` 的号。
> - 材质扩展里照写 `sizeM`，只当给 1.2 老版本看的回声；新版本有 `channels` 就不看它。
> - `content` 多一种「不认识的」：更新的版本写的种类，整行和字节原样带回。
> - 新文件被老版本存过一遍之后：图不丢，贴图的身份号换一个，表里多一行孤儿。不按内容认图。两个材质共用一张贴图的，存过这一遍之后变成各有各的一张（共用关系丢了，多一份同样的字节）。
> - 清材质不顺手清图；贴图有自己的清理指令（`purgeTextures`）和资源页上的一节。
> - 下面校验里和贴图坐标、分层画布大小有关的几条，等贴图坐标（1-2、1-3）和存盘（1-8）那几张工单再做。

## 五、形状（提案 `.h`，实现中变了要回写）

```ts
// —— 顶层扩展（可选）：CATSUP_textures 1.0。空 = 不写这个扩展。major 比本版新 → 不拒开（同 desk / references / shelf）。
export type TextureContent =
  | { kind: "image"; mimeType: string; bytes: Uint8Array }   // 原图：导入的字节，一字不动
  | { kind: "layered"; ora: Uint8Array | null };             // 分层：画画内核 encodeOra 的字节（本层不解释）。内存里可以是空：新建的画还没编过码（施工单（八）第三节）；文件里永远有字节

export type TextureValue =
  | { kind: "color" }
  | { kind: "scalar" }                                       // 0..1
  | { kind: "tag"; table: { id: number; guid: Guid; name: string; color: [number, number, number] }[] };   // 编号只是对照表的代号（家规）
export interface TextureDoc {
  guid: Guid; name?: string;
  value: TextureValue;
  content: TextureContent;
  /** 自由的图：真实尺寸（米）。老规矩：每张图必须带长度尺度。照着贴图坐标画的图不写这个键（尺寸跟那一套坐标走）。
   *  CATSUP_textures 1.2（2026-11-12，施工单二十一第 3 刀，Claude Opus 5.5）：content 是分层的、带 sizeM、没有 layout = 平铺的画——贴着它的面按 sizeM 平铺显示它的合成图，
   *  和自由的图同一种铺法；只在画布小窗里画（一格对着模型上很多个地方）。形状没变（1.0 起就允许这个组合，只是以前没有意思）；问它只经 tiledPaintIn（和 colorMapIn、paintIn 三个互斥）。
   *  1.1 的读者（v0.19.60 及以前）：colorMapIn 要原图、paintIn 要 layout，两个都答不是 = 按底色显示，行原样带回（拿 v0.19.60 的真代码验过，scripts/old-reader-check.mjs）。 */
  sizeM?: [number, number];
  /** 单品的画：硬绑定到哪个定义的哪一套贴图坐标。有 layout 就没有 sizeM，反之亦然；两个都有或都没有 = 文件坏了。 */
  layout?: { definition: Guid; uvSet: Guid };
}

// —— 槽：通道的名字 → 贴图。名字是开放集（渲染器 material/ 登记表里的，或用户自己起的）；本层不解释、认不出的原样带回。
export type ChannelSlots = Record<string, Guid[]>;   // 每个通道一摞，从下往上盖；1.0 只写一张。写成一摞是为了以后叠第二张（细节图、贴花）不用改格式

// DefinitionDoc 不加键：面走什么只问材质（面 → 槽号 → materialSlots → 材质），第 4 版起物件上没有槽。

export interface UvSetDoc {
  guid: Guid; name?: string;
  width: number; height: number;     // 画布，像素
  pxPerM: number;                    // 铺的时候用的密度（设置；自动铺和给新面铺时用。不是贴图的性质，各块实际密度可以不一样）

  loopUv: Float32Array;
```

- **校验（读取时，不猜）**（11-11 改成一条统一的规矩；原来的写法留在下一行）：**贴图坐标是模型的附属数据。它坏了，模型照开；坏的那一部分按「没有」处理，记进 `readNotes`，打开之后明着告诉用户（并说明再存盘会把坏的部分去掉）。只有模型本体读不出来、或者拍子比自己新，才拒开。** 逐条：
  - 一张面在一套坐标上有的角有数、有的角是 NaN；或者角上的数是无穷大、落在画布外面 → 这张面在这一套上整面按没有位置处理。不夹回画布里。
  - 一套坐标本身的数不对（宽高不是正整数、密度不是正的有限数、身份号缺了或不是字符串、`loopUv` 长度不对）→ 这一整套不认，当它不存在。
  - 同一个网格体里几套坐标用了同一个身份号 → 这几套都不认（不挑第一个）。不同网格体之间重号不算错。
  - 面的材质用了某套坐标上的画、而这张面的角在那一套上没有位置 → 照材质的底色显示，记一笔。
  - 接了单品的画的材质被别的定义引用 → 那个引用当没有材质，记一笔。贴图的 `layout` 指向不存在的定义或 `uvSet` → 这张贴图当孤儿留着，记一笔。槽指向的 GUID 不在表里或种类不对 → 当这个槽空着，记一笔。
  - 读进来之后内存里的自检要全过：规矩在读的这一层收口，不把坏数据放进场景。
  - 分层贴图的画布大小和那一套的宽高要不要一致、不一致怎么办：归 1-8（11-11 定过画板可以比坐标高一截）。给别的软件看的那一半带 `TEXCOORD_n`：归 1-8。
- （原来的写法，11-11 之前，留作记录）`loopUv` 长度不对 → `fail`。面的材质用了某套坐标上的画、而这张面的角在那一套上是 NaN → 不拒开，这张面照材质的底色显示，`readNotes` 记一笔（11-10 夜改：画布加到上限还放不下的新面就是这个状态，施工单（八）第四节；原来写的是 `fail`）。接了单品的画的材质被别的定义引用 → 那个引用当没有材质，`readNotes` 记一笔。贴图的 `layout` 指向不存在的定义或 `uvSet` → 这张贴图当孤儿留着，`readNotes` 记一笔，不拒开。同一套 `uvSet` 上的分层贴图画布大小和 `width × height` 不一样 → `fail`。槽指向的 GUID 不在表里 / 种类不对（物件的槽指了自由的图）→ 当这个槽空着，`readNotes` 记一笔。
- **`ImageAsset` 退役**：材质不再装图。内存里 `scene/scene.ts Material.texture` 改成 `channels`。全仓读 `.texture` 的地方约 20 处（`format/write.ts` 7、`editor.ts` 3、`render3.ts` 2、`pool-mesh.ts` 2、`ops.ts` 2、`main.ts` 2、`scene-doc.ts` 2、`read.ts`、`resources.ts`、`stream-provider.ts`、`paste-actions.ts` 各 1）。渲染器的贴图缓存键从「材质对象」换成「贴图条目 + 它的版本号」。
- **角上的列是通用的**：网格体内核里「角上的一列数」做成通用的东西，贴图坐标是它的一种，可以有任意多列。新建面时交代来历（`addFace(from)`）之后，每一列按同一段代码继承。以后角上的别的属性（按面画的顶点色、拆开的法线）也走它。
- **拍子**：
  - `CATSUP_textures` 1.0：新扩展。
  - `CATSUP_material` 1.2 → 1.3（minor）：多一个键 `channels`。标准那一半（`baseColorTexture` → 图）照写，老读者读到的和现在一样；它存回去贴图的身份号会换一个，内容不丢（提示一次）。材质的槽指着**分层**的贴图时这个材质盖 2.0（major）：老读者会丢图层。第一版不开这个入口，拍子先定下。
  - `CATSUP_definitions` 不动（7.0）：物件上没有新键。
  - `CATSUP_mesh` 2.0（major，user 同意）：带 `uvSets` 才盖；没有的盖 1.2，字节和现在逐字一样。这是「写入器只写当前拍」的例外，写进 `migrate/index.ts` 头注释。
- **导出时的坐标通道**：贴图坐标在我们这里按 GUID 指；写标准那一半时按出现的顺序编成 `TEXCOORD_0`、`TEXCOORD_1`……，每张图的引用带上对应的 `texCoord` 号。1.0 只会出第 0 套。
- **glTF 标准那一半**（`bake.ts` / `write.ts`）：每个材质照现在的办法写成一个 glTF material；颜色槽那一摞合成成一张图（over 材质自己的底色；有单品的画就补边）当 `baseColorTexture`，带上对应的 `texCoord`。烘出来的 primitive 按材质分（现在就是），用到哪一套坐标就带哪一套 `TEXCOORD_n`（= 像素坐标 ÷ 画布宽高）。不再需要现生成的 material。别的通道 1.0 不进标准那一半。
- **引用和孤儿**（`scene/resources.ts` 那一套）：贴图被槽、素材架引用就活着；贴图坐标被贴图的 `layout` 引用就活着。没人引用 = 孤儿，列出来、能删，不许哪个动词顺手删。「重新生成」只新建，不删旧的。跨文件粘贴、把组件变成独立的：贴图坐标和照着它画的贴图一起按值拷、铸新 GUID、`layout` 重新对上。
- **存盘的字节缓存**：`content` 的字节由宿主按「这张贴图的版本号没变就复用上次的」给；格式层不管。

## 六、迁移和样本

- `CATSUP_mesh` 1.2 → 2.0：STEPS 里登记一条空迁移（1.2 的形状是 2.0 的子集）。
- `CATSUP_textures` 1.0：新扩展，登记进 `FORMAT`、`CATSUP_EXTENSION_ORDER`、`extensionsUsed`（有才列）。
- `CATSUP_material` 1.2 → 1.3：读老文件时把嵌着的图搬进贴图表（`migrate/material.ts`）。
- 冻样本：一个没有贴图的文件；一个材质带原图的老文件（读进来贴图表里有一条、标准那一半的字节不变）；一个定义带一套贴图坐标和一张两层的颜色贴图的文件；一个定义带两套贴图坐标、其中一套没有贴图引用的文件（确认孤儿读得进、写得回）。`node scripts/freeze-format-fixtures.mjs`。
- 守卫：定义带自己贴图的文件用上一版的读取器读，必须是 `FormatTooNewError`，不是静默打开；src 里除了格式层和贴图表的访问口，不许有第二种「一张图」的类型（`ImageAsset` 只许参考卡片用，或者删掉）。

## 七、没定的

- 蒙版存在 ORA 里的哪（归内核，0-8 那张工单定）。
- 槽上的用法参数：倍数（材质想把图故意铺大铺小）、取样方式跟贴图还是跟槽。等材质窗口那一段定。
- 材质的颜色加「透明」这一档（头发片、睫毛要用）。
- 把一个物件上的两套画布压成一张的动作（合并物体之后用）。
- 一张贴图的某一个分量当一个通道用（比如红色那一路当粗糙）。现在是一张贴图整张接一个通道，可以接多个；按分量拆以后要再加。
- 标签贴图怎么画（硬边、不模糊）归内核的动作分类表管，具体的笔到做的时候定。
