## 一、只有一种条目：贴图（第 2 版）

> 第 1 版把「画」和「贴图」写成了两个类型。user 11-10 深夜：「画和贴图的区别是什么？为什么他们是两个不同的类型，而不是同一个类型的不同多态？」问得对，改成一种。
> 第 1 版分成两类的原因不成立：现有代码里贴图是嵌在材质里的一张图，我没把它一般化，而是在旁边另开了一张表。那样素材架、孤儿管理、跨文件粘贴、导出、显存记账，以后每一样都要对两种东西各写一遍。

**它们真正的区别不在图本身，在另外两件事上：**

| 区别 | 是什么 | 归谁 |
|---|---|---|
| 内容的形态 | 导入进来没动过的原图；画过之后带图层的 | 贴图自己的两种状态。原图上画了一笔，就变成带图层的 |
| 谁在用它、怎么铺 | 材质用它 = 平铺；物件用它 = 独一份地铺在自己身上 | 用它的那一方 |

**所以文件里是这样：**

1. **一张「贴图」表。** 一行是一张贴图，有自己的身份号，名字只是显示。现在嵌在材质里的那张图，搬进这张表。
2. **材质指向一张贴图**，铺法是平铺（按贴图的真实尺寸）。和现在的行为一样，只是从「里面装着一张图」变成「指着表里的一张」。
3. **物件也可以指向一张贴图**，铺法是「按我自己角上的坐标」。这就是之前说的「物件的画」。没画过的物件没有这一格。
4. **网格体的每个角上多一列贴图坐标**，存的是「第几个像素」。只有指着贴图的物件才有这一列。

一张贴图里面装着：

| 内容 | 说明 |
|---|---|
| 身份号、名字 | |
| 真实尺寸（这张图代表多少米宽、多少米高） | 现有的老规矩：每张图必须带长度尺度，真实尺寸是准的，像素只是分辨率。密度（每米多少像素）= 像素 ÷ 真实尺寸，界面上给你看的是密度 |
| 意思 | 这张图是「表面的颜色」。登记的是意思，不是渲染器的哪个槽。渲染器那边本来就有一张「语义通道」的表，颜色是其中一个 |
| 内容，两种形态之一 | **原图**：导入的那张图的原始字节，一个字节不动。**分层**：画画软件的开放格式（ORA），图层、草稿层、以后的蒙版都在里面，取出来画画软件能直接开 |

给别的软件看的那一张合成图不算贴图的内容，它是每次存盘现做的（见下）。

## 二、几条规矩

- **原图上第一次动笔，它就从「原图」变成「分层」**：原图成为最底下一层，之后的笔画在上面。这一步明着告诉你（比如 JPG 导入的图画过之后不再是 JPG）。没动过的原图永远原样保存，不重新编码。
- **指着贴图的物件，每个角都有贴图坐标。** 第一版以物件为单位：物件一旦有了自己的贴图，它所有的面都铺好、都存。新长出来的面在长出来的那一步就铺好、存上。
- **物件的贴图叠在材质上面。** 没画的地方是透明的，透出材质。第一版材质只支持纯色当底；底下也是贴图的情况（砖墙上画苔藓）放到「接住现成的」那一段。
- **同一个组件摆好几份，共用一张贴图。** 和几何一样。把组件变成独立的时候，它的贴图跟着复制一份。
- **材质的贴图也能画**（你定的：通用的东西可以做成材质）。因为是同一种东西，同一套笔直接能用；画的时候它是平铺的，画到边上会从另一边绕回来。这一条第一版不开入口，到材质窗口那一段开。
- **物件新建贴图时的默认密度**：按物件的大小算，让整张图大约是 1024 见方。你可以改。改密度等于重新采样，会明说。
- **画布有上限**：受显卡限制（iPad 上一般是 4096 或 8192）。快到上限时提前告诉你。
- **存盘的大小**：分层的贴图比几何大得多（一张 2048 见方、几层的是几 MB）。没改过的贴图，存盘时直接用上一次编好的字节。
- **给别的软件看的那一张**：材质的贴图 = 它自己（原图就是原图，分层的就是合成结果）。物件的贴图 = 合成结果再叠到每张面的材质底色上、补过边。Blender、Windows 预览看的是这一张；我们自己读文件时不用它。

## 三、要你定的一件事：旧版本打不开带画的文件

- **这是什么**：旧版本的三维软件不认识「角上的贴图坐标」这一列。如果让它打开一个物件带贴图的文件，它不知道有这一列，你在里面切一刀，面和角都变了，那一列还是旧的。存回去之后，画和模型就对不上了，而且没法恢复。
- **所以**：凡是带着自己贴图的网格体，在文件里盖一个新的大版本号。旧版本看到这个号会拒绝打开，并且明说「要更新才能打开」。和 11-04 定义表升大版本时是同一种做法。
- **影响谁**：你别的设备上如果还开着没更新的旧版本，要刷新一下才能开这些文件。没有画的文件不受影响，旧版本照开。正式版的用户打不开开发版存的带画的文件，直到正式版也更新。
- **不这么做会怎样**：旧版本能打开，但只要在里面动过模型再存，画就废了，而且是悄悄废的。
- 我的建议：盖大版本号。

## 四、我自己定了、你没逐条说过的

- 贴图坐标用小数存（单精度）。边界上的点落在像素角上是整数；面被切开后中间新出来的点是小数。
- 物件没有自己的贴图、材质的贴图也都是没动过的原图时，旧版本照样能开（它读的是文件里标准的那一半）。
- 现有文件里嵌在材质里的图，打开时搬进贴图表、现给一个身份号；存一次之后身份号就定了。两个材质用了一模一样的图，也是两条，不按内容合并（家规：不拿内容当身份）。
- 「给别的软件看的那一张」是每次存盘现做的，不是正本；正本是分层的源文件。
- 贴图表如果被更新的版本写过、当前版本不认识：不拒绝打开，原样带着，贴图先按那张合成图显示、不能改。这和参考窗、素材架现在的做法一样。

## 五、形状（提案 `.h`，实现中变了要回写）

```ts
// —— 顶层扩展（可选）：CATSUP_textures 1.0。空 = 不写这个扩展（抠）。major 比本版新 → 不拒开（同 desk / references / shelf）：
//    原字节进 carry.extensions 原样写回、readNotes 记一笔、这些贴图只读显示。
export type TextureContent =
  | { kind: "image"; mimeType: string; bytes: Uint8Array }   // 原图：导入的字节，一字不动
  | { kind: "layered"; ora: Uint8Array };                    // 分层：画画内核 encodeOra 的字节（本层不解释）
export interface TextureDoc {
  guid: Guid;                       // 身份；名字只是显示、可重名
  name?: string;
  sizeM: [number, number];          // 真实尺寸（米）。老规矩：每张图必须带长度尺度，sizeM 是真源，像素只是分辨率
  channel: string;                  // 语义通道 id（渲染器 material/ 的登记表）；1.0 只写 "color"；认不出的原样带回
  content: TextureContent;
}
export interface CatsupDocument { /* … */ textures: TextureDoc[] }      // 列表顺序没有语义

// —— 用它的两方
export interface MaterialDoc { guid: Guid; name: string; color: [number, number, number];
  texture?: Guid }                                                      // 以前 = 嵌着的 ImageAsset；现在 = 指向贴图表。铺法 = 平铺（按 sizeM）
export interface DefinitionDoc { /* … */ texture?: Guid }               // 这个定义自己的贴图；铺法 = mesh.loopUv。只在有时写

// —— CATSUP_mesh 2.0（major）：带 loopUv 的网格体才盖 2.0，没有的照旧盖 1.2
export interface MeshDoc { /* … */
  /** 每个角一对贴图坐标（像素单位，f32 成对；长度 = 2 × loopVert.length；和 loopVert 同序）。只在定义有自己的贴图时写。 */
  loopUv?: Float32Array;
}
```

- **`ImageAsset` 退役**：材质不再装图，`document.ts` 里那个类型只剩参考卡片在用就留给它，不然删掉。内存里 `scene/scene.ts Material.texture` 同步改成指向贴图。全仓读 `.texture` 的地方约 20 处（`format/write.ts` 7、`editor.ts` 3、`render3.ts` 2、`pool-mesh.ts` 2、`ops.ts` 2、`main.ts` 2、`scene-doc.ts` 2、`read.ts`、`resources.ts`、`stream-provider.ts`、`paste-actions.ts` 各 1），都改成「按 GUID 到贴图表里取」。渲染器的贴图缓存键从「材质对象」换成「贴图条目 + 它的版本号」。
- **拍子**：
  - `CATSUP_textures` 1.0：新扩展。
  - `CATSUP_material` 1.2 → 1.3（minor）：多一个键 `texture: guid`。标准那一半（`baseColorTexture` → 图）照写，所以老读者读到的和现在一样；它存回去会把图重新嵌进材质、丢掉 `texture` 键和贴图表里的那一条的联系 = 贴图的身份号换一个，内容不丢（minor 语义，提示一次）。
  - 材质指着一张**分层**的贴图时，这个材质盖 `CATSUP_material` 2.0（major）：老读者会把合成图当普通图读进来、存回去丢掉图层，属于悄悄丢内容，所以拒开。第一版不开这个入口，拍子先定下。
  - `CATSUP_definitions` 7.1（minor）：`texture` 键。
  - `CATSUP_mesh` 2.0（major）：见下。
- **为什么 mesh 要 major**：老读者不认 `loopUv`，照 minor 语义会原样带着它（`carry`），而 `loopVert` 被它改过 → 两列对不上、无法恢复。三级语义里这是「不可兼容 → 拒开」。
- **「有才盖新的大版本」是「写入器只写当前拍」的例外**，要在 `migrate/index.ts` 头注释和编码处写明：`FORMAT.CATSUP_mesh` 记 2.0，`loopUv` 缺 → 盖 1.2 的拍子（字节和现在逐字一样）；`CATSUP_material` 同理。冻结样本两种都要有。
- **读取**：`loopUv` 在、长度不对 = 文件坏了，`fail`，不猜。定义有 `texture` 但 mesh 没有 `loopUv`、或者反过来 = 同样 `fail`。`texture` 指向的 GUID 不在表里 = 当没有贴图，`readNotes` 记一笔，不拒开。老文件（没有贴图表）：材质的 `baseColorTexture` 图读进贴图表、现铸 GUID（和 11-04 材质的 GUID 同法）。
- **glTF 标准那一半**（`bake.ts` / `write.ts`）：材质的贴图照现在写（分层的写合成图）。有自己贴图的定义，烘出来的 primitive 带 `TEXCOORD_0`（= 像素坐标 ÷ 宽高），用一个现生成的 glTF material（`baseColorTexture` = 合成图 over 每张面的材质底色、补过边，`baseColorFactor` = 1）；这个 material 不带 `CATSUP_material`，读的时候跳过。
- **存盘的字节缓存**：`content` 的字节由宿主按「这张贴图的版本号没变就复用上次的」给；格式层不管。
- **引用和孤儿**：贴图被材质、定义、素材架引用就活着；没人引用 = 孤儿，进现有的那一套（`scene/resources.ts`），不许哪个动词顺手删。跨文件粘贴带着贴图走（按值拷、铸新 GUID），和材质同法。把组件变成独立的 = 它的贴图复制一份、铸新 GUID。

## 六、迁移和样本

- `CATSUP_definitions` 7.0 → 7.1：加可选键，不用迁移函数。
- `CATSUP_mesh` 1.2 → 2.0：STEPS 里登记一条空迁移（1.2 的形状是 2.0 的子集）。
- `CATSUP_textures` 1.0：新扩展，登记进 `FORMAT`、`CATSUP_EXTENSION_ORDER`、`extensionsUsed`（有才列）。
- `CATSUP_material` 1.2 → 1.3：读老文件时把嵌着的图搬进贴图表（`migrate/material.ts`）。
- 冻样本：一个没有贴图的文件；一个材质带原图的老文件（读进来贴图表里有一条、标准那一半的字节不变）；一个定义带自己的分层贴图、两层的文件。`node scripts/freeze-format-fixtures.mjs`。
- 守卫：定义带自己贴图的文件用上一版的读取器读，必须是 `FormatTooNewError`，不是静默打开；src 里除了格式层和贴图表的访问口，不许有第二种「一张图」的类型（`ImageAsset` 只许参考卡片用，或者删掉）。

## 七、没定的

- 蒙版存在 ORA 里的哪（归内核，0-8 那张工单定）。
- 多个通道（粗糙、发光）各一张贴图，还是一张贴图里多个通道。现在只有颜色，先不定。
