## 零、这一版怎么做

和第 1 版同一套：一口气做完，做完统筹一口气审、小弟一口气修；施工单没写到的细节照已有的规矩先定、记进施工记录；顾虑和小调整记进第八节，不停工。**停下报统筹只有三种**：会丢数据或写坏文件；挡住做不下去；要动文件格式、撤销里存什么、存盘、修改锁。

这一版**看得见的应该不变**（例外只有第二节第 4 条那一种，要列出来）。它买的是：第 3 版换键位、给硬表面加键盘起手、加新工具时，不用一把一把工具改。

## 一、它现在是什么毛病、以后会长成什么

- **毛病**：同一件事每把工具各做一遍。取点那一串（求吸附 → 意图门 → 粘性 → 套锁 → 取整 → 充能 → 画光标）硬表面 12 把工具各拼一遍，拼得不齐；24 个工具文件各自直接提交指令；马后炮各写各的重做闭包。锁那一轮的三个老毛病都出在这，当时是三把各改一遍。
- **不收会长成什么**：每多一种起手方式（键盘起手、笔的重按、回车改数、以后的软鼠标）× 每把工具 = 都要改一遍，每改一遍就多一处拼得不齐。
- **收了之后的样子**：工具只说「我要一个东西 / 一个点 / 一个量 / 一笔」和「要齐了是哪条命令、什么参数」。怎么取到、怎么预演、怎么落定、怎么重做，各只有一处。

## 二、四种「要」，每种只有一处满足

1. **要一个点** = `ctx.point(s, ask, travel)`，新模块 `editor/acquire.ts`（不进 editor.ts）。接口钉在这里：
   ```ts
   /** 工具要一个点时说的话：只说要什么。 */
   export interface PointAsk {
     /** 在哪个世界里取：live = 带着这一下的预演（缺省）；static = 真身（刀：预演里那条边已经劈开了）。 */
     readonly view?: "live" | "static";
     /** 落在哪张平面上（先定平面的工具）；缺 = 由吸附和视线定。 */
     readonly plane?: DrawPlane;
     /** 从哪一点量起：有它 = 这是一段的另一头（对齐、意图门、锁、取整都相对它）；缺 = 第一点。 */
     readonly anchor?: Pt3;
     /** 手里的东西：哪些点在手里（不吸自己）、手里的膜挡不挡。「只算这一下新生的」照旧由 ToolHandler.draws 说。 */
     readonly hand?: { readonly moving?: (vid: VertexId) => boolean; readonly opaque?: boolean };
     /** 工具自己另加的吸附目标（现在的 toolTargets）。 */
     readonly targets?: AlignQuery["toolTargets"];
     /** 吸附被否掉 / 没吸到时的自由点；缺 = 平面上的点（有 plane）或视线上的点。 */
     readonly free?: (sx: number, sy: number) => Pt3 | null;
   }
   export interface PointAnswer {
     /** 最后落在哪（套完锁、取完整）。 */
     readonly p: Pt3;
     /** 给人看的吸附（标签、光标）= 套完锁的那个。 */
     readonly snap: Snap3;
     /** 光标真压着的东西（锁之前）：充能充它；要知道「压着哪条边」的工具读它。 */
     readonly under: Snap3;
   }
   ```
   - **顺序只写在 `acquire.ts` 一处**，照 v0.19.112 定的：求吸附 → 意图门 → 粘性 → 套锁（最后一道）→ 取整 → 充能充 `under` → 画光标和吸附标签。`probe-lock-last` 照旧守。
   - 吃不吃约束照旧只问 `ToolHandler.lock`，不在 `PointAsk` 里重复。
   - 悬停取点（`hoverSnap`）是同一条路的「没有 anchor」那一种，不另留一份。
   - 拼这一串用的零件（`snap` / `applyLock` / `hysteresis` / `dropHysteresis` / `charge` / `intentOn` / `setSnap` / `currentSnap` / `alignSources` / `hand` 这一类）**从 `ToolCtx` 上拿掉**，工具想自己拼也拼不了。拿不掉的逐个写原因。
2. **要一个东西** = `ctx.thing(s, ask)`：拾取 → 拾取范围（点 / 边 / 面的开关）→ 够不够得着（第 1 版那张表，哪一行由 ask 说）→ 分类。现在的 `pick` / `pickStatic` / `pickFace` / `classify` 四个口子合成它。形状小弟清点后提，过统筹。
3. **要一个量**（长度 / 角度 / 倍数）= `ctx.quantity(ask)`：手拖出来的原始数进去；打了数就是打的数，否则照整格的规矩取整（`increments.ts` 一处）；出来的数同时给尺寸文案和马后炮。工具自己不取整、不读打的数。形状小弟清点后提，过统筹。
4. **拼得不齐的怎么办**〔默认〕：以前某把工具少了意图门、充能、锁，清点时分清是**有意的**（写出原因，变成 ask 里一个说得出理由的选项）还是**漏的**。漏的 = 收进来之后自然就有了。这是这一版唯一看得见的变化，版末清单里逐把列出来给 user 判。
5. **要一笔**（画画、雕塑：一串带压力和时间的样本）：现在走 `ctx.paint` 那条路，这一版**不动**，只在清点表里登记成第四种。它归画画内核，以后和共用撤销库一起想。

## 三、命令和工具分开

规矩（user 定的）：**命令 = 给参数做一次变换，不认手和屏幕；工具 = 只管手势；预演和落定是同一条命令、同一组参数，只差作用在影子还是真身。**

1. 手势工具交给底座的是一次命令调用（现成的 `CommandCall`：哪条命令、对谁、什么参数），不再自己造指令、自己提交。底座每帧拿它跑 `plan` 作用在影子上 = 预演，落定时同一组参数再跑一次作用在真身上。
2. **马后炮 = 同一条命令换参数重跑**，和菜单里的命令同一条路。各工具手写的重做闭包拿掉。
3. `ToolCtx` 上直接提交的口子（`commitOp` / `commitXform` / `commitCopies` / `previewXform` / `xformMoveOp` / `copyPayload` / `offerAfterthought` 这一类）拿掉，变成命令里面的事。只读的工具（卷尺、量角器的参考线）也走命令。
4. **命令不读屏幕**：参数里带齐（点用这个单位的本地坐标、数、元素的 id）。`CommandEnv.eye()` 那笔欠账在这里还：改成造面的一个参数，由调用的那一头填；`CommandEnv` 上不留和视图有关的读法。
5. **两族移动 / 旋转 / 缩放 = 同一条命令两种要法**：对齐式和自由式是两把工具（第 1 版合租小三角的那两把），交出来的是同一条命令（移动 = 一个位移；旋转 = 轴心、轴、角度；缩放 = 轴心、坐标架、倍数）。硬表面的选区、网格体的选区、子物体各是一种单位，照现有的「一个动词在每种单位上一条命令」。
6. **撤销里存什么不变**（还是指令）。`CommandCall` 进不进撤销记录、复现包，不在这一版——要动就是停下报统筹的那一种。
7. **快慢**：每帧预演不许比现在慢。整体移动这类现在有快路（影子场景 + 子池叠加变换），要留着：底座认得「计划结果是纯变换」。改前改后在同一次运行里各量一遍（真显卡的无头浏览器），数字进施工记录。
8. 尺子（守卫）：`src/editor/commands/` 不许 import 工具、指针帧、拾取、视口；随便拿一条命令，只给「名字、单位、参数、场景」就能在单元测试里跑。

## 四、起手和收尾归底座（形状清点后定，过统筹）

`ToolHandler` 上有一批口子说的不是「这把工具做什么」，是「这一下怎么开始、怎么结束」：`startModal` / `tap` / `fingerTap` / `awaitsClick` / `commitInPlace` / `sameSpotEnds` / `escFinishes` / `finishLabel` / `pressKind` / `typedQuantity`。第二、三节做完之后，工具 = 「依次要什么」加「要齐了交哪条命令」，这批口子应该能收成工具报的一小张表，由底座照着跑。

清点时每把工具列出它实现了这里面的哪几个、各自特殊在哪。统筹看了表再定形状。收不进去的工具（操纵手柄、雕塑、画画）留一个直接接指针的出口，写明为什么。

## 五、自动测试不写死按键
