> 给谁：Catsup小弟。**等 Fable 看过才合。** 分支 `paint-display`，副本文件夹里。
> 这是短的那种施工单（11-10 夜分工收紧之后）：只写要达到什么、关键的形状、不能破的规矩、碰到什么停。读代码侦察、要改哪些地方、测试的细节，你动手前补在页末「施工细则」里，然后直接做。
> 没有界面入口；只有调试用的钩子和探针够得着（存盘落地之前造得出画的入口不进普通界面）。

## 要达到什么

一张画有了内容之后，模型上走这张画的面显示的就是它；放大看是一格一格的，点到哪格就是哪格。

## 关键的形状

1. **画板**（放 `src/paint/`，不认识 three）：一张贴图一块画板，按贴图的 GUID 登记。画板 = 画画内核的一份作品（画布大小 = 那一套贴图坐标的宽高）加「只合成、不上屏」的入口（0-5）。
   - 整个程序只有一个内核的显卡接口，建在渲染器的显卡画面上（`BrowserGl2Port.fromContext`，0-4）。渲染器那半边只给两样：显卡画面、「内核动过显卡了，你的状态缓存作废」（`resetState`）。three 仍然只出现在 `src/minccino/providers/three/`。
   - 画板不在创建贴图时建。**没有画板的画 = 还没画过 = 照材质的底色显示**（现在就是这样）。这一张里画板只由调试钩子建；以后落第一笔（1-4b）、读文件（1-8）时建。
   - 画板的画布大小跟着那一套贴图坐标走（改模型会让画布加高，撤销会缩回去）。多出来和缩掉的行一定是空白；不是空白就抛。
   - 换文件时全部销毁。显卡画面丢了又恢复：画板和显示用的图都能重建，内容不丢（探路时验过的那条路，转正）。
2. **渲染器的口**（`minccino/contract/stream.ts`）：一张图除了「一包要解码的字节」之外，多一种「别人已经放在同一个显卡画面里的图」。
   - 形状参考：`{ kind: "live", width, height, current(): { handle, version } | null }`。渲染器每帧开画之前问一遍 `current()`；谁要重新合成就在这时候做；问完统一 `resetState` 一次。
   - 渲染器自己备一张**专用的显示图**（普通八位、带多级缩小图、夹边）：`version` 变了就把内核那张拷过来、重新生成缩小图。内核池子里的图不许改采样设置、不许长期拿着。
   - **放大时最近邻**（不跟画风预设走），缩小时用缩小图。
   - 合成时拿材质自己的底色当不透明的底，所以交出来的图不透明。
3. **面的贴图坐标**：走画、而且角上有位置的面，贴图坐标 = 角上的数 ÷ 画布宽高（不翻转：画布第 0 行就是贴图第 0 行）。走画但没有位置的面、没有画板的画，走现在按底色画的那条路。画板出现或消失、材质指的画换了 = 那几块重建。

## 不能破的规矩

- **看得见的结果是唯一的标准**：同一张图，当原图贴上去和当画显示出来，屏幕上同一格的颜色相同；白模不打光时，屏幕上读到的颜色就是那一格的字节。（颜色空间怎么转、在哪一步转，你照这个结果来定。）
- **点到哪格就是哪格**：给每一格涂上互不相同的颜色，随机取屏幕上的点，读屏幕上的颜色对回是哪一格；再用 1-3a 的落点求同一点的格子。两者相同。测试模型里要有一张拉伸过的、四个点不共面的四边形，正面和斜着各测一遍；镜像的两半各测一遍。
- 现有的贴图（导入的图）怎么显示，一个像素不变。截图基线不变。
- 没有任何画板时，渲染器每帧不多做事（量一下）。
- 选中、淡出、几种画风：导入的图在哪种画风里能显示，画也要能；没验到的画风在记录里写明。

## 碰到这些就停下来报

- 内核改画布大小必须经过它自己的撤销。
- 专用显示图要靠改 vendor 里的 three 才做得出来。
- 「同一格颜色相同」做不到逐字节，只能做到差一。
- 合成加拷贝加生成缩小图，1024 见方一次超过 4 毫秒（软件显卡上量的只作参考，写进记录）。
