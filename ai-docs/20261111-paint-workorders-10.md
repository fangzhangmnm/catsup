# 贴图主线施工单（十）：把画显示到模型上（1-3c）

> created 20261111 by Claude Fable 5.2 · as-of 三维 v0.19.15、画画 v0.14.71 · 2026-11-11 凌晨
> 给谁：Catsup小弟。**等 Fable 看过才合。** 分支 `paint-display`，副本文件夹里。
> 这是短的那种施工单（11-10 夜分工收紧之后）：只写要达到什么、关键的形状、不能破的规矩、碰到什么停。读代码侦察、要改哪些地方、测试的细节，你动手前补在页末「施工细则」里，然后直接做。
> 没有界面入口；只有调试用的钩子和探针够得着（存盘落地之前造得出画的入口不进普通界面）。

## 要达到什么

一张画有了内容之后，模型上走这张画的面显示的就是它；放大看是一格一格的，点到哪格就是哪格。

## 关键的形状

1. **画板**（放 `src/paint/`，不认识 three）：一张贴图一块画板，按贴图的 GUID 登记。画板 = 画画内核的一份作品（画布大小 = 那一套贴图坐标的宽高）加「只合成、不上屏」的入口（0-5）。
   - 整个程序只有一个内核的显卡接口，建在渲染器的显卡画面上（`BrowserGl2Port.fromContext`，0-4）。渲染器那半边只给两样：显卡画面、「内核动过显卡了，你的状态缓存作废」（`resetState`）。three 仍然只出现在 `src/minccino/providers/three/`。
   - 画板不在创建贴图时建。**没有画板的画 = 还没画过 = 照材质的底色显示**（现在就是这样）。这一张里画板只由调试钩子建；以后落第一笔（1-4b）、读文件（1-8）时建。
   - 画板的画布大小跟着那一套贴图坐标走（改模型会让画布加高，撤销会缩回去）。多出来和缩掉的行一定是空白；不是空白就抛。
   - 换文件时全部销毁。显卡画面丢了又恢复：画板和显示用的图都能重建，内容不丢（探路时验过的那条路，转正）。
2. **渲染器的口**（`minccino/contract/stream.ts`）：一张图除了「一包要解码的字节」之外，多一种「别人已经放在同一个显卡画面里的图」。
   - 形状参考：`{ kind: "live", width, height, current(): { handle, version } | null }`。渲染器每帧开画之前问一遍 `current()`；谁要重新合成就在这时候做；问完统一 `resetState` 一次。
   - 渲染器自己备一张**专用的显示图**（普通八位、带多级缩小图、夹边）：`version` 变了就把内核那张拷过来、重新生成缩小图。内核池子里的图不许改采样设置、不许长期拿着。
   - **放大时最近邻**（不跟画风预设走），缩小时用缩小图。
   - 合成时拿材质自己的底色当不透明的底，所以交出来的图不透明。
3. **面的贴图坐标**：走画、而且角上有位置的面，贴图坐标 = 角上的数 ÷ 画布宽高（不翻转：画布第 0 行就是贴图第 0 行）。走画但没有位置的面、没有画板的画，走现在按底色画的那条路。画板出现或消失、材质指的画换了 = 那几块重建。

## 不能破的规矩

- **看得见的结果是唯一的标准**：同一张图，当原图贴上去和当画显示出来，屏幕上同一格的颜色相同；白模不打光时，屏幕上读到的颜色就是那一格的字节。（颜色空间怎么转、在哪一步转，你照这个结果来定。）
- **点到哪格就是哪格**：给每一格涂上互不相同的颜色，随机取屏幕上的点，读屏幕上的颜色对回是哪一格；再用 1-3a 的落点求同一点的格子。两者相同。测试模型里要有一张拉伸过的、四个点不共面的四边形，正面和斜着各测一遍；镜像的两半各测一遍。
- 现有的贴图（导入的图）怎么显示，一个像素不变。截图基线不变。
- 没有任何画板时，渲染器每帧不多做事（量一下）。
- 选中、淡出、几种画风：导入的图在哪种画风里能显示，画也要能；没验到的画风在记录里写明。

## 碰到这些就停下来报

- 内核改画布大小必须经过它自己的撤销。
- 专用显示图要靠改 vendor 里的 three 才做得出来。
- 「同一格颜色相同」做不到逐字节，只能做到差一。
- 合成加拷贝加生成缩小图，1024 见方一次超过 4 毫秒（软件显卡上量的只作参考，写进记录）。

## 做完

**画布大小（统筹 11-11 裁定，代替「关键的形状」1 里那两句）**：① 画板的「步的去处」是一个参数，这一张不给（内核记录随手丢，改大小不留步）；② 显示时贴图坐标按**画板实际的宽高**除；③ 坐标的画布加高了画板跟着加高；缩回去时要砍的行（列同理）全空白才缩，有内容就不缩、留着比坐标大，在调试日志里记一笔，不抛、永远不砍有内容的；④ 长远（1-8）画板用 HostedSteps、改大小那一步并进三维的同一步撤销——这一张不做。

**侦察到的、照着做的**
- 内核口：`BrowserGl2Port.fromContext(gl)`（0-4）、`port.glTextureOf(fbo)`、`port.onInvalidated`；作品 = `PaintingWorkpiece({ tree: { width, height } })`（不给 `undo` = 记录随手丢）；合成 = `GLBoard.composite(doc, [r,g,b,1], …)`（0-5，返回 `PooledFBO`，第 0 行 = 画布第 0 行，下一次合成前有效）；改大小 = 令牌里 `layerTiles.resizeAllLeaves(lp => lp.cropped(0, 0, w, h))` + `layerTree.setTreeProp("width"/"height")`（和画画仓 `crop` 同一批动词）。作品 → `GLDoc` 的那一步我在画板里写（树的 view + 每叶的 `LayerPixels`）。
- three r185 的 `ExternalTexture` 绑定时只认 `sourceTexture`、不碰采样设置（`three.module.js setTexture2D`）：专用显示图是渲染器自己用原始 GL 建的一张，采样设置自己定，**不改 vendor**。
- 导入的图：`SRGBColorSpace`、多级缩小图、平铺、画风是像素风时换最近邻。专用显示图要和它「屏幕上同一格颜色相同」：建成 `SRGB8_ALPHA8`（和 three 给导入的图建的同一种），拷贝用一遍小着色器 `texelFetch` 内核那张（字节 = sRGB 编码值）→ 解成线性 → 写进 sRGB 的图（显卡写的时候再编码回去）→ `generateMipmap`。解码再编码能不能逐字节回来，探针里 256 个值全量验；不能 = 停下来报（施工单那一条）。放大 `NEAREST`、缩小 `LINEAR_MIPMAP_LINEAR`、夹边，不跟画风走。
- 网格体的面三角化直接用角的编号（`faceTriangles` 给的是角的下标），所以三角形每个顶点能对回第几个角，贴图坐标 = `cornerValues(面, 那一套)[2i..]` ÷ 画板实际宽高。

**放在哪**
- `src/paint/board.ts`：一块画板（作品 + 自己的 `GLBoard` + 底色 + 改大小的规矩 + 合成）。`src/paint/boards.ts`：按贴图 GUID 登记、换文件（`docEpoch` 变了）全部销毁、`sync(场景)` 跟着坐标改大小、每块一个 `LiveImage`。不认识 three。
- 契约 `minccino/contract/stream.ts`：`LiveImage { kind: "live", width, height, current(): { handle, version } | null }`，`MaterialRef.map` 可以是它。`contract/render-provider.ts` 多两样：`paintGl()`（显卡画面）、`resetPaintState()`（内核动过显卡）。
- 渲染器 `minccino/providers/three/live-image.ts`：专用显示图 + 拷贝那一遍（原始 GL）；`render3.ts` 每帧开画前问一遍用到的 `LiveImage`、有变的拷、统一 `resetState` 一次；没有 `LiveImage` 时一步不多走。
- 编辑器 `stream-provider.ts` / `pool-mesh.ts`：走画、有画板、角上有位置的面进「画」那一组（贴图坐标 = 角上的数 ÷ 画板宽高）；其余照旧。画板出现 / 消失 / 改大小进材质槽签名（那个池整份重建）。`editor.ts` 行数零余量：只把 `provider` 那个字段改成对外只读（同一行），别的都不进它。
- 调试钩子 `__catsup.paint`（`main.ts`）：给一张走画的贴图建画板、灌像素、列出来。

**这一张要跑的**：新测试 `test/paint-board.test.ts`（node，内核软件显卡：建板、灌、合成、加高 / 缩回空白 / 缩回有内容不缩、换文件销毁）、`test/paint-display-uv.test.ts`（池网格给画的面的贴图坐标）；新探针 `probe-paint-display`（点到哪格、导入的图和画同一格同色、sRGB 256 值回环、丢画面再恢复、没画板时每帧不多做事、几种画风截图、量合成 + 拷贝 + 缩小图的时间）；老的：截图基线、`probe-style`、`probe-mesh-bucket`、`probe-paint-spike` 退役（探路分支删掉时一起）。全套一次在交审前。

**五条规矩的结果**（探针 `test/probes/probe-paint-display.mjs`，新；无头 Chromium + SwiftShader）
1. **看得见的结果是唯一的标准**：W-14 之后两句都成立。画在白模不打光下读到的就是字节（灰 0、1、10、54、127、128、200、254、255 逐个相等；③ 的解码要求逐字节，几千个点全对上 = 这一句在模型上成立）；专用显示图读回整张逐字节等于内核那张、256 个值全覆盖（「解码再编码」回环无损，不是差一）。导入的图 = 字节由 W-14 的 `probe-texture-srgb` 管；所以同一张图当原图贴和当画显示同一格同色。⑥ 每种画风旁边放一张导入的单色图、画板灌同一个颜色：白模、像素风、1-bit、剪纸、Tron 两边逐字节一样；写实差 1–3 级（两张面一张在地上一张在盒子顶上，阴影不同）；铸铜两边都不显示贴图（这种画风本来就不照模型上色），差在光照。导入的图能显示的画风（白模、像素风、写实）画都能显示。
2. **点到哪格就是哪格**：每格一个编码色，白模不打光、不画线，屏幕上随机取点读颜色解出格子，和 `cellAt`（1-3a `pickSurface`）比——斜着 300 / 300、正面 200 / 200、右侧（拉歪、四点不共面的面）150 / 150、左侧（镜像的另一半）150 / 150、丢画面恢复之后 120 / 120，**对不上 0**。跳过的：离格子边 < 0.05 格的点（几十个）、缩小的地方（一个像素走 ≥ 0.7 格，取的是缩小图，「点到哪格」不管它；每轮 0–3 个）、读到的颜色不是任何一格编码的点（右侧、恢复之后各 1 个：那一点上盖着别的东西，不是画的颜色，没逐个查是什么）。模型 = 方盒子转网格体、离地 0.5、底下靠前两点往外往下拉（两侧四点不共面、左右对称）、密度 40 格 / 米，画板 1024×256。镜像：两半是对称几何、各自一块铺法（2-7 之前开强行对称两半各铺各的），各测一遍；两半共用同一块画布多边形的情况现在造不出来（没有指令能让两半共用坐标），没测。
3. **现有的贴图一个像素不变 / 截图基线不变**：W-14 已改过并单独重冻那 4 张；这一张在 W-14 之后的 main 上跑截图基线 28 张全过、没重冻。
4. **没有任何画板时渲染器每帧不多做事**：没画板时 `render3.live` 是 null（活的图那一套没建），`update()` 第一行就返回；拉流多一次 `paint.sync`（登记处空 = 立刻返回）。不变的一帧 0.8 ms（软件显卡）。
5. **选中、淡出、几种画风**：画那一组走的是和导入的图同一套材质（`texMats` / 画风的 `texUniform`），选中 / 淡出两支同一个式子；画风见第 1 条。选中 / 淡出没单独截图验。

**量**（软件显卡，只作参考，施工单说软件显卡上的不设线）：1024×256 合成一次 5.4–6.8 ms；内容变了的那一帧（合成 + 拷贝 + 缩小图 + 画）约 6 ms，不变的一帧 0.8 ms；照像素数推 1024 见方约 4 倍。拷贝那一下 CPU 上 0.1 ms（显卡活在后面）。

**测试**：`test/paint-board.test.ts`（node、内核软件显卡：字节一字不差、透明处垫底色、版本、加高 / 缩回空白 / 有内容不缩记一笔、登记处换文件 / 画没了 / 跟着坐标长大）；`test/paint-display-uv.test.ts`（池网格画那一组的贴图坐标 = 角 ÷ 画板宽高、不翻转、拉歪的四边形、画板比坐标大按画板除、有角没位置不进）。`npm test` 全套 1969 过 0 红、画画内核 595 过；截图基线 28 张过；`probe-paint-display` 过。探针进了 `probe-map.json` 渲染那一行。`api/` 重打；流程图加一节。

**和施工单不一样的地方**
1. 画布大小那两句照裁定改了（见上）。
2. 引擎契约里那个字段叫 `gpuImage`（施工单写的 `handle` 撞词汇守卫）。
3. 「点到哪格」只在放大的地方比（缩小的地方取缩小图，数出来跳过）。
4. 每块画板一个 `GLBoard`（各自一个图块池，开局 64 片 ≈ 16 MB 显存、按需长到 256 MB 预算）；没有共用一个。

**不放心的**
- 每块画板一个 `GLBoard` = 一个图块池：画板多了显存按块数涨。几块画板时不要紧，以后（多件物件各有画）可能要几块共用一个池。
- 合成在渲染器问 `current()` 的那一刻做（每帧画之前）：内容变了的那一帧多花合成 + 拷贝的时间；1-4b 一笔一笔画的时候每帧都会变，到时候量。
- 画板改大小现在在拉流的时候做（`sync`），是个有副作用的读；这一张改大小不留步，所以没问题；1-8 换成 HostedSteps 之后，改大小要挪到提交那一步里（和模型那一步并成一步）。
- 读到的颜色不是画的颜色的那两个点没逐个查是被什么盖住的。
- 探路分支 `paint-spike-1`（两个仓）合的时候删。
