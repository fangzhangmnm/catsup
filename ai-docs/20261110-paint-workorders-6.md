## 要达到什么

三维里的一笔是这样走的（设计稿第四⅞节）：

```
笔尖列表（空间里的） → 【三维的空间层：把每颗笔尖画到贴图的格子上，得到这一笔的薄层】 → 【画画内核：把薄层按浓度、混合方式、橡皮、锁透明、选区盖到图层上，预览和落层用同一段着色器】
```

中间那一步归三维（它知道模型的表面）；后面那一步归画画内核，而且**一行都不用新写**：内核现在预览和落层吃的就是「一张和画布一样大的薄层」，只是这张薄层现在只有三个来源：内核自己把二维笔尖画出来的、填色的、区域笔（涂抹、液化）的。

这一张加第四个来源：**宿主已经画好的**。另外把内核里「合成整幅画」和「画到屏幕上」拆开，让宿主能只要合成好的那张图。

对画画软件是纯加法加一处小重构，结果逐像素不变。

## 一、形状（Fable 定的，照做；觉得不对停下来说）

### 1. 第四种薄层（`gl-room.ts`）

```ts
export interface HostOverlayInput {
  kind: "host";
  /** 宿主画好的这一笔。和画布一样大，预乘，第 0 行 = 画布第 0 行。宿主借的、宿主还；内核只读，不归还，不改它的采样设置。 */
  tex: PooledFBO;
  bx: number; by: number; bw: number; bh: number;   // 这一笔碰到的范围（画布像素）；落层时只读回这一块
  layerId: number; opacity: number; erase: boolean; blendMode: string; lockAlpha: boolean;
  selMask: { data: Uint8Array; ox: number; oy: number; ow: number; oh: number } | null;
}
```

- `_addOverlay` 里它走的就是二维笔尖那一支**去掉「把笔尖画出来」之后剩下的部分**：预乘转直值、带上选区、登记。两支后半段是同一段代码，不许抄成两份。
- 「空不空」的判断：范围的宽或高不大于零 = 空。
- `bakeStamps`、`compositeOnce`、取色，凡是收薄层的地方都自然能收它，不另开入口。

### 2. 一笔的档口多一种预览方式（`stroke-session.ts`）

现在有四种：`overlay`（二维笔尖）、`livesync`、`shadow`、`region`。加第五种 `host`：

- 开始：照旧开一个写令牌。
- 画的过程中：宿主每帧调 `session.setHostLayers(list)`，把自己画好的薄层交上来（每个图层最多一张；浓度、橡皮、混合方式由宿主给，锁透明和选区由档口照现在的办法补上）。档口转给显示那一侧（`deps.setHostOverlays`）。
- 抬笔：逐张落层（`deps.commitHost`，里面就是现在落二维笔尖的那条写回链）。**有一张没落成 → 整笔取消令牌、响亮地抛**，照区域笔现在的做法，不许落半笔。
- 取消：撤掉显示，取消令牌，零痕迹。
- 一次手势 = 一个令牌 = 一步撤销，不变。
- 引擎那个参数照旧要给（四个方法的小接口）；宿主的引擎抬笔时返回空。

### 3. 只合成、不上屏（`render-tree.ts`、`gl-board.ts`）

- `RenderTree.renderFrame` 现在是「合成整幅画到一张离屏图 → 画到屏幕」。拆成两步：新方法只做前一半、把那张离屏图返回；`renderFrame` = 前一半 + 画到屏幕。同一段代码，不抄。
- 返回的那张图归内核：下一次合成之前有效，宿主不许归还它、不许改它的采样设置。
- `GLBoard` 加一个对应的入口（参数和 `render` 一样，去掉和屏幕有关的那几个）。
- 底色：宿主可以给一个不透明的颜色当底（现在的 `Background` 本来就支持）。三维那边会用它放材质自己的底色，这样交出去的图是不透明的。
- **`src/shell/gl-board.ts` 进内核的名单**（`test/kernel-tests.json` 的 `kernelFiles`）：它只有一百多行，只引用内核，不碰页面，三维要原样用它。进名单之前确认它过得了内核边界的守卫；过不了就停下来说。

### 4. 笔尖边缘的曲线只有一份（`gl-stamp.ts`）

三维的空间层要自己写「把笔尖画到贴图格子上」的着色器（距离是空间里量的）。但笔尖从硬芯到边缘怎么淡下去、淡彩和叠色怎么累积、淡彩最后怎么上色，必须和画画软件是同一份。

- 把「距离、半径、硬度 → 这一点有多浓」那几行着色器代码提成一个导出的片段；内核自己的着色器改成用这个片段。算式一个字不改。
- 把淡彩最后上色的那一遍（`stamp-color`）做成 `GLStampRasterizer` 上一个公开的方法；`rasterize` 自己也调它。
- 累积用的两种混合方式（取最大、预乘叠加）本来就是显卡接口里有名字的，不用动。
- **软件显卡里的那一份也导出**（11-10 夜补，Fable；施工单（九）要用）：内核的软件显卡（`soft-shaders.ts`）里和这条曲线对应的 JavaScript 写法，同样提成一个导出的函数，软件那边的着色器自己也改成调它。三维要拿它在 CPU 上算标准答案。

## 二、门

1. 画画仓 `npm test` 全过，逐像素基线不变，显卡冒烟基线不变，`tsc` 干净。现有测试文件不改（要改先说）。
2. **新测试 A：宿主的薄层和二维笔尖走的是同一条路。** 拿一串二维笔尖，先用内核自己的办法画成一张薄层（就是 `rasterize` 的结果），再把这张薄层当成「宿主画好的」交回去。预览合成的结果、落层之后图层的像素，和直接把这串笔尖交给内核，逐像素相同。普通笔、橡皮、锁透明、带选区、几种混合方式、浓度小于一，各一遍。能在 node 里用内核的软件显卡跑的就放进 `npm test`。
3. **新测试 B：只合成的那张图是对的。** 和现有的一次性合成（`compositeOnce`）读回来逐像素相同；连着合成几帧（中间改图层、挂薄层、撤薄层），每帧都相同。
4. **新测试 C：档口。** `host` 方式画一笔：抬笔后是一步撤销，撤销、重做像素对；取消后没有痕迹；故意让落层失败，令牌被取消、抛出来、图层没变；小块池泄漏为零。
5. **新测试 D：宿主的图内核不碰。** 一笔从头到尾，宿主借的那张离屏图没被内核归还过。
6. **守卫**：`_addOverlay` 里两支共用后半段（扫源码：预乘转直值那一句只出现一次）；笔尖边缘的算式全仓只有一处。
7. **共用画面那一轮补齐**：0-4 的显卡冒烟测试里，渲染树、提交、裁剪实时、填充四个用例因为画到屏幕，在共用画面那一轮被跳过了。这一张有了「只合成、不上屏」之后，把这四个换成只合成的走法补回那一轮，结果和独占画面时逐字节相同。
8. `api/` 重新生成；画画仓流程图里「一笔」和「一帧」两条更新；内核测试名单加上新测试；升一个末位版本。

## 三、碰到这些就停下来报

- `gl-board.ts` 过不了内核边界的守卫。
- 拆 `renderFrame` 时发现画到屏幕那一步和合成那一步有共用的状态拆不开。
- 新测试 A 对不上：说明两支后半段不是真的同一条路。
- `StrokeSession` 的现有四种方式里有哪一种要跟着改。

## 这一张不做的

三维的空间层（1-3、1-4）；独立于选区的蒙版（0-8，做的时候和选区在同一个地方接）；交出去的那张图怎么采样、要不要另备一张带多级缩小图的（1-3 定）；预算的出口（0-3）。
