## 条目

- **I1 / I2 · v0.18.1（Opus 5.5 2026-10-30）**：
  - 物件树：纯模块 `src/editor/object-tree.ts`（场景 → 树、你在哪一层、这一行藏 / 显 = 一条指令）、窗口 `src/app/hierarchy-window.ts`、左上「层级」钮（物件钮左边，图标 `hierarchy-tree` 是图标库待过目层新画的）。
  - **组不进树**：开工时差点把组也放进去。锁那条测试的注释引了 user 10-24「组永远不进hierarchy」，回原话核了三处（「组永远不进hierarchy，是brep的内部矛盾」「组不是物体层级，只是brep模式下面方便编辑的分组拆组」「组不是物体只是管理sticky geometry用的」）。所以组只在路径里当「怎么走进去」：放在组里的物件直接挂在它所在的物件下。
  - 第一行叫「根」，和左上面包屑、user 的「根节点」同一个叫法。
  - 交互：点名字 = 走进它挂的那一层并选中它（编辑器加了一行 `selectPools` / `selectedPoolKeys`，editor.ts 4152 行）；双击 = 进去；小眼睛 = 实例的藏标记、一步撤销；「…」/ 右键 = 物件菜单（根那行 = 空白处菜单），不另拼菜单项。
  - 名字：没起名 = 四位十六进制码，等宽淡色；新组件默认名 = `hex4()`（`src/config.ts`，和文档默认名同一个函数）。

- **I4 · v0.18.2（Opus 5.5 2026-10-30）**：新指令 `rename`（`ops.ts`；撤销按「只动场景骨架」那类记，和锁定同类；演示锁照样拦）。物件菜单「改名…」（层级窗「…」和画布右键同一张表）→ 输入框：这一份有自己的名字（导入带来的）就只改它、清空 = 回到显示组件名；没有就改组件名（提示「这个组件摆了 N 份，名字一起改」），清空 = 四位码。组不改名（组不是物件）。单测 + 探针 `probe-hierarchy` 改名一步。
- **I10 / I11 · 组件定义会被炸开顺手删（user 10-30）**：原话「为什么删实例会有删组件定义的风险？这个风险就不应该有。你看一下这是什么系统性的问题。一共有几层瑞士奶酪？」「为什么炸开会删除组件。我们没有一个中心化的按引用计数的东西吗？学blender……然后到时候也有这种引用和孤儿管理面板……你先非常认真小心地做。到时候fable审核」「这样，我们先写一个。然后高中时代让fable重写一个」「无人使用的材质会悄悄残留。这个现在小学时代能修复吗。」「反正就是要么被引用要么被素材库引用。和blender的逻辑一样」「能改成guid吗 然后物体之类的同理，定成家规」「不要用序号」。
  - 查到的（Opus 5.5）：删实例本身不删定义；**炸开**把一个组件的最后一份炸掉时会删定义（`ops.ts` 同种硬表面一处、跨种类一处）；**合并**恰好不删。同一件事三条路两种结局 = 定义的生死没有统一的主人，各个动词自己写。测试 `object-ops-kinds` 还把「定义没了」当对的钉着。孤儿森林（UX26，10-28）只钉了存读那一层。
  - 瑞士奶酪（「定义只在用户点清理时才死」这件事有几层）：① 场景模型 = 平表、实例只记定义编号 ✓；② 指令层 ✗（炸开两处删）；③ 存盘写 ✓；④ 读盘 ✓（③④ 同一条往返测试）；⑤ 撤销能找回 ✓（这是补救，不算防线）；⑥ 结构守卫 ✗（没有）；⑦ 指令层测试 ✗（反而钉着删）；⑧ 披露 ✗（炸开不说定义没了，孤儿哪都看不见）。
  - v0.18.3 补：② 炸开不删；⑥ 守卫 = 源码里不许出现删定义的写法；⑦ 炸开（两种身体）/ 删实例 / 合并之后定义一个不少；⑧ 炸开最后一份时提示「定义照样留在文件里」+ 资源清点（I10）。
  - 材质：材质表只增不删（不会丢），但没人用的会悄悄留着；按「第几个」编号，删一个后面全挪号（每个组件的槽表、剪贴板里攥着这些号）→ 材质清理等 I11 换 GUID，不在序号上硬做。
