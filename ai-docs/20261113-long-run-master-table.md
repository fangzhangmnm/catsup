**11-13 晚改的做法和排法（以这一段为准；下面那张旧排法里顺序不一样的作废）**

user 的话：「我的目标是尽量减少版本号，一次多多做一点再审核。」「能不能做到每一波只用一个小版本号？」「你现在的没问题，开始做了，我就提醒你一下，我这个礼拜我是用了平常的百分之二百五十的额度，现在是百分之二百五十的最后百分之五十。我希望在我额度彻底用完之前，我们能有一个比较好的收尾。」

做法（统筹照这几句定的）：
- **一波一个号**：一波一个主题，小弟在一条分支上做完整波，合一次 = 一版。波中间不发版。
- **随时停得下来**：一波里的活按要紧的先后排，一件做完、测完再开下一件；任何时候叫停，分支上做完的那几件都能直接合。
- **统筹只审过关的东西**（文件格式、内核对外接口、撤销 / 存盘 / 修改锁、吸附怎么排）和波末的清单；别的信小弟的施工记录和探针，不逐行读。
- user 自己碰到的卡建模的毛病照旧插队单发。发出去之后用出来的问题：不挡人的攒进下一波。
- 账实时记：每做完一件，施工记录和这张表当场更新，不攒到最后。

**同一晚 user 纠正（以这一段为准）**：统筹听到额度紧，把目标砍成两件小的、大的全推到「额度回来之后」，还说三样收工条件这周收不齐。user：「我又 PTSD，我就不敢跟你说额度不够，因为额度不够，你又劝我说妥协，不要想那么多，不要要那么多。但这个其实又还是你用这些额度做小事。现在很简单，我们要用少额度做大事，明白吧？」

改成（统筹的读法）：**目标不缩，省的是统筹这头的花法。** 额度花在只有统筹能做、一次管很久的地方（结构、文件格式、存盘这一关）；小改动不再一条条来回、一版一版细审，攒到波末一起看。要 user 定的细节不一条条问：统筹照 user 已定的规矩和 Blender / Unity 的惯例定一版默认写进施工单，小弟整块做出来，user 判实物；只有文件格式先拿给 user 点头。

user 同一晚接着说的：「我就怕你保守，我就怕你刮痧，这个说白了就是强化学习的问题嘛，奖励你保守惩罚你犯错」「现在的问题是不要砍东西，做多少就做多少，尽量想办法多快好省的做，一个一个版本的做，明白吧？不要砍东西。真要砍的话，必须得主动经过我同意。现在就是整理你整理吧，它系统的整理。」
