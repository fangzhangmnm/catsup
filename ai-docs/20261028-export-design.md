# 导出设计稿：工程文件 vs 模型（给 Opus 落地）

> created 20261028 by Claude Fable 5.1 · as-of v0.16.7 / 2026-10-28 晚 · 账本 UX39 · 家族周账 F-119
> user 原话：「现在的导出有数据安全问题，你导出的是工程文件还是glb，这个极端误导。工程文件要不要叫catsup. vroid也是glb换皮」「看一下weebpaint是怎么做的。其实是无地骑士的一大堆决策」「我说的隐患是你以为是工程备份但只是baked的坏模型」「工程文件导出本来就是原样不要改任何东西」「对齐一下weebpaint的方案？或者就是一个导出工程文件 导出模型 然后导出模型要弹一个对话框，就是机器面板。你弄好设计稿交给opus就行了」。

## 0. 一句话

☰ 文件页两条：**「导出工程文件」**（.catsup，工程原样一个字节不改，一点就下载）和 **「导出模型…」**（弹一个面板选格式和范围，出来的是给别的软件看的烤好的模型）。后缀说话：`.catsup` = 工程，`.glb` / `.obj` = 模型。隐患（手里那份 .glb 到底是工程备份还是别的软件烤过的坏模型）靠后缀 + 打开时按内容认两层挡住。

## 1. 隐患的真身（不是参考图）

- 今天 ☰「导出 .glb（下载一份）」写出去的字节 = 整份工程（`session.export()` = `encode()`，本来就带烤好的三角形给别的查看器）。字节没问题。
- 问题是 `.glb` 这个后缀不说话：CatsUp 的工程叫 .glb，Blender 转一圈存回来的也叫 .glb——后者硬表面 / 尺规 / 对称设置全没了。user 过几个月翻硬盘，分不清哪份是备份。
- 参考图跟着工程走是**应该的**（expected behavior），不是隐患；工程文件导出**原样不改**。

## 2. WeebPaint 怎么做的（无地骑士那一批拍板，照形状抄）

- ☰ 一个入口「导出与另存…」→ 弹三个去向：① 导出图片（烤平的交付物，按配置一键，主按钮）② 存为本地 .ora（工程原样，锁「所有图层」）③ 复制一份到图库（另存为）。
- 后缀本身就是身份：工程永远 .ora，交付物永远 png / jpg，没有人会把 png 当备份。
- 保存 = 回家、导出永不清脏；下载开始 = 责任移交 + 一句「.ora 已下载」。
- 代码：`20260524 WeebPaint/src/export-import-menu.ts`（hub + 配置 popup）、`ai-docs/20260825-localfile-knight-grill-verdicts.md`。

CatsUp 按 user 说的简化成两条（不做三去向 hub）；「复制一份到图库」= 另存为，CatsUp 今天没有这个动作，不在这稿里。

## 3. 菜单（☰ 文件页）

| 行 | 做什么 | 备注 |
|---|---|---|
| 保存 | 照旧（回家） | — |
| **导出工程文件** | 下载 `模型名-YYYYMMDD-HHMM.catsup` = `encode()` 原样 | 一点就下载，不弹面板；状态行「.catsup 已下载（工程原样，可开回 CatsUp）」；永不清脏 |
| **导出模型…** | 开面板（§4）→ 导出 .glb / .obj | 取代今天的「导出 .glb（下载一份）」和「导出 OBJ…」两行 |
| 导入 glb… | 照旧（别的软件的 glb → 网格体组件） | — |

## 4. 「导出模型…」= 模态 sheet（grill 10-28 深夜定：导出和保存一家，锁屏、认真答、答完消失；不是马前炮、不是指令板）

用应用内的 sheet（`openConfirmSheet` 那一族，加字段），字段：

| 字段 | 选项 | 默认 | 说明 |
|---|---|---|---|
| 格式 | glb / obj | glb | obj = Blender 逃生口；文件边界做 Z-up ↔ Y-up（照旧） |
| 范围 | 整个模型 / 选中的物体 | 整个模型 | 没选物体时只有「整个模型」 |
| 贴图 | 嵌进文件 / 不带 | 嵌进文件 | 只 glb 有；obj 不带贴图（照旧） |
| 边线 | 带 / 不带 | 带 | 只 glb 有（今天 bake 写 LINES primitive；有的查看器画出来怪，给个关） |

说明行（固定一句 + 估算）：「给别的软件看的烤好的模型（三角形 + 材质 + 贴图）。**不是工程备份**——备份用「导出工程文件」。约 N MB。」
按「导出」→ 下载 `模型名-YYYYMMDD-HHMM.glb|obj`，sheet 关、状态行「.glb 已下载」；「取消」/ Esc 关；永不清脏；下载开始 = 责任移交（WeebPaint 拍板）。sheet 里的选择记进桌面态（`CATSUP_desk`，不进指纹）。

## 5. 出来的字节

- **导出工程文件** = `encode()` 逐字（守卫测试钉死），后缀 `.catsup`。
- **导出模型 .glb** = 标准 glTF：节点层级 + 烤好的 TRIANGLES（+ LINES）+ materials / textures / images 里真被材质引用的；**不带任何 `CATSUP_*` 扩展、不带参考图、不带缩略图**（别的软件不认、徒增体积；备份走工程文件）。写入器 = `format/write.ts` 加一个「只写 glTF core」的开关，不另写一套。
- **导出模型 .obj** = 照旧 `obj-io.ts`。

## 6. 后缀 `.catsup`（VRoid 的 .vrm 同款：glb 换皮；**user 10-28 晚「叫.catsup同意」**）

**为什么是单后缀 `.catsup`、不是 `.catsup.glb`**（user 问「.glb还是.catsup.glb 不过后者可能工具会留着catsup」）：`.catsup.glb` 唯一的好处是别的看图软件双击就能开；坏处正好是要害——Blender 导入 `房子.catsup.glb` 再导出，默认还叫 `房子.catsup.glb`，一份烤过的坏模型顶着工程的名字。单后缀 = 别的软件默认不列它、就算开了再存出来也只叫 `房子.glb`，**catsup 这个名字只有 CatsUp 会写**，这是安全性的来源。想给别人看走「导出模型」有意地产 .glb。VRoid 的 .vrm 同理。和小黑屋的 `.webxiaoheiwu.zip` 约束不同：那边 zip 只是容器不是交付物，没人会把 zip 再存成小黑屋工程，双后缀只有好处；CatsUp 的 glb 既是容器又是交付物格式、别人改了再存是有损的，容器和交付物撞成一种格式时后缀必须分开。WeebPaint 的 .ora 是第三种：公开标准、Krita 开了再存图层还在，所以敢用标准后缀。一句话：**容器 = 交付物格式且别人改了会有损 → 单后缀自己的名字；容器只是容器 → 双后缀无妨；标准格式无损互通 → 标准后缀。**

- `session.ts DOC_EXT` → `.catsup`；新建 / 保存 / 导出工程文件都写它。
- **认工程靠内容**，不靠后缀：打开时有 `CATSUP_document` 扩展 = 工程（.catsup 或老 .glb 都行）；没有 = 外来模型 → 照旧拒开、指去「导入 glb…」（T11 / DT2）。
- 老的 .glb 工程**永远照开、不改名**（改叫法不迁移旧数据）；图库两种后缀都列。
- 图库 / store 的后缀筛选（`@internal/gallery` / `@internal/store` 的 suffix 白名单、缩略图读头）= **红线区边上**：先读 `20260601 MyPWAPatterns/docs/MASTER.md`，库要改就 escalate user，不在 app 端绕。
- PWA manifest 的 `file_handlers`（如果有）加 `.catsup`；MIME 用 `model/gltf-binary` 照旧。

## 7. 验收

- 单测：「导出工程文件」字节 == `encode()` 逐字；「导出模型 .glb」里没有任何 `CATSUP_*` 键、`images` 里没有参考图 / 缩略图、每个 image 都被某个 texture 引用；老 .glb 工程照开；.catsup 往返指纹一致；外来 glb 拒开走导入。
- 探针：☰ 两行都在、旧两行不在；「导出模型…」面板字段 = 格式 / 范围 / 贴图 / 边线 + 说明行含「不是工程备份」；点「导出」触发下载（无头拿 blob）；导出的 glb 用 three 的 GLTFLoader 能载（探针里 import three）。
- 冒烟 + 图库探针（后缀改了之后）。

## 8. 顺手一起记（user 10-28 晚，给 Opus）
