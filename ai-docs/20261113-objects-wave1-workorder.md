## 一、层级的显示（规矩在层级显示施工单）

统筹对清点的裁定：
1. **默认的「线稿」画风不变：物体本来就有线，正在编辑的物体多出点**（user 11-13 晚纠正：「默认的『线稿』画风 默认物体有线，在编辑的物体有额外的点，不要改变默认的画风，没有active的时候是默认的画风」。统筹和小弟先前定的「线稿的线只画在能改的那一层」作废）。所以线稿和像素描边 / 1-bit / Tron 一样，线算画风自己的，谁都照画；能直接改的那一层靠顶点小圆点区分（硬表面也接上）。「这个画风自己带不带线」就是画风表里现有的 `material.edges` 那一格（线稿 = 带），不另加字段。
2. **「正在编辑的」= 你当前站的这一层自己的几何，根也算；「没在编辑的」= 所有不在这一层的物体**（user 11-13 晚再纠正：「root也有root的geometry的，我说的没在编辑就是所有不在当前你的层级的物体」。统筹先前的读法「根层不加点」作废）。所以只有一条规矩、没有根的特例：这一层自己的几何 = 画风原样 + 顶点小圆点；别的（子物体、外面的、分身）= 画风原样。硬表面和自由建模同一条。上了修改锁、在预演里 = 不在编辑 = 不加点（照现状）。
   - 〔默认〕进了组：点只画在组里的东西上（组外的同层几何这时候不能直接改）。「这个顶点在不在当前的组里」要是没有现成的判定，先画整层、记进第九节顾虑。
2½. **收成一个深模块、窄接口，不要每个画风都重写一次**（user 同一句：「然后收成深模块窄接口，不要每个画风都重写一次」）。下面四条是统筹的读法：
   - 画风只说自己长什么样（`material.edges` = 自己带不带线），不知道层级、不知道在不在编辑。**加一个新画风，不用为层级的显示写任何东西。**
   - 「这个槽相对当前这一层是什么」只在 `relationOf` 算；「每一档怎么对待」只在第二节那张表里。
   - 编辑用的点只在 `edit-marks.ts` 画一次，对所有画风一样。入口收窄：`insideObject` 拿掉（没有根的特例了）；「这个工作台改不改几何」由工作台自己报，不在这里比工作台的名字——这一半跟着第五节第 1 条一起收，不单做。
   - 渲染那一侧（`src/minccino/`）知道的只有每个摆放上的一位「是不是当前这一层」；画线只有现在那一处判断（画风自己带线，或者是当前这一层）。守卫：`src/minccino/` 里不许读档、不许读那张表、不许按画风的名字给编辑用的线和点分路。
3. 〔默认〕**分身**（正在改 A 时别处的 A）照「不能直接改的」办：没有编辑用的线和点。淡出、点不中、吸得到都照现状。
4. 淡出不动。
5. 〔默认〕光标移到子物体上 = 整个子物体亮一下（现在不亮，人不知道点下去拿到的是整个）。
6. 「粗线」是轮廓线不是选中——user 记错了，统筹告诉他，不改。

## 四、文件格式：空物体这个种类（user 11-13 晚点头：「这个本来就是我的设计，去做」；读写的 diff 合之前过统筹）

统筹的方案：
1. `CATSUP_definitions` 的 `kind` 多一个值 `"empty"`。空物体的定义不带几何，照样带 `instances`。具体写成什么样小弟出，**读写的 diff 过统筹**。
2. 老版本读到不认识的种类会整份拒开，所以这是不兼容的改动：`CATSUP_definitions` 升大号，写的时候一律写新号。新程序两个号都读。
3. **老文件原样读，不转换**：文件里写着硬表面 / 网格体、里面没有几何的定义，就读成没有几何的硬表面 / 网格体。不猜、不悄悄改成空物体。想改 = 人自己点「切换种类」（它们没有几何，所以切到空物体可用），看得见、能撤销。
4. 读 `kind: "empty"` 的定义时只认子物体；写的时候不带几何载荷。
5. 从这一版起新造的：网格体里把子物体包成新组件 = 空物体（不再是空的网格体）；导入的空节点 = 空物体。硬表面里只选子物体建组件：照旧是硬表面（里面能接着画），不改。

**统筹看过读写的改动（2dc804de，Claude Fable 5.2，11-13 晚）：可以，补一处再合。**
6. **一个定义 = 每个种类都一样的头 + 这个种类自己的载荷**。头 = `guid` / `name` / `kind` / `axes` / `nodes` / `instances` / `extras`，每个种类照同一个样子写（所以空物体照写 `axes` 和 `nodes`，不为它少写两个键）；载荷各写各的，空物体没有载荷。材质槽表算有面的种类的载荷，空物体不写、读回来是空表。以后加种类（曲线）照这一条：只加载荷，不动头。
7. **要补的一处**：文件里写着 `kind: "empty"`、却带着 `brep` / `groups` / `mesh` / `materialSlots` / `guides` / `drawFrame` 的定义——照旧不读、不写，但**打开时说一句**（数出有几个，记进读的备注，话照「不认识的标记」那一条的样子：没读进来、保存之后不再保留）。理由：不读可以，悄悄丢不可以（硬规则 #9 第 4 条；和 11-13 定的「不认识的位：不读、说一句、不写」同一条规矩，不留第二种做法）。顺带：空物体不要再跑材质槽那一段解析（现在跑了再丢，会留下不相干的备注）。
8. 「只改版本号」的那一步（7 → 8）可以：没有转换内容，和网格体 2 → 3 那一步同一种。6.x 的迁移语义测试跳过空物体那个场景，可以。
9. 根是空物体的来回测试，跟着「给根包一层」那一份 diff 一起交（现在的冻结样本里空物体不在根上）。

## 五、物体的种类（规矩在物体种类施工稿第二到第七节）

1. **每个种类自己报选项**：接口照施工稿第四节的提案做，统筹在这里批了；形状要改再发统筹。先搬家、看得见的不变。界面那一层不许出现种类的名字，加守卫。
2. **物体窗口四页**：物体 / 种类自己的 / 元素 / 材质和贴图。第四页这一版只看，外加「把画拿掉」的出口。
3. **空物体**：能挂子物体，没有几何。工作台只有选、变换（主工具）、移动 / 旋转 / 缩放、新建子物体；要几何的工具不显示。
4. **切换种类**：物体窗口第一页。列出能切到哪几种、各丢什么；切到空物体只在自己没有几何时可用。
5. **新建子物体**：种类当场选（硬表面 / 自由建模 / 空物体），建完直接进去（user：「可以」）。〔默认〕入口三处：右键空白处「新建子物体 ›」、物体窗口第一页、层级窗口。〔默认〕放在哪：右键点在面上 = 那一点；别处进来 = 这一层的原点；朝向 = 这一层的轴。
6. **凡是会换种类的入口都说出带不过去多少**：炸开跨种类、跨种类粘贴、第三节的「移到…」。拿不到数的入口先让它拿得到。
7. **创建父物体**：物体窗口第一页，和切换种类是两个按钮。新父亲 = 空物体，原物体整个放到它下面，位置不动。在根上用 = 给根包一层：照定稿做，新的根 = 空物体；动 `rootIndex` 和根的 GUID 的那两处 **diff 过统筹**；要有反过来的动作。
8. **两族移动 / 旋转 / 缩放**：三格各带小三角，里面两把（对齐式、自由式）。每个种类都能选两族；默认硬表面 = 对齐式，自由建模和空物体 = 自由式。
9. 施工稿第七节第 6 步那两处顺带修的，进第九节「顾虑」，版末一起修。

### 2½、「把画拿掉」要真能逃生（统筹 11-13 夜；更正自己同一晚的「同意、不用改」）

换回默认材质这一点照旧同意（文件里没有「画之前是什么」这回事，不猜）。要改的是另一处，统筹读代码看到的，没跑：
- 拿掉之后这个物体的 `uvSetSlots` 还在。`scene/paint.ts paintMoveBlocked` 对整个物体的动作看的是 `hasUv(b)`（速查表不空就拦），所以转硬表面、炸开、建组件、做成唯一、复制粘贴照样被拒，拒绝的话还说「这些面上有画」——已经不是实话。
- user 要这个出口是为了逃生（「如果有drop贴图我也能逃生」）。现在逃不出去。

做法：
1. **先验**：`probe-object-pages` 加一格——把画拿掉之后转硬表面。绿 = 统筹读错了，回一句；红 = 照下面改。
2. **「把画拿掉」= 这个物体退出这张画**：面换回默认材质；这些面交出在那套排法上的位置（角上的数清掉，走 `scene/uv.ts` 的写口）；这个物体的速查表里那一套、没有面在用的那个材质槽同一步拿掉（代号同一步重新对上）。贴图、材质、排法那一行留在文件里（孤儿，资源页清；不在这里删）。一步撤销。空出来的位置照旧由每一步的收尾记。
3. **验收**：拿掉之后 `paintMoveBlocked(s, { def })` 是 null；转硬表面、炸开、建组件各走一次，不被画拦；撤销之后画、位置、槽都回来（像素对得上）。
4. **提示行说实话**：「把画拿掉了：N 张面换回默认材质，这个物体不在这张画上了。画留在文件里（资源页能清），要回来只能撤销」。
5. **什么时候做**：手上的第 3、4 条做完接着做，不打断。

结构上的毛病（记一条，这一版不收）：「这个物体带不带画」现在有好几种问法——`hasUv` 看速查表、`paintUvOf` 看面的位置、`paintedFaces` 看面的材质、粘贴那条看槽表。拦搬家的那几处要问的是「占没占着位置」，显示和数张数问的是「材质是不是画」。第 5 版放开带画的物体能搬时收成这两个问题、各一处；到那时重看「拿掉」要不要留着位置（留着就能放回去）。

### 4½、「换种类带不过去什么」只算一处（统筹 11-13 夜；第 4、6 条照这个做）

现状（统筹读代码，没跑）：同一个问题三处各答各的——
- `KindDef.castsTo[].loses`：写死的几句话，说的是「一般会丢什么」，不是这一次；
- `meshToBrepCheck`：只数藏面、藏边那两种，只有「转回硬表面体」在问；
- 炸开跨种类（`editor/ops.ts` 调 `castBody` 的两处）、跨种类粘贴和「移到…」（`editor/transfer.ts` 的两处）拿到的只有转好的身体，丢了什么拿不到。
- 写死的清单已经漏了：网格体转硬表面那一行没写对称设置、默认平滑、贴图坐标的表（转空物体那一行写了）。〔未证实：这些转过去是不是真没了、来回一趟回不回得来，小弟核一下。user 的核心做法是两个种类来回切，这一处漏了就是来回一趟悄悄少东西〕

接口（`scene/kinds.ts`，钉住；形状要改发统筹）：

```ts
/** 一种带不过去的东西一个名字（字面量联合；不是开放集）。 */
export type CastLossId = /* 小弟照现有清单和下面第 5 条的单子列全 */;
/** 这一次带不过去的一样东西；0 个的不出现。设置这类不可数的 count = 1。 */
export interface CastLoss { readonly what: CastLossId; readonly count: number }
/** 真转。 */
export function castBody(body: Body, to: BodyKind, opts?: { softDeg?: number }): { body: Body; losses: readonly CastLoss[] };
/** 只问不转：和真转同一份算法（照转一遍，只要清单）。 */
export function castLosses(body: Body, to: BodyKind, opts?: { softDeg?: number }): readonly CastLoss[];
/** 给人看的一句；全仓只此一处造句。 */
export function lossText(l: CastLoss): string;
// KindDef.castsTo: readonly { to: BodyKind; loses: readonly CastLossId[] }[]   —— 这个方向可能丢的那几种
```

规矩：
1. 真转返回的清单里出现这个方向没声明过的 `what` = 抛（程序错误）。「可能丢」和「这一次实际丢」是同一组名字，漂不开。
2. `meshToBrepCheck` 和 `meshToBrepWith` 那两个数并进来（各成一个 `CastLossId`），不留第二条问的路。
3. 四个入口（切换种类、炸开跨种类、跨种类粘贴、「移到…」）同一个做法：做之前调 `castLosses`；空 = 不为丢东西多问（各自原有的「要不要转」照旧）；不空 = 在**同一个**询问里逐条列出（`lossText`），不另弹第二个框。
4. 物体窗口那一页列「能切到哪几种、各可能丢什么」用声明的那一份，不为了开窗口把模型转一遍；点下去才算这一次的数。
5. **守卫**（单元测试）：每个种类自己的载荷有哪几样，列一张单子（和第四节「头 + 种类自己的载荷」是同一张）；每个转换方向对源种类的每一样都写明去向——带过去 / 换算成什么 / 丢（哪个 `CastLossId`）。少写一样 = 红。以后种类加载荷、加属性列（顶点色、用户自己加的列）时，不写去向过不了。
6. 先不缓存「只问不转」那一遍（点一下 = 转两遍）。转一次超过半秒再想办法，先报统筹。
7. 它会长成什么：带画的物体能转（第 5 版）时，「画」就是清单里的一样，不再是一句拒绝；硬表面归一之后两边属性表合一，清单变短。

### 7½、给根包一层的门口两刀：统筹的裁定（11-13 夜，小弟中途报之后；diff 照旧过统筹）

**b. 认不出的硬表面内容怎么带：这一版只做「包一层不新添丢东西的路」，不顺带扩大。**

### 第五节第 7 条后半之一：根的门口两刀（给根包一层定稿第 2 条）（Claude Opus 5.5，2026-11-13；照统筹 11-13 夜的定法）
- **a. 画图坐标架住在定义的头上**：`Definition.frame`（三个种类都有；缺 = 跟定义原点）。`Scene.axes` 和 `BrepBody.drawFrame` 都没了；问坐标架一律 `Scene.frameOf(def)`，`frameOfContext` 不再分根和组件。根的那一份在门口写明：新建场景 = 世界帧，读文件 = `document.axes`，存盘写回 `document.axes`；别的定义 = 头上的 `drawFrame`，三个种类都读都写。空物体那张「带着就不读」的单子拿掉了 `drawFrame`。8.0 原地改，没升号。转种类照带：4½ 的「另摆的画图坐标架」从丢的清单、去向表、载荷清单里拿掉（`CastLossId` 剩 17 个）。设坐标架的指令不再只认硬表面体的池（以前网格体的根一调就抛）。
- **一处细微的行为差别（报统筹）**：重置一律 = 删掉（回到这个定义的坐标系，根 = 世界帧）。以前根重置 = 写一份世界帧。区别只在「先重置根的绘图轴、再换根的原点」这一串：以前绘图轴钉在世界原地；现在它跟着新原点走（和组件一样）。「原点换到坐标架」那一下根照旧不删（`root` 只留在这里管这一条和提示语）。
- **b. 认不出的硬表面内容按 GUID 写回**：`carry.brepKeepOf` = 那份内容是哪个定义的（读的门口照旧只给打开时的那个根收）；`write.ts` 按 `d.guid === brepKeepOf` 写回，不再问是不是根。包完一层之后旧根带回的东西照样跟着旧根。

- **小表（统筹要的）：种类 × 能不能设 / 谁在读 / 文件写不写**

  | 种类 | 界面里能不能设 | 谁在读（这一层的坐标架） | 文件 |
