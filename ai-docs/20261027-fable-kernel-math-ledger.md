## 1. 挡在「小红帽白模」路上的（先做）

做一只低模角色要的动词：
- 盒子起型；
- 环切（刀绕一圈）；
- 挤出；
- 拖点 / 边 / 面塑形；
- 合并、补洞、删、溶解；
- 左右自动镜像。

拖点会把四边以上的面拖得不平——这正是下面两个坑踩的地方。

## 4. 内核优化：写清取舍，推给 user 拍（不直接动手）

**先拍 K1，再拍这些**：如果另做网格内核，下面三条的数据布局要一起考虑。对小红帽这种 300 三角的模型，这几条都不挡路；卡的是大坦克（3–5 万三角）。

| # | 题目 | 实测 | 候选路（Opus 列的，可全丢） | → |
|---|---|---|---|---|
| O1 | **拖动预演每帧整份拷内核** | 全合并坦克每帧 95–166 ms；分件坦克最大零件 25–47 ms；iPad 上约每秒 6–10 帧。渲染那半已做（只重建改过的面，≈ 1 ms） | ❶ 拖动开始拷一次，之后每帧把上一帧改过的东西退回原样再算（今天的改动日志是底子）；❷ 只拷会被碰到的那一小块；❸ 摊平成数组，拷贝 = 整块内存复制；user 另提可持久化数据结构（共享没动过的分区，像 WeebPaint 分 tile）。**不变量**：回滚 = 没动过，**包括各表的遍历顺序**，否则预演和提交在平手时分叉 | 周账 F-97 ②；狗咬坦克账本 DT96 |
| O2 | **结算里还在随整个模型涨的两步** | 「含任一脏边的平面」每步 1–3 ms（仍 O(平面数)）；影响域计算 20–33 ms（不是扫全图但最贵） | 给平面加空间索引（只长不缩 = 超集，多占内存、要维护）值不值 / 有没有更好的切法 | 周账 F-97½；代码流程图 `20261026-pipelines.md` |
| O3 | **内核改成按属性分列的数组 + 纯函数**（为 WASM 纪元准备） | 3.2 万面内核 78 MB JS 堆（≈ 2.4 KB / 面）。Metasequoia 开同一只坦克约 +91 MB，CatsUp 分件版约 104 MB，同一量级（口径不全一样） | 要先有「新内核 vs 旧内核」逐动词对拍网再动刀；user 目标：「wasm时代我希望内存能做到ecs级别的少存元数据和json overhead」 | 周账 F-99；狗咬坦克账本 DT92 |
