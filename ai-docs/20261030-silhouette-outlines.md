# 外轮廓怎么画（现状 + 做法 + 建议）

> created 20261030 by Claude Opus 5.5 · as-of v0.18.4 / 2026-10-30
> 起因：user 10-30「记账做好这一批做：软边没有变成外轮廓。到时候系统性的理一下外轮廓是怎么做的。我的图形学常识告诉我说不能只是靠边，有时候外轮廓不在边上。折腾好组件hierarchy一大堆之后做，先记账」。纪元账本 I12。
> 只是理清 + 建议，没动渲染器。要 user 拍的三个问题在 §5。
> **user 10-30 拍了**：光滑那片沿软边画折线（SketchUp 同款）、不画交线、Opus 直接做。**v0.18.7 做了第一步的粗线那条路**（iPad 默认线宽 1.5 / Tron）；细线那条路（电脑 1 像素线稿）还没做——见 §4 第 1 条。

## 1. 现状：每个画风的外轮廓从哪来

| 画风 | 边怎么画 | 外轮廓怎么来 | 软边转到侧面时 |
|---|---|---|---|
| 线稿（线宽 1，默认） | 原生 1 像素线，只画「看得见的边」 | **没有判外轮廓这一步** | 不出现 |
| 线稿（线宽 > 1） | 粗线（每条边一条实例） | 顶点着色器逐条边判：两张面伸向「过这条边和视线的平面」的同一侧 = 外轮廓，加粗（`src/editor/profile-edges.ts` + GLSL 镜像 `src/minccino/providers/three/profile-line-shader.ts`） | 不出现 |
| Tron | 同上（粗线） | 同上 | 不出现 |
| 像素描边 / 1-bit | 1 像素线（在 1/3 分辨率的小图里） | 后处理：小图的深度图上，挨着背景或前后深度跳变的那一格描一格 | **出现**（这个方法不看边） |
| 剪纸 / 写实 / 铸铜 | 不画边 | 不描 | — |

**软边为什么不出现**：收集「看得见的边」时（`src/editor/pool-mesh.ts buildEdgeRec`），软边、折线、隐藏边一律跳过——它们根本进不了线批，判外轮廓的那一步看不到它们。像素描边能描出来，是因为它根本不看边、只看画面。

## 2. 外轮廓在不在边上

- **平面拼成的东西**（CatsUp 现在所有几何都是平面拼的）：真实的外轮廓**一定在边上**——每张面是平的，「朝着你 / 背着你」只可能在边上翻转。所以「按边判」对它是精确的；软边也是边，只是被我们扔了。这就是这次的 bug。
- **不在边上的三种**（user 的直觉对）：
  1. **光滑明暗**：软边那一片按顶点法线插值着色，看起来是一个光滑曲面。光滑曲面的轮廓（法线正好和视线垂直的那条线）穿过面的中间。按边画出来是一段段折线，和明暗对不上（明暗是圆的，轮廓是多边形）。
  2. **两个物件互相插在一起的交线**：不是任何一方的边。SketchUp 也不画，除非用「相交面」真的切出边来。
  3. **以后在显卡里才变形的东西**（细分、置换、骨骼动画）：几何在显卡里才定，CPU 那边没有边可判。

## 3. 做法（图形学里通行的四种）

| 做法 | 怎么做 | 好 | 不好 | 接得住 §2 哪几种 |
|---|---|---|---|---|
| A 按边（物体空间） | 每条边判它是不是正好在转折处 | 矢量、干净、粗细稳定；和 SketchUp 一样 | 只认边 | 平面几何精确；①画成折线；②③不行 |
| B 按画面（深度 / 法线图跳变） | 画完后在深度图、法线图上找跳变的像素描一圈 | 什么都接得住 | 线是像素的，粗细跟着分辨率走；远处细节糊成一团；多一遍全屏 | ①②③ |
| C 光滑轮廓（逐三角求等值线） | 光滑区域里，每个三角在显卡里算「法线和视线垂直」的那一小段（三个顶点法线·视线的符号变了才有线） | 矢量、和光滑明暗对得上；视角变了不用重建 | 每个光滑三角一条候选（多一批）；只管光滑区域 | ① |
| D 外扩反面（inverted hull） | 把背面沿法线外扩一点画成黑色 | 卡通描边常用、便宜 | 只描外圈、尖角会裂、开口的面不行 | 部分 ① |

## 4. 建议

1. **第一步（必做，SketchUp 同款）**：软边进线批，打一个「只在外轮廓时画」的标记；粗线、细线两条路用同一条判法（CPU 镜像 `profile-edges.ts` 已有）。
   - 细线那条路要一份自己的着色器（和粗线那份一样，受守卫逐字比对）。
   - 所有线材质变体（普通 / 淡出 / X 光隐线 / Tron 两种 / 选中标记）都得换上，漏一个 = 所有软边全画出来。要加一条守卫：线材质必须用这份着色器。
   - 代价：软边多的模型（导入的光滑模型）线批变大，每条软边一条。要实测再报。
2. **第二步（看 user 选）**：光滑区域要不要用 C 代替第一步那种折线轮廓（轮廓跟着明暗走，更像手画）。
3. **交线**：先不画（SketchUp 同款）；要画就给线稿加 B 那样的兜底。
4. **归谁**：这是渲染器线批接口的改动（多一种「只在外轮廓时画」的线 + 细线着色器 + 守卫）。按分工可以先给 Fable 看接口；或者 user 点头 Opus 直接做第一步。
