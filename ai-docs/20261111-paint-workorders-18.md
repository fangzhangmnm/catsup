> 词：**排法** = 一套贴图坐标（代码里一直叫 `uvSet`，文件和代码都沿用这个词）；对 user 说的「一张 atlas」= 一套排法连同挂在它上面的图。

## 一、做完是什么样

- 带着画的面并进别的物件、炸开、分出去、建组件、做成唯一、在同一个物件里复制，都直接成功，画一格不动。结果是几个物件的面在同一套排法上各占各的位置（或者副本和原件占同一块，画一处两处都变）。
- 把画过的材质给别的物件的面：那些面在这套排法上找地方（照这套排法「定住的是什么」的规矩）。
- 「这张画属于哪个物件」这句话从文件和代码里消失。
- 这一张**不做**的见第八节（跨文件粘贴带画的东西还是拒，等下一张单的「搬画」）。

## 二、三条不变量（审查只对着这三条看）

1. **同一个版本**：一套排法的那一行、挂在它上面的图、所有物件的面在它上面的位置，永远是同一个版本。同一份文件里靠「一步撤销里一起翻」保证；剪贴板和素材架是唯一能把旧版本带回来的路，所以那条路要查（第六节第 4 刀），查不过就拒。
2. **新面的位置上没有旧画**：一张面新得到的位置，那几格在每个图层里都是空的。（现在不成立：`layoutAppend` 只把「这个网格体里现在有值的面」算占着，删掉画过的面之后，新面会落在旧画上。第 0 刀先写一条红的检查。）
3. **改几何不悄悄毁画**：没被碰到的面，像素逐位不变；丢了位置的面要数得出来、说得出来（方向稿第五¾节的表）。

## 三、文件格式（统筹定；改一个键先问）

### 3.1 新的一节 `CATSUP_uvsets` 1.0（可选的顶层扩展；表空 = 不写）

`{ version: 1, list: [ 行… ] }`，一行：

| 键 | 值 | 规矩 |
|---|---|---|
| `guid` | GUID | 表里两行同一个号 = 这几行都不认（不挑第一个、不现铸：列是按这个号找它的） |
| `name` | 字符串 | |
| `width` `height` | 正整数，单位格，每边 ≤ 16384 | 16384 = 内存里 32 位浮点还能把 1/1024 格表示精确的上限；现在铺法的上限是 4096 |
| `pxPerM` | 正的有限数 | |
| `fit` | 字符串，必写 | `"density"`（定密度：画布跟着长）/ `"size"`（定大小：不自己长）。不认识的值原样带回，行为 = 什么都不自动动（不给新面找地方、不长大）。以后的「手工」到有人能造它的时候再加 |
| `freed` | 整数列表，四个一组 `[x0, y0, x1, y1]`（格，左上含、右下不含）；缺 = 空 | **空出来的地方**：原来有面、现在没面了，里面可能留着旧画。**可以记大**：框可以盖到现在还有面占着的格，有面占着的格归那张面、不算空出来（真正空着的 = `freed` 减去现在有面占着的格）。补面绕开它；以后的重排只收回、清空没有面占着的那部分。形状不对 = 当不认识的键带回，并且这套排法不自动给新面找地方 |
| 别的键 | | 连同它们指着的字节原样带回（照贴图表那一行的 `carryJson` / `landCarried`） |

- 表里的先后没有意思。坏的一行 = 这一行不认、记进 `notes`，模型照开（和现在读贴图坐标的收口同一条规矩）。
- 大版本比本版新 = 拒开（不学桌面态那几个「带回、先不显示」的例外：建模的每一步都要碰它）。
- 记给以后的两条：① 行里带着不认识的键 = 静默重排不碰这一套；② 任何会让已有位置失效的动作（重排、换大小、手工改坐标）必须给这一行加一个版次，版次键到第一个这样的动作出现时加（缺 = 0），剪贴板靠它认旧载荷。

### 3.2 `CATSUP_mesh` 3.0：`uvSets` 键没了，换成 `columns`

`columns: [ 列… ]`。两种列：

- **uv 列 = 一个通道**（2026-11-13 改，见下面「为什么改」）：`{ kind: "uv", arity: 2, sets: [GUID, …], faceSet: { bufferView, count }, data: { bufferView, count } }`
- **别的种类**：`{ guid, kind, arity, data: { bufferView, count }, …别的键 }`

> **为什么改（2026-11-13，edited by Claude Fable 5.2）**：原来写的是「一套排法一列、列头的 `guid` 就是排法的号」。user 看了问：「为什么不是id列加uv列，而是每个画布一个uv列」。他说得对：那个形状是从 2.x 顺下来的（那时排法归物件、一个物件通常一套）；排法成了公共的之后，一个物件跨几套排法就要存几列、每列大半是空的，大小跟着排法数涨。改成每张面一个代号（带对照表）加一列坐标，大小只跟面数走，和通用模型格式里贴图坐标的形状一致，也合家规「编号只能是对照表的代号」。只改文件；内存里还是按排法分的列，读写时在门口转换（内存随时能改，文件改了难回头）。第 1 刀这时已经做完、还没推。

- **uv 列的三样**：
  - `sets`：对照表，代号（下标）→ 排法表里那一行的 GUID。重复的 GUID 允许。
  - `faceSet`：每张面一个 32 位有符号整数（小端）= `sets` 的下标；−1 = 这张面在这个通道里没有位置。`count` = 面数。
  - `data`：每个角两个 32 位有符号整数（小端，和 `loopVert` 同序），**单位 1/1024 格**；面没有位置 = 两个数都是 −2147483648。`count` = 角数。
- **通道数** = 这个网格体里一张面同时在几套排法上的最大值，平时是 1。没有任何面有位置 = 不写 uv 列。
- **写**：每张面把它有位置的排法按 GUID 字典序排好，第 k 个进第 k 个通道；每个通道的 `sets` = 这个通道里出现的 GUID，字典序。同一份内存写出来逐字节一样。
- **读**：每个通道展开回内存里按排法分的列。坏了不拒开、按「没有」、记提示：长度不对 = 这个通道不认；下标越界、`sets` 里那一项不是 GUID = 这张面没有；`faceSet` 说有而角上是「没有」或一半有一半没有、`faceSet` 是 −1 而角上有数 = 这张面没有；同一张面在两个通道里指同一套排法 = 后一个不认。`sets` 里的 GUID 在排法表里找不到 = 那些面没有（记 `notes`）。
- uv 列对象里不认识的键不带回（通道是写的时候现排的，没有地方挂）。
- **列按槽分（2026-11-13，user 定方向；第 2 刀落地，开工前和统筹对一遍）**。user 看了「需要时再加第二组」之后：「不同的槽用不同的列。其实这样还有一个好处就是以后可以bake」。统筹的读法（user 没逐字说的）：
  - 一个 uv 列对应一个槽（材质里放贴图的位置；现在只有颜色一个）。**一张面在一列里最多在一套排法上有位置**。一张面要同时在两套排法上 = 两个槽、两列。
  - 所以上面「写」那一条里「第 k 个进第 k 个通道」的凑法只是过渡：它让列的先后没有意思。第 2 刀改成：面换到另一套排法 = 旧位置空出来（记进那一行的 `freed`）；写的一头这一版只写一个 uv 列；同一套排法出现在两个列的 `sets` 里 = 后一个不认。
  - 平常的文件（每张面最多一套）两种规矩写出来逐字节一样，所以第 1 刀照现在的做法推，不用改。
  - 「有没有这一列」那个成员关系跟着没有了（见下一条）。
  - **内存留着按排法分列（统筹 11-13 定，照小弟的估计）**。小弟查了：改成「一列代号 + 一列坐标」要给内核加一种每张面一个数的列，十来个会长出新面的动作都要定它怎么继承，角上坐标的插值还得认代号，读贴图坐标的地方全改，估是第 1 刀的两三倍、动的是内核的高风险区。分列还有一个统筹先前没看到的好处：两张画布的坐标在结构上混不到一起（并面时一列半有半无 = 整面没有）。到什么时候再看：一个物件跨的排法多到建模每步变慢或内存吃紧。
  - **第 2 刀怎么守住「一张面最多一套」**：
    - 一个写口「给这张面在排法 B 上安位置」：同一步清掉它在别的排法上的位置，旧位置记进那一行的 `freed`，提示行说一句人话（几张面原来在哪张画上的位置空出来了），撤销能回去。会写 uv 值的三处（开始画、补位置、强行对称抄位置）都走它。
    - 小弟实跑出来的三条能造出「一张面在两套上」的路，都归这个写口管：面从画 A 换成普通材质再点「开始画」；同样换走之后「把这几张面加进来」另一张画；面还走着画 A 直接换成画 B 的材质再收尾补位置。
    - 内核自检加一条「一张面最多在一列 uv 上有值」，撤销随机探针每步核；写文件的门口发现违反 = 内部出错、抛，不悄悄挑一个。
    - 读：这一版只有颜色一个槽，只认第一个 uv 列；后面再出现 uv 列 = 这一版没有的槽，不认、记一笔（算会丢的）。写：最多一个 uv 列。第 1 刀那条「手造两个通道来回逐字节」的测试改成「第二个不认 + 提示」。3.5 第 3 条「一张面可以同时在两套排法上」改到有第二个槽的时候再放开。
  - **「有没有这一列」的八处**（小弟清点）：`facePaint`、补面的三处捷径、`paintPlaceOf`、渲染判要不要走画、「开始画」没选面时、画画工作台、读文件收口——第 2 刀改成看面；换材质那条拒绝（「这个网格体不在那张画的排法上」）的判据就是这个关系本身，留到第 3 刀放开时一起拿。所以空的 GUID 写到第 3 刀。第 2 刀会变的两处行为：没有那一列而材质是画的面，以后算「走画没位置」、收尾去补；画过的面全换成普通材质之后再点开始画，以后给全部的面开一张新的。
  - bake：两列同时在 = 原来的位置 + 新的位置，把像素从一边烤到另一边。下一张单的「搬画」照这个做：新位置先放进另一列、烤过去、再换回来，一条指令一步撤销，另一列不落进文件。
- **`sets` 里允许有没有任何面引用的 GUID**（小弟 11-13 抓到的，统筹同意）：意思是「这个网格体在这套排法上，零张面有位置」。内存里有这种状态（画过的面全删了，列还在、全空），而且 facePaint、补面、`paintPlaceOf`、拒绝挪画现在都看「有没有这一列」；不写出来的话存了再开行为就变了，第 1 刀要求行为不变。写：空列的 GUID 也进第 0 个通道的 `sets`，这时就算没有面有位置也写第 0 个通道。读：`sets` 里出现的每个 GUID 都建一列。**第 2 刀要回头看**：「有没有这一列」这个信号是排法归物件那个年代留下的成员关系，按排法看所有定义之后应该拿掉；拿掉之后空的 GUID 不用再写，格式不变。
- 别的 `kind`（这一版一种都不造）：`guid` 是这一列自己的号；`data` = 每个角 `arity` 个 32 位浮点，NaN = 没有值。这一版把它当普通的一列带着走完每一步建模（继承规则本来就是所有列共用的）、`kind` 和别的键原样写回。
- 别的种类的列收口照 2.x：一张面在一列上半有半无 → 这张面在这一列上整面没有，记 `notes`；同一个网格体里两列同一个号 → 这两列都不认，记 `notes`。有值落在画布外的面（uv）→ 整面没有，记 `notes`。
- 拍子：不带列的网格体照旧盖 1.2（逐字节不变，没画过的文件旧版本照常开）；带列的盖 3.0；2.0 / 2.1 不再写。
- 两条规矩写进文件头注释：① 以后跟着角走的数据一律做成新的一列，不许塞进列的行里当别的键（旧版本改了网格它就过时了）；② 换编码、或者哪个种类受不了线性继承 = 大版本。

### 3.2½ 内存也做单列，内核对属性无感（2026-11-13 夜 user 定；第 1½ 刀，行为不变，排在第 2 刀之前）

> **这一节盖过 3.2 里「内存留着按排法分列」和「第 2 刀怎么守住一张面最多一套」两条**（那两条作废；「列按槽分」「有没有这一列的八处」照旧）。edited by Claude Fable 5.2
>
> user 11-13 夜，按先后：
> - 「为什么分列反而没有，我觉得分列更麻烦吧」
> - 「单列唯一的麻烦就是物体之间的移动得重新定义编号的语义，不过这个取决于你用的是绝对编号for texture还是每个物体有一个短编号到真实texture编号的速查表」
> - 「那么现在就做单列，我感觉你说的那个例子又犯了恋旧的毛病：因为你说的那个规矩反而是我没有拍的，是以前算法不成熟的时候留下的，可能那个算法碰到单列会错本来就说明了它的脆弱性。think critically about it」
> - 「more over, why the geometry engine is sensitivity to attribute. they should be agnostic to it. they should only know if they are face, vertices, or corners. but have no idea what they mean. is it correct?」
> - 「我现在强烈建议用单列做」
>
> 统筹认的账：`corner-columns.ts` 里「一张面在一列上要么都有要么都没有、半有半无整面清空」和「并面时共用的点值都一样才算数」是统筹 11-10 审 1-2 时定的，user 没拍过。它们只因为分列要表示「这张面不在这套排法上」才存在；而且只对贴图坐标讲得通（角上存一列颜色，两张颜色不同的面并成一张，整面颜色会被清空）——是把贴图坐标的意思写进了号称通用的列里。统筹先前把它当成「分列的好处」，是拿旧结构自己带来的规矩替旧结构辩护。

**原则（user 定；限定那一句是统筹补的）**：几何内核对属性无感。它只知道一份数据挂在哪一类东西上（点 / 角 / 面 / 边）、是什么类型的数、是连续的还是离散的（连续的切面时插值，离散的照抄——这是数学性质，不是意思）。属性是什么意思、什么时候算坏了，归用它的那一层。内核只如实报告每张新面是怎么来的。

**这一刀做的**（内核对外的接口先由小弟出草案，统筹审过再动工）：

1. **面上的通用列**（新）：离散的整数列。新面的值照来历定，全在一处：是原来那张面的一块 / 一份 = 原面的值；新长出来的 / 凭空来的 = 缺省值（或调用方给）；几张面并成的 = 来源都一样就是那个值，不一样取排在最前的来源的值、并报告「这一列在来源之间对不上」。
2. **角上的列变成真正通用的**：每个角永远有数，没有「没有值」这种状态；`NaN` 不再有特殊意思。来历的规矩里去掉两条：半有半无整面清空；并面时共用的点对不上就整面清空。改成：并面时共用的点取排在最前的来源的值，并报告「这一列对不上」。内核不再根据数值清空任何属性，`takeDroppedFaces` 这类计数搬到上层。
3. **内核的报告**：每一步里每张新面 / 改过的面的来历，加上「哪几列在来源之间对不上」。
4. **贴图坐标 = 画画那一层的两列加一张表**（每个槽一组，现在只有颜色）：网格体上的速查表 `sets`（短代号 → 排法 GUID，和材质槽表并排）、面上一列代号（−1 = 没有位置）、角上一列坐标（每角两个数；没有位置的面这里是 0，没有意思）。
5. **贴图坐标的规矩搬到画画那一层**（`scene/paint.ts`，在每一步的收尾里，同一步撤销）：有没有位置只看代号；读内核的报告——并出来的面代号对不上、或者坐标对不上 → 这张面的代号改成 −1，数出来、说得出来（不变量 3 照旧）。写位置只有一个口。
6. **面在物件之间搬**（并物件 / 分出去 / 炸开）：合并 `sets`、把搬过来的面重新对号，照材质槽现成的那条路。
7. **`MeshDoc` 和文件同一个形状**：门口不再打包 / 展开。文件格式不变（v0.19.80 已经是 `sets` / `faceSet` / `data`）。读的一头照旧：`faceSet` 是 −1 = 没有位置，不看角上写了什么。
8. **别的种类的角上的列**（文件里 `{ guid, kind, arity, data }`，这一版一种都不造）：跟着改成每角都有数、`NaN` 没有特殊意思；3.2 里「NaN = 没有值」「半有半无整面没有」对它们作废。

**验收**：行为一点不变（全套测试、全部探针；并两张不同画布的面 = 没有位置并且数得出来；并两张同一画布但接不上的面同样）。新加：角上存一列别的数（比如颜色），并两张值不同的面，这一列不被清空。内核的测试里不出现「贴图」「画」这类词。

**小弟重估（11-13 夜，和统筹的决定交叉到达，结论一致）**：他上次估高了——新面角上的数全仓只在 `writeCorners` 一处按来历定，代号照来历在同一处定就够；不走来历、要单独管代号的只有「直接给值」的几条路（`ops.ts` 分出去、`appendMesh`（并物件、炸开）、装载、从快照建）。读坐标的地方 23 个文件、大多一两处。估这一版约第 1 刀的一半到三分之二，之后第 2 刀再小一截。验收用他提的：**换之前和换之后写出来的文件逐字节一样**（冻结样本、随机 200 份、user 那份文件），内存快照对拍。为保证这一条：写文件时 `sets` 照旧按 GUID 字典序、面上的代号跟着换号；没有面引用的项照旧写到第 3 刀。材质槽现在的合并和重新对号在 `appendMesh`，代号照抄同一处。渲染那一头不用动。

## 四、坐标的精度

- 内存里照旧是 32 位浮点、单位格。**凡是产出贴图坐标的地方，最后一步量化到 1/1024 格**：铺法的输出、`corner-columns.ts` 里唯一的那份插值（只对 `uv` 这一种列；所以 `ColumnDef` 要带 `kind`）。照抄的不用管（本来就是）。
- 内核自检加一条：`uv` 列里每个有值的数乘 1024 是整数。这样存成整数再读回来逐位相同。
- 1024 这个数和归属表取样点用的 `SAMPLE_Q` 是同一个数：收成一个常量，两边都从它来。
- **不取整格**：只量化到 1/1024，哪个点都不往整格上凑（方向稿第五½节第四版：有画的点一个都不挪）。

>   1. **同一步里先空出来、后补面，新面会落到刚空出来的旧画上**。记空位现在在整步的最后；补面在每条指令的收尾里，排在它前面，补面时这一步刚空出来的框还不在清单里。最容易撞上的：并面两边位置对不上 → 拿掉位置 → 同一步重新找地方，这时两张原面的框正好空着。改：收尾里每次补面之前先记一次空位（同一个 `freedOp`，多跑一次结果一样），整步最后那一次照留。加两条测试：并面对不上的那张面重新找到的地方不碰两张原面的旧框；随便一条「同一步里删掉画过的面又长出新面」的。

## 七、两道防线

1. **登记表**：每条会改网格的指令登记它对画做什么，漏登记 = 测试红（照 `mesh/mirror-ops.ts` 那张表和它的守卫）。类：位置不变 / 按公式继承 / 长出没位置的新面 / 面没了 / 并面（可能丢位置）/ 整面搬到别的物件。一条指令可以占几类。
