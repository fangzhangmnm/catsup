## 1. user 口述的 spec（M-spec，2026-09-01 原话大意）

1. 拖线=线刚性动、拖面=面刚性动；**其他都不动**，连着角的线跟着连。
2. 拖拽中间纯视觉（甚至可以非平面渲染），**不做拓扑裁决**。
3. 松手时自愈：重算拓扑/intersect——「就和用笔画没区别，相当于重新用笔画并且设置面」。

## 2. 重现实锤（node 直跑 kernel，输入→预期→实际）

**重现①**：静态边 S=(5,5)-(5,15)；被移边 M=(0,0)-(10,0) 整体 +20y。
预期（M-spec）：M 直着到 (0,20)-(10,20)，S 原样。
实际：

```
边#3: (5,5)-(5,10)      ← S 被幽灵交点切开
边#4: (5,10)-(5,15)
边#5: (0,20)-(5,10)     ← M 变成 V 形折线，焊在幽灵交点上
边#6: (5,10)-(10,0)     ← M 的另一端根本没动（move 被静默吞掉）
事件: []
```

**重现②**：方形膜 (0,0)-(20,20)；边 M=(30,5)-(30,15) 整体 -25x（终位应全在膜内）。
预期：膜边界原样、膜活、M 成膜内悬边。
实际：膜边界被幽灵交点 (20,11) 切开；M 变成 (5,5)-(20,11)+(20,11)-(30,15)——一半戳进膜、
一半留在半路；B 端 move 被吞；事件流零输出。

## 3. 五病（机制定位）

- **病① 逐顶点串行裁决（根因）**：`moveVertices` 一个顶点一个顶点地动+立刻 sticky 裁决。
  裁决对象是「一半已动一半没动」的**幽灵中间态**——重现①的 (5,10) 就是幽灵对角线
  (0,20)-(10,0) 与 S 的交点，用户的真实意图里这条对角线从不存在。且结果依赖 moves 数组顺序。
  违反 M-spec 第 1+3 条（先整体刚移完、再一次 resolve）。
- **病② 第二套私搭 resolve 管线**：松手裁决没走「用笔画」正门 `insertSegment`，而是在
  moveVertices 里重新发明（mergeVertexInto / findEdgeContaining / dirtyIncidentEdges + rip&reinsert）。
  两套管线必然漂移；rip&reinsert 是私货中最露骨的发明。M-spec 说「和用笔画没区别」= 应**复用正门**。
- **病③ 静默吞 move**：rip&reinsert 删旧边重插会铸新顶点 id；同批后续顶点 `hasVertex` 查无此人
  → `continue` 静默丢弃（重现①②里 B 端留在原地的原因）。「错误路径吞掉之后照报成功」的家规违反。
- **病④ 撞面裁决缺席 + 收尸逻辑弱**：边横穿膜的 DIVIDE 挂 todo 没做；`reconcileMove` 只快照外环
  （洞环没快照）、anchor 找不到后继就**静默删膜**、`taken` 先到先得可让错误的膜抢走 region。
- **病⑤ 预览连播错误**：拖拽中每帧 clone+moveVertices 当预览——机制（预览=预演松手）没错，
  但预演的正是病①②③的错误语义，等于把怪行为做成了实时动画。

## 4. M-spec 蕴含的正确形状（提案，未拍板）

松手 = **detach + redraw**：
1. 收集被移边集 E（被抓实体 + 共角牵连边），记录关联膜的身份与填空态；
2. 把 E 整体摘除（纯拓扑，不裁决）；
3. 顶点刚性平移（纯坐标，不裁决）；
4. E 按新位置逐条 `insertSegment` 重插——正门自动打交点/sticky/切他边；**不带手势身份**
   （守恒律 by construction：move 永不生膜，与 golden「move 闭合开折线不出面」一致）；
5. 「设置面」：把第 1 步记下的膜按 anchor 搬回对应 region（该 DIVIDE/MERGE 的照发事件）——
   取代现 reconcileMove 的收尸逻辑。
病①②③⑤同死，病④的撞面切割由正门自动痊愈；拖拽中改纯 ghost 渲染（连非平面都容忍），
预览若保留则预演的就是上述正确松手。

**待 user 裁**：同平面两膜被 move 压出**重叠区**时归谁（SU 的 sticky dedup-merge 语义在 2D
的对应物；可先 golden 挂 todo）。
