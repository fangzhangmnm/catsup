## 0. 判据

「编辑器专用」= **纯看 / 纯玩的游戏引擎不需要、编辑器（和建造类游戏）才需要的画面语义**。分四档：

| 档 | 含义 | 游戏引擎（纯玩）| 建造类游戏 | CatsUp 编辑器 |
|---|---|---|---|---|
| **A** | 任何有玩家的世界都要（不是编辑器专用，只是现在恰好从编辑器那边喂进来） | 要 | 要 | 要 |
| **B** | 建造类游戏要 | 不要 | 要 | 要 |
| **C** | 只有编辑器（CAD / 建模）要 | 不要 | 不要 | 要 |
| **D** | **过渡期私货**：编辑器语义烤在内容流 / 后端里，不走叠加层契约——是要退役或改成显式字段的 | — | — | — |

风格能不能认领（T58「只有写实的才有叠加层；像素 / 风格化的大多得自己接」）另列一栏：**叠** = 按原分辨率叠在画面上（写实一路的默认）；**认** = 风格自己画（进小图 / 换颜色 / 进辉光 / 不画）。

## 2. 分档小结（= 「可拔」的边界）

- **纯玩的游戏引擎**只要 A：文字标签、teleport 弧 / 落点环、胶囊虚影、近平面、控制器指针、单面身体。叠加层回调不给 = 没有（契约已如此），**引擎里零编辑器 import**（守卫 ③′ 已清零）。
- **建造类游戏**加 B：选中的面 / 边、吸附提示 + 小球、变换 gizmo、锁轴线、地面网格、X 光。
- **编辑器**再加 C：其余全部（点、尺规、量角器、参考几何、刀线、柄、三轴、镜像中缝、软边、充能、断口刻度、缩略图）。
- **D 档**（活动池 / 淡出烤在流里）是真正的越狱残留：编辑器语义藏在内容流的旗子里，后端按它挑材质——风格要认领「正在编辑的东西」（T60）时没有干净的钩子，只能在 render3 里 if。

## 3. 接口怎么窄（v2，user 10-29 深夜改口后；v1 的「语义词表 + 认领表 + frame graph 分派」作废）

user 原话：「你的语义走的太过了。我想的只是一些辅助线的几何，高亮的面。我想的就是分两批提交，普通的面。高亮的面用不同的材质，然后线和gizmos，小仓鼠不应该认识编辑器。它只认识最少的东西，不应该有graphics.drawgizmosline这种东西，接口要窄！」「gizmos类的可能像素接不住，但是小心一下配色，不然可能看不见。就是相当于分辨率高但是画风fake地差不多。color coding可以牺牲一下。」

**引擎只认识三批东西 + 两张表：**

| 批 | 引擎看到的 | 编辑器 / 玩家 / 游戏怎么用 |
|---|---|---|
| ① 普通的面 | 面块 + **材质槽** | 内容流原样 |
| ② 高亮的面 | 同一组三角、**另一个材质槽**（画在 ① 之后，同深度后画的赢） | 选中 / 悬停 / 刮擦 / 检查 / **淡出** = 各挑一个槽；选什么是编辑器的事，引擎不知道「选中」这个词 |
| ③ 线 / 点 / 标记 / 文字 | 几何 + **一种通用线材质**（细 / 粗 / 压最上 / 透视 / 虚线…，一只手数得过来）+ **调色板槽位名** | 轴线、锁轴线、参考线、尺规、gizmo、刀线、隐线、teleport 弧…全是「线 + 材质 + 颜色名」；引擎不知道哪根是 gizmo |

| 表 | 谁给 | 内容 |
|---|---|---|
| **材质表**（material/ 开放槽表，已有） | 风格 | 每个槽在这个风格里怎么画：normal / selected / hover / dim…（Tron 的 selected = Clu 橙 + 辉光；写实的 selected = 叠色〔T66〕；像素 = 换色） |
| **调色板**（palette.ts，现在是一份死的） | 风格 | 槽位名 → 颜色：axisX / axisY / axisZ / guide / lock / edge / edgeSelected / hint…；**风格可以把几个槽位映成同一色（牺牲 color coding），必须保证在自己的背景上看得见**（Tron 深底上黑参考线 = 看不见，现在就是这个问题） |

**推论（比 v1 少掉的东西）：**
- 没有语义词表、没有认领表、没有按 role 分桶的 frame graph 分派。风格 = 材质表 + 调色板 + 屏幕 / 后处理，和现在的预设结构一致，只是材质表和调色板从「一份死的」变成「风格给的」。
- **gizmo 类一律原分辨率**（像素接不住）：线 / 点 / 标记在风格的小图放大之后、按风格的调色板画 —— 「分辨率高但画风 fake 地差不多」。像素 / Tron 里选中 / 轴线「进小图」（T55）的那半作废，只有 ② 高亮的面天然在风格里（它就是内容）。
- **X 光引擎也不认识**：隐线 = 编辑器用「透视线材质」提交的线（X 光开 = 提交、关 = 不提交，T60 / T63 自动成立）；Tron 淡青实线 / 蓝图 0.38 虚线 = 那个风格的调色板 + 线材质参数。
- **D 档私货的归宿**：淡出 = ② 的一种（dim 材质槽），不再烤顶点色；活动池的深度阶梯留在引擎（那是「同深度谁赢」的正确性规则，引擎只认识「优先级档」这个数，不认识「活动池」）。
- 像素里「正在编辑的东西显示网格、别的不显示」（T60）：风格在预设里声明一个数据字段（如 `edges: "none" | "all" | "active"`），编辑器读了决定提交哪些边 —— 决定在编辑器，引擎还是只画线。
- 现在 `LINE_STYLES` 的 17 个 id（hint / protractor / guide / tape / knife / lock / gizmo / xg / poolAxes…）**名字就是编辑器概念** = user 说的 `drawGizmosLine` 的味道。收成一只手数得过来的通用线材质（细 · 细压最上 · 粗 · 粗压最上 · 透视 · 虚线 · 共享边线），编辑器侧自己记「锁轴线 = 细压最上 + 调色板 lock」。点 / 标记表同理。
- 游戏引擎可拔 = 不提交 ③、材质表里没有 selected 槽就行；玩家侧（teleport 弧 / 胶囊 / 控制器指针）自己提交 ③，不经编辑器的 ViewState。
- 高亮的面「画两遍」保留（T65：① 完整、② 后画 = 悬停变化只重建 ②，不动内容流）；贴图面 / 找不到槽的那两处膜改走 ②（贴图材质的 selected 变体）。掩码方案不做。
