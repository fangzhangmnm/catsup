## 0. 一句话

左半屏 = 浮动摇杆走，右半屏 = 拖动转头，右下 = 跳 / 蹲，上方正中两侧 =「离开」「原地编辑」（iPad 没有 Esc / Tab）。只在有触屏的设备、步行的 FPS 阶段露；只接移动，武器一概没做。

## 1. 调查（这次没有上网查；下面是我对几款手机射击游戏通行做法的了解，真机上不对就改参数表）

- **移动摇杆**：吃鸡（PUBG Mobile）默认是固定摇杆，有「浮动」选项；使命召唤手游默认浮动。浮动 = 拇指按在左半屏哪里，底座就出现在哪里——不用看着按，竖屏拇指够得着的范围也就左下那一片，固定位置反而常常按偏。**选浮动。**
- **跑**：吃鸡的肌肉记忆是「推到底再往外 = 跑」，再往上推到一个锁的图标 = 自动跑（冲刺锁）。**做了「推出底座边缘 = 冲刺」；冲刺锁没做（wishlist）。**
- **底座跟手**：拇指滑出底座很远时，底座跟着挪（不然拇指已经在别处了，摇杆还以为在推满）。
- **死区**：拇指放下的那一下会抖，中心一小圈不算推；过了死区就该是最慢的那一档走，而不是「推了一段不动、然后突然动」。
- **转头**：右半屏任意处拖（触控板式），**不加速、不平滑**——加速会让同样的手指位移转出不同角度，平滑会多出延迟，射击游戏的视角都是跟手第一。灵敏度用「每像素多少角度」，常见默认大约半个屏幕一划转 90° 上下。
- **按钮**：跳在右下拇指上方一点；蹲在旁边（点一下切换，不用一直按）。
- **竖屏**：分区按百分比（左右各半、顶上 15% 留给 HUD），竖屏横屏一样能用；竖屏时拇指主要在下半屏，按钮都在下半。

## 2. 做法（代码在哪）

- 数学 `src/player/touch-stick.ts`（零 DOM，node 测过：`test/touch-stick.test.ts`）：`stickOutput`（死区 → 从模拟器死区起线性给到 1，封顶，过冲刺线 = 冲刺）、`followBase`（底座跟手）、`placeBase`（贴边按下底座往里挪到整个露出来）。
- 界面 `src/app/touch-controls.ts`：一层透明覆盖（`.touch-ctl`），左右两个区抓指针（`setPointerCapture`，抓不到也照样用）；鼠标指针不进来（键鼠照旧 WASD + 锁鼠标）。
- 接线：`Locomotion.touch` 每帧和键盘合并（推得远的那个算、按钮取或）；转头走 `Locomotion.lookRad`（弧度）。模拟器（`player.ts`）一行没改：它本来就按推多远定速度。
- 探针 `test/probes/probe-touch-stick.mjs`：iPad mini 竖屏 + 横屏各一遍（推满半秒走 1.5 m = 3 m/s、冲刺 3 m = 6 m/s、右拖 100 px 转 0.45 rad、跳离地、原地编辑收起）。

## 3. 参数表（调参纪律：每个量按自己的量纲单独定，想改哪个就改哪个）

| 量 | 值 | 量纲 | 为什么是这个数 |
|---|---|---|---|
| 推满的距离 `STICK.radius` | 56 | CSS px（iPad mini ≈ 9 mm） | 拇指不挪手腕够得着；再小一抖就满速 |
| 死区 `STICK.deadzone` | 0.12 | 占推满距离的比例 | 拇指放下的抖动 |
| 冲刺线 `STICK.dashAt` | 1.3 | 同上（> 1 = 推出底座边缘） | 推满后再往外一点点，不会误触 |
| 底座跟手 `STICK.followAt` | 2.2 | 同上 | 留出冲刺那一段，再远才跟 |
| 起步速度 `STICK.simDeadzone` | 0.15 | 速度比例（= 模拟器死区） | 过了死区就动，不出现「推了不动」 |
| 转头 `TOUCH_LOOK_RAD_PER_PX` | 0.0045 | 弧度 / CSS px（≈ 0.26°/px） | 竖屏右半屏一整划 ≈ 370 px ≈ 95° |
| 走 / 冲刺速度 | 3 / 6 | m/s | 模拟器原有（`DEFAULT_CONFIG.walkSpeed / dashSpeed`），和键盘同一套 |

## 4. 没做的（都等 user 想好）

- 武器、开火、瞄准（user「吃鸡有几种武器还没想好」）。
- 冲刺锁（推到最上面锁住自动跑）。
- 陀螺仪瞄准（很多手游有，iPad 上举着转身体看）。
- 灵敏度 / 按钮位置可调（和「步行参数怎么配置」一起想，纪元账本 FM169 那条）。
- 震动反馈（网页拿不到 iPad 的触感马达）。
