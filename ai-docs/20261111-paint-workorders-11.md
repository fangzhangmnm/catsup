# 贴图主线施工单（十一）：空间里的笔，显卡的那一半（1-4b）

> created 20261111 by Claude Fable 5.2 · as-of 三维 v0.19.15、画画 v0.14.71 · 2026-11-11 凌晨
> 给谁：Catsup小弟。**等 Fable 看过才合。** 排在 1-3c 之后；1-3c 等审的时候，分支可以从 1-3c 的分支开。分支 `paint-stroke-gl`。
> 短的那种施工单：细则你动手前补在页末。没有界面入口，只有调试钩子和探针。

## 要达到什么

用调试钩子喂一串屏幕上的点，模型上出现一笔；边画边看到的就是最后落下的；抬笔之后落进图层。橡皮是同一支笔换成擦。

```
1-4a 的控制器：笔尖列表 + 每颗笔尖碰到的面
   → 【这一张】画成贴图格子里的薄层（走内核的显卡接口，不经过渲染器）
   → 内核的档口（0-5 的 host 方式）：浓度、混合、橡皮、锁透明、选区照内核现成的
   → 画板合成 → 1-3c 的显示
```

## 关键的形状

1. **薄层怎么画**：每一格吃多少，定义就是 1-4a 的标准答案（每格认画布多边形、有取样点；位置按每张面自己显示的三角形算；同一颗笔尖对同一格只算一次、取最近的距离；浓淡用内核导出的那条曲线）。显卡上画出来的要和它对得上。
   - 着色器在内核的软件显卡里要有一份对应的 JavaScript 写法（内核自己的着色器都是这么测的），那一份就调 1-4a 的标准答案，不另写算式。
   - 数据怎么进着色器你定。已知的限制：内核的显卡接口每个实例只给四个数，别的放单通道 32 位浮点的数据图里取；位置不许放半精度；所有位置先减去这一笔落笔的那一点再上传。
2. **定型的只画一次**：定型的笔尖攒在一张「定型层」上，只画一次；还会变的尾巴每帧重画。每帧的活只随「新定型的 + 尾巴」涨，不随这一笔已经多长涨。
3. **交给内核的范围**：往薄层里画的时候，把裁剪框设成报给内核的那个范围，范围之外写不进去（审 0-5 时定的）。
4. **上色、累积**：用内核公开的那一遍上色和它现成的两种累积方式（取最大、叠加），不自己写。
5. **档口**：每张被画到的贴图开一个内核的档口。一次手势在每张贴图上是一步。这一张里步先进内核自带的撤销栈；接进三维的撤销是 1-8。
6. **第一笔时建画板**：这张画还没有画板就建一块空白的（1-3c 的登记处）。
7. **抬笔**：收笔的渐细这时才知道总长，最后一小段重画；然后落层，只读回碰到的那一块。取消 = 零痕迹。

## 不能破的规矩

- **显卡画出来的 = 标准答案**：随机的笔画（软笔、硬笔、取最大、叠加、压在镜像中缝上、跨过好几张面），薄层逐格和标准答案比，相差不超过 1/255。
- **预览就是结果**：抬笔前最后一帧合成出来的图，和落层之后合成出来的图，逐像素相同（收笔渐细重画的那一小段除外，说清楚是哪一段）。
- **范围之外全是零**：把整张薄层读回来验。
- **过缝不断**：一笔画过两张相邻的面（它们在画布上不挨着），屏幕上的线是连着的，没有缺口。
- **斜面上线宽不变**：同一支笔在正对着的面和斜 60 度的面上各画一条，量模型上的线宽（按格数乘格长），两者相同，只差一格。
- **镜像**：画在右半边，左半边同时有。
- **铺法换掉，结果不变**：1-4a 测试 11 的显卡版，至少一例。
- 画画软件那边一个字不用改；要改内核先停下来说。
- 没在画的时候不多做事；显卡画面丢了又恢复，正在画的那一笔可以算取消，但不许坏掉已经落层的内容。

## 要量的（写进记录，不设及格线）

一帧里各段各花多久（射线、走步、找面、画薄层、内核合成、拷到显示图）；1024 和 2048 见方的画布上各种数据图加起来占多少内存；一千颗笔尖的长笔画，第 1 帧和第 500 帧的花费是不是差不多。

## 碰到这些就停下来报

- 显卡和标准答案对不到 1/255 以内，而且不是你写错了。
- 内核的显卡接口缺东西（比如着色器里的循环、整数图）。
- 一格对着的面太多（复制了很多份的面叠在一起），着色器里循环不下来。
- 1-4a 的目标（三角形、相邻表、索引）每次改模型都要整份重建，在这一张里成了挡路的。

## 做完

`api/` 重新生成；流程图加一节「空间里的一笔」；一个末位版本。交审：最后一个提交、七条规矩各自的结果、量出来的数、和这里不一样的地方、不放心的地方。

**接内核的地方（侦察到的）**
- 档口 = 内核 `StrokeSession(deps, engine, [叶], { historyType, finalize }, "host")`；`deps` 照内核测试 `host-overlay.test.mjs` 的 rig 拼：`begin` / `tokenChanged` / `tokenBeforeImage` 接作品，`setHostOverlays` 交给画板（画板合成时把这些薄层传给 `GLBoard.composite` 的 `stampOverlays`），`commitHost` = `GLBoard.commitBrushStroke`（= `bakeStamps` 写回链，在令牌内），区域笔那几个不用（抛 / 空）。一张贴图一个档口；一次手势在每张贴图上是一步，这一张进**内核自带的栈**（作品给 `UndoStack`；1-8 换 HostedSteps）。
- 薄层 = `HostOverlayInput { tex（和画布一样大的预乘图）, bx, by, bw, bh（报给内核的范围）, layerId, opacity, erase, blendMode, lockAlpha, selMask }`；锁透明、选区由档口补。
- 上色 = 内核公开的 `GLStampRasterizer.colorize(accum, color, ow, oh, scissor)`；累积 = 显卡接口里有名字的两种混合（取最大 / 预乘叠加）。
- 我自己的着色器（名字 `catsup-space-tip` 一类，带 `catsup-` 前缀免得撞内核）用 `registerProgram` 交 GLSL + JavaScript 版；JavaScript 版对每个像素调 1-4a 的 `tipCellsInPoly` 那一套（标准答案），不另写算式。

**数据怎么进着色器（定的方向，动手时细化）**
- 每颗笔尖 × 它碰到的每块画布多边形 = 一个实例（四个数：笔尖号、多边形号、和两个备用），实例的方块 = 那块多边形的范围 ∩ 笔尖在画布上的外接框。笔尖（球心减去落笔点、半径、浓度）、多边形下挂的面、每格归属 / 取样点 / 每张面上的位置放进单通道 32 位浮点的数据图里取；**位置不放半精度，上传前一律减去这一笔落笔的那一点**。
- 一格对着的面多于着色器里那一圈的上限（镜像两半 = 2；复制叠在一起的更多）= 停下来报。
- 定型的笔尖只画一次，攒在「定型层」上；每帧把定型层拷到当帧那张、再画还会变的尾巴（每帧的活只随新定型的 + 尾巴涨）。
- 往薄层里画时裁剪框 = 报给内核的范围；读回整张薄层验范围之外全是零。

**统筹 11-11 留给这一张的两件**
1. 两半共用同一块画布多边形的镜像（强行对称的网格体上 startPaint 出来的就是）要能造出来；在它上面测「画在右半边、左半边同时有」和「点到哪格」（1-3c 的探针那一套）各一遍。
2. 选中 / 淡出状态下的画截一张图看一眼。

**已知的别扭（照裁定，不为它多做东西）**：这一张用内核自带的栈，画板跟着坐标改大小会落成那个栈里的一步；只有调试钩子够得着，记录里写明。

**这一张要跑的**：新测试（node，软件显卡）——薄层逐格 = 标准答案（软笔、硬笔、取最大、叠加、压在镜像中缝上、跨好几张面，差 ≤ 1/255）、预览 = 结果、范围之外全是零、档口一步撤销 / 取消零痕迹；探针（浏览器）——过缝不断、斜面线宽、镜像同时有、铺法换掉结果不变一例、丢画面、量各段时间；截图基线、`probe-paint-display`、`probe-texture-srgb`。全套一次在交审前。

### 统筹 11-11 再定的取向（照做）：轻量，省内存和 CPU

> user 11-11 凌晨（统筹转）：「我还是希望我们这个在性能上还是相对比较轻量的，就能省点内存和 CPU 就省一点。我们不是做高精度的，除非以后需要。」

1. 全程每通道 8 位（和裁定 ② 一致）。
2. 每格的数据用紧凑的格式：三维自己的显卡接口不受内核「只有单通道 32 位浮点」的限制——编号够用 16 位就 16 位；取样点只有块边上的格子和中心不一样，只存那些。每个三角形一份的位置公式照旧 32 位浮点。打算：每格一张 RG16UI（R = 画布多边形编号，G = 块边格子在取样点表里的号，0 = 用格子中心），取样点表 = 只有块边格子的 32 位浮点（精确，和软件版逐位一样）。
3. 内存一张账：1024 见方和 2048 见方一张画，三维这边一共占多少显存和内存，从大到小列每一项（定型层、尾巴层、交给内核的薄层、各张数据图、显示图和缩小图、画板的图块池和合成图）；目标 1024 见方新增不超过约 30 MB，超了的几项说明原因、统筹定砍哪项。
4. 没在画的时候这一笔用的离屏图和数据图放掉（抬笔 / 取消时 SpaceLayer.dispose）。
5. 每帧的活只随这一帧新增的笔尖涨：每帧只上传这一帧要画的实例（新定型的 + 尾巴），定型的笔尖碰到哪些三角形算过就不再算；量落笔那一下建各种表花多久。

**1. 照「轻量」改的（统筹 11-11 那五条）**

### 起因和统筹定的

- 起因：1-7 里拿细分过的盒子试，第一笔就开不了——1-4b 的每格紧凑表用 16 位的号指到另一张「只存块边格子的取样点」表，默认密度（1024 见方铺满）下块边格子 7 万多个，96 张面就溢出（`too many block-edge cells (> 65535)`）；96 / 384 / 1536 / 6144 / 24576 张面全都画不了。

### 做了什么

- **定义**（`texel-table.ts`）：`sampleOffset` = 取样点离中心的偏移（整数份，中心在块里 = 0）；`samplePoint` = 中心 + 偏移 / 1024。标准答案、软件版、显卡版、落点（cellPosition）全用这一个。间隔 gap ≤ `MAX_GAP` = 63（偏移才放得进 16 位），超了建表就抛。
- **每格的表**（`space-layer.ts cellTable / packCell / uploadCellTable`）：每格 8 字节，1024² = 8 MB，4194304 格 = 32 MB；编号和偏移在 `packCell` 查容量。着色器读 `uvec4`，块号拼起来比，取样点 = 中心 + 偏移 / 1024（32 位浮点里正好精确，和 samplePoint 逐位一样）。
- **显卡接口**（契约 `offscreen-gpu.ts`）：数据图格式 `rg16ui` → `rgba16ui`（全仓只有这一处用）；多一个 `maxSize`（每边上限，真显卡 = MAX_TEXTURE_SIZE），建图超了就抛，不许让显卡静默建出空图；软件版 `maxSize` 可以调小（测试顶容量用）、`live` 数没放的图。
- **画画的准备**（新 `space-prep.ts SpacePrep`）：`ensure(目标们)` 建缺的 / 过期的、只留这几份；`problem` 问能不能直接落笔；`take` 借现成的（不现成 = `PrepPendingError`「画布的表还在准备（刚才改了模型），等一下再画」；建不了 = 那句人话）；`checkEpoch` 换文件全放（宿主每帧开画前调）；`release` 离开工作台全放。`SpacePaintStroke` 只取现成的（不现建）；`SpaceStroke` / `SpaceLayer` 多一个「借来的」口子（不给 = 测试里自己建）。主界面：`main.ts paintPrep`（每帧 `checkEpoch`）；调试钩子 `paint.prep.{ensure, problem, stats, release, take}`，钩子的一笔先替没有的工作台做准备、单独报 `prepMs`。**进工作台、撤销后重建这两处在 1-7 里接**（工作台在 1-7）。
- **容量上限**（`checkLayerLimits` 只跟物件和画布有关的那几个，准备时就查，落笔前就知道画不了；`PaintLimitError` = 开发看的英文 + 提示行的人话 `say`，新文件 `paint-limit.ts`）。清单见下一节。
- **顺手查出来、改了根上的**：上传给显卡的三角形公式以前钉在画布原点（位置 = o + du·x + dv·y，x、y 是整张画布上的坐标）；4194304 格（画布四千多格高）时两个很大的数相减，硬度 1 的边上真显卡和软件版差到 3/255。改成钉在这个三角形自己的第一个角上（位置 = A + du·(取样点 − 角)，A 用 64 位算好），误差不再随画布多大涨：同一处回到 1/255。没动放行线。
- **规模样本** `test/probes/probe-paint-scale.mjs`（登记 probe-map：改 `src/paint/`、三维的离屏接口 / 渲染器、会话就提醒跑）。仓里现造的一档每次都跑；真模型一档 `--models=<文件夹>` 或 `CATSUP_USER_MODELS`。
- **拷模型的小脚本** `scripts/extract-lab-model.mjs <实验室 .js> <输出 .glb>`：路径都从命令行给。实验室的 GLB 是压过的（KHR_mesh_quantization，位置 16 位、法线 8 位、坐标 16 位，都按 normalized）；三维的导入读整数时不看 normalized（位置会大三万多倍），照统筹说的不改导入、拷出来时还原成浮点。
- 调试钩子另外：`lab.layoutFaces`（探针用铺法自己的二分算「256 见方」的密度）；`cellAt` 改成按世界里的槽找（导入的模型嵌在组件里，以前只找最外层的摆放 = 找不到），三角形格子按网格体 + 修改号留着（探针一格一格问）。
