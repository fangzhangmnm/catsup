## 一、一句话，一张图

**这一轮做成一件事：把这个角色的脸在模型上画出来。** 眼睛是斩杀线：高分辨率，位置精确到可以信任，画完能在视图里反复调。

整个工程是三层：

```
┌──────────────────────────────┐      ┌──────────────────────────────────┐
│ 画画软件自己的界面              │      │ 三维软件自己的界面（画画工作台）      │
└──────────────┬───────────────┘      └───────────────┬──────────────────┘
               │                                      │
               │                      ┌───────────────┴──────────────────┐
               │                      │ 空间层（新写，在三维仓）              │
               │                      │ 这一轮的数学全在这                   │
               │                      └───────────────┬──────────────────┘
┌──────────────┴──────────────────────────────────────┴──────────────────┐
│ 画画内核（两边逐字节同一份；正本在画画仓，三维机械拷贝，只在画画仓改）          │
└─────────────────────────────────────────────────────────────────────────┘
```

| 层 | 管什么 |
|---|---|
| **画画内核** | 手感（滤抖、按间距走步、压感）；把一张薄层合进图层（橡皮、锁透明、混合、选区和蒙版挡着）；图层；撤销的记录怎么产生；小块存储和显卡缓存；在一小块平的图上跑的程序（涂抹那十来步） |
| **空间层** | 屏幕上一点落在模型的哪里（射线，精确到贴图像素）；把笔尖在空间里的形状画成贴图格子里的一张薄层；把一小块平面和贴图互相取放（涂抹用的切平面、套索和贴花用的虚拟屏幕）；补边；怎么铺贴图；面的来历 |
| **界面** | 各写各的 |

内核和空间层之间只交接三样东西：

1. **笔尖的列表**（内核 → 空间层）：手感算完之后的一串笔尖。
2. **贴图格子里的一张薄层**（空间层 → 内核）：这一笔、这一次贴花、这一次填色落在贴图上的样子。
3. **一小块平的图**（来回）：涂抹、模糊要处理的那一小块。

内核里没有相机、网格、三角形；空间层里没有具体工具的名字。

## 二、跳出来看，查出来要改的三处

设计稿是两天里一块一块补出来的。通读一遍，施工部分有三处已经对不上了：

1. **内核不用认「坐标表」了，画画软件要动的地方因此变少。**
   - 设计稿第 2、3 版让内核去认一张坐标表（烤笔画时照表取、浮层变换前后各垫一张表）。
   - 定了「笔在空间里」「落点反算、不查近似的表」「统一按空间做」之后，照表取样这件事整个落在了空间层自己的着色器里。内核只需要多认一种薄层：「宿主已经画好的」。
   - 我核了内核的代码：它现在认三种薄层（笔尖的、填色的、整块替换的），加第四种是照着第一种抄几行、去掉「自己画笔尖」那一步。
   - 所以设计稿里「取样的两处改成照坐标表取」「浮层变换前后垫表」两张工单取消。遍历贴图像素、反查来源这个原则没变，只是做这件事的着色器住在三维仓。
2. **漏了几张工单。**
   - **画画的界面和输入**：进出画画状态、笔和橡皮的按钮、大小浓度硬度、取色、笔和手指的分工（笔画画、手指转视角、防手掌误触）。没有这些，第一笔画不出来。
   - **预算归宿主**：设计里说了「给多少内存和显存由宿主说了算」，没有对应的工单。
   - **存盘和崩溃恢复**：一份画比几何大得多。存盘的大小、崩溃快照带不带画、没在画的画在显卡上只留一张合成图，这些是数据安全的事，要单列。
   - **变换手柄的数学**：画画软件里浮层的手柄（拖角、拖边、三种模式）是纯数学，可以共用；但它和「怎么抬起、怎么放下像素」写在同一个文件里，后者三维这边不能用。要把纯数学单独抽出来。
3. **顺序：共用显卡画面的探路提到最前面。**
   - 它是你定的硬要求，也是最大的未知数。它只需要内核的原样拷贝就能试，不依赖别的工单。先知道它通不通，再投后面的。

## 三、五段路线和每一段的工单

大小是粗分的：小 = 一处改动、有现成的测试罩着；中 = 一个新模块或十来处改动；大 = 要动很多地方或者有没验证的数学。

### 第 0 段：整理内核（在画画仓做，画画软件的行为一个像素都不变）

| 号 | 做什么 | 为什么 | 大小 |
|---|---|---|---|
| 0-1 | 拷贝机制：拉取脚本、文件哈希清单、两边的守卫；内核自己的测试在三维这边也跑 | 同一份内核的地基 | 中 |
| 0-2 | 撤销的出口做成接口：内核封好一步的记录，交给宿主的撤销栈；顺序由内核自己把关。画画软件自己那条路不动。施工单 = `20261110-paint-workorders-4.md` | 画画和建模一条撤销线 | 小 |
| 0-3 | 预算的出口做成接口：小块池和显卡缓存的额度由宿主给，占了多少报给宿主，宿主可以叫它让出来 | 你 10-30 说的「不要各管各的」 | 小 |
| 0-4 | 显卡接口：能建在别人已有的显卡画面上；能把合成好的图交出去、把别人的图收进来 | 共用显卡画面 | 小 |
| 0-5 | 多认一种薄层：宿主已经画好的 | 空间里的笔、贴花、放下浮着的那块，都靠它交货 | 小 |
| 0-6 | 走步按空间走：平滑完的点先交给宿主落到表面上，再沿着落好的路按间距走；走步的代码不管几维。做法是把「一笔的手感」从二维图层里拆出来，画画软件的结果逐位不变。施工单 = `20261110-paint-workorders-5.md` | 间距在空间里量 | 中 |
| 0-7 | 写入的遮挡合在一处：选区、蒙版、画布的形状三样相乘；每个动作标上「只看一个像素」还是「看邻居」的表 | 选区是重灾区；贴图上的空地不能被填脏 | 中 |

### 第 3 段：铺得好

UV 实验室；硬边当线稿分块；带子拉直（可选项）；最小拉伸；密度；整理（只平移）；重采样（明着做）；自己做缩小图。毕业条件：从零建的整个角色，不知道 UV 是什么也有能看的贴图；加一只手臂，旧的画一个像素不变。

### 第 4 段：接住现成的

贴图独立成条；导入图片；导入带贴图的模型不丢贴图和坐标；材质窗口；导出时两层压成一张。毕业条件：小红帽带着贴图打开，补两笔，导出，Blender 里看是一样的。

### 第 5 段：往后

每件一小版：涂抹和模糊（切平面跟着每个笔尖走）、形状笔、锁透明和混合模式的界面、调色、笔架、贴一张图上去、扒取窗口、扫漆和渍洗、VR 里画。

## 六、守卫清单（机器查的，红了就停）

| 守的是什么 | 怎么查 |
|---|---|
| 画画软件没被改坏 | 它现成的两百来份测试，加逐像素的基线 |
| 两边的内核是同一份 | 三维这边每个内核文件的哈希对清单 |
| 内核里没有三维，空间层里没有工具名 | 扫源码里的词 |
| 贴图上只调「只看一个像素」的动作 | 动作分类表；没登记的调不到 |
| 点到哪格就是哪格 | 每格一个颜色，屏幕读色对格子；含一张拉伸的、四点不共面的四边形 |
| 和贴图怎么铺无关（过缝、粗细均匀） | 同一个模型两份铺法，一份规整一份故意很难看，同样的操作结果一样 |
| 改了模型画还在 | 每个建模操作一条：继承来的面上任取一点，对应的空间位置没变 |
| 套索不糊 | 抬起放下一百次，像素不变；浮着拖一百次再放下，和拖一次到同一位置一样 |
| 撤销不坏 | 现有的随机撤销测试，加进画画的步骤 |
| 老文件能开 | 冻结样本 |

## 七、最大的五个风险

1. **共用显卡画面走不通。** 最先试。备选两条：改我们自己那份三维渲染库的拷贝；贴图这一路绕开它直接用显卡接口。
2. **把画画软件改坏。** 它是你天天出活的工具。第 0 段每张都极小、行为不变、有基线罩着；内核要动的地方已经从九处压到七处，而且其中没有一处是改它现有的画法。
3. **四十几处建模操作带贴图坐标，改出建模的回归。** 你同时在用它建角色。每个操作有现成的不变量测试，加一条来历的性质测试；这张工单拆成几版推。
4. **iPad 上跟不跟手。** 结构上的对策第一天就做，但显卡那一半我量不了，只能做读数给你看。
5. **放下浮着的那块时的精确度。** 「原地放下一个字节不变」和「只取一次样」是没验证的设计，先用纯 CPU 的实现当标准答案。

## 八、这一轮明确不做的

写在这里是为了不让范围悄悄变大：

- 球以外的笔尖形状、扫漆、渍洗、刷毛（接口留口，不实现）。
- 涂抹、模糊、液化。
- 选区的羽化、扩大缩小、魔棒、线稿填色。
- VR 里画。
- 改小块的边长。
- 抬笔读回改成不等它完成（除非量出来必须）。
- 画画软件换用三维的撤销栈。
- 套索顺着表面滑；只画和落笔处连着的那一片以外的更聪明的判断。
