# 属性规程：几何引擎怎么带着属性走（两个引擎共用）

> created 2026-11-13 by Claude Fable 5.2 · as-of 三维 v0.19.80（开发版）
> 状态：**第一版定稿（2026-11-13 夜）**。第一到第六节是统筹定的抽象；第七节的操作清单小弟已经对着两个引擎的代码核过（细节、出处、行号在第七½节），统筹据此改过第七、八节。还开着两件：第十节里要 user 定的。
> 读者：user、统筹、施工。写给以后往模型上加任何「跟着几何走的数据」的人。

## 〇、为什么有这一页

user 2026-11-13 夜（定贴图坐标的存法时），按先后：

- 「why the geometry engine is sensitivity to attribute. they should be agnostic to it. they should only know if they are face, vertices, or corners. but have no idea what they mean.」
- 「属性的容器是什么，然后角，面，边，点，然后我再加一个，面边，能不能两个几何引擎先写好抽象的处理规程？最好每种操作有文字方案。然后这样的话以后加东西可以直接用，几何引擎应该永远不知道贴图是什么意思」
- 「先做这个，数据结构是地基」「我建议是这些抽象先做」
- 「这样的话贴图只是一个角上面的id和一个角上面的vec2」
- 「然后操作也是以后越来越多的操作应该分解成原子」「分解成基本操作，除非有优化的需求」

三条原则（前两条 user 定，第三条的限定是统筹补的）：

1. **几何引擎永远不知道一份属性是什么意思。** 它只知道这份数据挂在哪一类东西上、是什么类型的数、怎么继承。「贴图」「材质」「柔边」这些词不出现在引擎里。
2. **操作分解成基本操作（原子）。** 规矩只给原子定；大操作是原子的序列，自己不碰属性。只有为了性能才允许把几步原子合成一步写，合成的那一步结果必须和拆开做逐位一样。
3. **引擎只报告事实，不替上层下结论。** 值对不上、取不到的时候，引擎照规矩取一个值，并把这件事报出来；算不算坏了、要不要清掉、要不要告诉人，归用这份属性的那一层。

## 一、现在是什么样（2026-11-13 核的代码）

| | 硬表面的引擎（`src/kernel/`） | 自由建模的引擎（`src/mesh/`） |
|---|---|---|
| 容器的名字 | 属性层（`layers.ts`） | 没有统一的容器 |
| 面上 | 面层：名字 → 每面一个整数（`material`、`materialBack`、`hidden`） | `faceMat`、`faceFlags` 两条写死的数组 |
| 边上 | 边层：名字 → 有标记的边的集合（`soft`、`curve`、`smooth`、`hidden`、`fold`） | `edgeFlags` 写死的数组 |
| 角上 | 没有 | 通用的列（`corner-columns.ts`），现在只有贴图坐标 |
| 点上 / 面边上 | 只有位置 / 没有 | 只有位置 / 没有 |
| 谁管 | `layers.ts` 一个模块，全部规矩集中 | `MeshKernel` 这个类自己拿着数组；角上的列另有一个模块 |
| 新东西的值怎么来 | 按事件血缘：切开 = 子面继承；合并 = 取第一个有值的；炸掉 / 擦掉 = 清 | 按来历：一块 / 一份 / 新长的 / 并成的 / 凭空的 |

和原则的差距：

- 两个引擎两套词（层 / 列，事件血缘 / 来历），规矩也不完全一样。
- 自由建模只有角是通用的，面和边是写死的。
- 自由建模角上的列带着两条只对贴图坐标成立的规矩（半有半无整面清空；并面时共用的点值不同就整面清空）。统筹 11-10 定的，这次拿掉。
- 硬表面的推拉里有一张表：柔边 / 曲线边 / 平滑边的侧棱 = 柔边 + 平滑。这是引擎在认「柔边」的意思。记在这里，这次不改。
- 小弟核出来的（都记在这里，这一轮不改；出处见第七½节）：
  - 自由建模：材质槽号、面的开关位、边的标记这三样是写死的数组，操作直接写它们，不走来历。角上的列没有绕过来历的。
  - 自由建模：把面切成两张时，新的那一半没抄面的开关位（藏着的面被切开，新的一半会露出来）。现存的小毛病，搬到属性表上之后自然没有。
  - 自由建模：焊点时几个角挤成一个 = 悄悄挑一个；焊出重复的面 = 悄悄留一张。都不报告。
  - 自由建模：倒角把倒角带里的边直接标成「平滑」，转网格体时把柔边换成平滑——操作在写有意思的值。
  - 硬表面：帽边不继承折线层；正反两面的材质在面翻到反面时互换；折线有一条「恰好两张面而且不共面」的检查。都是引擎在认意思。
  - 硬表面的曲线（一串有先后的边 + 种类 + 参数）不是「每个东西一个值」，这一页装不下，另算。

## 二、容器：属性表

- 一个几何体对**每一类东西**有一张属性表。表里是若干**列**。一列 = 一份声明 + 一条和这类东西一一对齐的数组（第 i 个东西的值在第 i 格）。
- 引擎负责：东西增加、删除、重新编号时，所有列的数组跟着动；东西被造出来时，照第五节的规矩填值。
- 引擎不负责：这一列是什么意思、它的值合不合理。

**一列的声明**（引擎只知道这些）：

| 项 | 取值 | 说明 |
|---|---|---|
| 号 | 一个字符串 | 引擎只拿它当名字用，不解读 |
| 挂在哪 | 点 / 边 / 面 / 角 / 面边 | 见第三节 |
| 类型 | 几个小数（每个东西 n 个 32 位小数）或一个整数（32 位） | |
| 连续还是离散 | 连续 = 可以按权重混；离散 = 只能照抄 | 小数可以是连续的也可以是离散的；整数一定是离散的。这是数学性质，不是意思 |
| 缺省值 | 一个值 | 没有来源的东西填它 |
| 格子多细（可选） | 一个整数 q | 只对连续的小数：值永远是 1/q 的整数倍，混出来之后取整到这一格 |
| 新长的跟不跟旁边 | 跟 / 不跟 | 见第五节「新长」 |
| 并成时怎么取 | 取排在最前的 / 取第一个不是缺省值的 / 不一致就回缺省值 | 三选一，见第五节「并成」 |

- **开关一位一列。** 「几个开关挤在一个字节里」不是一列：并成的时候每一位的取法不一样（现在的边标记：手标的棱、平滑、不画线是「两边都有才留」，接缝、隐藏是「有一边有就留」）。一位一列之后，「都有才留」= 不一致就回缺省值，「有一个就留」= 取第一个不是缺省值的，三选一正好装下。存的时候挤在一起是存法，可以，规程看不见。
- 声明在代码里的形状见第七½节 E（`ColumnDef`）。

## 三、五类东西

| 类 | 是什么 | 一张 n 边形面上有几个 |
|---|---|---|
| 点 | 一个顶点 | — |
| 边 | 两个点之间的一条棱；被几张面共用也只算一条 | — |
| 面 | 一张面 | 1 |
| 角 | 某张面的某个顶点（面 × 点） | n |
| 面边 | 某张面的某一条边（面 × 边）；同一条边被两张面用 = 两个面边 | n |

角和面边数量相同、可以用同一种编号（面的环上第 i 个位置：角 i 是第 i 个顶点，面边 i 是从角 i 到角 i+1 的那一段），但规矩不同，所以是两类：

- 在面的一条边中间加一个点：新角的值由两头的角混出来；两段新面边都照抄原来那一段。
- 一刀把面切开：切口在两张新面上各有一个面边，都是新长的。

## 四、来历

引擎里每一个被造出来、或者形状被改过的东西，都带着一句「我是怎么来的」。**操作只申报来历，不提属性。** 来历只有七种：

| 来历 | 意思 | 例子 |
|---|---|---|
| 原样 | 没变 | 挪点时所有的面、边 |
| 一块（原来的 X） | 是 X 的一部分，X 是同一类 | 面被切成两张；边被一个新点分成两段 |
| 一份（原来的 X） | X 的拷贝 | 复制；镜像出来的另一半 |
| 之间（X₁ 占 w₁、X₂ 占 w₂…） | 夹在几个同类的东西之间 | 边上新加的点；面里新加的点 |
| 并成（X₁、X₂…，有先后） | 由几个同类的东西合成 | 消掉一条边后两张面并成一张；焊点 |
| 新长（可以指一个「旁边」） | 没有来源 | 挤出的侧面（旁边 = 被挤的那张面）；切口那条新边 |
| 给定（值由调用方交） | 值不从几何来 | 读文件；从别的物件搬进来；上层直接写 |

硬表面引擎现有的事件对应过来：切开的子面 = 一块；合并 / 吸收 = 并成；一对一承继 / 拉伸 = 原样；出生 = 新长；炸掉 / 擦掉 = 删除。

- **来历可以由操作申报，也可以由引擎自己从几何里认出来。** 自由建模是前一种；硬表面的结算机是后一种（新画的一段正好落在一条已有的边上 = 认作那条边的一块，所以带着它的标记）。规矩表两边一样。
- **「之间」可以借「一块」来表达。** 自由建模的引擎现在没有单独的「之间」：面是原面的一块，新角写一个位置，在原面里按位置取值。落在原面一条边上的点，取出来的值和「两头的角按比例混」相等（差在浮点的最后一位）。这一页不要求改名，只要求结果是这个。

**角和面边的来历由面的来历推出来**，操作不用另外申报：

| 面的来历 | 它的角 | 它的面边 |
|---|---|---|
| X 的一块 | 正好是 X 的某个角 → 那个角的一份；不是 → X 的几个角之间（按位置的权重） | 落在 X 的某个面边上（整段或一截）→ 那个面边的一块；落在新切口上 → 新长 |
| X 的一份 | 对应的角的一份 | 对应的面边的一份 |
| 并成 | 来源面里在这个点上的那些角并成（先后照面的先后） | 外圈的 → 原来那个面边的一份；被消掉的内部边上的 → 没有了 |
| 新长 | 新长 | 新长 |

## 五、规矩表

对任何一类东西、任何一列，都是这一张表：

| 来历 | 连续的列 | 离散的列 |
|---|---|---|
| 原样 | 不动 | 不动 |
| 一块 | 照抄 X 的值 | 照抄 X 的值 |
| 一份 | 照抄 | 照抄 |
| 之间 | 按权重混；有格子就取整到格子 | 取权重最大的那个来源的值；一样大取排在最前的 |
| 并成 | 照这一列声明的取法取一个；来源的值不全一样 → 报告 | 同左 |
| 新长 | 这一列声明「跟旁边」而且操作指了旁边 → 照抄旁边的值；否则缺省值 | 同左 |
| 给定 | 调用方交的值；没交的列填缺省值 | 同左 |
| 删除 | 值跟着没了 | 同左 |

再加四条：

- **取不到来源的值**（比如「之间」要在一张退化的面里算权重，算不出来）→ 填缺省值，报告。
- **变换**（挪、转、缩放、镜像）不改任何列。以后要是有「方向」这种跟着转的数，是加一种类型，不是给某一列开特例。
- **翻面**（环倒过来）：角和面边按新旧位置的对应关系照抄，值不变。
- **引擎不根据值清空任何东西，也不拒绝任何操作。**

## 六、引擎交出来的报告、跨物件、读写、撤销

- **报告**：每一步之后，引擎交出一张单子——哪些东西的哪几列，值不是干干净净照来历得来的（并成时来源不一致；取不到）。并成不一致的，带上每个来源的值。上层拿它决定要不要清、要不要告诉人。没人取走的报告在下一步开始前丢掉。
- **跨物件搬**（并物件、分出去、炸开、粘贴）：列按号对上。目标没有这一列 → 目标加这一列，原有的东西填缺省值；来源没有 → 搬过来的东西填缺省值。有些离散的列存的是「这个物件自己的一张表里的代号」（材质槽号、画布代号）：引擎不知道，由调用方给这一列交一个换号的函数，引擎照着换。
- **读写文件**：一列写成声明 + 数组。不认识的列原样带回是文件格式那一层的事，不归这一页。
- **撤销**：属性表整张跟着几何的快照走。

## 七、原子，和每个操作的文字方案（已对代码核过，细节见第七½节）

> 2026-11-13 Catsup小弟（Claude Opus 5.5）对着代码核过：对不上的地方和补的事实写在第七½节，这一节原文没改。

### 7.1 原子

| 原子 | 造出 / 改了什么 | 各自的来历 |
|---|---|---|
| 加点 | 一个点 | 新长，或给定 |
| 挪点 | — | 全部原样 |
| 分边（在边 E 上加一个点） | 一个点；E 变成两段；用到 E 的每张面多一个角、一个面边 | 点 = E 两头之间；两段 = E 的一块；那些面 = 原样（环变长）：新角 = 两头的角之间，两段面边 = 原面边的一块 |
| 分面（在面 F 的两个角之间连一条边） | 一条边；F 变成两张 | 边 = 新长（旁边 = F 的任意一条边由操作指，或不指）；两张面 = F 的一块 |
| 并面（消掉两张面之间的边 E） | 一张面；E 没了 | 面 = 并成（两张面，先后由操作指）；E 删除 |
| 并边（消掉只连着两条边的点 V） | 一条边；V 没了；用到它的面少一个角、一个面边 | 边 = 并成；面 = 原样（环变短）：合起来的面边 = 并成 |
| 建面（给一圈点） | 一张面，缺的边 | 面 = 新长（可指旁边），或给定；新边 = 新长 |
| 删面 / 删边 / 删点 | — | 删除 |
| 焊点（几个点合成一个） | 一个点；退化的边和面被删 | 点 = 并成，或「之间」（焊到中点时）；受影响的面 = 原样（环变了） |
| 拷贝（一批面连同它们的点和边） | 新的点、边、面 | 都是对应那个的一份 |
| 翻面 | — | 面 = 原样；角、面边按位置对应照抄 |
| 搬进来（从别的物件） | 新的点、边、面 | 给定（带换号） |
| 写值（上层改某一列在某些东西上的值） | 不造东西 | 不走来历；引擎照写，不问为什么（油漆桶、标棱、开始画写坐标） |

**现状和这张表差在哪（小弟核的）**：自由建模的引擎对外只有更低一层的口——加点、挪点、建面（带来历）、改一张面的环（带来历）、删、补边、写值。上面表里的分边、分面、并面、并边、焊点现在是各个操作自己拿这几个口拼出来的，没有收成共用的函数。照 user 的话（操作分解成基本操作），方向是把这张表里的每个原子收成**一个**共用的函数，操作只调它们；这一轮不做，以后动到哪个操作就收哪个。

硬表面的引擎不让操作直接调这些原子：操作交出一批多边形，由结算的那台机器决定哪里分边、分面、并面，再发出事件。对它来说原子就是那些事件；这张表对它同样成立。

### 7.2 自由建模的操作

| 操作 | 拆成原子 | 值得说的 |
|---|---|---|
| 新建基本体、手建一张面 | 加点 + 建面 | 全是新长 |
| 挤出 | 拷贝（顶上那圈点）+ 建面（每条边界边一张侧面，旁边 = 被挤的面）+ 挪点 | 被挤的面 = 原样；侧面新长 |
| 插入 | 加一圈点 + 原面分成里面一张和外面一圈 | 里面那张和外面那一圈都是原面的一块（外圈本来就在原面里；统筹初稿写成「新长」是错的，代码是对的） |
| 倒角 | 分边 + 分面 + 建面（倒角带，旁边 = 相邻的面）+ 挪点 | 被削的面 = 一块；倒角带新长。现在它还直接把倒角带里的边标成平滑（见第一节的差距） |
| 切刀 | 分边（刀口只落在点和边上，不落在面里）+ 分面 | 新点 = 之间；面 = 一块；刀口的边新长 |
| 环切 | 一圈分边 + 一圈分面 | 同切刀 |
| 细分 | 每条边分边 + 每张面加中心点 + 分面 | 中心点 = 面的各个角之间 |
| 并面（消边） | 并面 | 来源不一致就报告 |
| 消点 | 并边，或并面 | |
| 合并点 | 焊点 | 焊到第一个 = 并成；焊到中点 = 之间 |
| 删除 | 删面 / 删边 / 删点 | |
| 补洞、搭桥 | 建面 | 现在是新长、不指旁边（材质是缺省的）。规程允许指旁边，要不要跟邻面是以后的事 |
| 复制 | 拷贝 | |
| 翻转朝向 | 翻面 | |
| 压平、挪、转、缩放 | 挪点 | 全部原样 |
| 清理（去重点） | 焊点 | |
| 镜像编辑 | 对面那一半做同样的原子 | |
| 强行对称 | 沿面切开（分边 + 分面）+ 删另一半 + 拷贝 + 翻面 + 焊中缝的点 | 新的一半 = 这一半的一份 |
| 并物件、炸开、分出去 | 搬进来 / 拷贝 + 删 | 带换号 |
| 挤出边、挤出点 | 拷贝（点）+ 建面 / 补边 | 新面、新边新长 |
| 粘贴 | 搬进来 | 现在故意不带角上的数 |
| 转成网格体、导入 | 给定 | 转的时候柔边换成平滑是在这里换的意思（见差距） |
| 自动标接缝 | 写值 | |

### 7.3 硬表面的操作

| 操作 | 结算机发出的事件 | 值得说的 |
|---|---|---|
| 画线、矩形、圆、弧 | 分边；围出新的一圈 → 新面；穿过一张面 → 分面 | 新面 = 新长；被分的面 = 一块 |
| 推拉 | 被推的面 = 原样（换了平面）；侧面 = 新长（旁边 = 被推的面）；帽边 = 原边的一份；侧棱 = 新长（旁边 = 底下那个角对着的边） | 现在「柔边的侧棱变柔边 + 平滑」那张表要搬到上层 |
| 擦边 | 两边的面共面 → 并面；不共面 → 两张面删除（或变折线） | |
| 删面 | 删除 | |
| 移动、旋转、缩放 | 挪点；之后结算可能焊点、并面、分面 | 结算出来的事件各按各的来历 |
| 偏移 | 新的一圈边 + 分面 | 里面那张 = 原面的一块 |
| 复制、镜像 | 拷贝（镜像再翻面） | |

## 八、贴图坐标照这一页怎么放

> 「交给显卡」那一行的现状事实见第七½节 D（小弟核过）。

引擎里只是两列，意思全在画画那一层：

- 一列离散的整数：这张面在这个物件的画布速查表里的代号，−1 = 不在任何画布上。「不跟旁边」，「不一致就回缺省值」。
- 一列连续的、每个东西两个小数、格子 1/1024、挂在角上：坐标。

第一列挂在面上还是角上，两种都合这一页：

| | 代号挂在面上（统筹的默认） | 代号挂在角上（user 那句话的字面） |
|---|---|---|
| 一张面在哪张画布上 | 只有一个答案，结构上不可能自相矛盾 | 各角可能不一样，要画画层检查 |
| 每个东西多占 | 每面 4 字节 | 每角 4 字节 |
| 引擎要支持 | 面这一类的列 | 只要角这一类（现成的） |
| 交给显卡 | 要先按面分批 | 每个顶点自己带着编号，可以直接当顶点格式 |
| 并面时两张面不同画布 | 引擎报告「这一列来源不一致」，画画层清掉 | 不用报告：并出来的面各角编号不同，画画层一眼看出来 |

**统筹定：挂在面上**（user 改口以 user 为准）。小弟核的事实（第七½节 D）去掉了角上那一栏唯一的好处：面交给显卡时本来就是不带索引的三角形，每个三角形顶点各填一份；每张画单独一组、一次绘制，同一组里用不着代号；以后几张画合进一次绘制时，代号挂在面上也只是上传时抄给三个顶点。而挂在角上每张四边面多占 12 字节，还多一种自相矛盾的可能。

代号这一列声明成「不一致就回缺省值」之后，并两张不同画布的面，引擎照通用的规矩自己就给出 −1，画画层读报告只是为了数丢了几张；只有「代号一样、但公共的点上坐标接不上」这一种，要画画层在收尾里把代号改成 −1。

画画层据此做的事：有没有位置只看代号；读引擎的报告，并出来的面代号或坐标对不上 → 判成没有位置、数出来、告诉人；面在物件之间搬时给代号那一列交换号的函数。

## 七½、对着代码核过（2026-11-13 Catsup小弟 = Claude Opus 5.5；三维 v0.19.80 的代码）

### A. 7.1 原子：现在真正的改动入口

自由建模的引擎（`MeshKernel`）对外改东西的口只有这些：加点 `addVertex`、挪点 `setPos`、建面 `addFace(环, 材质槽, 来历)`、改环 `setFaceRing(面, 环, 来历)`、删 `removeFace / removeFaces / removeEdge / removeVertex / removeVertices`、补边 `ensureEdge`、写边标记 `setFlags / setEdgeFlags`、写面上的东西 `setFaceMat / setFaceFlags`、写角上的数（以前 `setFaceValues`）、默认平滑 `setSmoothDefault`。分边、分面、并面这些「原子」**不在内核上**，是 `src/mesh/ops/` 里的函数拿上面那几个口拼的。

| 7.1 的原子 | 现在在哪 | 和 7.1 对不上的地方 |
|---|---|---|
| 加点 / 挪点 | `addVertex` / `setPos` | — |
| 分边 | `ops/split.ts splitEdge` | 用到这条边的面申报的是「一块」（整张面，`piece`），新角在旧面的三角形上**按新点的位置插值**——7.1 写的是「原样（环变长）、新角 = 两头的角之间按 t 混」。数学上同一个数，浮点不保证逐位相同。两段边的标记由算子手抄。 |
| 分面 | `ops/split.ts splitFace` | 两半都是「一块」✓；第二半的材质槽算子手抄；**第二半的面开关位（隐藏）没有抄**（`addFace` 给 0）——一张藏着的面被劈开，新的那一半会露出来。新边标记 0（= 新长）✓ |
| 并面 | `ops/join.ts joinFaces` | 角上的列走「并成」✓；面上的材质槽、开关位 = 留下的那张原来的（等于「取排在最前的」，不报告） |
| 并边（消点） | `ops/join.ts dissolveVertex` | 用到这个点的面 = 「一份」去掉那个角（`copy`）✓；合起来那条边的标记**逐位**合（`mesh/edge-mark-rules.ts` 的 JOIN 表：手标的棱 / 平滑 / 不画线要两条都有才留，接缝 / 隐藏有一条就留）。规程第二节「并成时三选一」装不下逐位与 / 或——要对上，边标记得拆成每一位一列（「都有才留」=「不一致就回缺省值」，「有一条就留」=「取第一个不是缺省值的」） |
| 建面 | `addFace(…, FRESH / GROWN)` | 材质槽由调用方传，引擎不知道「跟旁边」；角上的列 `grown` 永远填缺省值，不跟旁边 |
| 删 | `ops/delete.ts` + 内核的 remove* | ✓ |
| 焊点 | `ops/merge.ts mergeVerts` | **不是「并成」**：几个角挤成一个时挑一个照抄（落点上原来那个角；没有就挑原环里最靠前的），不报告。另外并完会剪零面积的刺（`cutSpurs`），并出一模一样的两张面时删一张（`dedupeFacesAround`，留下那张的值悄悄赢） |
| 拷贝 | `ops/duplicate.ts`、`mirror.ts` 强行对称 | ✓（`copy`；材质槽算子手抄） |
| 翻面 | `ops/geometry.ts flipFaces` | ✓（`copy`，对应表倒过来） |
| 搬进来 | `editor/ops.ts appendMesh`（并物件、炸开）、`separateObject`（分出去）、读文件 `mesh-doc.ts`、内核快照 | 给定 ✓；材质槽换号 = `appendMesh` 里的 `slot()`（规程第六节说的「换号的函数」现在就长这样） |
| **（缺）改值** | 油漆桶 / 换材质 `setFaceMat`、标棱 / 接缝 / 隐藏 `setEdgeFlags`、开始画写贴图坐标 | 7.1 没有「上层直接改一个已有东西的某一列」这个原子。它和「给定」不同：东西没新造，只换值。建议加一行：改值（给定的值，引擎照写，不报告） |
| **（缺）之间** | 没有单独的来历 | 现在靠「一块」里的取样处表达：`piece.from[i]` 写一个位置 = 那个位置在旧面三角形上的重心坐标当权重；不写 = 按这个角的点现在的位置。细分的边点、面点、插入的外圈都是这么来的。离散列「取权重最大的」现在没有实现（离散的面上的列只照抄原面） |

### C. 7.3 硬表面：结算机的事件和 `layers.ts` 的规矩

- 结算机发出的面事件七种（`kernel/face-lifecycle.ts`）：出生 BIRTH、分开 DIVIDE、合并 MERGE、吸收 ABSORB（一张并进另一张、留在被并进去的那张身上）、炸掉 BURST、拉伸 STRETCH（形状变了、身份不变 = 原样）、擦掉 FACE_ERASED。对应：出生 = 新长，分开 = 一块，合并 / 吸收 = 并成，拉伸 = 原样，炸掉 / 擦掉 = 删除。
- 面层的规矩（`layers.ts` 头注释）：分开 = 子面继承；合并 / 吸收 = 取第一个有值的（= 规程的「取第一个不是缺省值的」）；炸掉 / 擦掉 = 清。一对一承继保留身份。和第五节的表一致，只是取法写死成一种。
- 边层四条：① 切开 = 父传子（= 一块）② 删边出集 ③ **新段落在已有的有标记的边上 = 入集**（第五节没有这种来历：几何上重合就继承，结算机重画边时用）④ 溶解时两边都有才有（= 「不一致就回缺省值」）。
- 引擎懂意思的地方（第一节记了推拉那张表，还有三处）：
  1. 推拉 / 跟随的帽边继承全部层，**但折线层除外**（`CAP_EXCLUDE`）；侧棱按表：柔边 / 曲线边 / 平滑边的侧棱 = 柔边 + 平滑。
  2. **正反两面**：面换到法向相反的平面上（结算机按身份像的绕向判），引擎把「正面材质」「背面材质」两层互换（`swapSides`）——引擎认得这两层的名字。
  3. **折线**：引擎每步都查「恰好两张面、两张不共面」，不满足就退回普通边——引擎懂折线的意思。
  4. **曲线**：一条曲线 = 一串有序的边；结算尾声按「同平面的外来边 → 断开，出平面不断」重新串（`curves.ts rechain`）——曲线是挂在边上的一个实体，不是一列值，规程现在装不下。

### D. 第八节的事实：交给显卡时

- 面交给显卡是**不带索引的三角形汤**：每块 5461 个三角形、每个三角形三个顶点各一份属性（`editor/pool-mesh.ts RegionStore`）。贴图坐标 = 这个顶点对应的那个角上的数 ÷ 画板宽高，逐个顶点填（`rec.corner[i]` 把三角形的顶点对回面的角）。所以**角上的数本来就是每个三角形顶点一份**。
- 每张画是单独一组（键 `paint:<贴图>`）：自己的顶点数组、自己一张图、一次绘制调用。所以现在不需要每个顶点带代号——同一组里的面都在同一张画上。
- 代号挂在角上 → 可以直接成为一个顶点属性；挂在面上 → 上传时把面的代号抄给它三个顶点，一行的事。**对显卡两种一样省事**。真用得上「顶点自己带代号」的是以后把几张画放进一次绘制（图组 / 合批），那时两种存法都能现填。
- 内存：面上每面 4 字节；角上每角 4 字节（四边形 = 每面 16 字节）。

### E. 第 1½ 刀的接口照这一页收的结果（给统筹审；和小弟上一份草案冲突的地方标【变】）

```ts
type Domain = "vertex" | "edge" | "face" | "corner" | "faceEdge";   // 这一刀只实现 corner、face，别的声明了就抛「还没做」
interface ColumnDef {
  id: string;                       // 引擎只当名字
  on: Domain;                       // 【变】挂在哪（上一份分成 CornerColumnDef / FaceColumnDef 两个类型）
  type: { floats: number } | "int"; // 这一刀：corner 上只做 floats、face 上只做 int，别的组合抛「还没做」
  continuous: boolean;              // 【变】新加：连续 = 「之间」按权重混；离散 = 取权重最大的来源（int 一定离散）
  fill: number;                     // 缺省值（floats 每个分量同一个数）
  quantum?: number;                 // 格子多细（只对连续的 floats）
  followNeighbor?: boolean;         // 【变】新加：新长的跟不跟旁边
  merge: "first" | "firstNonDefault" | "defaultIfMixed";   // 【变】新加：并成时怎么取（上一份写死「取最前的」）
  kind?: string; extra?: unknown;   // 不透明
}
// 来历（面的来历；角由面推出，第四节）——现有五种对应规程七种：
//   原样 = 不申报（面没被动）；一块 = piece（「之间」= piece.from 里写位置，见 A）；一份 = copy；并成 = joined；
//   新长 = grown，【变】可带 neighbor（面编号，followNeighbor 的列照抄它）；给定 = fresh（值由调用方交，没交的列填缺省值）。
//   离散列遇到「之间」：取重心坐标权重最大的那个旧角的值（一样大取编号小的）。
interface FaceReport {   // 第六节
  odd: Map<number /* 面 */, {
    face: Map<string, number[]>;     // 面上的列：并成时各来源的值（来源的先后 = 来历里的先后）
    corner: Map<string, "mixed" | "missing">;   // 【变】角上的列：并成不一致 / 取不到。上一份只给 id；不带各来源每个角的值（并面的公共点可能很多，上层只拿它判「对不对得上」）
  }>;
}
```
- **【变】报告的寿命**：第六节「没人取走的在下一步开始前丢掉」——编辑器每一步开头（收尾的快照那一刻）调一次 `takeReport()` 丢掉。一步之内「对不上」的标记照旧跟着来历传给新面（并完又被切开的那几块也算），不然收尾会漏掉同一步里并了又切的面。
- **【变】贴图坐标两列的声明**：代号 `{ on: face, type: int, fill: −1, merge: "defaultIfMixed" }`——来源代号不一致时**引擎自己就给 −1**，画画层读报告只为了数「丢了几张」；坐标 `{ on: corner, floats: 2, continuous, quantum: 1024, fill: 0, merge: "first" }`。代号一致但公共点上坐标对不上（同一张画布上接不起来的两张面）：坐标照「取最前的」，报告里 corner 是 mixed，画画层在收尾把代号改成 −1（这一种还要上层改值）。
- 内核里不再有 `takeDroppedFaces`；自检 M7 / M7½ / M8 照上一份草案（quantum 当类型）。
