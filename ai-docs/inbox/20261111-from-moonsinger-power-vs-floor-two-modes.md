## 背景：MoonSinger 今天定的参照系

MoonSinger 在做简谱前讨论「尊老爱幼」，user 定：不做儿童产品，用两根轴当 UX 设计的参照（「k12只是设计理念，用来逼出一个好设计的」）。两根轴的展开 user 回「嗯合理」：

- **认知轴**（跟年龄走）：能读多少字、一屏放得下几样、记得住几个看不见的状态（模式、锁着的修饰键）、手指点得多准、懂不懂「撤销 / 文件」这种抽象。
- **教育轴**（和年龄无关）：学过哪一套——哪种谱、哪个软件的肌肉记忆。
- 观察：教育轴主要管显示和习惯，认知轴主要管交互。user 那边另一句：看不见的状态和自作主张，「别说孩子了，我都会奇怪」。

## AI 的评论（Claude Opus 5.5，没拍）

1. **「SketchUp 模式 / Blender 模式」一个名字里捆着三件事**：
   - (a) 认知轴：新手接不接得住（SketchUp 直觉 = 工具少、推断吸附、直接拖；Blender = G / R / S 模态、看不见的状态多）；
   - (b) 教育轴：你手上练的是哪一套肌肉记忆；
   - (c) 模型数据：B-rep 和网格是两种（user 10-24 已定「blender和sketchup是不同的模型数据，可以互转，但是不建议blender直接动brep」；`ai-docs/20261024-editor-state-and-modes.md`）。
   三件捆成一个开关 = 邯郸学步的根：为了 Blender 用户在 SketchUp 那边留模态、为了新手在 Blender 那边砍快捷键，两边都学一半。user 10-29「不要把su行为覆盖了」已经是在守 (a) 和 (b) 不被混。
2. **拆开的样子（候选，不是方案）**：
   - (c) 归 type / Tab 进编辑模式（far-horizon §3.5 已经这么想）；
   - (b) 肌肉记忆 = 键位表的预设，和工具本身分开。Blender 自己就是这么做的：同一套工具，偏好设置里两套键位（Blender / Industry Compatible）；
   - (a) 新手的地板 = 每个快捷键都有一个看得见的入口（按钮 / 菜单项上写着键名），快捷键只是加速，不是唯一的门。CatsUp 已有的状态行键名芯片、从数据生成的快捷键表，就是这一路。
3. **MoonSinger 的教训**：小键盘一开始就是 MEDO 那样的大键琴，一层层加旋钮之后门槛悄悄抬高了（user 原话）。每加一个旋钮 / 快捷键，问一句它把地板抬了多少——和家规「不拿改动小当理由，先想它会长成什么」同一路。
4. **最贵的是看不见的状态**：模态、锁着的修饰键、没有画在屏幕上的「现在是哪种模式」。不管哪种模式，这一项在认知轴上谁都吃不消。
