## 一、一页结论

1. **画画那边的核心已经是一台能单独搬走的发动机。** 我读了它的代码：约 1.7 万行的后端只依赖自己和四个第三方小库，几乎不碰界面；套索、变换、形状笔、涂抹、液化这些工具的引擎（约四千行）也都不碰界面，只是文件还放在界面那一层。所以「抄」不用重写，要做的是划清边界、原样搬。
2. **加功能的成本想不涨，靠一条规矩：工具不知道三维，三维不知道工具。** 所有工具只认识一块平面（下面叫「笔画台」）；屏幕和贴图之间怎么对应，由三维这边算成「坐标表」交给内核，内核只管照表取样。
3. **三维这边不是薄薄一层接头，这一轮真正的数学都在这里**（第四½节）：屏幕和贴图之间的变换与逆变换要配成一对；自动铺和自动打包；改了模型接着画。上面那条规矩的意思是这三块数学各做一次，不跟着工具成倍变多，不是说它们简单。
4. **两边用逐字节相同的一份内核，正本放在画画那边，三维机械地拷、不许手改。** 只抄一次、各自长的话，以后每搬一个功能都要先比对两边漂了多远，成本会越来越高，正好是你不要的那种。这一条改了 10-30 的说法，要你点头（第八节第 1 件）。
5. **草稿层和套索是第一批，和笔、橡皮一起。** user 11-10：画画软件是靠草稿笔和套索活下来的，能在模型上磨草稿、细调眉毛眼睛才算能画；液化没有套索有用。
6. **第一笔不用等铺贴图的算法。** 先用最笨的铺法（每张面自己一小块，10-30 已经认过这是自动铺的退化情况）和「从现在的视角铺」（小红帽的脸就是这么铺的），就能画。好的铺法后面换。
7. **路线**：整理内核 → 第一笔 → 能磨草稿（**毕业 = 把这个角色的脸在模型上画出来**）→ 铺得好 → 接住现成的带贴图模型 → 往后每件都是「拉过来加个按钮」。

## 二、两条路怎么走：角色就是这一轮的考卷

你问：先做贴图纪元，还是你老老实实做一个二次元角色、边用边暴露问题；没有创作实践会不会飘。

- **架构和数据结构对，只能保证不返工，保证不了好用。** 飘有三种：地基错了（最贵，靠设计防，今天这份）；做了你用不上的东西（靠拿真作品排顺序防）；一千个小别扭（只有你真做东西才冒得出来）。后两种设计防不了。
- **所以不是二选一。** 你做角色的前半段是白模，这段冒出来的多半是操作上的事，改接线就行，一版一版小修，和内核整理互不挡路。等白模差不多了，第一笔和磨草稿也该到了。
- **毕业条件绑在这个角色上（user 11-10 定）**：「把这个角色的脸在模型上画出来」。user：「这个东西 Blender、Procreate 都接不住。」之后每一段先做哪个，看角色下一步缺什么。
- 做二次元角色还缺哪些建模功能，我没有逐项查（细分、对称、倒角、环切、挤出这些都有）。缺的让角色来告诉我们，比我猜的准。

## 三、成本从哪来，怎么压住

加第 N 个功能会变贵，原因就四个。每个原因对一条对策：

| 变贵的原因 | 对策 |
|---|---|
| **两份代码各自长**：搬功能前要先看两边差了多少 | 两边同一份内核，机械拷贝，测试拦手改 |
| **每个工具都要自己处理三维的事**（投影、遮挡、接缝、一笔画到两个物件、镜像） | 这些全在三维这边算成坐标表（第四½节），每件做一次；工具里一个字都不出现 |
| **每个工具都要自己处理画画的老规矩**（选区、锁透明、混合模式、图层、撤销） | 画画那边已经做对了：所有笔走同一条落笔流程，这些规矩都在流程里，不在工具里。原样继承 |
| **每个工具要在两套界面里各写一遍面板** | 工具自带一张参数清单（滑杆、开关、下拉），两边各用自己的通用面板照着画。三维这边已经有一个参数面板的模块（能不能直接照清单画，我没细看） |

结果是一张加法表，不是乘法表：

| 要加的东西 | 内核 | 三维这边的数学 | 界面 |
|---|---|---|---|
| 一种新笔 / 新工具 | 写一次，两边都有 | 不动 | 各加一个按钮 |
| 画画那边已有的工具搬到三维 | 不动（已经在内核里） | 不动 | 三维加一个按钮 |
| 三维特有的本事（对称着画、整理贴图、补接缝） | 不动 | 写一次，所有工具都有 | 一个开关或右键项 |

**你关心的「要读多少代码」**：加一个工具，要读的是内核里一页契约、一个现成工具当样子、这个工具自己的文件。和已经有多少个工具没关系。这一条我会做成测试：工具的文件里出现三维的词、或者三维那边按工具名分情况，测试就红。

## 四、架构：一张图，四个词

```
        画画软件                               三维软件
 ┌─────────────────────┐            ┌──────────────────────────────┐
 │ 界面 · 手势 · 图库     │            │ 界面 · 手势 · 模型 · 渲染        │  各写各的
 ├─────────────────────┤            ├──────────────────────────────┤
 │ 画布就是笔画台         │            │ 屏幕是笔画台                    │  各做一次
 │ 坐标表 = 「原地」       │            │ 坐标表 = 屏幕 ⇄ 模型 ⇄ 贴图的数学  │  和工具无关
 ├─────────────────────┴────────────┴──────────────────────────────┤
 │                 画画内核（两边逐字节同一份）                         │
 │  笔 · 橡皮 · 套索 · 变换 · 涂抹 · 填色 · 滤镜 · 图层 · 选区          │
 │  小块存储 · 合成 · 撤销记录 · 显卡接口（另有纯 CPU 的一份，测试用）    │
 └──────────────────────────────────────────────────────────────────┘
```

四个词：

- **内核**：上图最下面那一层。不碰界面、不知道自己在哪个软件里。
- **笔画台**：手在上面动的那块平面。画画软件里它就是画布；三维里它是屏幕（像隔在你和模型之间的一块玻璃）。笔的手感、平滑、压感全在笔画台上算，所以三维里的笔和画画软件里是同一支。
- **一份画**：一个物件身上那份分层的画，就是画画软件里的一个文档，只是没有自己的窗口。图层、草稿层、混合模式、选区都是它自带的。
- **推和拉**（各是一张坐标表，细节在第四½节）：
  - **推（落点表）**：每个贴图像素去笔画台的哪里取颜色、看不看得见。画画软件里是「原地」；三维里是把贴图像素在模型上的那一点投到屏幕。这就是你 8 月说的「贴图整张反算屏幕坐标、拿屏幕的笔画缓冲、按深度筛」，也是你 2012 年论文 3.1.3「逆转思维」反过来用：遍历要填的那一边，反查来源，所以不漏像素。
  - **拉（回读表）**：笔画台上每一格底下是哪份画的哪个贴图像素。它是推的逆变换。涂抹、套索抬起、取色用它。注意拉回来的是「坐标」，不是一张已经采过样的平面图——第 1 版写成了后者，那样套索每抬一次放一次就糊一次。

为什么说有了推和拉就够了。画画那边的工具按「边画边看」的方式分四类，每一类在三维里都有着落：

| 画画那边的做法 | 哪些工具 | 三维里怎么来 |
|---|---|---|
| 笔画先攒在一张浮着的薄层上，抬笔烤进图层 | 画笔、橡皮、形状笔、填色 | 薄层在笔画台上，烤的时候照**落点表**取 |
| 把一块像素抬起来、变换、放下 | 套索、贴图片 | 源像素原样留着；放下时把「落点表 → 变换的逆 → 抬起那一刻的回读表」串起来，对源像素只取一次样 |
| 把图层的一块拷到显卡上直接改，抬笔写回 | 涂抹、模糊、水彩式的笔 | 照**回读表**把这一块取到笔画台上改，再照落点表写回 |
| 在一份替身上改，抬笔换回 | 液化、滤镜笔 | 同上 |
| 直接改图层的像素 | 像素笔；套索「沿贴图格挪」 | 笔尖点到模型上，算出是哪个贴图像素，直接改（10-30 拍过的像素笔） |

所以三维这边为画画要算的东西是固定的几张表：落点表、回读表、点到哪个像素，再加写完之后的收尾（补接缝、缩小图）。不会随工具变多。

另外几件事在这个架构里是白送的，列出来是想说明「越后面越便宜」不是口号：

- **对称着画**：镜像开着时两半共用同一块像素，画一边另一边就有（第四½节第三块）。想左右不一样再分开。
- **一笔画过两个物件**（脸和头发是两个物件）：同一块笔画台，分别推进两份画，撤销算一步。
- **贴上去的图转视角时怎么办**（10-30 留着没定）：图浮在笔画台上，你转模型，它在玻璃上不动，落点表跟着变。这是架构自然给出的答案，像 Blender 的模板。
- **换一种铺法、重铺**：也是一张表（新贴图像素 → 旧贴图像素），内核照表取一次样。和套索放下是同一段代码。
- **修改锁**：内核的写入口本来就有一道门，三维以后做修改锁时直接接上。

## 四½、三块数学（这一轮真正难的地方）

第 1 版把这里写轻了。下面每一块先说要保证什么，再说靠什么保证。标了「没验证」的是我的设计，要先在实验室里量。

### 第一块：屏幕和贴图之间，变换和逆变换配成一对

一条链，每一环都能正着算、反着算：

```
手指 ⇄ 屏幕（可能是像素化的、弯的）⇄ 相机的像平面（笔画台）⇄ 模型表面上的一点 ⇄ 贴图像素
        └ 屏幕的逆变换（10-28）┘          └ 投影 / 射线求交 ┘        └ 这张面自己的铺法 ┘
```

三维这边把它算成两张表，交给内核：

- **落点表**（每份画、每个视角一张）：贴图像素 → 笔画台坐标，外加这个像素此刻看不看得见。
- **回读表**（每个视角一张）：笔画台上每一格 → 哪份画、哪个贴图像素，外加这一格附近坐标变化的快慢（局部斜率）。

内核只会一件事：**照一张坐标表去取样**。这是它现有「浮层变换」那段代码的推广——现在逆映射是一个 3×3 矩阵，推广成一张表。内核里没有相机、没有深度、没有矩阵；这些全在三维这边，算成表。六月那份稿子说的「2D 自由变换和 3D 画是同一个骨架」，在这里落成了同一段代码。

要保证的五件事：

1. **不漂移。** 你在屏幕哪画，颜色就进投到那一点的那个贴图像素。靠的是没有单独的「预演」：边画边看到的，就是照落点表真算出来的贴图，抬笔只是把它记下来。（六月稿的结构保证，原样继承。）
2. **不画穿、边上不脏。** 六月稿用的是比深度，留了一个没解决的问题：容差太小漏刷、太大画穿，掠射面上会起麻点。我建议换成「**来回一趟要回到自己**」：一个贴图像素照落点表到了屏幕某处，再照回读表反查回来，如果回到的是它自己（或它那张面），就是看得见的；回到别的面，就是被挡住了。低模的面是平的，这个判断是精确的，没有容差可调。深度只当兜底。**没验证。**
3. **细线不断、不闪。** 拉近了看，一个贴图像素在屏幕上占好几格，只取中心一点会漏掉细线。按它在屏幕上占的范围取平均（范围从落点表相邻两格的差算出来）。
4. **套索不糊。** 三档，从严到松：
   - 抬起来原地放下：一个字节不变。抬起时留的是源像素本身和那一刻的回读表，放下时串成的总变换是「原地」，直接照抄。
   - 沿贴图格挪（挪整数个贴图像素、转 90°、翻转）：无损。这就是画画软件里的套索原样跑在贴图上，它本来就认得整数挪动。手往哪拖，按回读表的局部斜率换算成贴图上的格数。细调眉毛用这一档，调一百次也不糊。
   - 在屏幕上自由变换（任意挪、转、缩）：对源像素只取一次样，和画画软件里一次自由变换的损失一样。
5. **接缝不露底、不断色。** 每块贴图外面留一圈补边。补边里放的不是「往外抹的颜色」，而是**缝对面那张面的颜色**：把三维上隔着缝的邻面沿那条边展开过来，补边的每个像素对应邻面上的一点（你 10-30 说的「填缝对面那一侧的颜色，沿缝延展，不是简单往外扩」）。这也是一张表（邻面表，铺法不变就不用重算），任何工具写完之后统一照表补一遍，所以平滑采样和缩小图在缝上都是连续的。开口的边（没有邻面）按自己那张面延出去。10-30 定的「防渗色和补边是强制的」在这里兑现。**没验证。**

另外两条如实说：

- **掠射面会糊**是信息极限（六月稿 5.5 节）：侧着看的面在屏幕上只有几格，没有足够的像素承载细节。位置不会错，只是糊。做法是转过去画；斜得太厉害的贴图像素不吃颜色，边缘软过渡。
- **视图是像素风或弯屏时**：笔先过屏幕的逆变换回到相机的像平面（10-28 你要的「鼠标位置的逆变换」，选东西本来也要用它），笔画台永远按真实屏幕的精度算，不跟着像素风变粗。

### 第二块：自动铺和自动打包（你 10-30 那十二轮，串成一条流水线）

你的思路我按原话理出来是这样（括号里是状态）：

1. **用户不管 UV**：没有 UV 工作台，只有右键的「自动生成 / 整理 / 重采样」；用户只关心像素密度，密度挂在物件上，脸单独一个物件。（拍了）
2. **一套坐标、像素对齐**：贴图坐标存「第几个像素」，岛的外沿落在像素角上；不执着 2 的幂。（拍了）
3. **打包只平移、不旋转，画布只增**：加了东西就加一点画布；平移不重采样，所以布局随便变，像素一个不变。「人类不这么做是因为 rebake 繁琐。我们这个全量自动化，只要保证 pixel 不变就行了。」（拍了）
4. **画过的岛钉死**，以后加东西旧岛不动；某块兜不住或拉伸太大，才明着申请重采样。（拍了）
5. **怎么分岛**：硬边、开口、材质分界就是线稿，照画画软件「线稿填色」那样推出一片片区域；人也可以给边刷一个「缝」，三分钟。（拍了）
6. **每片怎么摊平**：一圈圈的四边形带子拉成矩形，行宽列宽取整数像素、按面积比例分（你想亲手做的那题）；其余按「最小拉伸」加「按密度分面积」；保角不要。锥形带子怎么切、摊平后自己压到自己怎么办，放进 UV 实验室做出来看图挑。（方向拍了，两题开着）
7. **兜底**：每张面自己一块（Ptex 那样），是自动铺的退化情况。（拍了）
8. **更早的两个方案**：每层自己一套坐标和分辨率、加了手臂在新层上画（10-24 / 10-27，10-30 你自己降成了脑洞）；最后烘成一张、中间不敢改几何（Klee 那次的做法，你说「我要的是一起吃」）。现在这套就是为了「一起吃」。

我在这条流水线上只加一样：**「从现在的视角铺」**。把朝着你的那些面按当前视角压平成一块，小红帽的脸就是这么铺的。它是机械的（你看得见、你自己指定角度），不用科研，正好够毕业条件用，所以排在第一批。

### 第三块：改了模型接着画

贴图坐标是面的角上的数据，跟着面的来历走。每种建模动作对应一条规则：

| 你做了什么 | 画怎么办 | 糊不糊 |
|---|---|---|
| 挪点、挪边、挪面 | 像素不动，画跟着面一起拉伸 | 不糊 |
| 把面切开（刀、环切、细分、内插、倒角） | 切出来的每一小块继承原来那张面上的那一块 | 不糊 |
| 长出新面（挤出来的侧面、加一只手臂、补洞） | 新面是空白的，自动给它铺一小块、画布加一点；没画的地方透出材质 | 无 |
| 删面 | 那块像素留着，不偷偷删；「整理」时才问清不清 | 无 |
| 把缝两边的两张面合成一张 | 这一块得重铺，做之前说清会糊一点 | 糊一次 |
| 镜像开着 | 两半共用同一块像素，画一边另一边就有；想画得不一样时点「分开两半」，无损复制一份翻过来 | 不糊 |
| 换铺法、重铺 | 明着做的重采样，一步撤销 | 糊一次 |

- **来历是机械的，不靠猜**：建模操作每新建一张面，都说明「它是从哪张面来的」。内核按原来那张面自己的铺法，算出新面角上的坐标。全仓现在新建面的地方约 45 处，各加一个参数；以后新写的建模操作也只是多写这一个参数，不用懂贴图。
- **为什么是「一套坐标 + 钉死旧岛」而不是「每层一套」**：每层一套时，几何一变，每一层都要各自处理一遍；一套时只处理一次，所有图层（包括草稿层）跟着同一份坐标走。
- **强行对称要一起改**：现在强行对称每一步会重建另一半，重建出来的面必须认得自己是谁的镜像，不然每一步都会把那一半的画变成孤儿。我上周审对称时记过这条，这里正式进计划。

### 草稿画在哪：画在表面上

- 草稿层就是这份画里的一层，画在模型表面上；落在模型轮廓外面的笔画不留。手办师的铅笔线也是画在手办上的。
- 这样草稿转视角还在、能用套索调、能和成品层叠着看，而且不用另做一套「屏幕上的二维草稿」。
- 一份画里的所有层共用同一套坐标，所以草稿层和成品层永远对得上。
- 以后想要更细的草稿，可以让草稿层的密度是成品的整数倍（同一套坐标放大），这次不做。

## 五、画画那边要动什么（「父母和小孩对齐」）

好消息是不用大动。我按「磨草稿需要什么」排，不搞一次性大搬家：

**毕业之前必须做的（都不改变画画软件的行为）：**

1. **取样的两处改成「照坐标表取」**：烤笔画时去哪取颜色（现在写死「原地」）；浮层变换时去哪取源像素（现在是一个矩阵，前后各能再垫一张表）。画画软件不给表，走的还是原来那条路，输出逐像素不变。
2. **撤销记录的出口做成接口**。现在内核封好一步的记录，直接塞进画画自己的撤销栈；改成交给「宿主的栈」。三维这边的撤销本来就是同款设计（它的文件头写着照画画的撤销栈做的），画的记录登记成它的一个部件，建模和画画共用一条撤销线、共用 128 MB。（那个文件头还记着你 10-27 的一句话，意思是画画不另开一条栈；这句我没回原始记录核。）
3. **显卡接口加两个小口**：能上传浮点数的坐标表；能把合成好的图交给三维的渲染器直接用（只在浏览器那份实现里，内核本身不用）。
4. **套索和变换的引擎挪进内核的文件夹**（内容不改，只挪位置）。它们是第一批要用的，所以这次就挪。
5. **拷贝机制和守卫**（第十一节）。

**以后哪一段用到再做的：**

- 小块的边长从写死的 256 改成开机时给的数（三维用小的，贴图小，256 一块太浪费。你 10-30 说的「不是 256 池」）。
- 形状笔、涂抹、液化这些引擎的文件，从界面那层挪进内核的文件夹（内容不改，只挪位置），搬到哪个挪哪个。
- 「边画边看」现在由画画的界面层编排，底下的两个动作（合成一帧带笔画的画、抬笔烤定）已经在内核里。三维先直接用这两个动作；等画画那边要收拾界面层时，再把编排也收进内核。

**对画画软件的风险和怎么防**：它是你天天用来出活的工具，这是最要小心的。每一步都必须「行为不变」，拿它现成的两百来份测试加逐像素比对的基线把关，一小版一小版推开发版，正式版不动。

## 六、数据：现在必须定死的，和可以慢慢做的

**必须现在定（以后改要迁移老文件，贵）：**

1. **画属于物件，不属于材质**（要你拍，第八节第 2 件）。
   - 材质管的是「能平铺的图案」：砖墙、木纹，很多物件共用，按真实尺寸铺。这部分现在就有。
   - 物件身上的画是独一份的：小红帽的脸、墙角那块苔藓。它叠在材质上面，没画的地方透出材质。
   - 这样你 10-27 卡住的那件事（平铺的墙想在局部画东西，又不想把整面墙变成独一份）就有答案了：墙还是砖墙材质，苔藓画在物件自己的那份画上。
   - 同一个组件摆了三份，三份共用一份画（和几何一样）；想单独画就先变成独立的。
   - 你 10-30 定的「用户只关心像素密度，密度挂在物件上，脸单独一个物件」和这条是一回事。
2. **文件里怎么存一份画**：一份分层的源文件（就是画画软件的那种开放格式，ORA）加一张合成好的图。合成图给 Blender、Windows 预览这些别的软件看；分层的给我们自己读。这是你 9-06 就说过的「存档文件可以内嵌 ora」。好处是零新格式，拿出来画画软件能直接开。
3. **贴图坐标存「第几个像素」**，挂在「角」上（10-30 定的四种挂点之一），只在画了东西之后才存；一套；画过的小块钉死不动。（10-30 都拍过，这里只是确认进这一版格式。）新面从哪张面来的，是建模操作当场交代的，不进文件。
4. **贴图是文件里独立的一条**，有自己的身份号，材质引用它（家规，账上本来就排着）。

**可以慢慢做（先用最简单的，够用再换）：**

- 显存统一记账：先让内核的池子报数，统一调度以后做（10-30 你同意的两步走）。
- 没在画的那些画，在显卡上只留一张合成图，内核的那套设备只给正在画的开。
- 自己做缩小图：先用现成的，铺得好那一段再做。（接缝补边不在这里：它是磨草稿那一段的必做项。）
- 笔的大小：先按屏幕算（和画画软件同一个手感，拉近了画细节），「按模型上的真实大小」以后加。

## 八、要你拍的五件事，和我先按默认走的五件

**要你拍：**

1. **两边用同一份内核，还是抄一次各自长。**
   - 这是什么：10-30 你设想的是一个独立的小孩，画画软件不用它的代码，可以亲也可以冷落。我现在建议改成：内核只有一份，正本在画画软件里，三维机械地拷。画画软件仍然不依赖三维任何东西；三维随时可以停止跟随、从那一刻起自己长，所以随时能反悔。

   - 选各自长：这一轮省事，画画软件完全不动。代价是以后每搬一个功能都要先看两边差了多少，越往后越贵。
   - 我的建议：同一份。
2. **画属于物件、叠在材质上面**（第六节第 1 条）。
   - 选是：小白不用知道贴图是什么，画就是画在这个东西上；平铺材质和局部手绘能共存。代价是导出给别的软件时要自动把两层压成一张（全自动，你看不见）。
   - 选否（画属于材质）：和 Blender 的习惯一样，但平铺的墙一画就得整面变独一份，而且「密度挂在物件上」会对不上。
   - 我的建议：属于物件。
3. **文件里用画画软件的那种分层格式存一份画**（第六节第 2 条）。
   - 选是：不发明新格式，取出来画画软件能直接开。
   - 选否：我们自己定一种存法，能更省空间，但多一份要永远兼容的格式。
   - 我的建议：选是。
4. **第一笔和磨草稿排在材质窗口、导入现成模型前面。**
   - 选是：最大的风险最早见分晓，你最早能在自己建的角色上画；小红帽晚一些才能带着贴图打开。
   - 选否（照 10-30 的顺序，先材质和导入）：先得到一批稳的小功能，能马上在小红帽上试笔；风险晚暴露，毕业晚到。
   - 我的建议：选是。
5. **两个正式版要不要先推。**
   - 三维：现在开发版比正式版新很多（强行对称那一批都在）。升纪元前推一次，线上就有一个稳定的快照。
   - 画画：动它的内核之前把现在的开发版推成正式版，万一整理出了岔子，正式版是干净的退路。你 11-08 说过画画的正式版「等我用一段时间之后再推」，所以这条你定。

**我先按默认走，不同意说一声：**

- **草稿画在表面上**，是这份画里的一层；落在模型外面的不留。不另做屏幕上的二维草稿。
- 面被切开，小块继承原来的画；新长出来的面是空白；镜像开着时两半共用同一块像素。
- 贴上去的图浮着时，转视角它**贴着屏幕**不动（架构白送的答案）。
- 一笔只画进**你当前站在里面的那个物件**，别的物件只挡笔、不吃颜色（和建模时「只能改当前这一层」一致）。
- 笔的大小先**按屏幕**算。

## 十、提案接口（草案，实现中形状变了要回写）

```ts
// —— 内核 ——（正本在画画仓；三维只读）。内核里没有相机 / 深度 / 矩阵，只有「照表取样」。

/** 一张坐标表：目标像素 → 去源的哪里取。identity = 原地（画画软件永远给这个）。 */
export type CoordTable =
  | { kind: "identity" }
  | { kind: "table";
      xy: Gl2Texture;                // rg32f：源坐标（像素单位）；和目标同尺寸
      weight?: Gl2Texture;           // r8：这个目标像素吃多少（看不看得见 × 掠射软过渡）；缺省全 1
      footprint: "point" | "area";   // area = 按相邻两格坐标的差定取样范围（缩小时不漏细线）
    };

/** 烤笔画 / 填色：笔画薄层在笔画台上，目标是图层。 */
export interface OverlayInputBase { /* 现有字段 */ place?: CoordTable }      // 缺省 identity

/** 浮着的那块：源像素原样留着 + 两张表夹着现有的 3×3 变换。
 *  取样链 = 目标像素 —pre→ 笔画台 —hinv→ 抬起时的笔画台 —post→ 源像素。 */
export interface FloatInput { /* 现有字段：源平面、hinv、取样方式 */
  pre?: CoordTable;                  // 三维 = 现在视角的落点表；画画 = identity
  post?: CoordTable;                 // 三维 = 抬起那一刻的回读表（带局部斜率，见下）；画画 = identity
}

/** 回读表多带一张局部斜率（2×2），取样点不在格心时按它外推，不在表上做双线性（缝两边的坐标不能插值）。 */
export interface ReadbackTable { xy: Gl2Texture; jac: Gl2Texture; owner: Gl2Texture /* 哪份画、哪张面 */ }

/** 撤销记录的出口：内核封好一步，交给宿主的栈。画画 = 自己的 UndoStack；三维 = History 的部件。 */
export interface UndoSink {
  /** 令牌提交时内核调：一步的记录。 */
  push(step: UndoStepInput): void;
  /** 宿主的栈翻某一步之前 / 之后，回头告诉内核（令牌开着不许翻；翻完版本号 +1）。 */
  bind(hooks: StackWorkpieceHooks): void;
}

/** 工具自带的说明：两边界面照着它生成按钮和面板；三维这边不许读 id 分情况（守卫）。 */
export interface ToolDef {
  readonly id: string;
  readonly space: "stage" | "texel";                       // 在笔画台上工作，还是直接在贴图格里工作
  readonly preview: "overlay" | "region" | "shadow" | "livesync";
  readonly needsReadback: boolean;                         // 要不要先知道笔底下是什么
  readonly params: readonly ParamSpec[];                   // 滑杆 / 开关 / 下拉，带单位和范围
  make(ctx: ToolContext): StrokeEngine;
}

// —— 三维这边 ——（`src/paint/`，不在内核里）。数学都在这：纯函数，node 里用参考实现测。

/** 铺法不变就不用重算的三张表（每份画一套）。 */
export interface LayoutTables {
  posmap: Float32Array;              // 贴图像素 → 物件本地的位置 + 所属的面；补边里的像素按邻面展开算位置
  gutter: CoordTable;                // 邻面表：补边像素 → 它该抄的那个正主像素
  faceOf: Int32Array;                // 贴图像素 → 面
}
/** 跟视角走的两张表。 */
export interface ViewTables {
  place(doc: PaintDoc): CoordTable;  // 落点表：posmap × 相机 → 笔画台坐标；weight = 来回一趟回到自己 × 掠射软过渡
  readback: ReadbackTable;           // 回读表：三维渲染器按「每格是哪份画的哪个像素」画一遍
}
/** 换铺法：新贴图像素 → 旧贴图像素（逐面算，精确）。内核照表把每一层取一次样。 */
export function relayoutTable(before: LayoutTables, after: LayoutTables): CoordTable;

/** 性质测试（守卫）：对每个看得见的贴图像素 t，readback(place(t)) 回到 t（误差 < 0.01 像素）。 */

// —— 网格体内核 ——（`src/mesh/mesh-kernel.ts`）

/** 新建面时交代来历。from = 母面：角上的贴图坐标按母面自己的铺法算（顶点在母面环上 = 照抄；在母面的边上 / 里面 = 按位置内插）。
 *  不给 from = 新地（没有坐标，等自动铺）。镜像出来的面给 mirrorOf。 */
addFace(ring: readonly number[], mat?: number, from?: { face: number } | { mirrorOf: number }): number;
```

## 十一、同一份内核的机制

- 正本：画画仓的 `src/backend/` + `src/common/`（文件夹名不改，省得动几百处 import）；工具引擎以后挪进 `src/backend/tools/`。
- 三维：`src/paint/kernel/backend/`、`src/paint/kernel/common/`、`src/paint/kernel/vendor/`（相对路径照搬，文件一字不改）。
- `scripts/pull-paint-kernel.sh <画画仓的提交>`：拷文件 + 写 `KERNEL-MANIFEST.json`（来源提交、画画版本、每个文件的 sha256）。可以只拉一部分（不要录像、PSD 就不拉）。
- 守卫（三维）：内核文件夹里每个文件的哈希必须和清单一样（拦手改）；`src/paint/` 以外不许直接 import 内核内部文件，只走 `src/paint/` 的出口；`src/paint/` 里不许出现工具的 id。
- 守卫（画画）：`src/backend/`、`src/common/` 不许 import 这两个文件夹和 vendor 以外的东西；不许出现界面接口（白名单：`ImageData`）；内核里不许出现相机 / 深度 / 投影矩阵这些词（三维的数学不许漏进来）。
- 规矩：**内核只在画画仓改**。三维需要内核变 → 在画画仓改、跑它的测试、推它的开发版（升末位）、再拉。内核自己的测试跟着拷，三维的 `npm test` 里也跑（用纯 CPU 的那份显卡实现）。
- 不做成 `@internal/*` 包：只有两个用户，改得又勤，包的仪式（打包、钉版本、升中间位要批）太重。出现第三个用户时再升级成包。

## 十二、头三段的工单切法（每张一个末位版本；门 = Fable 审）

第 0 段（画画仓，行为不变）：

- K-1 照表取样（烤笔画）：`blend-glsl.ts` overlay 分支的 `ovUv` / `suv` 两处 + `soft-shaders.ts` 等价实现；`place` 进 `OverlayInput`，缺省 identity。门：`gl-smoke` 基线逐像素不变、软实现对拍。
- K-2 照表取样（浮层变换）：warp 那段前后各垫一张表（`pre` / `post`），回读表按局部斜率外推；`integerRigidOf` 的无损路照旧。门：同上 + 「两张表都是 identity 时和现在逐位相同」。
- K-3 撤销出口：`Workpiece` / `History` 认 `UndoSink`；画画自己的 `UndoStack` 实现它。门：撤销相关测试全绿、泄漏门不红。
- K-4 显卡接口：坐标表要 32 位浮点。两种做法 Opus 选一种、写进施工记录：`TexUploadFormat` 加浮点格式，或者用现成的 `r32f` 拼（不动枚举）；`BrowserGl2Port` 加「拿出 / 收养贴图」两个口（只在这个类上，不进 `Gl2Port`）。
- K-5 套索和变换的引擎挪进 `src/backend/tools/`（`lasso.ts`、`floating-transform.ts` 和它们带的零界面依赖；`bitmap.ts` 那 10 行碰界面的留在外面、改成注入）。只挪不改。
- K-6 画画仓的守卫 + 三维仓的拉取脚本、清单、守卫；内核测试接进三维的 `npm test`。

第 1 段（三维仓）：第一笔

- P-1 数据契约（Fable 先出一页 + 提案 `.h`）：`CATSUP_painting` 扩展（ORA 字节 + 合成图）、定义上挂「这份画」的身份号、角上的贴图坐标列（像素单位）、密度。迁移 + 冻结样本。
- P-2 探路：共用显卡上下文；内核合成图 → three 材质。只做到「内核画一个点，模型上看得见」。**不通就停下来报**，退路是读回再上传（慢但对）。
- P-3 角这一级的数据 + 面的来历：`mesh-kernel.ts` 加角上的列；`addFace` 认 `from`；45 处调用点逐个交代来历（切开 = 母面；新长的 = 不给；镜像 = `mirrorOf`）；`mirror.ts` 的对称化、对称判定、测试里的独立检查三处一起加（审查记录里记过）。门：每个算子一条「做完之后，继承来的面上任取一点，贴图坐标对应的三维位置没变」的性质测试。
- P-4 铺法表：最笨的铺法（每张面一块，像素对齐，只平移打包）；`posmap` / `faceOf`（CPU，确定性，node 里测；岛边上的像素按保守覆盖算）。

- P-6 撤销部件 + 存盘读盘 + 流程图文档 + 接口签名树。

第 2 段（三维仓）：能磨草稿 = 毕业

- P-8 可见性换成「来回一趟回到自己」，深度兜底。门：性质测试 `readback(place(t)) = t`；和比深度的结果在一组固定视角下对拍、差异逐条解释。
- P-9 邻面表 + 写完统一补边。门：缝两边在平滑采样下连续（取缝上若干点，两侧取样差 < 1 级）。

## 十三、和以前定的东西怎么对

**照旧有效（10-30 拍的）**：整个内核搬过来、撤销接上；UV 像素对齐；一套 UV；打包只平移不旋转；换布局像素不变；画过的小块钉死；自己做缩小图；全在视图里画、不做平面绘画；没有 UV 工作台，只有右键的「自动生成 / 整理 / 重采样」；静默重排；用户只管密度；像素笔；显存两步走。

**这份改了的（都在第八节里问了）**：

1. 「小孩是独立项目、只抄一次」→ 同一份内核，正本在画画仓。
2. 「不是 256 池」→ 不另写一个池，同一个池把边长做成开机参数。
3. 10-30 素材稿里「每层自己的 UV」早已降成脑洞，这里按「一套」设计。

**这份新定的（等拍）**：画属于物件、叠在材质上；用 ORA 存。

**这份新设计的（Fable 的设计，没拍、部分没验证）**：内核只认坐标表，三维的数学全在表里；可见性 = 来回一趟回到自己；补边 = 邻面展开；套索三档；面的来历由建模操作当场交代；镜像两半共用像素；「从现在的视角铺」排第一批。

**第 1 版说错、第 2 版改了的**：「拉 = 把一层画成平面图」（每抬一次糊一次）→ 拉回来的是坐标；套索排第三段、图层排最后 → 都进第一批；「三维这边只是接头」→ 三块数学。

## 十四、没设计的（如实列）
