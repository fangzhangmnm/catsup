## 一、一页结论

1. **画画那边的核心已经是一台能单独搬走的发动机。** 我读了它的代码：约 1.7 万行的后端只依赖自己和四个第三方小库，几乎不碰界面；套索、变换、形状笔、涂抹、液化这些工具的引擎（约四千行）也都不碰界面，只是文件还放在界面那一层。所以「抄」不用重写，要做的是划清边界、原样搬。
2. **加功能的成本想不涨，靠一条规矩：工具不知道三维，三维不知道工具。** 所有工具只认识一块平面（下面叫「笔画台」）；屏幕和贴图之间怎么对应，由三维这边算成「坐标表」交给内核，内核只管照表取样。
3. **三维这边不是薄薄一层接头，这一轮真正的数学都在这里**（第四½节）：屏幕和贴图之间的变换与逆变换要配成一对；自动铺和自动打包；改了模型接着画。上面那条规矩的意思是这三块数学各做一次，不跟着工具成倍变多，不是说它们简单。
4. **两边用逐字节相同的一份内核，正本放在画画那边，三维机械地拷、不许手改。** 只抄一次、各自长的话，以后每搬一个功能都要先比对两边漂了多远，成本会越来越高，正好是你不要的那种。这一条改了 10-30 的说法，user 11-10 夜拍了：同一份，不各自长。
5. **草稿层和套索是第一批，和笔、橡皮一起。** user 11-10：画画软件是靠草稿笔和套索活下来的，能在模型上磨草稿、细调眉毛眼睛才算能画；液化没有套索有用。
6. **第一笔不用等铺贴图的算法。** 先用最笨的铺法（每张面自己一小块，10-30 已经认过这是自动铺的退化情况）和「从现在的视角铺」（小红帽的脸就是这么铺的），就能画。好的铺法后面换。
7. **路线**：整理内核 → 第一笔 → 能磨草稿（**毕业 = 把这个角色的脸在模型上画出来**）→ 铺得好 → 接住现成的带贴图模型 → 往后每件都是「拉过来加个按钮」。

## 二、两条路怎么走：角色就是这一轮的考卷

你问：先做贴图纪元，还是你老老实实做一个二次元角色、边用边暴露问题；没有创作实践会不会飘。

- **架构和数据结构对，只能保证不返工，保证不了好用。** 飘有三种：地基错了（最贵，靠设计防，今天这份）；做了你用不上的东西（靠拿真作品排顺序防）；一千个小别扭（只有你真做东西才冒得出来）。后两种设计防不了。
- **所以不是二选一。** 你做角色的前半段是白模，这段冒出来的多半是操作上的事，改接线就行，一版一版小修，和内核整理互不挡路。等白模差不多了，第一笔和磨草稿也该到了。
- **毕业条件绑在这个角色上（user 11-10 定）**：「把这个角色的脸在模型上画出来」。user：「这个东西 Blender、Procreate 都接不住。」之后每一段先做哪个，看角色下一步缺什么。
- 做二次元角色还缺哪些建模功能，我没有逐项查（细分、对称、倒角、环切、挤出这些都有）。缺的让角色来告诉我们，比我猜的准。

## 三、成本从哪来，怎么压住

加第 N 个功能会变贵，原因就四个。每个原因对一条对策：

| 变贵的原因 | 对策 |
|---|---|
| **两份代码各自长**：搬功能前要先看两边差了多少 | 两边同一份内核，机械拷贝，测试拦手改 |
| **每个工具都要自己处理三维的事**（投影、遮挡、接缝、一笔画到两个物件、镜像） | 这些全在三维这边算成坐标表（第四½节），每件做一次；工具里一个字都不出现 |
| **每个工具都要自己处理画画的老规矩**（选区、锁透明、混合模式、图层、撤销） | 画画那边已经做对了：所有笔走同一条落笔流程，这些规矩都在流程里，不在工具里。原样继承 |
| **每个工具要在两套界面里各写一遍面板** | 工具自带一张参数清单（滑杆、开关、下拉），两边各用自己的通用面板照着画。三维这边已经有一个参数面板的模块（能不能直接照清单画，我没细看） |

结果是一张加法表，不是乘法表：

| 要加的东西 | 内核 | 三维这边的数学 | 界面 |
|---|---|---|---|
| 一种新笔 / 新工具 | 写一次，两边都有 | 不动 | 各加一个按钮 |
| 画画那边已有的工具搬到三维 | 不动（已经在内核里） | 不动 | 三维加一个按钮 |
| 三维特有的本事（对称着画、整理贴图、补接缝） | 不动 | 写一次，所有工具都有 | 一个开关或右键项 |

**你关心的「要读多少代码」**：加一个工具，要读的是内核里一页契约、一个现成工具当样子、这个工具自己的文件。和已经有多少个工具没关系。这一条我会做成测试：工具的文件里出现三维的词、或者三维那边按工具名分情况，测试就红。

## 四、架构：一张图，四个词

```
        画画软件                               三维软件
 ┌─────────────────────┐            ┌──────────────────────────────┐
 │ 界面 · 手势 · 图库     │            │ 界面 · 手势 · 模型 · 渲染        │  各写各的
 ├─────────────────────┤            ├──────────────────────────────┤
 │ 画布就是笔画台         │            │ 屏幕是笔画台                    │  各做一次
 │ 坐标表 = 「原地」       │            │ 坐标表 = 屏幕 ⇄ 模型 ⇄ 贴图的数学  │  和工具无关
 ├─────────────────────┴────────────┴──────────────────────────────┤
 │                 画画内核（两边逐字节同一份）                         │
 │  笔 · 橡皮 · 套索 · 变换 · 涂抹 · 填色 · 滤镜 · 图层 · 选区          │
 │  小块存储 · 合成 · 撤销记录 · 显卡接口（另有纯 CPU 的一份，测试用）    │
 └──────────────────────────────────────────────────────────────────┘
```

四个词：

- **内核**：上图最下面那一层。不碰界面、不知道自己在哪个软件里。
- **笔画台**：手在上面动的那块平面。画画软件里它就是画布；三维里它是屏幕（像隔在你和模型之间的一块玻璃）。笔的手感、平滑、压感全在笔画台上算，所以三维里的笔和画画软件里是同一支。
- **一份画**：一个物件身上那份分层的画，就是画画软件里的一个文档，只是没有自己的窗口。图层、草稿层、混合模式、选区都是它自带的。
- **推和拉**（各是一张坐标表，细节在第四½节）：
  - **推（落点表）**：每个贴图像素去笔画台的哪里取颜色、看不看得见。画画软件里是「原地」；三维里是把贴图像素在模型上的那一点投到屏幕。这就是你 8 月说的「贴图整张反算屏幕坐标、拿屏幕的笔画缓冲、按深度筛」，也是你 2012 年论文 3.1.3「逆转思维」反过来用：遍历要填的那一边，反查来源，所以不漏像素。
  - **拉（回读表）**：笔画台上每一格底下是哪份画的哪个贴图像素。它是推的逆变换。涂抹、套索抬起、取色用它。注意拉回来的是「坐标」，不是一张已经采过样的平面图——第 1 版写成了后者，那样套索每抬一次放一次就糊一次。

为什么说有了推和拉就够了。画画那边的工具按「边画边看」的方式分四类，每一类在三维里都有着落：

| 画画那边的做法 | 哪些工具 | 三维里怎么来 |
|---|---|---|
| 笔画先攒在一张浮着的薄层上，抬笔烤进图层 | 画笔、橡皮、形状笔、填色 | 薄层在笔画台上，烤的时候照**落点表**取 |
| 把一块像素抬起来、变换、放下 | 套索、贴图片 | 源像素原样留着；放下时把「落点表 → 变换的逆 → 抬起那一刻的回读表」串起来，对源像素只取一次样 |
| 把图层的一块拷到显卡上直接改，抬笔写回 | 涂抹、模糊、水彩式的笔 | 照**回读表**把这一块取到笔画台上改，再照落点表写回 |
| 在一份替身上改，抬笔换回 | 液化、滤镜笔 | 同上 |
| 直接改图层的像素 | 像素笔 | 笔尖点到模型上，算出是哪个贴图像素，直接改（10-30 拍过的像素笔） |

所以三维这边为画画要算的东西是固定的几张表：落点表、回读表、点到哪个像素，再加写完之后的收尾（补接缝、缩小图）。不会随工具变多。

另外几件事在这个架构里是白送的，列出来是想说明「越后面越便宜」不是口号：

- **对称着画**：镜像开着时两半共用同一块像素，画一边另一边就有（第四½节第三块）。想左右不一样再分开。
- **多选多画**（user 11-10 夜：「我希望引擎支持多选多画」）：同一块笔画台，分别落进选中的每一份画，撤销算一步。脸和头发是两个物件时一笔带过。
- **一笔画过好几个物件**是引擎的本事（每份画各有一张落点表）；界面上默认画哪些物件另定。
- **换一种铺法、重铺**：也是一张表（新贴图像素 → 旧贴图像素），内核照表取一次样。和套索放下是同一段代码。
- **修改锁**：内核的写入口本来就有一道门，三维以后做修改锁时直接接上。

## 四½、三块数学（这一轮真正难的地方）

第 1 版把这里写轻了。下面每一块先说要保证什么，再说靠什么保证。标了「没验证」的是我的设计，要先在实验室里量。

### 第一块：屏幕和贴图之间，变换和逆变换配成一对

一条链，每一环都能正着算、反着算：

```
手指 ⇄ 屏幕（可能是像素化的、弯的）⇄ 相机的像平面（笔画台）⇄ 模型表面上的一点 ⇄ 贴图像素
        └ 屏幕的逆变换（10-28）┘          └ 投影 / 射线求交 ┘        └ 这张面自己的铺法 ┘
```

三维这边把它算成两张表，交给内核：

- **落点表**（每份画、每个视角一张）：贴图像素 → 笔画台坐标，外加这个像素此刻看不看得见。
- **回读表**（每个视角一张）：笔画台上每一格 → 哪份画的哪个三角形。只回答「是哪个三角形」；具体是哪个贴图像素，用这个三角形自己的精确公式在那个位置上现算（第四⅞节「落点要反算」）。

内核只会一件事：**照一张坐标表去取样**。这是它现有「浮层变换」那段代码的推广——现在逆映射是一个 3×3 矩阵，推广成一张表。内核里没有相机、没有深度、没有矩阵；这些全在三维这边，算成表。六月那份稿子说的「2D 自由变换和 3D 画是同一个骨架」，在这里落成了同一段代码。

要保证的五件事：

1. **不漂移。** 你在屏幕哪画，颜色就进投到那一点的那个贴图像素。靠的是没有单独的「预演」：边画边看到的，就是照落点表真算出来的贴图，抬笔只是把它记下来。（六月稿的结构保证，原样继承。）
2. **不画穿、边上不脏、斜面不乱。** user 11-10 夜：「需要小心 near parallel 和遮挡和 z fighting」。六月稿用的是比深度，留了一个没解决的问题：容差太小漏刷、太大画穿，斜面上起麻点。这里不比深度，分三件事各自处理：
   - **遮挡**：显示那一遍顺手多画一张「每个屏幕像素看见的是哪张面」。一个贴图像素投到屏幕某处，那里（半个屏幕像素以内）看见的正是它自己那张面，它才吃颜色。意思就是「你看见哪张面，颜色就落在哪张面上」，依据和你眼前的画面是同一遍画出来的。
   - **深度打架**：因为不另外比深度，所以不会出现「显示上是这张面赢、落笔时算成那张面赢」。两张面真的叠在同一个平面上时，显示上谁赢，颜色就给谁；这种叠面本身是模型的毛病，修复工具里已经有合并它的动作。
   - **接近平行的斜面**：这种面在屏幕上只占窄窄一条，一个屏幕像素要管它一长串贴图像素，画上去只会拉成一道。做法是按面朝向你的程度给一个权重：正对着的吃满，斜到一定角度开始变淡，再斜就不吃。因为预演就是结果，你当场看得见哪里没吃上，转过去再画。角度的门槛是一个看得见的笔刷选项，不藏。背对你的面不吃。
   - **还剩的误差，如实说**：遮挡边界上有不到半个屏幕像素的不确定（把那张「看见哪张面」的图画成两倍大，可以再减半）；比一个屏幕像素还细的遮挡物可能漏判。这两条都是亚像素级的。**没验证，开工先用纯 CPU 的参考实现对拍。**
3. **细线不断、不闪。** 拉近了看，一个贴图像素在屏幕上占好几格，只取中心一点会漏掉细线。按它在屏幕上占的范围取平均（范围从落点表相邻两格的差算出来）。
4. **套索不糊。**
   - 抬起来原地放下：一个字节不变。抬起时留的是源像素本身和那一刻的回读表，放下时串成的总变换是「原地」，直接照抄。
   - 在屏幕上自由变换（任意挪、转、缩）：浮着期间原件一直留着，调多少次，放下时只对原件取一次样。
   - 以后：顺着表面滑（像水贴在手办上滑），是三维空间的做法。user 11-10 夜：进愿望单。
   - 去掉的一档：我写过「沿贴图格一格一格挪，无损」，user 当时说了「套索三档 赞」，但随后定了「反正绝不uv空间」。这一档是在 UV 里挪，靠近块的边缘就会越界，按后一句去掉。

**「pixel accurate」具体保证什么**（user 11-10 夜：「需要 pixel accurate」）：
- 你在屏幕上看见笔画盖住的地方，和贴图里被改的地方，是同一次计算；提交前后画面一个像素都不变（下一段「锁视角」）。
- 落点的位置误差来自浮点数，量级是千分之一个屏幕像素；遮挡边界是上面说的不到半个屏幕像素。
- 屏幕像素的中心怎么算、设备像素比怎么乘，笔画那边和落点表这边用同一套约定，写成一个函数两边都调。
- 贴图里已经有的像素：不碰到的一个字节不变；套索原地放下一个字节不变。

**锁视角**（user 11-10 夜：「每一笔的时候屏幕锁住不能旋转，但是commit之后就烤上去了，以及看到的preview应该是预演，就是不能commit的时候突然视觉跳变」）：

- 第 2 版写的「浮着的时候转视角、它贴着屏幕不动」作废（user：「听上去是个坏想法」）。想换个角度看：先放下，转过去看，不对就撤销重来。

### 第二块：自动铺和自动打包（你 10-30 那十二轮，串成一条流水线）

### 第三块：改了模型接着画

贴图坐标是面的角上的数据，跟着面的来历走。每种建模动作对应一条规则：

| 你做了什么 | 画怎么办 | 糊不糊 |
|---|---|---|
| 挪点、挪边、挪面 | 像素不动，画跟着面一起拉伸 | 不糊 |
| 把面切开（刀、环切、细分、内插、倒角） | 切出来的每一小块继承原来那张面上的那一块 | 不糊 |
| 长出新面（挤出来的侧面、加一只手臂、补洞） | 新面是空白的，自动给它铺一小块、画布加一点；没画的地方透出材质 | 无 |
| 删面 | 那块像素留着，不偷偷删；「整理」时才问清不清 | 无 |
| 把缝两边的两张面合成一张 | 这一块得重铺，做之前说清会糊一点 | 糊一次 |
| 镜像开着 | 两半共用同一块像素，画一边另一边就有；想画得不一样时点「分开两半」，无损复制一份翻过来 | 不糊 |
| 换铺法、重铺 | 明着做的重采样，一步撤销 | 糊一次 |

- **来历是机械的，不靠猜**：建模操作每新建一张面，都说明「它是从哪张面来的」。内核按原来那张面自己的铺法，算出新面角上的坐标。全仓现在新建面的地方约 45 处，各加一个参数；以后新写的建模操作也只是多写这一个参数，不用懂贴图。
- **为什么是「一套坐标 + 钉死旧岛」而不是「每层一套」**：每层一套时，几何一变，每一层都要各自处理一遍；一套时只处理一次，所有图层（包括草稿层）跟着同一份坐标走。
- **强行对称要一起改**：现在强行对称每一步会重建另一半，重建出来的面必须认得自己是谁的镜像，不然每一步都会把那一半的画变成孤儿。我上周审对称时记过这条，这里正式进计划。

### 草稿画在哪：画在表面上

- 草稿层就是这份画里的一层，画在模型表面上；落在模型轮廓外面的笔画不留。手办师的铅笔线也是画在手办上的。
- 这样草稿转视角还在、能用套索调、能和成品层叠着看，而且不用另做一套「屏幕上的二维草稿」。
- 一份画里的所有层共用同一套坐标，所以草稿层和成品层永远对得上。
- 以后想要更细的草稿，可以让草稿层的密度是成品的整数倍（同一套坐标放大），这次不做。

### 规矩哪里错，改成什么

  - 10-30 拍过的像素笔不算例外：它是在三维里点到哪一格就涂哪一格，只写那一格，不看邻居，所以碰不到边界。

### 能跨过接缝，是最重要的一条

user 11-10 深夜：「如果变换涂抹，他们能跨过 UV 接缝，这个才是最重要的。这个肯定不能在 UV 上做，就视图或者空间上做。」

- 变换：放下时每个贴图像素只认自己在屏幕上的位置，反查变换之前那里是哪个贴图像素。它不认自己在贴图的哪一块，所以缝两边各算各的，在模型上拼起来是连续的。
- 涂抹：每个贴图像素要的「旁边的颜色」，是模型表面上挨着它的那一点，不是贴图上挨着它的那一格。
- **守卫（缝换位置，结果不变）**：同一个模型，把缝换个位置重新铺，做同样的笔画、变换或涂抹，模型上的结果必须一样，只差贴图分辨率的取整。哪个工具在贴图上找了邻居，这条会红。所有工具都过这一条。
- 涂抹原来开着的那一处（借屏幕查，还是在空间里找）user 定了：空间。做法见第四⅞节「统一按空间做」。

### 眼睛这条斩杀线，对设计的要求

你 11-10 夜：「眼睛是斩杀线。高分辨率，高绝对位置精度。其他的反而随便纯色刷一下拉倒。」

- **高分辨率**：脸单独一个物件、单独一个密度（10-30 定的）。这一轮不为别的部位操心画法，按面上纯色现在就有。
- **位置信得过**：边画边看到的就是照表真算进贴图的结果，没有单独的预演，所以不会「画的时候在这、松手跑那」。
- **调多少次都不变糊**：浮着的那一块一直留着原件，挪、转、缩多少次，最后只对原件取一次样。这是画画软件浮层本来的做法，三维里靠第四½节那条取样链保住。
- **调得细**：手柄拖动；方向键一个屏幕像素一个屏幕像素地挪；想更细就拉近了再挪。浮着的时候视角是锁住的。
- **另一只眼**：镜像开着就自动有；不开镜像时复制一份翻过来。

### 穿透和不穿透（user 11-10 深夜：圈一条腿，一次填完）

user 给了一张图：一个白模角色，用套索把一条小腿连鞋圈起来，圈画到了模型外面。「x ray mode, lasso select this leg, fill all. if we can support this it will be very speedpainting」。

- **能做，而且是这套架构里最稳的一种操作。** 选区的定义是：一个贴图像素投到屏幕上，落在你圈的范围里，就算选中。圈到模型外面没关系，外面本来就没有贴图像素。
- **不穿透**：还要过「看得见」那一关，只选朝着你、没被挡住的那一面。
- **穿透**：不过那一关。圈里的面不管朝前朝后、有没有被挡，全选中。圈住一条腿再填色，整条腿前后左右一次上完。
- 为什么稳：填的是纯色，每个贴图像素只回答一个问题「我的落点在不在圈里」，是或否。斜面拉长、深度打架这些只影响「取什么颜色」，这里不取颜色，所以没有它们的事。
- 要注意的一件：穿透会把圈里所有选中物件的面都带上。另一条腿如果正好在这条腿后面，也会中。隔开的办法是下面的蒙版，或者先把不相干的部分藏起来（藏面现在就有），或者只选这一个部件来画。
- 「穿透」是操作上的一个开关，笔也能用（一笔画穿前后两面）。它只是落点表里「看不看得见」那一项要不要算，所有工具同一个开关。
- 画画软件现成的「套索填色」可以直接用：选区按上面的规则生成，填色那一步不用改。

### 蒙版：保护住不让画的地方，和选区是两回事

user 11-10 深夜：「我们也许还需要mask，这个weebpaint没有，我们非常需要，而且和选区独立」。

- **选区**是「这一下我要对哪里动手」，做完就换。**蒙版**是「这些地方先别碰」，一直在，直到你清掉。两个同时起作用：能被改的 = 选中的、并且没被蒙住的。
- 蒙版跟着一份画存、进撤销、转视角不丢。能做的事：用笔画蒙版、把选区变成蒙版、把蒙版变成选区、反过来、清空、边缘变软。
- 三维这边还能直接按面生成蒙版：按部件、按材质、按你给面贴的标签。「只画脸，别碰头发」就是把头发的面蒙住。
- **做在内核里**，画画软件同时得到这个功能。内核里所有工具现在都是「问一下当前选区」，改成问「选区扣掉蒙版之后剩下的」，工具本身不用改。这是「新功能写一次、两边都有、已有工具不用动」的一个现成例子。

| 它们的做法 | 对我们意味着什么 |

### 接缝和去白边（user：「接缝看一下weebpaint的png defringe」）

- 画画软件导出 PNG 时有一步去白边：把完全透明的像素的颜色，换成离它最近的不透明像素的颜色，透明度一个字节不动。这样别的软件做平滑采样和缩小图时，边上混进来的是边缘自己的颜色，不是黑或白。
- 我们的补边分两层，第二层就用这个算法：
  1. 缝对面有邻面的：补边里放邻面的颜色（第四½节第 5 条）。
  2. 没有邻面的开口边、岛和岛之间的空地、画里透明的地方：用去白边那套，从最近的有颜色的像素往外延。
- 导出给别的软件的那张合成图，出门前整张再过一遍。
- **给画画软件记的账**（user 11-10 深夜）：保存时默认强制去白边，不给开关，默认开；以后有空和这边一起做。已记进画画仓的账本。

### 一支笔其实是三件事

| 这件事 | 在哪个空间 | 说明 |
|---|---|---|
| 手怎么走 | 分开看，见下面「手这一段再拆开」：滤抖在手所在的地方，间距和走了多远在空间 | 第 4 版把这一行整个写成「屏幕」，user：「间距明显得空间，另外几个也think critically」 |
| 每个笔尖落在哪 | 从屏幕打一条射线到模型上，落点是空间里的一个点 | 精确，不经过深度图 |
| 笔尖盖住多大、多浓 | 空间 | 每个贴图像素按「自己在模型上的位置」到笔尖中心的真实距离算 |

我之前把这三件事捆成了一件。按空间做之后，笔画的中心线和按视图做完全一样（都是你在屏幕上画的那条线落到模型上），变的只有笔尖在表面上占多大。

### 和按视图做比

| | 按视图（笔尖是屏幕上的圆） | 按空间（笔尖是空间里的球） |
|---|---|---|
| 斜着看的面 | 一笔拉得很长，越斜越长；只能靠「太斜就不吃颜色」硬挡 | 笔尖在表面上永远是同样大的圆，没有这个问题 |
| 被挡住的地方 | 每个贴图像素都要判断看不看得见，这是最难的一块 | 不用判断。球碰得到的才吃 |
| 两张面叠在一个平面上 | 要和显示保持一致，不然打架 | 没有这回事 |
| 放大缩小时的锐利程度 | 笔画的清晰度受屏幕分辨率限制，拉远了画会糊 | 浓淡是公式算的，任何缩放下都按贴图自己的分辨率锐利 |
| 靠得近但不相连的两处（手臂贴着身子、头发贴着额头） | 圆底下看得见的都吃 | 可以只吃和落笔处连着的那一片 |
| 鼻子后面的脸颊 | 圆盖到了就吃 | 不吃（离落点远），画鼻子不会蹭到后面 |
| 对称着画 | 要把相机镜像一遍 | 把笔尖的位置镜像一下就行 |
| VR | 做不了 | 同一支笔，中心换成手柄尖 |
| 一笔跨几个物件 | 每份画各算一张表 | 每份画各自量距离，天然就行 |
| 要准备的东西 | 「每个屏幕像素看见哪张面」的图、相机进表、朝向权重 | 每个三角形的位置公式、一张「这个贴图像素属于哪个三角形」的表 |
| 屏幕上看到的粗细 | 处处一样粗 | 斜的地方看起来细一些，像真的画在物体上的线 |
| 笔尖中心在模型外面 | 圆蹭到模型的部分照样吃 | 不吃（可以补一条「离射线最近的表面点」，以后） |
| 贴图案、套索、形状、渐变 | 天生是视图的 | 不适用，这些仍然按视图 |

按空间做唯一丢掉的是「屏幕上处处一样粗」。从正面画眼睛时两种几乎没有差别；差别只出现在斜面上，而斜面上按视图做的结果正是你说的那个问题。

### 手这一段再拆开（user：「间距明显得空间，另外几个也think critically」）

我原来把平滑、防抖、压感、间距一股脑写成「屏幕」，错了。逐个看：

| 环节 | 在哪 | 为什么 |
|---|---|---|
| **间距**（每隔多远落一个笔尖） | **空间**：沿着笔在表面上走过的路，用空间里的长度量 | 按屏幕量的话，斜面上笔尖稀、正面上密，线的深浅会跟着你从哪看而变。VR 里根本没有屏幕可量 |
| **走了多远**（起笔收笔的渐细、颜料越刷越少） | 空间，同上 | 它们说的是物体上这条线的事 |
| **笔尖朝哪**（跟着走向转的笔） | 空间：表面上的走向 | 同上 |
| **滤掉手抖**（平滑、防抖的死区、收笔的拖尾） | 手所在的地方。桌面上是屏幕，它在这里是一块输入板，不是画布；VR 里是手柄在空间里的位置 | 抖是手抖出来的，在它产生的地方滤最干净。如果落到表面上再滤：斜面会把抖放大；笔从鼻子滑到后面的脸颊时路径是断开的，滤波会滤出悬在半空的点 |
| 平滑的快慢 | 时间 | 它本来就是按时间算的 |
| **压感** | 哪个空间都不是，是手的力度 | 压感曲线原样用；它换算出来的「这一下多大」是空间里的大小 |

- 我读了画画内核，这个分法和它现在的做法其实一致：平滑的快慢是时间；防抖的死区在它那里就是按屏幕像素定的，再除以缩放换成画布像素。所以滤抖那一段可以原样搬，喂它屏幕像素就行。
- **间距那一段要改内核。** 现在它是沿着平滑后的二维点一段一段走，用平面上的距离。改成：平滑之后先把点落到表面上（落得足够密），再沿着空间里的这条路走。走步的代码做成不管几维都能走；画画软件走原来的二维，输出逐像素不变。
- **一笔自己的尺子**：落笔那一刻定一把尺，一个单位等于落笔处的一个屏幕像素在表面上的长度，这一笔里所有长度都用它量。这样画画内核里的数字（间距是直径的百分之几、最小步长半个像素）原样有意义，也正好就是「笔的大小语义是屏幕大小，落笔时定，一笔之内不变」。

### 薄层之后，内核哪些能原样用，哪些不能（user：「think critically. 选区可能是重灾区」）

我说过「得到薄层之后，合进图层、橡皮、锁透明、选区、撤销、边画边看全用内核现成的」。这句话只对一半。画画内核把画布当成一整张连着的图；贴图不是，它是一块块拼起来的，块和块之间在贴图上挨着不代表在模型上挨着。所以内核的操作要分两种：

- **只看这一个像素的**：安全，原样用。
- **要看旁边像素的**：在贴图上一用就错（越界、过不了缝、随铺法变）。

| 内核的东西 | 哪一种 | 在三维这边 |
|---|---|---|
| 薄层合进图层、橡皮、锁透明、混合模式、透明度、图层和组、合并图层 | 只看一个像素 | 原样用 |
| 撤销、边画边看 | 只看一个像素 | 原样用 |
| 选区**存着**、选区**挡着笔**、选区的加减交反、填色、清空、从图层的透明度生成选区 | 只看一个像素 | 原样用 |
| 逐像素的调色（色相、曲线、色彩平衡、渐变映射） | 只看一个像素 | 原样用 |
| 选区**怎么圈出来**（套索的多边形） | 看邻居（它在画布上画多边形） | 不用内核的。隔着虚拟屏幕圈：每个贴图像素投过去看在不在圈里 |
| 选区的**蚂蚁线** | 看邻居（沿着画布上的边界描线） | 不用内核的。它会在看不见的缝上描出线来。改成在屏幕上找「这一格选中、旁边一格没选中」的地方 |
| 选区**羽化、扩大、缩小、平滑、描边** | 看邻居 | 先不给。以后隔着虚拟屏幕做，或按空间里的距离做 |
| **魔棒、按颜色找连着的区域、线稿填色** | 看邻居 | 先不给。以后在虚拟屏幕上「看到的画面里」找 |
| 模糊、锐化这类滤镜 | 看邻居 | 先不给。以后走贴着表面的小平面 |
| 把图层整个挪一下、翻转画布、旋转画布 | 看邻居（在贴图上挪就是在 UV 里挪） | 永远不给 |
| 浮着的那块放下时的取样 | 看邻居（平滑取样要读旁边的像素） | 走虚拟屏幕那条链；取样只许双线性或双三次，并且只从补过边的拷贝里取。内核里有一种更高级的取样会沿整行整列做预处理，会穿过别的块，三维这边不许用 |

**选区确实是重灾区**：它一半安全（存、挡、加减交反、填），一半全是坑（圈、描边界、羽化、扩缩、魔棒）。第一批只开安全的那一半，加上「隔着虚拟屏幕圈」。

顺着这条线又查出三件要改的事：

1. **写入要被「画布的形状」挡住。** 贴图上有不属于任何面的空地。内核不知道，「全选再填」「反选再填」会把空地也填上颜色。空地以后会分给新长出来的面，那些面一出生就带着脏颜色。所以除了选区和蒙版，还要有第三道：只许写属于某个面的像素。三道在内核里是同一个地方合起来的（「选区扣掉蒙版」那一处再多乘一项），这一项由三维这边给，用户看不见。
2. **补边不存在图层里。** 补边只在「合成好、交给显示的那张图」和「导出的那张图」上做；图层里只有真正属于面的像素。这样图层里没有重复的副本，内核的任何操作都不会把正本和副本弄得不一致。
3. **凡是在贴图上做平滑取样，都算在找邻居。** 只有补边里放对了邻面的颜色，它才是对的。所以浮着的那块的原件、涂抹要取的那一块，都要先补过边再取样。补边因此是一个共用的小零件，显示、导出、浮层、涂抹都用它。

**守卫**：内核的每个动作在一张表里标上「只看一个像素」还是「看邻居」。三维这边默认只能调前一种；后一种必须登记它走的是哪条空间的路（贴着表面的小平面，或者虚拟屏幕），没登记的调不到。再加上「铺法换掉，结果不变」那条在后面兜底。

### 2012 年的思路还在

那篇论文的要点是：遍历要填的那一边，反查它的来源，这样不漏点、不挤点。按空间做还是这样：遍历的是贴图像素，每个像素反查「我离笔有多远」。

变的只是来源。原来的来源是屏幕上的一张笔画图，贴图像素要投到屏幕上去取；现在的来源是空间里的笔本身，贴图像素直接量距离。因为笔尖是一个公式而不是一张图，连取样都省了，所以没有重采样。

### 具体怎么算

1. 平滑和防抖在屏幕上把手的轨迹滤干净。这一步和画画软件完全一样。
2. 把滤干净的轨迹落到表面上：沿轨迹打射线，打得足够密（相邻两个落点在空间里离得远就在屏幕上取中间点再打）。得到一条空间里的路；笔从一个面滑到后面另一个面时，路在那里断开。
3. 沿着这条空间里的路按间距走，每一步出一个笔尖：中心在路上，大小按这一笔的尺子，浓度按压感。
4. 从落点那张面出发，沿着共用的边往外找，找出球碰得到的那几张面。这一步顺带实现了「只吃和落笔处连着的那一片」，而且不需要额外的空间索引。
5. 对每一对「笔尖 × 三角形」，在贴图上画一个小矩形（这个三角形被球盖住的那一块的外框）。矩形里每个贴图像素做三件事：确认自己属于这个三角形；用这个三角形自己的公式算出自己在空间里的位置（三角形是平的，公式是精确的；不平的面是按显示用的那套三角形拆开各算各的）；量到笔尖中心的距离，得到浓淡。
6. 累积方式（一笔之内取最大，还是一层层叠）和画画软件是同一套。得到的仍然是一张「这一笔的薄层」，在贴图的格子里。
7. 之后把薄层合进图层、橡皮、锁透明、选区、蒙版、撤销、边画边看，全是画画内核现成的，一行不改。

橡皮就是同一支笔换成「擦」的合成方式。

### 统一按空间做：先想 VR 里拿着刷子的人（第 5 版，user 11-10 深夜拍）

user：「涂抹和模糊，我建议是用空间，而不是用屏幕。就是我们放弃屏幕，我们就统一用空间做……只有极少数的东西，比如说我们如果想贴花，对吧？我们可以用屏幕做参考，但是尽量是能用空间做。或者你那么想，如果我们 VR 里面一个艺术家拿着刷子在刷，这个时候是完全没有屏幕了。我建议是你一开始想的就是 VR 里的情况……只有极少数情况，这时候 VR 里你会有一个强行的虚拟屏幕，就跟我们说的选区」。

这和三维仓里一条老规矩是同一件事。VR 的指针 9-08 就改成了「只有一条射线，没有虚拟屏」，当时你的话记在代码里：「需要投影平面的时候 explicit，no 静默」。所以：

**规矩：一切工具按空间做。需要一块平面的时候，平面要明着摆出来，不许悄悄拿屏幕当空间。**

按「要不要一块平面」把工具分三类：

| 类 | 哪些工具 | 平面在哪 | VR 里是什么样 |
|---|---|---|---|
| 不要平面 | 笔、橡皮、像素笔 | 没有。只看贴图像素和笔尖在空间里的关系 | 手柄尖就是笔尖 |
| 要一小块、跟着笔走 | 涂抹、模糊、锐化、液化 | 贴在笔尖底下的表面上，朝着那里的法线，随笔移动 | 像用手指或刮刀贴着表面抹 |
| 要一大块、人摆好的 | 圈选区、贴花、把一块画抬起来挪 | 「虚拟屏幕」：桌面上就是当前视图；VR 里是一块悬在空间里的板 | 一块可以摆位置的板，隔着它圈、隔着它贴 |

- 第三类是「极少数」。第二类和第三类用的是同一套算法（一块平面加一个朝向，贴图像素往平面上投、平面上每一格反查是哪个三角形），区别只是平面由谁定、多大。所以涂抹不是在屏幕上做的，它的平面是表面自己的切面，和你从哪看没有关系。
- **锁视角**换个说法就是：操作进行中，那块虚拟屏幕不动。桌面上它和你的眼睛是同一个东西，所以表现为不能转；VR 里锁的是那块板，人可以走动。

**涂抹和模糊在空间里怎么做：**

1. **每个笔尖各立一块切平面**（user 11-10 深夜：「如果是一个长stroke的话最好也是切平面跟着每个stamp走」）。中心是这个笔尖的落点；朝向取这一下碰到的那几个三角形的平均朝向，不只看落点那一个三角形（低模的棱上不会一过边就突然翻一个角度）；大小比笔尖大一圈。
2. **取**：平面上每一格，沿法线看下去是哪个三角形（只在和落点连着的那几个三角形里找），用那个三角形的精确公式算出贴图坐标，取颜色。得到一小张平的图。
3. **算**：在这张小图上跑画画内核现成的涂抹或模糊。我读了画画内核的涂抹：它每一下只做两次和图层的交道，「把笔尖下面那一块取出来」和「把结果放回去」；中间的十来步、还有它记着的那块「沾在笔上的颜料」，都是跟着笔走的小图。所以只要把「取」和「放」换成经过切面的版本，中间一个字不用改。
4. **放**：笔尖碰到的每个贴图像素，用自己三角形的公式算出空间位置，投到这块平面上取结果，按笔尖的浓淡和**自己原来的值**混。自己原来的值不重新取样。
5. 下一个笔尖重新立自己的平面。笔尖之间带过去的只有「沾在笔上的那块颜料」；它的方向从上一个平面顺着表面转到下一个，不突然转，这样拖出来的纹路方向是连贯的。每一下读到的都是上一下改完之后的样子。
6. 绕着很弯的地方画时，一块平面管不到侧面，侧面由「拐角另一边吃不吃」那个笔刷选项挡掉；后面的笔尖的平面自然转过去接上。

这样做的性质：过缝不断（「取」和「放」都不看贴图上的邻居）；和从哪看无关；VR 里原样能用；铺法怎么变都不影响结果。

**如实说的代价**：画画软件里的涂抹每一下是整数像素对齐的，零重采样；空间里「取」的那一步要重新取样。但被重新取样的只有笔带走、再放下的那部分颜料，它本来就是被抹开的东西；每个贴图像素自己原来的值不重新取样，所以没被笔碰实的地方保持原样，不会平白变糊。液化这种挪像素的，可以把「贴图像素 → 平面 → 挪回去 → 平面上那一点是哪个贴图像素」串起来，对贴图只取一次样。小平面的分辨率取得比当地贴图密。这些都没验证；涂抹和模糊不在毕业那一段里，做到时先量。

**把一块画抬起来挪**现在归第三类（它就是揭下来再贴一次的贴花）。你说过「顺着表面滑」进愿望单，那是它的空间版本，以后做。

**笔的大小（user 拍了）**：「笔的大小应该是屏幕大小，因为这个是你的语义。然后这一笔之内都不变，我同意。」落笔那一刻把屏幕上的大小换算成空间里的大小，这一笔用到底。VR 里没有屏幕，直接给空间里的大小。

**铺法再难看，画出来也要规整（user 拍了）**：「我不希望你因为这的变化而让笔线粗细发生变化。因为我一开始反对 UV，就是因为你画的线会粗细不一样……如果我们这个 UV 〔展得〕和〔人名略〕的那个conformal论文一样非常难看的话，我们画出来的东西只要贴图分辨率支持，还是很规整的。」

- 空间里的笔天然满足：粗细是在空间里量的，和贴图怎么铺没有关系。铺得稀的地方只是格子大、边缘粗糙一些，线的宽度不变。
- 边缘软化的宽度按当地一个贴图像素在空间里有多大来定，所以铺得密的地方边缘细腻、铺得稀的地方边缘粗，但都是「一格」的软化，不会一边糊一边锯齿。
- **守卫升级**：原来那条「缝换位置，结果不变」扩成「**铺法换掉，结果不变**」。同一个模型准备两份铺法：一份规整的，一份故意铺得很难看（密度差十倍、拉伸、歪斜）。做同样的笔画、涂抹、变换，在模型上量线宽和位置，两份必须一致，只差各自贴图分辨率的取整。

### 笔按真实笔刷的物理来想（第 5 版，user 11-10 深夜）

user：「以后我们做艺术家笔刷vr笔刷也不一定需要球。我们可以day 1就按照真实的笔刷的物理来做。因为以后做warhammer模型的这种画occlusion，扫漆，（就是用很稀薄的黑墨水做出occlusion,或者用很硬的刷子只刷到棱角），这些我们都应该支持，然后vr笔刷是有手势，刷毛的。其实变成物理模拟就反而思路很清晰了」。

**一支真的笔做三件事，每个贴图像素也就问三个问题：**

| 笔做的事 | 贴图像素问的 | 最简单的那一种（第一天做的） |
|---|---|---|
| **碰**：笔尖是空间里一个有形状、有软硬的东西 | 我陷进笔尖里多深？ | 形状是球，毛很软：离中心越近陷得越深 |
| **给**：笔上带着颜料，碰得越实给得越多 | 这一下我拿到多少？ | 颜料永远是满的；给多少只看陷多深和笔压 |
| **留**：颜料到了表面上会流、会干 | 最后我这里留下多少？ | 给多少留多少 |

之前说的「笔尖是个球、按距离算浓淡」，就是这张表最右一列。球不是规定，只是「碰」这一栏里最简单的形状。

**你举的几种，各自只是换其中一栏：**

- **扫漆**（很硬的刷子、颜料很少，只刷到棱角）：换「碰」。笔尖是一片又平又硬的东西，轻轻架在表面最高的地方上；只有顶到它的地方才陷得进去，凹下去的地方碰不到。再换「给」：颜料少，越刷越淡。
- **渍洗**（很稀的黑墨水流进凹处，做出遮蔽的阴影）：换「留」。墨水稀，凸出来的地方留不住，凹进去的地方留得多。最简单的做法不用真的模拟流动：每个贴图像素事先知道自己这里凹得多深，留下的量按这个算。真的让墨水顺着表面流、汇到低处，是以后的事。
- **有毛的笔、VR 里带手势的笔**：换「碰」。一把毛就是很多根细的小笔尖，各自有位置、各自带颜料；手势决定这把毛怎么压在表面上、怎么散开。每根毛沿路留下一道细痕。

**所以第一天要留好的是这几个口，不是把物理都做出来：**

- 笔每一下交出来的不是「一个球」，而是「若干个有形状的小东西」（球、一小段、一小片），每个带着自己的颜料量。第一天只有球，一下一个。
- 每个贴图像素除了自己在空间里的位置，还能查到自己这里的**朝向**、**凸不凸**、**凹得多深**。这三样是从模型的形状算出来的，不是画出来的，模型变了才重算。第一天只用到朝向（拐角另一边吃不吃）。渲染器给剪纸画风烘遮蔽的那一步，将来可以直接拿来当「凹得多深」。
- 「陷多深 → 给多少 → 留多少」是三段分开的规则，换一种笔只换其中一段。

**哪些是真的要模拟的，如实说**：墨水顺着表面流动、毛的弯曲和回弹，这两样是模拟，量不小，不在这一轮。流动要在表面上相邻的贴图像素之间传递，到时候它也得过「铺法换掉，结果不变」那条守卫，不许顺着贴图的格子流。

**user 11-10 深夜确认了这个读法**：「同意，但是设计的时候以后要支持他们，以及各种奇怪的笔刷，可以想象成vr brush，不过也许我不对，think critically」。

**批判性地想「把笔想成 VR 里的刷子」**：作为总框架是对的，收紧三处、划清一处。

（user 11-10 深夜看过之后：「规则要是确定的，不默认做模拟 同意，模拟以后可以做着玩，但是会很贵。能procedural就不要simulation」「笔吃的应该是「空间里的一个姿态」 对」「嗯对」。下面第 1、2 条是拍了的。）

1. **物理的是形状和关系，规则要是确定的，不默认做模拟。** 笔尖在空间里有形状、有朝向、压多深，这是物理的。「接到多少、给多少、留多少」是能直接算出来的规则，同样的一笔永远出同样的结果（画画内核本来就有这条：同样的输入出同样的结果）。一步步模拟刷毛怎么弯、颜料怎么流，结果难预料、难重复；只有规则表达不了的才做模拟，而且是明着选的那一种「留」。颜料用完变淡这类也不是默认，是某一种笔的规则。
2. **笔吃的是「空间里的一个姿态」：在哪、朝哪、压多深。** 设备只负责把手的动作变成姿态：屏幕上的笔 = 射线落点 + 表面朝向 + 笔压（有倾斜就用倾斜）；VR = 手柄；鼠标只有位置。新设备只写一个转换，笔不用改。每个笔尖带的就是姿态，第一天只用到位置和大小，别的格子留着。
3. **「碰」说成「这一点接到多少」，不只是「陷进去多深」。** 喷枪是隔着距离喷过去的，朝着喷口、没被挡住的才接得到。这样屏幕上那种圆笔尖也成了框架里的一种：从眼睛的位置沿着视线喷出去的一束。
4. **不是什么都是笔。** 像素笔是按格子的，不是物理的；填色、套索、挪动是对一片区域做事；贴一张图是摆放。它们按「要不要一块平面」分在别的类里，不往刷子里套。
5. 「给」也要留宽：给的颜料可以是一个颜色，可以是一块图案（印章、有纹理的笔尖），可以是从别处取来的（仿制），可以是刚从表面上沾起来的（涂抹就是笔和表面互相交换颜料）。
6. **往远了看**：这三段规则如果放进两边共用的内核，画画软件也能用。平面上的「表面凹凸」就是纸的纹理，扫漆扫在纸纹的凸处、淡墨积在纸纹的凹处。不是现在做的事，记在这里说明这个框架不只对三维成立。

### 落点要反算，精确到贴图像素；像素笔第一笔就要有（user 11-10 深夜拍）

user：「算笔尖那个点在哪里需要像素精确，就是反算。而不是用不精确的矩阵查。因为对于有拉伸的不平面的quad，procreate会抽风。但是我们希望的是点到哪个texel就是那个texel。像素笔也是一开始就要好支持」。

**怎么保证「点到哪个贴图像素就是那个」：**

- **只认一套三角形**（准确地说：只认最后显示出来的那一套，见下面「和显卡画出来的一致吗」）**。** 三维这边的面可以有任意多条边、可以不平。显示的时候，每张面被切成三角形来画；显卡是在每个三角形里各自插值的。所以「屏幕上这一点底下是哪个贴图像素」，答案取决于面是怎么切成三角形的。规矩是：显示、求落点、算每个贴图像素在空间里的位置、导出给别的软件，四处用**同一套三角形**。我核了代码：显示和现有的射线吸附已经共用网格体内核那份三角形；导出是另调了一次同一个函数，要改成也用那一份。
- **每个三角形里是一对精确的正反公式。** 三角形是平的。「贴图坐标 → 空间位置」和「空间位置 → 贴图坐标」在一个三角形里各是一个一次式，互为逆运算，没有近似。不平的四边形就是两个三角形各算各的，不拿一个矩阵去近似整张面。Procreate 在拉伸的、不平的四边形上抽风，六月稿里推测是它用一个矩阵近似整张四边形；这个推测没核实过，但我们这里从结构上没有这一步。
- **落点用射线和三角形求交，在 CPU 上用双精度算。** 不从深度图读，不从任何表里读近似坐标。
- **表只回答「是哪个三角形」，坐标一律现算。** 第 2 段的套索要查「屏幕这一点底下是哪个贴图像素」。第 3 版写的是「表里存坐标和局部斜率，不在格心时外推」，那是近似，作废。改成：表只存三角形的编号；拿到编号以后，用这个三角形自己的精确投影公式，在屏幕上那个精确位置上算坐标。
- **光标和落笔是同一个答案。** 像素笔悬在哪个贴图像素上，那一格在模型上亮起来；亮的这一格是把格子编号交给显示用的着色器、由它在同一个取样坐标上判断出来的，所以亮的就是会被涂的。

**像素笔（第一笔那一段就做）：**

- **一格笔**：涂射线落点所在的那一个贴图像素，只写这一格，不看邻居。笔在走的时候，把相邻两个落点之间在屏幕上细分，直到相邻两格在表面上挨着，一路上每格恰好涂一次。画画内核现成有「按顺序落整数像素、每格一次」的入口，直接用。
- **粗一点的硬边笔**：就是空间里的笔，浓淡只有 0 和 1（贴图像素的中心在球里就涂，不在就不涂）。它不在贴图上数邻居，所以过缝是对的。
- 一格笔涂完，这一格在别的块的补边里的副本照邻面表同步。

**守卫（真 app 探针；user 11-10 深夜：「对的」）：**

- 给每个贴图像素涂上互不相同的颜色。随机取屏幕上的点，读屏幕上那个像素显示出来的颜色，对回是哪一格；再用反算求同一点的格子。两者必须是同一格。
- 测试模型里必须有一张拉伸过的、四个点不共面的四边形，从正面和斜着各测一遍。
- 纯计算的那一半：每个三角形上随机取点，「贴图坐标 → 空间 → 射线 → 贴图坐标」绕一圈回到同一格。

### 和显卡画出来的一致吗（user：「四边形是有变形的啊，这样不就不和opengl一致吗？」）

一致，而且正是为了一致才这么定的。

- 显卡只会画三角形。一张四边形交给它时已经被切成了两个三角形，它在每个三角形里各自做直线的插值。所以一张拉伸过的、或者四点不共面的四边形，贴图在那条对角线上会有一道折：这就是你说的变形，它是显卡真的画出来的样子。
- 我们的规矩是照着显卡来：它用哪两个三角形，我们就用哪两个；它在三角形里怎么插值，我们就怎么反算。所以那道折在显示里和在落点里是同一道，点到哪一格就是哪一格。
- 和显卡不一致的做法反而是「把四边形当成一整张光滑的面来算」。那样算出来的格子和屏幕上显示的格子在对角线两侧会错开，就是六月稿里推测的 Procreate 那种毛病。
- 所以更准确的说法是：**只认最后显示出来的那套三角形**。
- 你说的对，面全是平的（像 SolidWorks 那种）数学会干净得多：平的面怎么切都是同一个结果。硬表面那种身体就是这样。会出问题的只有网格体里不平的面。

**切法会不会自己变：会，不管它（user 11-10 深夜拍）。**

- 现在一张面怎么切成三角形，是按它在空间里的形状现算的。你挪一个点，一张不平的四边形的对角线可能从这一条跳到另一条，面里的画会跟着轻轻变一下形。
- 我提过「画过的面把切法钉死」。user：「没必要，和游戏引擎对齐。不过游戏引擎确实是认tri的。但是我觉得你挪点的时候有变形问题不太大」。**定了：不钉，切法照现在现算。** 规矩只有一条不变：显示、落点、算位置、导出，任何一刻用的都是同一套三角形。

### 镜像和曲面细分的修改器怎么接（user：「想一下mirror和曲面细分modifier怎么接得住」）

现状（我核了代码）：镜像的两半现在都是真的面；细分是一次性做完的动作，做完就是真的面。两样都还不是「实时的修改器」。所以现在的设计接得住现状（镜像的面交代自己是谁的镜像，两半共用同一块像素）。下面说的是以后它们变成实时修改器时怎么接。

**一条总规矩**：画画只认「最后显示出来的那套三角形」。修改器不管做了什么，交出来的每个三角形都要带两样东西：它的每个角对应贴图上的哪一点；它是从原来的哪张面来的。有了这两样，落点、笔、涂抹、套索全都不用知道有修改器。

- **镜像（只有一半是真的，另一半是照出来的）**
  - 照出来的那一半没有自己的面，它显示的是同一块贴图像素的镜像。所以画是天然对称的。
  - 点在照出来的那一半上：落点落在照出来的三角形上，它带着贴图坐标，直接知道是哪一格。
  - 笔尖靠近中缝、同时碰到两半：把笔尖照一份到另一侧，真的那一半的每个贴图像素看自己陷进哪一个更深。这就是「镜像出第二支笔」。
  - 想左右画得不一样：先把镜像变成真的面，再点「分开两半」。
- **曲面细分（你编辑的是粗的笼子，显示的是细分后的光滑表面）**
  - 贴图坐标存在笼子的角上。细分时每张笼子面的贴图区域按同样的方式一分四、再分四，不做平滑。这样每个贴图像素永远属于同一张笼子面，块的形状和位置都不变。
  - **显示的是细分后的面，坐标就用细分后的面算**（user 11-10 深夜问的就是这个）：求落点是射线和细分后的小三角形求交；每个贴图像素属于某个细分后的小三角形，用它的公式算空间位置。所以笔是贴在光滑的表面上画的，不是贴在粗的笼子上，和显示一致。
  - 改细分的级数、或者挪笼子上的点：贴图像素不动，画跟着表面走。
  - 细分后的小面几乎都是平的，上面那个「对角线会跳」的问题在这里基本不存在。
  - 代价是三角形多了（一张面变十六张或六十四张），落点要用加速结构，见下一节。

### 边画边看的速度（user：「realtime feedback这个性能也许得好好想一下」）

以下的数字都是估的，没量过。先说每一帧里要做的事和哪几处会贵，再说结构上怎么防。

**一帧里的事**（目标是 iPad 上一帧十六毫秒以内，Pencil 支持的话争取八毫秒）：

1. 收这一帧的笔点，平滑。几乎不花时间。
2. 把新的点落到表面上：每帧几十条射线。
3. 沿路走出新的笔尖，找每个笔尖碰到的三角形。
4. 把新的笔尖画进这一笔的薄层（在贴图的格子里）。
5. 薄层合进图层，得到合成图。
6. 合成图补边、更新缩小图。
7. 画三维场景。

**会贵的四处，和对策：**

| 哪里 | 为什么贵 | 对策（结构上的，第一天就这么做） |
|---|---|---|
| 射线求落点 | 每条射线和所有三角形挨个试，几千个三角形时一帧就要好几毫秒；细分之后更多 | 相机停下来时，把三角形按它们在屏幕上的位置分到一张格子里；每条射线只试自己那一格里的。相机不动就不用重建，而操作期间相机本来就是锁住的 |
| 长笔画 | 如果每帧把整条笔画的笔尖全部重画，笔越长越慢 | 已经定型的那一段只画一次，攒在一张图上；每帧只重画还会变的尾巴 |
| 大的软笔 | 一个笔尖盖住几万个贴图像素，一帧几十个笔尖 | 每个笔尖只画它碰到的三角形的外框，不画整张贴图；这是量级上最大的一块，要在 iPad 上量 |
| 补边和缩小图 | 整张图每帧重做太贵 | 只做这一帧改到的那一块 |

**另外三件：**

- **落笔那一下不能卡。** 分格子、建表、编译着色器，都放在进入画画状态时、相机停下来时、模型改完时提前做好，不放在落笔那一刻。
- **抬笔那一下。** 抬笔要把结果从显卡读回内存一次（内存里那份才是正本）。一笔如果碰到了贴图上离得很远的几块，整块读回会顿一下，接着排线的时候能感觉到。对策是按块分开读。还不够的话，要把读回改成不等它完成就继续，那是动内核的事，量了再决定。
- **跟不上的时候。** 宁可笔迹慢半拍追上来，也不画一个和结果不一样的简化预演。这是「预演就是结果」的直接推论。

**怎么量**：无头的环境里只能量 CPU 那一半（射线、走步、找三角形）。显卡那一半要在真机上看。我会做一个画画时能开的小读数（每帧各段花了多少毫秒），你愿意看的时候看一眼告诉我就行。

## 五、画画那边要动什么（「父母和小孩对齐」）

好消息是不用大动。我按「磨草稿需要什么」排，不搞一次性大搬家：

**毕业之前必须做的（都不改变画画软件的行为）：**

1. **取样的两处改成「照坐标表取」**：烤笔画时去哪取颜色（现在写死「原地」）；浮层变换时去哪取源像素（现在是一个矩阵，前后各能再垫一张表）。画画软件不给表，走的还是原来那条路，输出逐像素不变。
2. **撤销记录的出口做成接口**。现在内核封好一步的记录，直接塞进画画自己的撤销栈；改成交给「宿主的栈」。三维这边的撤销本来就是同款设计（它的文件头写着照画画的撤销栈做的），画的记录登记成它的一个部件，建模和画画共用一条撤销线、共用 128 MB。（那个文件头还记着你 10-27 的一句话，意思是画画不另开一条栈；这句我没回原始记录核。）
3. **显卡接口加两个小口**：能上传浮点数的坐标表；能把合成好的图交给三维的渲染器直接用（只在浏览器那份实现里，内核本身不用）。
4. **套索和变换的引擎挪进内核的文件夹**（内容不改，只挪位置）。它们是第一批要用的，所以这次就挪。
5. **拷贝机制和守卫**（第十一节）。

**以后哪一段用到再做的：**

- **小块的边长 256 要不要改**（user 11-10 深夜：「可以好好想想」）。我查了全部用到的地方，结论是这一轮先不改：
  - 没有按 256 预先开好的大数组。用到的地方分三种：运行时现算的（十几个文件，改成参数不难）；模块一加载就算好的两个常数（一块有多少字节）；着色器源码里直接写死的 `256.0`（两处，各有一份纯 CPU 的对应实现）。后两种改起来要小心，改漏一处就是画面错位。
  - 我重读了你 10-30 那句「不是 256 池」。结合同一天你说的「texture pool……得和我们自己的内存管理合并，而不是各管各的」，我现在的读法是：你不要的是一个自己管自己的固定大池子，不是 256 这个边长。这件事由上面「预算归宿主」解决。（这是我的读法，不对的话告诉我。）
  - 边长大了对小贴图的浪费，实际只发生在正在画的那几份画上：没在画的画在显卡上只留一张合成图，不占小块。一张 32×32 的小图醒着时多占 256 KB，量级上不是问题。

- 「边画边看」现在由画画的界面层编排，底下的两个动作（合成一帧带笔画的画、抬笔烤定）已经在内核里。三维先直接用这两个动作；等画画那边要收拾界面层时，再把编排也收进内核。

**对画画软件的风险和怎么防**：它是你天天用来出活的工具，这是最要小心的。每一步都必须「行为不变」，拿它现成的两百来份测试加逐像素比对的基线把关，一小版一小版推开发版，正式版不动。

### 发动机和撤销、显存怎么拆（两个软件用同一台发动机的前提）

user 11-10 夜：「if the engine is good enough, perhaps we can 结婚 instead of 分家生小孩，the two app use the same engine. that is ideal. but the problem is the engine is entangled with undo system and vram management. and catsup of course have a more superior one」；同夜拍：「同一份内核，不各自长，然后3d这边改了也要和画画协调」。

缠在一起的其实是两种东西，拆开看：

| | 留在发动机里（机制） | 交给宿主（谁说了算） |
|---|---|---|
| 撤销 | 一步的记录怎么产生：写的时候把旧的小块扣下来、开着的事务只许一个、取消就原样退回 | 撤销栈本身：顺序、配额、标签、一步算多少、能不能撤 |
| 内存和显存 | 小块池、压缩、显卡上的缓存、丢了上下文之后从内存重传 | 给多少预算、什么时候让出来、超了怎么告诉人 |

- **三维当宿主**：画的记录登记成它撤销栈的一个部件，建模和画画一条线、共用 128 MB；显卡缓存登记进它的常驻表。它的常驻表要的正好是两个钩子「放掉显存」「报现在占多少」，内核的显卡缓存扔了能从内存重建，对得上。
- **画画当宿主**：先把它现在的撤销栈和那几个预算常数挪到宿主一侧，行为不变。以后要不要换成三维那套，等三维这边跑稳了另说，不在这一轮。
- **如实说「三维的更好」好在哪**：撤销是整套都更好（部件登记、差量、每步带标签和会话、一个配额）。显存是记账和纪律更好（一个预算、超了披露、闲置几秒自动放）；但块一级的淘汰、钉住、丢上下文后重传，只有画画那边有。所以机制用画画的，账听三维的。
- **协调的规矩**：内核只在画画仓改。三维这边需要改内核时，先看画画软件受不受影响，跑它的全套测试和逐像素基线，推它的开发版，再拉过来；两边的账各记一行。

### 空间里的一笔怎么走（1-4 的草图；施工单还没写，写的时候以那时的代码为准）

```
按下
  落点（1-3a）：打中了哪个面、哪一格；这张面在不在某张画上
  笔的大小：屏幕上的直径 × 落点那里一个屏幕像素在空间里有多大 = 空间里的直径。定死，一笔之内不变
  要画的每张贴图各开一个档口（0-5 的 host 方式）；多选多画 = 好几个档口，宿主把它们并成自己的一步

每来一个点
  一笔的手感（0-6）：滤抖、压感 → 平滑好的中心线（屏幕上）
  落成路：中心线每隔几个屏幕像素取一点、各打一条射线 → 空间里的点；
          相邻两点在空间里隔得比屏幕上该有的远得多（从胳膊跳到了身子）= 断开
  走步（0-6）→ 笔尖列表：前一段已经定型，后一段是还会变的尾巴
  每颗笔尖：用空间索引找它这个球碰到的空间三角形
  画薄层（空间层自己的着色器，走内核的显卡接口，不经过渲染器）：
      每个「笔尖 × 空间三角形」画一次，盖住这个三角形在画布上的包围盒；
      每一格：归属表说这一格是不是这个画布三角形的 → 是，就用这个空间三角形的公式算出格子中心在空间里的位置
              → 到笔尖中心的距离 → 边缘曲线 → 这一格吃多少
      定型的笔尖画进「定型层」，只画一次；尾巴每帧重画进「尾巴层」；
      薄层 = 两层合起来（淡彩取最大，叠色按先后叠）→ 上色 → 交给档口
  内核合成 → 拷进显示图 → 渲染器画一帧

抬笔
  收笔的渐细要等这时才知道总长：最后一小段重画
  逐张落层（内核的写回链，只读回碰到的那一块）→ 每件作品封一步 → 宿主的栈收成一步
```

要点：

- **镜像的两半**共用同一块画时不用特别处理：笔尖在右半边，碰到的是右半边的空间三角形，画进的是两半共用的那几格，左半边自然也有。
- **每一帧的活只随「新定型的笔尖 + 尾巴」涨**，不随这一笔已经多长涨。
- **数据怎么进着色器**：显卡接口每个实例只给四个数，所以实例里只放「第几颗笔尖、第几个三角形」，笔尖、公式、归属表都放进单通道 32 位浮点的数据贴图里取。位置不许放进半精度的图。

  - 球碰到的面里，哪些算数。user 定过：拐角另一边吃不吃是笔刷的选项；只吃连着的那一片由笔自己判断，蒙版兜底。草图的默认 = 从落点所在的三角形出发，沿公共边走得到、而且和球相交的那一片。
  - 背对着视线的面吃不吃。
  - 落密的间隔取多少、断开的门槛取多少，要量着定。

## 十一、同一份内核的机制

- 正本：画画仓的 `src/backend/` + `src/common/`（文件夹名不改，省得动几百处 import）；工具引擎以后挪进 `src/backend/tools/`。
