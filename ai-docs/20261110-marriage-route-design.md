## 一、一页结论

1. **画画那边的核心已经是一台能单独搬走的发动机。** 我读了它的代码：约 1.7 万行的后端只依赖自己和四个第三方小库，几乎不碰界面；套索、变换、形状笔、涂抹、液化这些工具的引擎（约四千行）也都不碰界面，只是文件还放在界面那一层。所以「抄」不用重写，要做的是划清边界、原样搬。
2. **加功能的成本想不涨，靠一条规矩：工具不知道三维，三维不知道工具。** 所有工具只认识一块平面（下面叫「笔画台」）；三维这边只负责两件事：把笔画台上的东西落到模型上（推），把模型上的画按屏幕的样子取下来（拉）。这两件事各写一次，以后每个工具都自动能用。
3. **两边用逐字节相同的一份内核，正本放在画画那边，三维机械地拷、不许手改。** 只抄一次、各自长的话，以后每搬一个功能都要先比对两边漂了多远，成本会越来越高，正好是你不要的那种。这一条改了 10-30 的说法，要你点头（第八节第 1 件）。
4. **第一笔不用等铺贴图的算法。** 先用最笨的铺法（每张面自己一小块，10-30 已经认过这是自动铺的退化情况），就能在模型上画。好的铺法后面换。
5. **路线五段**：整理内核 → 第一笔 → 接住现成的带贴图模型 → 眼睛（套索 + 贴上去 + 调位置）→ 铺得好。之后的图层、涂抹、形状、滤镜都是「拉过来加个按钮」的量级。

## 二、两条路怎么走：角色就是这一轮的考卷

你问：先做贴图纪元，还是你老老实实做一个二次元角色、边用边暴露问题；没有创作实践会不会飘。

- **架构和数据结构对，只能保证不返工，保证不了好用。** 飘有三种：地基错了（最贵，靠设计防，今天这份）；做了你用不上的东西（靠拿真作品排顺序防）；一千个小别扭（只有你真做东西才冒得出来）。后两种设计防不了。
- **所以不是二选一。** 你做角色的前半段是白模，这段冒出来的多半是操作上的事，改接线就行，一版一版小修，和内核整理互不挡路。等白模差不多了，第一笔和「接住现成模型」也到了。
- **毕业条件我建议绑在这个角色上**：不是抽象的「能画」，而是「这个角色的脸，在三维软件里画出来，中间不切别的软件」。之后每一段先做哪个，看角色下一步缺什么。
- 做二次元角色还缺哪些建模功能，我没有逐项查（细分、对称、倒角、环切、挤出这些都有）。缺的让角色来告诉我们，比我猜的准。

## 三、成本从哪来，怎么压住

加第 N 个功能会变贵，原因就四个。每个原因对一条对策：

| 变贵的原因 | 对策 |
|---|---|
| **两份代码各自长**：搬功能前要先看两边差了多少 | 两边同一份内核，机械拷贝，测试拦手改 |
| **每个工具都要自己处理三维的事**（投影、遮挡、接缝、一笔画到两个物件、镜像） | 这些全收在三维的「接头」里，每件写一次；工具里一个字都不出现 |
| **每个工具都要自己处理画画的老规矩**（选区、锁透明、混合模式、图层、撤销） | 画画那边已经做对了：所有笔走同一条落笔流程，这些规矩都在流程里，不在工具里。原样继承 |
| **每个工具要在两套界面里各写一遍面板** | 工具自带一张参数清单（滑杆、开关、下拉），两边各用自己的通用面板照着画。三维这边已经有一个参数面板的模块（能不能直接照清单画，我没细看） |

结果是一张加法表，不是乘法表：

| 要加的东西 | 内核 | 三维的接头 | 界面 |
|---|---|---|---|
| 一种新笔 / 新工具 | 写一次，两边都有 | 不动 | 各加一个按钮 |
| 画画那边已有的工具搬到三维 | 不动（已经在内核里） | 不动 | 三维加一个按钮 |
| 三维特有的本事（对称着画、整理贴图、补接缝） | 不动 | 写一次，所有工具都有 | 一个开关或右键项 |

**你关心的「要读多少代码」**：加一个工具，要读的是内核里一页契约、一个现成工具当样子、这个工具自己的文件。和已经有多少个工具没关系。这一条我会做成测试：工具的文件里出现三维的词、或者接头里按工具名分情况，测试就红。

## 四、架构：一张图，四个词

```
        画画软件                               三维软件
 ┌─────────────────────┐            ┌──────────────────────────────┐
 │ 界面 · 手势 · 图库     │            │ 界面 · 手势 · 模型 · 渲染        │  各写各的
 ├─────────────────────┤            ├──────────────────────────────┤
 │ 接头：画布就是笔画台    │            │ 接头：屏幕是笔画台               │  各写一次
 │ 推 = 原地落下          │            │ 推 = 投到模型上；拉 = 反过来取     │  和工具无关
 ├─────────────────────┴────────────┴──────────────────────────────┤
 │                 画画内核（两边逐字节同一份）                         │
 │  笔 · 橡皮 · 套索 · 变换 · 涂抹 · 填色 · 滤镜 · 图层 · 选区          │
 │  小块存储 · 合成 · 撤销记录 · 显卡接口（另有纯 CPU 的一份，测试用）    │
 └──────────────────────────────────────────────────────────────────┘
```

四个词：

- **内核**：上图最下面那一层。不碰界面、不知道自己在哪个软件里。
- **笔画台**：手在上面动的那块平面。画画软件里它就是画布；三维里它是屏幕（像隔在你和模型之间的一块玻璃）。笔的手感、平滑、压感全在笔画台上算，所以三维里的笔和画画软件里是同一支。
- **一份画**：一个物件身上那份分层的画，就是画画软件里的一个文档，只是没有自己的窗口。图层、草稿层、混合模式、选区都是它自带的。
- **推和拉**：
  - **推**：把笔画台上的一块落进一份画里。画画软件里是原地落；三维里，每个贴图像素算出自己在屏幕上的位置，去笔画台上取颜色，被挡住的不取。这就是你 8 月说的「贴图整张反算屏幕坐标、拿屏幕的笔画缓冲、按深度筛」，也是你 2012 年论文 3.1.3「逆转思维」反过来用：遍历要填的那一边，反查来源，所以不漏像素。
  - **拉**：把一份画的某一层，按现在的视角画成笔画台上的一张平面图。涂抹、模糊、套索抬起、取色要先看到笔底下有什么，用的是它。

为什么说有了推和拉就够了。画画那边的工具按「边画边看」的方式分四类，每一类在三维里都有着落：

| 画画那边的做法 | 哪些工具 | 三维里怎么来 |
|---|---|---|
| 笔画先攒在一张浮着的薄层上，抬笔烤进图层 | 画笔、橡皮、形状笔、填色、贴图片、浮着的变换 | 薄层在笔画台上，烤的时候**推** |
| 把图层的一块拷到显卡上直接改，抬笔写回 | 涂抹、模糊、水彩式的笔 | 先**拉**出这一块，在笔画台上改，再**推**回去 |
| 在一份替身上改，抬笔换回 | 液化、滤镜笔 | 同上 |
| 直接改图层的像素 | 像素笔 | 笔尖点到模型上，算出是哪个贴图像素，直接改（10-30 拍过的像素笔） |

所以三维这边为画画要写的东西是固定的一份：推、拉、点到哪个像素，再加写完之后的收尾（补接缝、缩小图）。不会随工具变多。

另外几件事在这个架构里是白送的，列出来是想说明「越后面越便宜」不是口号：

- **对称着画**：推一次的时候用正常的视角，再用镜像过的视角推一次。所有工具同时获得。
- **一笔画过两个物件**（脸和头发是两个物件）：同一块笔画台，分别推进两份画，撤销算一步。
- **贴上去的图转视角时怎么办**（10-30 留着没定）：图浮在笔画台上，你转模型，它在玻璃上不动，落点跟着变。这是架构自然给出的答案，像 Blender 的模板。
- **修改锁**：内核的写入口本来就有一道门，三维以后做修改锁时直接接上。

## 五、画画那边要动什么（「父母和小孩对齐」）

好消息是不用大动。我按「第一笔需要什么」排，不搞一次性大搬家：

**第一笔之前必须做的（都不改变画画软件的行为）：**

1. **取颜色的那一行加一个接头**。现在烤笔画时写的是「在原地取」，改成「问接头去哪取」，画画软件给的回答永远是「原地」，输出逐像素不变。
2. **撤销记录的出口做成接口**。现在内核封好一步的记录，直接塞进画画自己的撤销栈；改成交给「宿主的栈」。三维这边的撤销本来就是同款设计（它的文件头写着照画画的撤销栈做的），画的记录登记成它的一个部件，建模和画画共用一条撤销线、共用 128 MB。（那个文件头还记着你 10-27 的一句话，意思是画画不另开一条栈；这句我没回原始记录核。）
3. **显卡接口加两个小口**：能上传高精度的位置表；能把合成好的图交给三维的渲染器直接用（只在浏览器那份实现里，内核本身不用）。
4. **拷贝机制和守卫**（第十一节）。

**以后哪一段用到再做的：**

- 小块的边长从写死的 256 改成开机时给的数（三维用小的，贴图小，256 一块太浪费。你 10-30 说的「不是 256 池」）。
- 套索、变换、形状笔、涂抹这些引擎的文件，从界面那层挪进内核的文件夹（内容不改，只挪位置）。做「眼睛」那一段时挪套索和变换。
- 「边画边看」现在由画画的界面层编排，底下的两个动作（合成一帧带笔画的画、抬笔烤定）已经在内核里。三维先直接用这两个动作；等画画那边要收拾界面层时，再把编排也收进内核。

**对画画软件的风险和怎么防**：它是你天天用来出活的工具，这是最要小心的。每一步都必须「行为不变」，拿它现成的两百来份测试加逐像素比对的基线把关，一小版一小版推开发版，正式版不动。

## 六、数据：现在必须定死的，和可以慢慢做的

**必须现在定（以后改要迁移老文件，贵）：**

1. **画属于物件，不属于材质**（要你拍，第八节第 2 件）。
   - 材质管的是「能平铺的图案」：砖墙、木纹，很多物件共用，按真实尺寸铺。这部分现在就有。
   - 物件身上的画是独一份的：小红帽的脸、墙角那块苔藓。它叠在材质上面，没画的地方透出材质。
   - 这样你 10-27 卡住的那件事（平铺的墙想在局部画东西，又不想把整面墙变成独一份）就有答案了：墙还是砖墙材质，苔藓画在物件自己的那份画上。
   - 同一个组件摆了三份，三份共用一份画（和几何一样）；想单独画就先变成独立的。
   - 你 10-30 定的「用户只关心像素密度，密度挂在物件上，脸单独一个物件」和这条是一回事。
2. **文件里怎么存一份画**：一份分层的源文件（就是画画软件的那种开放格式，ORA）加一张合成好的图。合成图给 Blender、Windows 预览这些别的软件看；分层的给我们自己读。这是你 9-06 就说过的「存档文件可以内嵌 ora」。好处是零新格式，拿出来画画软件能直接开。
3. **贴图坐标存「第几个像素」**，挂在「角」上（10-30 定的四种挂点之一），只在画了东西之后才存；一套；画过的小块钉死不动。（10-30 都拍过，这里只是确认进这一版格式。）
4. **贴图是文件里独立的一条**，有自己的身份号，材质引用它（家规，账上本来就排着）。

**可以慢慢做（先用最简单的，够用再换）：**

- 显存统一记账：先让内核的池子报数，统一调度以后做（10-30 你同意的两步走）。
- 没在画的那些画，在显卡上只留一张合成图，内核的那套设备只给正在画的开。
- 接缝补边和自己做缩小图：第一笔先用「不平滑采样」躲开，铺得好那一段再做。
- 笔的大小：先按屏幕算（和画画软件同一个手感，拉近了画细节），「按模型上的真实大小」以后加。

## 七、路线：五段，每段一个毕业条件

| 段 | 做什么 | 毕业条件 | 谁能感觉到 |
|---|---|---|---|
| **0 整理内核** | 第五节前四件；三维拷到内核，内核的测试在三维这边也跑 | 画画软件输出逐像素不变；三维里内核测试全绿 | 你感觉不到 |
| **1 第一笔** | 数据格式第一版；最笨的自动铺法；推；画笔和橡皮；压感；撤销；存盘再打开 | iPad 上在一个方块、一个你自己建的模型上画，笔的手感和画画软件一样；转视角接着画；撤销；关了再开还在 | 你 |
| **2 接住现成的** | 贴图独立成条；导入图片；导入带贴图的模型不丢贴图和坐标；材质窗口；导出 | 小红帽带着贴图打开，补两笔，导出，Blender 里看是一样的 | 你 |
| **3 眼睛** | 拉；套索；复制粘贴；浮着调位置（挪、转、缩）；取色 | 你 10-30 说的那条链：拿一张图或自己画的眼睛，套索复制，拍到脸上，调几次位置，再用笔描干净，全程不离开视图 | 你 |
| **4 铺得好** | 真正的自动铺法（一圈圈的带子拉直、其余按最小拉伸）；密度；整理（只平移，无损）；重采样（明着做）；补接缝；自己做缩小图；像素笔 | 从零建的角色，不知道什么是 UV 也能得到能看的贴图；加一只手臂，旧的画一个像素不变 | 你 |
| **5 往后** | 图层面板和草稿层、锁透明、涂抹、模糊、形状笔、填色、调色滤镜、对称画、笔架、扒取窗口 | 每件都是「拉过来 + 一个按钮」，一件一小版 | 你 |

- **为什么第一笔排在材质窗口前面**：最硬的三个未知数（三维的渲染器和内核共用一块显卡画面、投影的画质、iPad 上跟不跟手）都在第一笔里。先打最硬的，万一要改地基，改得早。（要你拍，第八节第 4 件。）
- **你做角色的白模**可以从现在开始，不用等。冒出来的操作问题我记账，在段和段之间一小版一小版修。
- **痛苦主要在哪**：第 0、1 两段。0 是在你出活的工具上动刀，必须极小心；1 是三样新东西第一次接到一起。过了第一笔，后面每段都是在通了的管子上加东西。
- 版本号：进新纪元要升中间那一位，按家规升之前问你要不要把现在的推正式版（第八节第 5 件）。

## 八、要你拍的五件事，和我先按默认走的三件

**要你拍：**

1. **两边用同一份内核，还是抄一次各自长。**
   - 这是什么：10-30 你设想的是一个独立的小孩，画画软件不用它的代码，可以亲也可以冷落。我现在建议改成：内核只有一份，正本在画画软件里，三维机械地拷。画画软件仍然不依赖三维任何东西；三维随时可以停止跟随、从那一刻起自己长，所以随时能反悔。
   - 选同一份：以后画画那边的每个改进三维白拿；三维逼出来的修正画画也白拿；搬功能不用比对。代价是这一轮里画画软件会有几版内部整理（行为不变），每次动内核都要跑它的全套测试。
   - 选各自长：这一轮省事，画画软件完全不动。代价是以后每搬一个功能都要先看两边差了多少，越往后越贵。
   - 我的建议：同一份。
2. **画属于物件、叠在材质上面**（第六节第 1 条）。
   - 选是：小白不用知道贴图是什么，画就是画在这个东西上；平铺材质和局部手绘能共存。代价是导出给别的软件时要自动把两层压成一张（全自动，你看不见）。
   - 选否（画属于材质）：和 Blender 的习惯一样，但平铺的墙一画就得整面变独一份，而且「密度挂在物件上」会对不上。
   - 我的建议：属于物件。
3. **文件里用画画软件的那种分层格式存一份画**（第六节第 2 条）。
   - 选是：不发明新格式，取出来画画软件能直接开。
   - 选否：我们自己定一种存法，能更省空间，但多一份要永远兼容的格式。
   - 我的建议：选是。
4. **第一笔排在材质窗口和导入前面。**
   - 选是：最大的风险最早见分晓，你最早能在模型上画；材质窗口晚几天。
   - 选否（照 10-30 的顺序，先材质和导入）：先得到一批稳的小功能，风险晚暴露。
   - 我的建议：第一笔先。
5. **两个正式版要不要先推。**
   - 三维：现在开发版比正式版新很多（强行对称那一批都在）。升纪元前推一次，线上就有一个稳定的快照。
   - 画画：动它的内核之前把现在的开发版推成正式版，万一整理出了岔子，正式版是干净的退路。你 11-08 说过画画的正式版「等我用一段时间之后再推」，所以这条你定。

**我先按默认走，不同意说一声：**

- 贴上去的图浮着时，转视角它**贴着屏幕**不动（架构白送的答案）。
- 一笔只画进**你当前站在里面的那个物件**，别的物件只挡笔、不吃颜色（和建模时「只能改当前这一层」一致）。
- 笔的大小先**按屏幕**算。

## 十、提案接口（草案，实现中形状变了要回写）

```ts
// —— 内核 ——（正本在画画仓；三维只读）

/** 推的时候，贴图像素去笔画台哪里取。画画 = identity；三维 = projective。一笔之内冻结。 */
export type Placement =
  | { kind: "identity" }
  | { kind: "projective";
      posmap: Gl2Texture;            // 每个贴图像素在物件本地的位置（rgb）+ 是否被面盖着（a）；rgba32f，取最近点
      toStage: Float32Array;         // 16 个数：物件本地 → 笔画台像素（模型 × 视图 × 投影 × 视口）
      depth: Gl2TexSource;           // 同一视角的深度图（三维渲染器给）
      depthBias: number;             // 量纲：归一化深度
      taps: 1 | 4 | 16;              // 一个贴图像素在笔画台上占多个像素时取几个样（细线不断）
    };

/** 撤销记录的出口：内核封好一步，交给宿主的栈。画画 = 自己的 UndoStack；三维 = History 的部件。 */
export interface UndoSink {
  /** 令牌提交时内核调：一步的记录。 */
  push(step: UndoStepInput): void;
  /** 宿主的栈翻某一步之前 / 之后，回头告诉内核（令牌开着不许翻；翻完版本号 +1）。 */
  bind(hooks: StackWorkpieceHooks): void;
}

/** 工具自带的说明：两边界面照着它生成按钮和面板；接头不许读 id 分情况（守卫）。 */
export interface ToolDef {
  readonly id: string;
  readonly space: "stage" | "texel";                       // 在笔画台上工作，还是直接点贴图像素
  readonly preview: "overlay" | "region" | "shadow" | "livesync";
  readonly needsPull: boolean;                             // 要不要先看到笔底下的东西
  readonly params: readonly ParamSpec[];                   // 滑杆 / 开关 / 下拉，带单位和范围
  make(ctx: ToolContext): StrokeEngine;
}

// —— 三维的接头 ——（`src/paint/`，不在内核里）

/** 一个物件身上的一份画接到视图上。 */
export interface PaintSurface {
  readonly doc: PaintingWorkpiece;                         // 内核的一份文档
  placement(): Placement;
  /** 屏幕上一点落在这份画的哪个像素（像素笔 / 取色）；没点到 = null。走 CPU 射线，不读显卡。 */
  hit(sx: number, sy: number): { x: number; y: number; face: number } | null;
  /** 把一层按现在的视角画到笔画台上（三维渲染器画）。 */
  pull(layerId: number, stageRect: Rect): PooledFBO;
  /** 写完之后的收尾：补接缝、缩小图、通知渲染。和是哪个工具写的无关。 */
  afterWrite(changed: Rect): void;
}
```

`bakeStamps` 现在把「笔画的包围盒」同时当「读回范围」。投影之后两者不是一回事：读回范围由接头给（保守 = 整张；以后按碰到的面收紧）。

## 十一、同一份内核的机制

- 正本：画画仓的 `src/backend/` + `src/common/`（文件夹名不改，省得动几百处 import）；工具引擎以后挪进 `src/backend/tools/`。
- 三维：`src/paint/kernel/backend/`、`src/paint/kernel/common/`、`src/paint/kernel/vendor/`（相对路径照搬，文件一字不改）。
- `scripts/pull-paint-kernel.sh <画画仓的提交>`：拷文件 + 写 `KERNEL-MANIFEST.json`（来源提交、画画版本、每个文件的 sha256）。可以只拉一部分（不要录像、PSD 就不拉）。
- 守卫（三维）：内核文件夹里每个文件的哈希必须和清单一样（拦手改）；`src/paint/` 以外不许直接 import 内核内部文件，只走接头的出口；接头里不许出现工具的 id。
- 守卫（画画）：`src/backend/`、`src/common/` 不许 import 这两个文件夹和 vendor 以外的东西；不许出现界面接口（白名单：`ImageData`）；工具文件里不许出现 `Placement` 的内部字段。
- 规矩：**内核只在画画仓改**。三维需要内核变 → 在画画仓改、跑它的测试、推它的开发版（升末位）、再拉。内核自己的测试跟着拷，三维的 `npm test` 里也跑（用纯 CPU 的那份显卡实现）。
- 不做成 `@internal/*` 包：只有两个用户，改得又勤，包的仪式（打包、钉版本、升中间位要批）太重。出现第三个用户时再升级成包。

## 十二、头两段的工单切法（每张一个末位版本；门 = Fable 审）

第 0 段（画画仓，行为不变）：

- K-1 取颜色加接头：`blend-glsl.ts` overlay 分支 + `soft-shaders.ts` 等价实现；`Placement` 进 `OverlayInput`，缺省 identity。门：`gl-smoke` 基线逐像素不变、软实现对拍。

- K-4 画画仓的守卫 + 三维仓的拉取脚本、清单、守卫；内核测试接进三维的 `npm test`。

第 1 段（三维仓）：

- P-1 数据契约（Fable 先出一页 + 提案 `.h`）：`CATSUP_painting` 扩展（ORA 字节 + 合成图）、定义上挂「这份画」的身份号、角上的贴图坐标列（像素单位）、密度。迁移 + 冻结样本。
- P-2 探路：共用显卡上下文；内核合成图 → three 材质。只做到「内核画一个点，模型上看得见」。**不通就停下来报**，退路是读回再上传（慢但对）。
- P-3 位置表：CPU 上把三角形按贴图坐标画进一张浮点表（确定性，node 里测）；最笨的铺法（每张面一块，像素对齐，只平移打包）。

## 十三、和以前定的东西怎么对

**照旧有效（10-30 拍的）**：整个内核搬过来、撤销接上；UV 像素对齐；一套 UV；打包只平移不旋转；换布局像素不变；画过的小块钉死；自己做缩小图；全在视图里画、不做平面绘画；没有 UV 工作台，只有右键的「自动生成 / 整理 / 重采样」；静默重排；用户只管密度；像素笔；显存两步走。

**这份改了的（都在第八节里问了）**：

1. 「小孩是独立项目、只抄一次」→ 同一份内核，正本在画画仓。
2. 「不是 256 池」→ 不另写一个池，同一个池把边长做成开机参数。
3. 10-30 素材稿里「每层自己的 UV」早已降成脑洞，这里按「一套」设计。

**这份新定的（等拍）**：画属于物件、叠在材质上；用 ORA 存。
