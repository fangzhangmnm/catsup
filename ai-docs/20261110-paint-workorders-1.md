## 0-1 拷贝机制：两边逐字节同一份内核

### 要达到什么

三维仓里有画画内核的一份原样拷贝；拷贝是脚本做的，不是手抄的；有清单能核对每个文件没被改过；内核自己的测试在三维仓里也跑。这一张**不改内核的任何行为**，画画软件一个像素都不变。

### 文件怎么摆

画画仓的相对位置原样搬进三维仓的 `src/paint/kernel/` 下面，把它当成一个小的「仓根」：

```
三维仓 src/paint/kernel/
  src/backend/…        ← 画画仓 src/backend/ 原样（先不拉 timelapse/）
  src/common/…         ← 画画仓 src/common/ 原样
  src/shell/browser-gl2-port.ts   ← 画画仓那一个文件（真显卡的实现）
  vendor/…             ← 内核 import 到的那几个 vendor 库（upng、fflate；别的用到才拉）
  test/…               ← 内核自己的测试和它们用到的夹具
  KERNEL-MANIFEST.json ← 来源提交、画画版本、每个文件的 sha256
```

这样内核文件里的相对 import（比如 `../../vendor/upng/…`、`../common/…`）一个字都不用改。

### 画画仓这一半

1. 守卫测试（新）：`src/backend/` 和 `src/common/` 里的文件，import 只许指向这两个文件夹和 `vendor/`；不许出现界面的全局（`document.`、`window.`、`HTMLElement`、`localStorage`、`indexedDB`、`navigator.`）。现在已有的零星几处（`createImageBitmap`、`OffscreenCanvas`、`new ImageData`、`zip.ts` 里一处 `window.`、`painting-view.ts` 里一处 `navigator.`）列成白名单，白名单只许变短。
2. 一份清单 `ai-docs/` 下的「哪些测试算内核自己的」：判据是这个测试 import 的源文件全在 `src/backend`、`src/common`、`vendor` 和测试自己的辅助文件里。把名单和它们用到的夹具路径写下来，三维仓的脚本按这份名单拉。
3. 不动任何内核源码。升一个末位版本只为带上守卫和清单。

### 三维仓这一半

1. `scripts/pull-paint-kernel.sh <画画仓的提交>`：从同一台机器上的画画仓（`../20260524 WeebPaint`）按上面的摆法拷文件，写 `KERNEL-MANIFEST.json`。脚本只读画画仓。
2. 守卫测试（新）：
   - `src/paint/kernel/` 下每个文件的 sha256 和清单一致（拦手改）。**守卫只看仓内的文件和清单，不去读画画仓**（家规：测试不引用仓外的东西）。
   - `src/` 里除了 `src/paint/` 自己，不许直接 import `src/paint/kernel/` 里的文件。
3. 现有那些扫 `src/` 的守卫（键名、页面标题、小栗鼠的 import 守卫、红线守卫……）可能会扫到内核文件。逐个看：该把 `src/paint/kernel/` 当 vendor 一样跳过的就跳过，在施工记录里列出改了哪几个、各为什么。
4. 内核的测试接进 `npm test`。跑的时候用内核自带的纯 CPU 显卡实现。全套测试的时间不许因此超过一分钟（家规）；超了就只接一个子集，名单写进记录。
5. `tsc` 要过。两个仓的编译选项一样，按理不用改内核文件；真有过不去的地方，**停下来报**，不许改内核文件凑合。
6. `./bump.sh v0.19.0-<日期>`，`CLAUDE.md` 改纪元那一行，流程图文档加一小节「画画内核是拷来的，正本在画画仓」。

### 门

- 三维仓：`npm test` 全过，含内核的测试；`tsc` 干净；随手改一个内核文件的一个字节，哈希守卫变红，改回去变绿（在记录里写你试过）。
- 打出来的包大小：内核还没被任何地方 import，包应该不变大。写下前后的字节数。

### 碰到这些就停下来报

内核文件在三维仓的 `tsc` 下不过；内核的测试依赖了画画仓里内核以外的东西；现有守卫和内核文件冲突而且不是「跳过」能解决的；全套测试超过一分钟。

## 1-1 探路：共用显卡画面

### 要达到什么

回答一个问题：**三维的渲染器（three）和画画内核的显卡实现，能不能建在同一个 WebGL2 画面上，互相不踩，并且把内核合成好的图不经过读回、直接给 three 当贴图用。** user 定的：这是硬要求，「不惜一切代价争取」。读回再上传只许当一两天的脚手架，不许当成品。

这一张是探路，成果是一个答案加一个最小的能跑的例子，不是成品代码。

### 已知的事实

- 内核的真显卡实现 `BrowserGl2Port` 现在的构造函数只收一张画布，自己去要画面；全仓只有这一处要画面。
- 三维这边 `providers/three/render3.ts` 里是 `new THREE.WebGLRenderer({ canvas, antialias: true, powerPreference: "high-performance" })`，three 是 vendor 进仓的（`src/vendor/three`），必要时可以改我们自己这份拷贝。
- three 支持用一个已有的画面来建（构造时给 `context`）。
- 内核的显卡接口约定：每次画都自带全部状态，画完还原。

### 要试的

1. **让 `BrowserGl2Port` 能建在别人给的画面上**（画画仓，改 `src/shell/browser-gl2-port.ts`）：加一个入口收现成的 `WebGL2RenderingContext`。原来收画布的入口行为不变。
   - 要查的坑：它有没有哪里默认了画面是「干净的初始状态」。和 three 共用时，three 会留下任意状态：绑着的顶点数组、程序、帧缓冲、混合、深度测试、剔除、裁剪框、像素上传的那几个开关（上下翻转、预乘、对齐）、当前的贴图单元。内核每次画、每次上传之前必须自己把用到的状态设对，不能靠默认值。把你查到的、补上的逐条列出来。
   - 画面丢失和恢复：两边都在同一张画布上听事件，要确认不打架。
2. **三维这边在 three 的画面上建内核的显卡实现**，内核每做完一批，调 three 的重置状态；three 画完一帧之后内核再画，同样不许受 three 留下的状态影响。
3. **把内核的一张图交给 three**：内核用它现成的合成（一份 64×64 的文档、一层、中间一个红点）得到一张离屏的图，不读回，直接让 three 的一个材质采样它，贴在一个方块的一张面上。
   - 两条路都看一眼，报哪条走得通、各要动什么：在 `BrowserGl2Port` 上加一个「把这张图的显卡贴图句柄拿出来」的口，three 那边把句柄装进一个贴图对象；或者反过来，three 建好贴图，内核把结果画进去。
   - 需要改 vendor 的 three 就改，把改了哪几行、为什么写清楚。
4. 例子的代码放在 `src/paint/spike/`，只挂在调试入口上（`globalThis.__catsup` 下面），不进任何界面。配一个探针 `test/probes/probe-paint-spike.mjs`。

### 门（探针里查）

- 方块那张面上看得见红点（截图，再读那一点的颜色确认）。
- 内核画过之后，三维现有的画面没变：现有的截图基线照过。
- 整个过程 `gl.getError()` 始终是 0。
- 连着切换一百次「three 画一帧、内核合成一次」，结果稳定，没有偶发的错帧。
- 模拟一次画面丢失再恢复（`WEBGL_lose_context`），两边都恢复，红点还在。
- 画画仓：`npm test` 全过，逐像素基线不变（改的是 shell 那个文件的新入口，老入口不变）。
