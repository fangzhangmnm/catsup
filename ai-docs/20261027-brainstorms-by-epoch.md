## 纪元顺序（user 10-27 定，FM58）

现在 = **自由建模** → **接 Shader 实验室**（最有杠杆，但要先做一批架构决策）/ **绘制**（先 Grease Pencil 式草稿笔，再和 WeebPaint 结婚）→ **物理（生命之粉）**、**验证（猫娘）**在后。

## 跨纪元的原则（都拍了）

- 数据契约保持通用；几个基本的、图灵完备的工具兜底；其余都是语义工具（FM59）。
- 历史不存在，只有被打歪了的原子：动词做完就烘进状态，不留事件串 / 修改器栈；能改参数的只有刚做完那一步的马后炮（FM60、FM40）。
- 高频操作永远做成内置指令（镜像这类），几何节点以后也许捏着鼻子做（FM41）。
- 能做成「修复」式动作（做一次、烘进状态）的都不做自动实时处理；只有手感确实要实时的镜像、细分才自动，且只在网格体上，硬表面体照旧手动——「这样是最稳定的。要自动以后geometry node纪元再说」（user 10-30，材质纪元讨论「标签和材质要不要连」选了「做一次的动作」，`talks/20261030-material-epoch-attributes.md`）。
- 10-26 起不再抗拒撒点 / AAA PBR / 几何着色器（user 10-27）；各赛道的面数预算照旧。
- 同一个工具在两个工作台里语义和用法别差太多（设计稿 §2 的标准）。
- SU 不是 CAD 也不是自由建模，更像 Minecraft：一条公理长出来的一整套人机交互（user 10-27，FM81）——所以 brep 和 mesh 是两种物体类型，不是一个内核加开关。

## 1. 现在：自由建模（0.15）

**本轮冲刺的验收线**：冲刺结束时 user 能做出小红帽级别的白模（FM61）。分工：Fable 只管内核、定理、架构，内核优化写清取舍推给 user 拍；界面接线归 Opus（FM62）。

**已经拍的方向**
- 套索常驻，「合」做成选区之后的按钮；框选 / 套索都归选择工具（FM1、FM2）。
- X 光一个开关管单击和框选：关 = 只选看得见的，开 = 连背面；补每张面的中心小点；放到右上角锁旁边，锁要看上下文（FM3、FM44、FM48、FM51）。
- 双击 = 环，三击 = 整块；加「同材质」等灌面方式（FM9）。
- 刀：双击一条边 = 环切（Ctrl+R），另有模式按钮；切完马上能滑；要吸点和边；不带 XOR；按住键临时变橡皮（橡皮去边 = Blender 的溶解）（FM10、FM11）。
- 拉面沿法线；点 / 边走屏幕空间、按轴键换方向（FM14、FM15）。
- 绑骨变换（= 转）：带轴心、软影响；各工具自己记轴心和方向，不要 Blender 的全局设置（FM6、FM7）。
- 软编辑半径全局一份，像 WeebPaint 的笔刷大小滑条（FM20）。
- 雕 = 笔刷式沿法线挪 + 软半径（FM21）。
- 自动镜像：硬表面和自由建模都有，以正在编辑的那边为准；镜像面淡画、中缝的点高亮；镜像只管焊，复制多份走组件摆实例（FM23、FM36、FM39）。
- 吸附：必须有永远不吸，偶尔吸 = 按住 Shift（FM24）。
- 硬表面不要软 TRS（FM25）。
- 不分点 / 边 / 面模式，另给可选的筛子；笔优先，手指靠软鼠标（FM29）。
- 「.」= 缩放到选区，已做（FM28，v0.15.1）。

**本纪元要做的整理**
- 不常用命令和右键命令的收纳规则（FM35）；SU 模式右下角参数小窗太吵（FM5）。
- 理一张「每个操作做完后选区是什么」的表（FM14）。
- 选区扩一圈 / 缩一圈（FM27）。

**还开着、等 user 拍**（账本 §3 清单）：刀还是线、拉点 / 边默认垂线还是屏幕、拉和插按拓扑合并、刀什么时候算切完、SU 双击面要不要改、扩缩选区的键、框选 / 套索怎么切、绑骨变换三个默认、缝等不等 UV。

**内核路线（10-27 下午）**：user 改口倾向另做网格内核 + 手动转换 + 按类型分工作台；Fable 推荐稿 `20261027-kernel-route-bmesh-recommendation.md` 同意，并建议折边退役、SU 自动折缝改软 + 平滑；**user 10-27 下午拍了**：另做网格内核、名字 brep / mesh、折边退役 + SU 自动折缝改软 + 平滑（FM64）。

**等 Fable**：~~用 brep 加开关还是另做网格内核~~（→ 推荐稿）、「同一个灵魂」（转网格时带着 brep 元数据）、两个坑（刀绕一圈长夹层面；拖乱了凹的 / 带洞的面会破或乱）、brep 自愈（一次装进去再修、公理是不是归纳）、证明留档（周账 F-104、F-105、F-106）。全部 Fable 的活（内核 / 定理 / 架构 / 要 user 拍的优化）汇总在 `20261027-fable-kernel-math-ledger.md`。

**本纪元里的小愿望**
- 3D 游标，可设、可「移到游标」，也许取代充能（DT21）。
- 自由建模里软边用细一级的线（DT89）；硬边标记（DT65）。
- 拉多张面 = 有选区时的拉（FM25 / B18）；把边 / 点竖直拉起来当墙，SU 模式也要（FM16）。
- SU 倒角，放低频区（FM8）。

## 2. 接 Shader 实验室 / 渲染（Tron）

- 渲染模式不照 Blender 四种：**覆盖模式**（各种风格化预设：读贴图、顶点色、白模、线框）+ **全量渲染**（卡就关一些，主要靠聪明的离线加速）（FM49）。
- 每个风格自己声明支不支持 X 光：接得住的（如 Tron）有开 / 关两种画法，接不住的（玉石这类雕刻用）就不支持（FM46、FM54）。
- 量 X 光多画多少像素、Quest 接不接得住（FM55）。
- 普通线框风格还没做（FM46）。
- **剪纸画风加 AO**（user 10-30「wishlist 剪纸加AO」；前一句说的是「wishlist 加折纸AO」，随即改口）：剪纸 · 色纸现在已有「20 个方向遮蔽烘焙」当多重阴影（v0.17.11 `ao-bake.ts`），做之前先看为什么它不够 / user 要的是哪一种 AO。
- Tron 纪元风格化覆写大合集，第一条「水晶」（纪念 2014 图形学作业）（DT98）。
- 网格用叠加混合画在面上（B38）；只有轮廓和悬线才是粗线（B45）。
- 实验室留给 CatsUp 拍的：和工作台描边打不打架、性能取舍、要不要颜色映射、天空离线烘（实验室 handoff §3）。
- 着色器编辑器第一步 = 聊天框 + 类 Shadertoy + 一个 LLM 的 API key；到时要先开外接服务白名单（FM42）。
- **架构（user 10-27 下午，B49）**：渲染器从第一天按「能长到 GI / AAA 大场景引擎、远期也许接 Cycles」设计；材质 = 语义机制（和绘制纪元同一套），不用 shader graph，graph 只产出 shader、shader 是原子；开工前 grill 物体私有效果 vs 全局特效。
- 剖面：本质还没想好（渲染用的标记实体？后处理器？），UX 也许放进图层（FM52）。
- 图层放右上角锁和 X 光旁边，点开是原神角色列表那样带小眼睛的列表（FM53）——纪元未定，可能提前随 UI 做。

## 3. 绘制

- 2D 草稿绘图：画立绘 / 立面，借 WeebPaint 的铅笔或只借手感做 Grease Pencil（FM30）；轴和格点的本质是用来 2D 画画的，「画画平面」和「格点」可能是两个职责（FM31）；freehand 重新设计（B31）。
- **画语义不画 PBR 槽**：颜色、苔藓、腐朽……材质读语义；换材质语义留着（蜡娃娃 → 塑料 → 剪纸）；单通道语义我们拼 RGBA；导出时才翻成 PBR 或烤成漫反射（B48）。
- 不做专门的 UV 编辑器：右键「创建画布」；要更多像素 = 再开一张画布；判定标准 = 不用管贴图名字、不用起名、不用指派（B48）。
- UV 像素级对齐 → 加东西、重排都不丢；拉伸太厉害的先说清再问要不要重采样，用 WeebPaint 最好的重采样（B48）。
- 「乐谱」= 现在原子身上的语义，不是历史（B48，user 10-27 纠正）。
- 缝（UV 切线）标记（DT66）。10-30 夜 user：「pixel肯定是需要手工展平的……智能算法顶多算一下怎么割刀，但其实人类标edge property也就三分钟」——缝 = 表面工作台里一列边属性，其余全自动（讨论日记 `talks/20261030-pixel-uv-straighten.md` 第六轮）。
- **导出折纸图谱**（user 10-30 夜「这个工作流反而可以有，以后可以导出折纸图谱，进wishlist」）：低模沿边剪开、零变形展开（纸模那种），画好的贴图跟着印出来，能折成实体模型；和「256 tri 折纸是神器」（10-26）一脉。
- 和 WeebPaint 结婚：画贴图不切 app；套索 + 变换是刚需；每层自己的 UV 的 bodypaint 方案留着备用；matte painting（设计稿 `20261024-design-weebpaint-marriage-bodypaint.md`）。
- 图片导入深模块（参考卡片和贴图共用）（B42）。
- **参考窗里放白板**（远期愿望，不排期；user 11-12：「这个我还是蛮想要的，就是参考小窗里面你可以白板画一点东西。不过这个也不急」）。参考窗是家族共享的库，账记在家族周账 F-262。连带的一句：参考窗现在「绝对不能全屏，不能停靠」；以后能放白板了，它也可以停靠。
- **墙上涂鸦：splat、喷枪、柏林墙**（wishlist，本轮筑基不做；user 11-11，贴图纪元能画的第一天：「wishlist: 软件affordance逼出一个人类直观：墙上涂鸦的splat，喷枪，柏林墙。这个可能是未来的killer app本轮筑基的时候不做，但是是一个高价值unexpected点子」；同日在 v0.19.25 上往一个柱子上写了「√2 I see you」「you are here」之后：「非常intuitive的开始想在墙上写字了」「真的完全没想到会有这个behavior」）。Claude Fable 5.2 记的旁注（user 没说）：筑基时留心别把三件事写死——笔尖只能是贴在表面上的一个球（喷枪是从手里出去的一个锥）；一笔只能落到一张画上（一面墙可能是好几个物件）；只有网格体能画（墙多半是硬表面体，涂鸦也可以是贴在表面上的单独物件）。真做之前再设计。同日 user 追加：「墙上涂鸦关键是要有喷枪的手感和物理模拟，2d的时候喷枪就是一个软笔刷，但是3d的时候能做3d几何敏感的喷枪吗，这个我觉得会是killer，你可以回顾一下一个高质量的顶配warhammer模型是怎么涂装的」——讨论（能做、五条规律、战锤涂装对照表、一族对几何敏感的笔）在 `talks/20261111-geometry-aware-airbrush.md`。
- **移动设备上做大场景要省显存：显卡专用的压缩格式 + 按远近载入贴图**（愿望单；user 11-11 晚：「为什么专用的贴图是另外一个对象，我们如果要在移动设备上面做gta的话需要尽量省显存」）。Fable 摆的账（数来自 `src/paint/open-memory.ts`，小弟逐字节核过）：1024 见方的画打开、画过一笔后占约 29 MB = 给渲染器的显示图连缩小图 5.6 + 内核四张画布大小的帧缓冲 16 + 每格的表 8；没在画的物件只剩显示图。500 张 1024 的贴图就算都睡着也要 2.8 GB，500 张 256 的是 175 MB——所以先靠小贴图和重复利用，然后是这两样（现在都没有，是渲染引擎那一层的题目，Tron 账本里「串流」那一条的邻居）。显示图和内核的合成结果是两张图的原因：内核那张是来回倒的工作缓冲、从池子借的、没有缩小图；没在画的物件只有显示图。近处的杠杆（内核那四张缓冲闲了还回去、只醒着一个物件）归「很多张 atlas 时的显存」那张单。
- **缩小显示时不串色（边缘填充）**（**11-11 晚 user 改成必做**：「边缘填充 defringe必做……防白边」——不再是愿望单，跟导出带上画那张单一起做，见方向稿第五节末尾；以下是改之前的记录；user 11-11：「更好的mipmap算法，这个可以到愿望单里」「等真正看到串色了再去想，因为我们最后还是导出游戏引擎，所以我们还是按照标准做，要游戏引擎能接住比较好」）。做法和边界在 `20261111-paint-moves-design.md` 第五节末尾：每层排列不变、缩之前把岛边上的颜色往外填；导出按标准留边。
- **悬空白板上的手写标注**（wishlist，本轮不做；user 11-11，贴图纪元能画的第一天：「然后也许需要一个悬空白板写grease pencil对话气泡的东西，就是手写标注。这个会非常库，本轮不做，进wishlist，也许白板需要是scratchpad这种矢量的单独物体」「反正就是在建筑上面画箭头说这里是厕所」）。和上面「2D 草稿绘图 / Grease Pencil」（FM30）是邻居。Claude Fable 5.2 记的旁注（user 没说）：照现在的结构，它会是一种新的物体种类（矢量笔画住在一块悬空的板上），不是贴图；真做之前再设计。
- WeebPaint 的纹理笔刷纪元可以由 CatsUp 的真实需求带着做（B46 里 user 原话；碰到 WeebPaint 时再提）。
- **算法清单分三个家**（user 10-30 夜「专门是uv的算法和专门绑骨的算法和动画的算法分三个家」；同晚「按缝延展的防渗填边，每个岛自己画 mipmap。 也许得跟着uv」）：UV → `20261030-algo-uv.md` · 绑骨 → `20261030-algo-rig.md` · 动画（含 IK、曲线、二次动作）→ `20261030-algo-animation.md`。画画内核自己的（笔画缓冲取色、贴图像素笔）留在 `talks/20261030-bodypaint-kernel-uv.md`。

## 4. 物理（生命之粉）

整件事 = 一条「做到静止就停」的长指令：结果是静止那一刻的几何 / 语义，一步撤销，不出时间轴（B46）。

- **user 给的 / 批了的**：选一张面变布或枕头（布料参数、自动细分，结果是网格）；打碎一堵墙；扔一堆垃圾物理堆好；灌水；倒土 / 沙 / 雪（物质点法）；积雪盖顶、落灰；撞瘪 / 凹痕 / 弹孔（烘成高模或烘进贴图）；下垂、软塌、帐篷；磕边、风化（程序化或烘进贴图）；撒草粉烘进贴图；做旧归物理不归绘制；树叶直接刷、烘死锁定（有法线覆盖等旋钮）。
- **公式物理（user「同意，记账」）**：悬链线、静水面、休止角堆积、积雪落灰、苔藓、雨痕、缝里积脏 / 边上掉漆、日晒褪色 / 烟熏、梁的下垂、印章式脚印车辙、沿表面长的藤蔓。
- 侵蚀之类，不一定改几何，以后有地形类型时也可以只改材质（B46）。
- 原则：不零敲碎打，UX 只是在抽象数学外面包一层「物理转译」；有 PBR 接法线 / 浮雕，只有漫反射也有路由。

## 5. 验证（猫娘）

- 像魔兽争霸一样往场景里拖小人，点地让她走，验碰撞体；拖好几个看拥堵（B47）。
- 占位美术 = 胶囊体 + 一块面罩；小人的身高、胖瘦、能不能跳 / 二段跳 / 跳多高可配（B47）。
- 偏路点不偏导航网格；「走到哪烤到哪」= 真物理当标准答案、路点图当缓存；拥堵要给边记宽度；寻路到时候再定（不寻路的老算法 / 撒探针）（B47）。
- 人自己进去：第一人称 + 枪（从眼睛射 / 手拿带修正）、弹着反馈、推东西和牵引光束（要刚体物理，和生命之粉同一块地基）、手游式键位（B47）。
- 验证 = 常开叠加层：射界、两个地点之间走几秒几拍、人的尺度（设计稿 `20261024-design-verification-overlay.md`）；读数后面加「相当于什么」（B43）。

## 5½. 像素和单位的纪元包（候选，没排期）

user 11-11 晚（贴图纪元统筹会话）：「帮我记账就行」「嗯我说的是斜切的」「另一种是宝可梦、塞尔达那种，房子的正面和屋顶都不缩，都正对着你。这个非常需要」「对，到时候清查，不急，到时候做像素摄像机和屏幕的时候做，你这些也整理一个大的纪元包，也许可以和单位整理合租」。

这一包里有什么（原话和细节都在第 6 节第一条「单位」下面，这里只是收到一处）：

- **单位整理**（user 说以后会系统整理一次）：只给四个预设——公制、英制、奇幻、像素，每个配齐，不在各处单独配置；老式单位（链、浪……，D&D 要用）；二头身和各种头身比用自己的单位制；尺度参考跟着单位制走。
- **像素单位**：基本单位是格；细分 8 / 16 / 32 像素；往上一屏一屏，横竖可以不同，从模板挑或自己配。
- **像素相机**：正交；视角预设顶视、斜视、侧视、1:2，也允许透视；可以锁相机、按整格移动；都能配、能关。

## 追记（2026-11-13，Claude Fable 5.2）：材质纪元的核心愿望——加、撤、拆、并各种画法都不用每次做兼容

user 11-13：「以及我们材质纪元的核心wishlist：能不能我们后期加各种材质或者sunset的时候，我们不需要一开始像一个uber材质然后后面后悔，而是可以比较好的迁移过去，最小的backward compatibulity 比如如果我们一开始做了一个uber standard material，然后之后专门做了一个genshin的二次元渲染，然后又把uber拆成了几个高性能的东西，还做了专门的1bit，然后又撤了觉得它可以并进uber。我不想每次都需要backward compatibility」

统筹的初步想法（没验证，user 还没回应）：文件里不存「它是哪一种材质」，分三层。

1. **人做的数据，永远兼容**：颜色、画的贴图、画的遮罩、有物理意义的量。用和算法无关的方式存（通道有名字、贴图是独立的条目、物理量用国际单位）。现在的格式已经是这个形状。
2. **渲染的做法，不进文件**：万能材质、二次元渲染、1bit 都是拿第一层的数据来画的算法，和渲染实验室的视口预设是同一个东西。
3. **某种做法专属的参数，各自一个小包**：带名字和自己的版本号；不认识的版本原样带着走。

走一遍 user 的例子：加二次元渲染 = 多一个小包，老文件不动；把万能材质拆成几个高性能的 = 算法内部的事，文件看不出来；撤掉 1bit = 小包留着没人读、画面退回默认并提示一次、数据不丢；并进万能材质 = 一个明着的动作，user 点了才转，不自动转。

代价：保证「老文件打得开、人做的东西不丢」，不保证「老文件看起来永远一样」。和 10-30「兼容只管人做的数据，不管算出来的东西」是一回事。

风险：第一层自己长成万能材质（规矩：和算法无关、说得出物理意义的才进第一层）；二次元渲染那类需要专门画的图要存成有名字的普通遮罩、由小包指明怎么用；小包自己改版是各自屋里的事。

材质纪元开工时，这一条排在最前面想。

**同一条的前提（user 11-13 接着说）**：「关键是shader实验室我无法保证能枚举世界上所有的材质，所以我们必须假设第一稿standard material之后会吃书，不然我又会觉得需要一个完美的uber standard material，然后就永远没法动工了」

- 写成第一条：第一稿标准材质按「以后会吃书」来设计。不用先枚举完所有材质，也不等一个完美的万能材质才动工。
- 让吃书便宜的办法（统筹的想法，没验证）：第一稿标准材质的一切——有哪些参数、各是什么意思、把哪张图当什么用——都装在它自己的小包里，可以整包作废；作废时不写迁移，旧的小包原样留着没人读，画面退回新的默认画法并提示一次；要转就是一个明着的动作。
- 不能作废的只有 user 画的图本身：内容、名字、怎么铺。这一层要小到没有东西可吃书。
- **比上面那段更严的一条**：上面把「有物理意义的量」（比如粗糙度）也放进了不能作废的那一层。这也是一种承诺——「粗糙度」本身是某一套画法的说法。更稳：那一层只认「一张有名字的图」，不认它代表什么；「这张图当粗糙度用」写在小包里。颜色倾向留在那一层（每种画法都要、现在已经在）。
- 对动工的意义：第一稿故意做小，只支持手上真要用的；吃书是计划内的事，代价是「用了第一稿的文件外观变一次」，不是文件坏了。

**愿望单，等属性地基做完顺手做**

- 自由建模的自动合并（拖动时一个点挪到离别的点够近就合并）。统筹查了代码：现在没有通用的，只有镜像编辑把点落到中线那一处；硬表面里两个点落到同一个位置本来就是同一个点。

**叫法（统筹的建议，等 user 说）**：attribute =「元素属性」（点、边、面、角、面边、面的一侧统称元素），property =「物体属性」。不用「图元」：Houdini 的中文圈里图元专指面。

**边的标记并起来的规矩，和 Blender 的区别**：Blender 合并点时不并标记，挤出时硬边和接缝都是「有一条有就算」；我们的硬边是三种状态（手标成硬 / 手标成平滑 / 没标照缺省），所以是「说法一致才算、不一致交给缺省」。「隐藏」现在是有一条隐藏就隐藏，统筹觉得该是看得见的赢，等小弟核它的意思再定。

**硬表面归一那一轮（下一轮，开工前好好讨论）**

- 顺序（user 定）：属性地基轮做干净 → 画画和材质的尾巴全部收掉 → 硬表面。统筹把「尾巴」读成：画跟着面走第 2 到 4 刀、搬画、导出带上画、展开接进「开始画」、材质面板第一版。
- 目的（user 定）：为了简化，不是为了复杂和多功能；找两个引擎的共同点，尽量归成一套。
- 要有的（user 定）：硬表面也支持贴图和画（他实际用硬表面更多：小房子、坦克）。现状：硬表面的面上不能直接画，只有按真实尺寸平铺的贴图（含平铺的画），正反两面分开。
- 属性表接不接得住硬表面（统筹的判断）：接得住。半边 = 面边；半面 = 面的一侧；带洞的面只是角和面边分成几圈；装不下的只有曲线。
- 一个先放着的想法（统筹的，没定）：硬表面的面是平的，平面上的贴图坐标 = 位置乘一个固定的变换，所以不用每个角存坐标，每张面的每一侧存一个变换（挂在「面的一侧」上的一列）就够；切开时两半照抄，没有误差；SketchUp 摆贴图就是这个思路。
  - **user 当晚的回答，这个想法降级**（语音转写，原样）：「哎，你说的这个有意思，就是印表面的贴图坐标是强制平的，但是说有没有这种可能，就是硬表面我们还是希望我们在给它进行一些uv编辑，有一些拉伸。就是我觉得这两种模式就相当于强制凭着的问题是，强制的不是就是你说一个变换的话，它的问题是我们对面移动的时候，这时候它上面显示的，比如说砖墙的纹理会跟着滑动，这对三平面投影这些东西是很好，但如果是手绘的就不行，所以我觉得是。变换只适合于那种平铺的材质，但是如果是这种手绘的单品的材质的话，我还是建议用 UV。」
  - 定下来的方向（user）：分两种，硬表面和网格体一样。平铺的贴图 = 坐标从位置算出来，面挪了贴图留在原地、面变大就多铺（砖墙、三平面投影）；手绘的单品 = 每个角存坐标，画粘在面上、跟着面拉伸。硬表面那一轮要给它的面的角也挂上属性。
  - 统筹补的理由：从位置算的坐标，面一拉大，它在画布上占的地方也变大，会压到别的面的画；每个角存坐标时面在画布上占的那一块是固定的。那个「每一侧存一个变换」的想法最多用来摆平铺贴图的位置和角度。
  - 留到那一轮讨论的难处（统筹）：硬表面共面的面会自动并起来，两张各有各的画的面一并，画对不上，怎么办、怎么告诉人。
  - **平铺的默认全自动；贴照片的工具记愿望单**（user 同一晚，语音转写，原样）：「然后是平坡的话，我建议是就默认自动吧，都甚至不需要。哦，不对，就有一种情况是 photo bashing，对你说的对，photo bashing 的话，我们到时候可以加一个专门的贴照片的贴图工具在印表面里面，这个会是一个杀手应用，以后有空做。」（「平坡」= 平铺，「印表面」= 硬表面。）
    - 平铺的贴图：按真实尺寸自动铺，不给每张面单独摆位置（现状就是这样）。
    - 贴照片（photo bashing）：以后在硬表面里做一个专门的工具，把照片摆到面上，调位置、角度、大小。「每张面每一侧存一个变换」用在这里。愿望单，不排期；和任务清单里的「从视角铺」「水贴」是一家。
    - user 随后：「平铺可以每个面不一样，对photobashing来说是神器」。统筹的读法：「这张面的贴图怎么摆」= 挂在「面的一侧」上的一列（一个变换）；没有这一列或取缺省值 = 自动平铺；只有单独摆过的面有自己的值。正好是属性表「可以没有 = 缺省值」的用法，不另起一套。
- **硬要求：两个引擎共用属性的数据结构；以后的蜡笔、曲线也可能共用**（user 同一晚）：「对，就是至少他们都共用你这个 attribute 的数据结构，我觉得这个我比较希望要。然后以后我们做像这种 grease 扳手、曲线或者别的东西，说不定也能共用。」记在规程第三节：属性表这一套不认识具体有哪几类，类别由几何的种类给。
